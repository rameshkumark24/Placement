# Part 1 — The flow

```
⭐⭐ THE FULL PATH, INCLUDING THE PARTS PEOPLE SKIP

⭐   ① ⭐ /login  ⇒ POST credentials
⭐   ② server sets HttpOnly cookies (Day 235), returns the user
⭐   ③ ⭐ client puts the user in the query cache under keys.users.me()
⭐   ④ ⭐⭐ REDIRECT TO ?next= — NOT TO THE HOME PAGE.
⭐      ⭐ The user clicked a deep link, got bounced to login, and
⭐        MUST land where they were going.
⭐   ⑤ every subsequent request carries the cookie automatically
⭐   ⑥ ⭐⭐ ON 401 ⇒ THE TRANSPORT REFRESHES ONCE (Day 273), retries
⭐      once, and only then redirects to /login?next=<current>
⭐   ⑦ logout ⇒ ⭐ server revokes, cookies cleared, ⭐⭐ QUERY CACHE
⭐      CLEARED, other tabs notified
```

| ⭐ The four skipped parts | |
|---|---|
| **`?next=`** | ⭐⭐ Without it, every expired session dumps the user on the dashboard. **Trivial to add, immediately obvious when missing.** |
| **Refresh before redirect** | ⭐ Otherwise a routine token expiry looks like being logged out |
| **Clearing the cache on logout** | ⭐⭐ A genuine cross-user leak on a shared machine (Day 235) |
| **Cross-tab sync** | ⭐ Tab 2 shows a logged-in UI that 401s on every action |

# Part 2 — Protected routes without the flash

```
⭐⭐ THE BUG: "AUTH FLASH"
⭐   ⭐ On load, `user` is undefined because the /me request has not
⭐     resolved. ⭐⭐ A NAIVE GUARD SEES "NOT LOGGED IN" AND REDIRECTS
⭐     A LOGGED-IN USER TO /login FOR 200 ms BEFORE BOUNCING BACK.
⭐   ⇒ ⭐ IT LOOKS BROKEN, AND IT IS THE MOST COMMON AUTH UI BUG.
```

```tsx
function RequireAuth({ children }: { children: React.ReactNode }) {
  const { data: user, isPending, isError } = useMe();
  const location = useLocation();

  if (isPending) return <FullPageSkeleton />;   // ⭐⭐ THREE STATES, NOT TWO
  if (isError || !user) {
    return <Navigate to={`/login?next=${encodeURIComponent(
      location.pathname + location.search)}`} replace />;
    //                                                   ⭐ replace: no
    //                                          history entry to go "back" to
  }
  return children;
}
```

| ⭐ Rule | |
|---|---|
| **⭐⭐ Three states, never two** | `loading` is not `logged out`. Conflating them **is** the flash. |
| **`replace`, not `push`** | ⭐ Otherwise Back returns to the guarded page and bounces again |
| **Preserve the full path** | ⭐ Including the query string — filters are state (Day 233) |
| **⭐ Guard at the route, not per component** | One place, and the layout does not half-render |

# Part 3 — ⭐⭐ Expiry mid-work

```
⭐⭐ THE SCENARIO THAT SEPARATES A DEMO FROM AN APP

⭐   The user has spent four minutes filling a form. The access
⭐   token expires. They click Save.

⭐   ❌ ⭐⭐ THE DEMO: 401 ⇒ redirect to /login ⇒ FOUR MINUTES OF
⭐      TYPING GONE. ⭐ The user will not do it again.

⭐   ✅ ⭐⭐ THE APP:
⭐      ① transport catches the 401
⭐      ② single-flight refresh (Day 235) — ⭐ the user sees NOTHING
⭐      ③ ⭐ THE ORIGINAL REQUEST IS RETRIED AND SUCCEEDS
⭐      ⇒ ⭐⭐ THE EXPIRY IS COMPLETELY INVISIBLE. THIS IS THE
⭐        NORMAL CASE AND IT MUST BE SILENT.

⭐   ✅ ⭐ AND IF THE REFRESH GENUINELY FAILS:
⭐      ① ⭐⭐ DO NOT NAVIGATE AWAY. Show a modal: "Your session
⭐         expired — sign in to continue."
⭐      ② ⭐⭐ THE FORM STAYS MOUNTED WITH ITS VALUES INTACT
⭐      ③ log in inside the modal ⇒ dismiss ⇒ ⭐ RETRY THE SAVE
⭐      ⇒ ⭐⭐ NOTHING TYPED IS EVER LOST. THAT IS THE STANDARD.
```

> ⭐⭐ **This is the single most demonstrable difference between your project and a tutorial project**,
> and it takes about an hour. **Demo it deliberately** (Day 271): expire the token live, click Save,
> and show the work surviving.

# Part 4 — Logout, and the tabs

```typescript
async function logout(qc: QueryClient) {
  try {
    await client.POST("/auth/logout");        // ⭐⭐ SERVER REVOKES. Await it.
  } finally {
    qc.clear();                               // ⭐⭐ THE LEAK, CLOSED
    localStorage.setItem("auth-event", String(Date.now()));  // ⭐ tell tabs
    window.location.replace("/login");        // ⭐ hard nav: nothing survives
  }
}

// ⭐⭐ every tab listens
window.addEventListener("storage", (e) => {
  if (e.key === "auth-event") window.location.replace("/login");
});
```

| ⭐ Detail | Why |
|---|---|
| **`await` the revoke, in `try`** | ⭐ Fire-and-forget logout can fail silently (Day 216) |
| **`finally`** | ⭐⭐ Even if the server call fails, **clear locally** — the user asked to log out |
| **`qc.clear()`** | ⭐⭐ Otherwise the next user sees cached data |
| **Hard navigation** | ⭐ Guarantees no in-memory state survives |
| **`storage` event** | ⭐ Cross-tab, and it is four lines |

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "walk me through auth in your app."**

Skip the easy half quickly. **Login posts credentials, the server sets HttpOnly cookies, and the client
caches the user. The interesting parts are everywhere else.**

Then the flash, because it is specific and common. **A route guard needs three states, not two —
loading is not logged out. If you conflate them, a logged-in user gets bounced to the login page for
two hundred milliseconds on every refresh before bouncing back. It looks broken, and it's the most
common auth UI bug there is.**

Then the part that is the actual answer. **What separates this from a tutorial project is what happens
when a session expires mid-work. A user spends four minutes on a form and clicks Save. The demo version
redirects to login and four minutes of typing is gone — they won't do it again. Mine catches the 401 in
the transport layer, does a single-flight refresh, and retries the original request, so the expiry is
completely invisible. And if the refresh genuinely fails, I don't navigate away at all — a modal
appears over the still-mounted form, they sign in there, and the save retries. Nothing typed is ever
lost.**

Close on logout as a security operation. **Logout is server-side: it awaits the revoke, but clears
locally in a `finally` so a failed call doesn't trap the user. It clears the query cache, which is a
genuine cross-user leak on a shared machine rather than tidiness, and it broadcasts to other tabs via a
storage event, because otherwise tab two keeps showing a logged-in UI that 401s on every action.**
