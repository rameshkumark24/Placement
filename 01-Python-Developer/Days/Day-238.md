# Part 1 — The cascade, and why component styling exists

```
⭐⭐ THE PROBLEM CSS HAS THAT NO OTHER LANGUAGE HAS:
⭐   ⭐ EVERY RULE IS GLOBAL, AND THE WINNER IS DECIDED BY A
⭐     SPECIFICITY SCORE RATHER THAN BY ORDER OR SCOPE.

⭐   specificity: inline(1000) > #id(100) > .class(10) > tag(1)
⭐   ⇒ ⭐⭐ SO A FIX SOMEWHERE ELSE BREAKS YOUR COMPONENT, AND THE
⭐     ESCALATION IS ALWAYS THE SAME:
⭐     .btn {} → .card .btn {} → #page .card .btn {} → !important
⭐     ⇒ ⭐ AND NOW NOBODY CAN OVERRIDE ANYTHING, EVER.

⭐   ⇒ ⭐⭐ EVERY MODERN APPROACH — CSS Modules, Tailwind, CSS-in-JS —
⭐     EXISTS TO MAKE STYLES **LOCAL**. That is the whole point.
⭐     It is the same instinct as module scope in any language.
```

| ⭐ Approach | Trade |
|---|---|
| **Tailwind** | ⭐⭐ Constraint by default (you can only pick from the scale), no naming, ugly JSX. **Recommended here** — the constraint is the feature. |
| **CSS Modules** | ⭐ Real CSS, locally scoped, you still invent every value |
| **CSS-in-JS** | ⭐ Dynamic styling, runtime cost, falling out of favour |
| **Plain CSS + BEM** | ⭐ Works, requires discipline nobody sustains |

> ⭐ **`!important` is a message, not a fix.** It means "the architecture lost". One in a third-party
> override is defensible; three in your own components means your scoping failed.

# Part 2 — ⭐⭐ Tokens

```css
:root {
  /* ⭐⭐ SPACING — one scale, powers of 2. NOTHING ELSE IS ALLOWED. */
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px;
  --space-4: 16px; --space-6: 24px; --space-8: 32px;

  /* ⭐ TYPE — 5 sizes. You do not need 11. */
  --text-sm: 14px; --text-base: 16px; --text-lg: 18px;
  --text-xl: 24px; --text-2xl: 32px;

  /* ⭐⭐ COLOUR — semantic names, not literal ones */
  --fg: #111827;  --fg-muted: #6b7280;
  --bg: #ffffff;  --bg-subtle: #f9fafb;
  --border: #e5e7eb;
  --primary: #2563eb;  --danger: #dc2626;

  --radius: 6px;
  --shadow: 0 1px 3px rgb(0 0 0 / 0.1);
}
```

```
⭐⭐ WHY THIS ALONE MAKES IT LOOK PROFESSIONAL

⭐   ❌ AMATEUR: padding 13px here, 15px there, 7px somewhere else.
⭐      ⭐ Nobody consciously notices. ⭐⭐ EVERYONE FEELS IT AS "OFF".
⭐   ✅ DELIBERATE: every gap is from ONE scale. ⭐ The eye reads the
⭐      repetition as intent — and it costs you NO design talent.

⭐   ⇒ ⭐⭐ NAME COLOURS BY ROLE (--danger), NEVER BY VALUE (--red-600).
⭐     Then dark mode is a second :root block, not a rewrite.
```

| ⭐ Rule | |
|---|---|
| **Never write a raw value in a component** | ⭐⭐ If it is not in the scale, either add it to the scale deliberately or use the nearest one |
| **Five type sizes, one family** | ⭐ Two families max. Three is where it starts looking like a ransom note |
| **A neutral ramp + one accent** | ⭐⭐ Greys do 90% of the work. **One** brand colour. A second is a design decision you are not equipped to make. |

# Part 3 — ⭐⭐ The eight decisions

```
⭐⭐ DO THESE EIGHT AND IT WILL LOOK FINE. SKIP THEM AND IT WON'T.

⭐ ① ⭐⭐ WHITESPACE. Amateur UIs are cramped. Double what feels right.
⭐ ② ⭐ ALIGNMENT. Everything lines up on a shared edge. ⭐⭐ ONE
⭐    MISALIGNED ELEMENT IS THE MOST VISIBLE FLAW THERE IS.
⭐ ③ ⭐ CONTRAST. Body text near-black on white. ⭐⭐ Grey-on-grey is
⭐    the #1 accessibility failure AND it looks weak (Day 239).
⭐ ④ ⭐ ONE ACCENT COLOUR, used only for the primary action.
⭐ ⑤ ⭐⭐ MAX LINE LENGTH ~65–75ch. Full-width text is unreadable
⭐    and instantly marks a page as unstyled.
⭐ ⑥ ⭐ CONSISTENT RADIUS AND BORDER. Pick one of each, use it
⭐    everywhere.
⭐ ⑦ ⭐⭐ VISIBLE FOCUS RINGS. Never `outline: none` (Day 239).
⭐ ⑧ ⭐ HOVER + ACTIVE + DISABLED on every interactive element —
⭐    ⭐⭐ A BUTTON WITH NO HOVER STATE FEELS BROKEN.
```

> ⭐ **Steal the scale, not the design.** Use a component library (shadcn/ui, Radix) for the hard
> parts — dialogs, menus, comboboxes — because they solve focus trapping, keyboard navigation and ARIA
> that you will otherwise get wrong. **That is not cheating; it is the same reason you did not write
> your own ORM.**

# Part 4 — Layout that stops fighting you

```css
/* ⭐ THE THREE LAYOUTS THAT COVER ALMOST EVERYTHING */

.stack   { display: flex; flex-direction: column; gap: var(--space-4); }
.row     { display: flex; align-items: center; gap: var(--space-3); }
.grid    { display: grid; gap: var(--space-4);
           grid-template-columns: repeat(auto-fill, minmax(260px, 1fr)); }
                                /* ⭐⭐ RESPONSIVE WITH NO MEDIA QUERIES */
```

| ⭐ Rule | Why |
|---|---|
| **`gap`, not margins** | ⭐⭐ No collapsing, no "last child" exception, no negative-margin hacks |
| **Grid for 2D, flex for 1D** | ⭐ Using flex for a grid is where the wrapping bugs come from |
| **`min-width: 0` on flex children** | ⭐⭐ The fix for "my text won't truncate" — flex items default to `min-width: auto` and refuse to shrink |
| **Mobile first** | ⭐ Base styles are small-screen; `min-width` queries add complexity upward |
| **`clamp()` for type** | ⭐ `font-size: clamp(24px, 4vw, 40px)` — fluid without breakpoints |

```
⭐⭐ THE THREE BUGS YOU WILL HIT, PRE-SOLVED
⭐   · ⭐ text overflows its flex container ⇒ min-width: 0
⭐   · ⭐ 100vh is wrong on mobile (browser chrome) ⇒ use 100dvh
⭐   · ⭐⭐ a fixed header covers anchored content ⇒ scroll-padding-top
```

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "you're not a designer — how did you make this look decent?"**

Answer with constraint, which is an engineering answer. **By removing choices instead of making them.
I defined a token set — one spacing scale on powers of two, five type sizes, a neutral ramp and one
accent — and nothing in a component uses a raw value. Amateur UIs have thirteen pixels here and seven
there; nobody consciously notices, but everybody feels it as off. Repetition from one scale reads as
intent, and it costs no design talent at all.**

Then the checklist, briefly. **Beyond that it's about eight decisions: generous whitespace, everything
aligned on a shared edge, real contrast for body text, one accent colour reserved for the primary
action, a max line length around seventy characters, consistent radius, visible focus rings, and hover
and disabled states on everything interactive. A button with no hover state feels broken even when it
works.**

Then the delegation, framed correctly. **I use a component library for dialogs, menus and comboboxes —
not to save time on the visuals, but because they solve focus trapping, keyboard navigation and ARIA,
which I'd get wrong. That's the same reason I didn't write my own ORM.**

Close on the architecture point, since it is the actual engineering. **All of this is scoped styling.
CSS's problem is that every rule is global and the winner is decided by a specificity score, so a fix
somewhere else breaks your component and you escalate until everything is `!important` and nothing can
be overridden. Tailwind, CSS Modules and CSS-in-JS all exist to make styles local — it's module scope,
arriving late.**
