# Part 1 — ⭐⭐ One template, two containers

```python
from collections import deque

def traverse(start, neighbours):
    frontier = deque([start])
    seen = {start}                    # ⭐⭐ MARK ON *PUSH*, NOT ON POP
    while frontier:
        node = frontier.popleft()     # ⭐ BFS
        # node = frontier.pop()       # ⭐ DFS — the only difference
        for nxt in neighbours(node):
            if nxt not in seen:
                seen.add(nxt)
                frontier.append(nxt)
```

```
⭐ ⭐⭐ THE ONE-LINE DIFFERENCE IS THE WHOLE THING: ⭐ `popleft()`
⭐   is BFS, `pop()` is DFS. ⭐ Say that in an interview and you
⭐   have demonstrated the structure rather than recited two
⭐   algorithms.

⭐ ⭐⭐ AND THE DETAIL THAT CAUSES REAL BUGS: ***MARK VISITED WHEN
⭐   YOU PUSH, NOT WHEN YOU POP.***
⭐   ⭐ Marking on pop lets the same node enter the frontier many
⭐     times before it is ever processed. ⭐⭐ ON A DENSE GRAPH
⭐     THAT IS A MEMORY BLOW-UP AND A SILENT PERFORMANCE
⭐     DISASTER, ⭐ and the output is still correct — which is why
⭐     it survives review.

⭐ ***WHEN TO USE WHICH:***
⭐   ⭐ ⭐⭐ BFS ⇒ ***SHORTEST PATH IN AN UNWEIGHTED GRAPH.*** ⭐ It
⭐     is the ***only*** reason to prefer it, and it is
⭐     sufficient.
⭐   ⭐ BFS ⇒ level-order, "minimum number of steps", ⭐ and
⭐     ⭐⭐ MULTI-SOURCE PROBLEMS (SEED THE QUEUE WITH ALL
⭐     SOURCES — ⭐ rotting oranges, walls-and-gates).
⭐   ⭐ ⭐⭐ DFS ⇒ ***EXPLORE-EVERYTHING, BACKTRACKING, CYCLE
⭐     DETECTION, TOPOLOGICAL ORDER.***
⭐   ⭐ ⭐⭐ WEIGHTED SHORTEST PATH IS NEITHER — ⭐ that is
⭐     Dijkstra (Day 475's heap).
```

# Part 2 — ⭐⭐ The recursion limit is a real answer

```
⭐ ***PYTHON'S DEFAULT RECURSION LIMIT IS ABOUT 1,000.***
⭐   ⭐ A DFS over a 100,000-node graph — ⭐⭐ OR A LINKED-LIST-
⭐     SHAPED TREE, WHICH IS THE COMMON CASE — ⭐ raises
⭐     `RecursionError`.
⭐   ⭐ ⭐⭐ IT IS NOT A HYPOTHETICAL. A SKEWED BST OF 5,000 NODES
⭐     CRASHES A RECURSIVE `inorder`.

⭐ ***WHAT TO SAY, UNPROMPTED, AFTER WRITING A RECURSIVE
⭐   SOLUTION:***
⭐   ⭐ ⭐⭐ "THIS IS RECURSIVE FOR CLARITY. ⭐ In Python I'd be
⭐     careful past a few thousand deep — ⭐ the default limit is
⭐     about a thousand and there's no tail-call optimisation, so
⭐     ⭐⭐ FOR A DEEP OR ADVERSARIAL INPUT I'D CONVERT THIS TO AN
⭐     EXPLICIT STACK."
⭐   ⭐ ⭐⭐ THAT SENTENCE IS A LANGUAGE-SPECIFIC SIGNAL THAT
⭐     ALMOST NOBODY GIVES, ⭐ and it costs five seconds.
⭐   ⭐ ⭐ `sys.setrecursionlimit(10**6)` is ***not*** the fix on
⭐     its own — ⭐⭐ THE C STACK STILL OVERFLOWS AND YOU GET A
⭐     SEGFAULT INSTEAD OF AN EXCEPTION, ⭐ which is strictly
⭐     worse. ⭐ Say that too.

⭐ ***ITERATIVE INORDER, WHICH IS WORTH KNOWING COLD:***
```

```python
def inorder(root) -> list[int]:
    out, stack, node = [], [], root
    while node or stack:
        while node:                 # ⭐ go as far left as possible
            stack.append(node)
            node = node.left
        node = stack.pop()          # ⭐ deepest unvisited
        out.append(node.val)        # ⭐⭐ VISIT ON POP — that is
        node = node.right           #    what makes it *in*order
    return out
```

# Part 3 — ⭐⭐ The three-colour cycle detection

```
⭐ ***THE BUG EVERYONE SHIPS:*** ⭐ using one `visited` set to
⭐   detect a cycle in a ***directed*** graph.
⭐   ⭐ ⭐⭐ THAT REPORTS A CYCLE FOR A SIMPLE DIAMOND — ⭐ A→B, A→C,
⭐     B→D, C→D has no cycle, ⭐⭐ BUT D IS REACHED TWICE, SO A
⭐     ONE-SET CHECK CALLS IT ONE.

⭐ ⭐⭐ THE FIX: ***"VISITED" IS TWO DIFFERENT QUESTIONS.***
⭐   ⭐ ***WHITE*** — not seen at all.
⭐   ⭐ ⭐⭐ ***GREY*** — ON THE CURRENT RECURSION STACK. ⭐ Reaching
⭐     a grey node means a ***back edge***, ⭐⭐ WHICH IS EXACTLY A
⭐     CYCLE.
⭐   ⭐ ***BLACK*** — fully explored, all descendants done.
⭐     ⭐ Reaching a black node is fine — ⭐⭐ IT IS A CROSS EDGE,
⭐     NOT A CYCLE.

⭐ ⭐⭐ IN AN UNDIRECTED GRAPH IT IS A DIFFERENT PROBLEM: ⭐ one
⭐   `visited` set plus ***skip the parent***, ⭐ because every
⭐   edge looks like a 2-cycle otherwise.
⭐   ⭐ ⭐⭐ BEING ABLE TO SAY "DIRECTED AND UNDIRECTED NEED
⭐     DIFFERENT ALGORITHMS, AND HERE IS WHY" IS THE WHOLE
⭐     SIGNAL ON THIS TOPIC.
```

```python
WHITE, GREY, BLACK = 0, 1, 2

def has_cycle(graph: dict[int, list[int]]) -> bool:
    colour = {n: WHITE for n in graph}

    def dfs(n) -> bool:
        colour[n] = GREY
        for m in graph[n]:
            if colour[m] == GREY:      # ⭐⭐ BACK EDGE ⇒ CYCLE
                return True
            if colour[m] == WHITE and dfs(m):
                return True
        colour[n] = BLACK              # ⭐ done, and safe to revisit
        return False

    # ⭐⭐ LOOP OVER ALL NODES — THE GRAPH MAY BE DISCONNECTED.
    # ⭐ Forgetting this is the second most common bug here.
    return any(dfs(n) for n in graph if colour[n] == WHITE)
```

```
⭐ ***AND ITS SIBLING — TOPOLOGICAL SORT, WHICH IS THE SAME
⭐   PROBLEM WEARING A HAT:***
⭐   ⭐ ⭐⭐ KAHN'S ALGORITHM: ⭐ compute in-degrees, ⭐ queue every
⭐     zero-in-degree node, ⭐ pop and decrement.
⭐   ⭐ ⭐⭐ IF THE OUTPUT IS SHORTER THAN THE NODE COUNT, THERE IS
⭐     A CYCLE — ⭐ so you get detection for free, and that is
⭐     usually the cleaner interview answer for
⭐     course-schedule-style problems.
```

# Part 4 — The mock: four problems, 45 minutes

```
⭐ ***P1 (10 min) — LEVEL-ORDER TRAVERSAL*** returning a list per
⭐   level. ⭐⭐ THE TRICK IS SNAPSHOTTING `len(queue)` BEFORE THE
⭐   INNER LOOP.
⭐ ***P2 (15 min) — NUMBER OF ISLANDS.*** ⭐ Then: ⭐⭐ "NOW DO IT
⭐   WITHOUT MUTATING THE INPUT GRID."
⭐ ***P3 (15 min) — COURSE SCHEDULE II*** — return a valid order,
⭐   ⭐ or empty if impossible.
⭐ ***P4 (5 min) — LOWEST COMMON ANCESTOR*** in a binary tree.
```

```python
# ⭐ P1 — the snapshot is the entire problem.
def level_order(root) -> list[list[int]]:
    if not root:
        return []
    out, q = [], deque([root])
    while q:
        n = len(q)                     # ⭐⭐ SNAPSHOT *BEFORE* the
        level = []                     # loop — the queue grows
        for _ in range(n):             # while we iterate
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        out.append(level)
    return out
```

```python
# ⭐ P2 — flood fill. Iterative, deliberately (Part 2).
def num_islands(grid: list[list[str]]) -> int:
    if not grid:
        return 0
    rows, cols = len(grid), len(grid[0])
    seen = set()                       # ⭐ no input mutation
    count = 0

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] != "1" or (r, c) in seen:
                continue
            count += 1
            stack = [(r, c)]
            seen.add((r, c))
            while stack:
                y, x = stack.pop()
                for dy, dx in ((1,0), (-1,0), (0,1), (0,-1)):
                    ny, nx = y + dy, x + dx
                    if (0 <= ny < rows and 0 <= nx < cols
                            and grid[ny][nx] == "1"
                            and (ny, nx) not in seen):
                        seen.add((ny, nx))      # ⭐⭐ ON PUSH
                        stack.append((ny, nx))
    return count
# ⭐ O(rows·cols). ⭐⭐ MUTATING THE GRID SAVES THE SET BUT
# DESTROYS THE CALLER'S DATA — say which you chose and why.
```

```python
# ⭐ P3 — Kahn's. Detection comes free.
def course_order(n: int, prereqs: list[list[int]]) -> list[int]:
    graph = [[] for _ in range(n)]
    indeg = [0] * n
    for course, need in prereqs:
        graph[need].append(course)
        indeg[course] += 1

    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        node = q.popleft()
        order.append(node)
        for nxt in graph[node]:
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                q.append(nxt)

    # ⭐⭐ THE CYCLE CHECK IS THE LENGTH COMPARISON. No extra pass.
    return order if len(order) == n else []
```

```python
# ⭐ P4 — the recursion is four lines; the reasoning is the answer.
def lca(root, p, q):
    if root is None or root is p or root is q:
        return root
    left  = lca(root.left,  p, q)
    right = lca(root.right, p, q)
    # ⭐⭐ FOUND ONE ON EACH SIDE ⇒ THIS NODE IS THE SPLIT POINT.
    if left and right:
        return root
    # ⭐ Otherwise both are in one subtree — pass up whichever
    # side found something.
    return left or right
```

# 💬 Interview

**1. "BFS or DFS here?"**

⭐ I choose on the property I need rather than by preference. ⭐⭐ BFS if I need a shortest path in an
unweighted graph — that's the only reason that genuinely requires it, and it's sufficient on its own.
⭐ Also level-order, "minimum number of steps", and multi-source problems where I seed the queue with
every source at once. ⭐⭐ DFS for explore-everything, backtracking, cycle detection and topological
order. ⭐ And I'd flag that they're the same six lines with a different container — `popleft` versus
`pop` — so the real decisions are what goes in the frontier and when I mark visited. ⭐⭐ If it's
weighted, it's neither: that's Dijkstra with a heap.

**2. "You marked visited on push rather than pop. Does it matter?"**

⭐ Yes, and it's the kind of bug that survives code review because the output is still correct. ⭐⭐ If I
mark on pop, the same node can enter the frontier many times before it's ever processed — on a dense
graph that's a memory blow-up and a large constant-factor slowdown, with no wrong answer to alert
anyone. ⭐ Marking on push means each node enters the frontier exactly once, which is what makes the
complexity actually O(V + E) rather than something worse that looks the same on small inputs.

**3. "Detect a cycle in a directed graph."**

⭐ The thing to get right is that "visited" is two different questions. ⭐⭐ A single visited set gives a
false positive on a diamond — A to B, A to C, B to D, C to D has no cycle, but D is reached twice.
⭐ So three colours: white is unseen, grey is on the current recursion stack, black is fully explored.
⭐⭐ Reaching a grey node is a back edge, which is exactly a cycle; reaching a black node is a cross edge
and perfectly fine. ⭐ And in an *undirected* graph it's a different algorithm entirely — one visited set
plus skipping the parent, because otherwise every edge looks like a two-cycle. ⭐⭐ Being able to say
those need different algorithms, and why, is most of the signal on this topic.

**4. "Would you write that recursively?"**

⭐ I'd write it recursively for clarity and then say the Python-specific caveat unprompted. ⭐⭐ The
default recursion limit is about a thousand and there's no tail-call optimisation, so a deep or
adversarial input — a skewed tree of five thousand nodes, or a DFS over a hundred thousand — raises
`RecursionError`. ⭐ For anything production-shaped I'd convert it to an explicit stack. ⭐⭐ And I'd add
that raising the limit isn't really a fix on its own: the C stack still overflows, so you trade an
exception for a segfault, which is strictly worse. ⭐ That whole caveat costs five seconds and almost
nobody says it.

**5. "Can you mutate the input grid?"**

⭐ That's the question I'd ask *before* coding, because it changes the solution. ⭐⭐ Mutating — writing
"0" over visited land — saves the whole visited set, so it's O(1) extra space instead of O(rows × cols).
⭐ But it destroys the caller's data, which is unacceptable in most real code and is exactly the kind of
thing that causes a bug three functions away. ⭐⭐ So I'd default to the set, say why, and mention that
if memory were tight and the caller were fine with it, mutation is a legitimate optimisation. ⭐ Stating
the trade-off is worth more than either choice.

**6. "Course schedule — cycle detection or topological sort?"**

⭐ Kahn's algorithm, because it gives me both. ⭐⭐ Compute in-degrees, queue everything with zero
in-degree, pop and decrement — and if the output is shorter than the node count, there's a cycle. ⭐ So
detection is a length comparison rather than a second pass with three colours. ⭐⭐ That's usually the
cleaner interview answer for anything phrased as "is there a valid ordering", and it's iterative, so the
recursion limit never comes up.

## 🎙️ Articulation drill

⭐⭐ **Two minutes, out loud: "how would you approach a graph problem?"**

Start with the structure, because it shows you have one. **"BFS and DFS are the same six lines with a
different container — a queue gives me BFS, a stack gives me DFS. So I don't really choose between two
algorithms, I choose a container based on one question: do I need shortest path in an unweighted graph?
If yes, BFS, and that's the only reason that genuinely requires it. If it's weighted, it's neither —
that's Dijkstra."**

Then the detail that separates people. **"The thing I'm careful about is marking visited on push rather
than on pop. Marking on pop lets the same node enter the frontier many times before it's processed —
on a dense graph that's a memory blow-up with a completely correct output, which is why it survives code
review. Marking on push is what makes it actually O(V + E)."**

Then the cycle question, precisely. **"For cycle detection I'd first ask whether it's directed, because
they're different algorithms. Undirected is one visited set plus skipping the parent, or every edge
looks like a two-cycle. Directed needs three colours, because 'visited' is two different questions:
grey means on the current recursion stack, and reaching grey is a back edge, which is exactly a cycle.
Black means fully explored, and reaching black is fine. A single visited set reports a false cycle on a
simple diamond."**

Close with the Python-specific caveat, unprompted. **"And if I write it recursively I'd flag that
Python's default recursion limit is about a thousand with no tail-call optimisation, so a skewed tree of
a few thousand nodes crashes it. For production I'd use an explicit stack — and raising the limit isn't
the fix, because the C stack still overflows and you get a segfault instead of an exception."**
