# Part 1 — ⭐ `pathlib`, and file handling

```python
from pathlib import Path

p = Path("data") / "raw" / "file.csv"     # ⭐⭐ `/` composes — no os.path.join, no separators
p.stem, p.suffix, p.name, p.parent        # ⭐ "file", ".csv", "file.csv", Path("data/raw")
p.exists(); p.is_file(); p.stat().st_size
p.read_text(encoding="utf-8")             # ⭐⭐ ALWAYS pass encoding (Day 037)
p.write_text(s, encoding="utf-8")
Path("out").mkdir(parents=True, exist_ok=True)     # ⭐ both flags, every time
list(Path(".").rglob("*.py"))             # ⭐ recursive glob
p.resolve()                               # ⭐ absolute, symlinks resolved
```

⭐⭐ **`pathlib` replaces `os.path` entirely** and is worth adopting for one reason above the others:
`/` composition means **you never write a separator, so the code is correct on Windows without
thinking about it.**

```python
# ⭐⭐ ATOMIC WRITE — the pattern that prevents a truncated file:
tmp = p.with_suffix(".tmp")
tmp.write_text(data, encoding="utf-8")
tmp.replace(p)          # ⭐⭐ os.replace is ATOMIC on the same filesystem
```

⚠️ ⭐⭐ **Writing directly to the destination means a crash mid-write leaves a half-written file** —
and the reader cannot tell. **Write to a temporary file and rename: the rename is atomic, so a reader
sees either the old file or the new one, never a partial one.** ⭐ This is the same idea as a database
transaction, at the filesystem level.

⭐ `tempfile.TemporaryDirectory()` as a context manager (Day 052) for scratch space that cleans
itself up, and `shutil` for copy/move/rmtree.

# Part 2 — ⭐⭐ `datetime` — the module with the most bugs

```python
from datetime import datetime, timezone, timedelta, date, UTC

datetime.now()                    # ⚠️⚠️ ⭐⭐ NAIVE — no timezone. The source of most date bugs.
datetime.now(UTC)                 # ⭐⭐ AWARE. Use this. Always.
datetime.now(timezone.utc)        # ⭐ the pre-3.11 spelling
```

```
⭐⭐ THE THREE RULES THAT PREVENT ALMOST EVERY DATE BUG:
⭐   1. ⭐⭐ STORE AND COMPUTE IN UTC. Convert to local time ONLY for display.
⭐   2. ⭐⭐ NEVER USE A NAIVE datetime FOR ANYTHING REAL. Comparing naive to aware
⭐        raises TypeError; comparing two naive ones from different zones is silently WRONG.
⭐   3. ⭐ USE ISO 8601 ON THE WIRE: .isoformat() / .fromisoformat() — unambiguous, sortable.
```

```python
from zoneinfo import ZoneInfo                      # ⭐ stdlib since 3.9 — no pytz needed
london = datetime.now(ZoneInfo("Europe/London"))
utc = london.astimezone(UTC)                        # ⭐ convert, never reinterpret
```

⚠️ ⭐⭐ **Use a timezone *name*, never a fixed offset.** `Europe/London` is +0 or +1 depending on the
date; **storing `+01:00` loses the rule and is wrong six months later.** ⭐ The same reasoning kills
`timedelta(days=1)` as "tomorrow at the same time" — **across a DST boundary that is 23 or 25 hours**,
so add the day in local time and convert, rather than adding 86,400 seconds.

```python
time.monotonic()          # ⭐⭐ for MEASURING ELAPSED TIME — never goes backwards
time.time()               # ⭐⭐ wall clock — ⚠️ NTP can move it, so an interval can be NEGATIVE
time.perf_counter()       # ⭐ highest resolution, for benchmarks (Day 064)
```

⭐⭐ **"Use a monotonic clock for durations and the wall clock for timestamps" is a rule worth stating
in an interview** — a timeout implemented with `time.time()` can fire immediately or never if NTP
steps the clock.

# Part 3 — ⭐⭐ `logging`

```python
import logging
logger = logging.getLogger(__name__)      # ⭐⭐ __name__ ⇒ the hierarchy matches your packages

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(name)s %(levelname)s %(message)s")

logger.info("user %s placed order %s", user_id, order_id)    # ⭐⭐ %s ARGS, not an f-string
logger.exception("failed")                                    # ⭐⭐ inside except — full traceback
```

```
⭐⭐ THE FOUR RULES:
⭐   1. ⭐⭐ getLogger(__name__) — never the root logger. The dotted hierarchy lets you set
⭐        levels per package: myapp.db at DEBUG, everything else at INFO.
⭐   2. ⭐⭐ %s ARGUMENTS, NOT f-STRINGS (Day 037): formatting is DEFERRED until the record
⭐        is actually emitted, ⭐ and the message TEMPLATE stays constant — which is what
⭐        log aggregators group on.
⭐   3. ⭐⭐ logger.exception() inside an except block. logger.error(str(e)) throws away
⭐        the traceback, which is the only evidence you had (Day 060).
⭐   4. ⭐ CONFIGURE ONCE, at the entry point. ⚠️ A LIBRARY must never call basicConfig —
⭐        it belongs to the application.
```

⚠️ ⭐⭐ **The `print` versus `logging` distinction matters in a service:** `print` has no level, no
timestamp, no module name, no way to turn it off, and it goes to stdout unbuffered-or-not depending on
how you were started. **`logging` is configurable at runtime by whoever runs your code.**

⭐ **Structured logging** — emitting JSON with fields rather than a formatted string — is what makes
logs *queryable* (`structlog`, or a JSON formatter). ⭐⭐ **In a service, add the request id from a
`ContextVar`** (Day 070) so every line for a request can be found together.

# Part 4 — ⭐ `subprocess` and `re`

```python
import subprocess

subprocess.run(["git", "status", "--short"],       # ⭐⭐ A LIST. Never a string.
               capture_output=True, text=True,
               check=True, timeout=30)              # ⭐⭐ check=True raises; timeout is mandatory
```

```
⭐⭐ shell=True IS THE DANGEROUS ONE, AND THE REASON IS INJECTION:
⭐   subprocess.run(f"git log {user_input}", shell=True)
⭐   ⇒ ⭐⭐ user_input = "; rm -rf /" ⇒ the shell runs BOTH commands.
⭐   ⇒ ⭐⭐ WITH A LIST there is no shell, so no parsing, so no injection —
⭐        the arguments are passed to execve directly. ⭐ Same principle as a
⭐        parameterised SQL query (Stage 5) and template autoescaping (Day 012).
⭐   ⇒ ⭐ you only need shell=True for pipes, globs or redirection — and you can
⭐        usually do those in Python instead.
```

⚠️ ⭐ **`check=True` and `timeout=` are both opt-in and both should be reflexes.** Without `check`, a
failed command returns quietly and your code continues with empty output; **without `timeout`, a hung
child hangs you forever** (Day 060, again).

```python
import re
pat = re.compile(r"^(?P<key>\w+)=(?P<value>.*)$")      # ⭐⭐ COMPILE once, at module level
m = pat.match(line)
if m: m["key"], m["value"]                              # ⭐ named groups read far better

re.findall / finditer / sub / split
re.sub(r"\s+", " ", s)
```

| ⚠️ `re` trap | ⭐ Note |
|---|---|
| ⭐ Not using a raw string | `"\d"` is a deprecation warning; `r"\d"` is correct |
| ⭐ `match` vs `search` | ⭐⭐ `match` anchors at the **start**; `search` scans |
| ⭐⭐ **Catastrophic backtracking** | ⭐⭐ `(a+)+b` on a long non-matching string is exponential — **a ReDoS** |
| Greedy by default | `.*?` for lazy |
| ⭐ Parsing HTML/JSON with regex | ⭐ Use a parser (Day 012) |

⭐⭐ **ReDoS is a real vulnerability, not a curiosity:** a regex with nested quantifiers applied to
attacker-supplied input can burn CPU for minutes on one request — **and on an event loop that freezes
the whole worker** (Day 072). **Avoid nested quantifiers, and never build a regex from user input.**

## Common mistakes

| Mistake | Correction |
|---|---|
| ⭐⭐ **`datetime.now()` with no timezone** | ⭐⭐ Naive. Use `datetime.now(UTC)`. |
| Storing a fixed offset instead of a zone name | ⭐ Loses the DST rule; wrong six months later. |
| `timedelta(days=1)` across DST | ⭐⭐ 23 or 25 hours. Add in local time, then convert. |
| `time.time()` for durations | ⭐⭐ NTP can move it backwards. `time.monotonic()`. |
| ⭐ f-strings in logging calls | ⭐⭐ Formats even when suppressed; breaks grouping. |
| `logger.error(str(e))` | ⭐⭐ No traceback. `logger.exception`. |
| ⭐ `basicConfig` in a library | ⭐ Configuration belongs to the application. |
| `print` in a service | ⭐ No level, no timestamp, not configurable. |
| ⭐⭐ **`subprocess` with `shell=True`** | ⭐⭐ Shell injection. Pass a list. |
| No `check=True` or `timeout=` | ⭐ Silent failure, or a permanent hang. |
| Compiling a regex in a loop | ⭐ Compile once at module level. |
| ⭐ Nested quantifiers on user input | ⭐⭐ ReDoS — exponential backtracking. |
| Writing a file in place | ⭐ Write to `.tmp` and `replace()` — atomic. |
| `open()` without `encoding=` | ⭐ Day 037. |

## Interview questions

**Q: How do you handle dates and times correctly?**
> Store and compute in UTC, convert to local only for display, and never use a naive datetime for
> anything real — comparing naive to aware raises, and comparing two naive values from different zones
> is silently wrong. On the wire, ISO 8601, because it's unambiguous and sorts lexicographically. And
> store a timezone *name* like `Europe/London` rather than a fixed offset, because the offset changes
> with DST and a stored `+01:00` is wrong six months later. The related trap is arithmetic: adding
> `timedelta(days=1)` across a DST boundary gives 23 or 25 hours, so "same time tomorrow" means adding
> in local time and then converting.

**Q: Which clock do you use for a timeout?**
> `time.monotonic()`. The wall clock can be moved by NTP, so an interval computed from `time.time()`
> can come out negative or huge, and a timeout can fire immediately or never. Monotonic never goes
> backwards, which is exactly the property a duration needs. `time.time()` is for timestamps —
> "when did this happen" — and `perf_counter` for benchmarks.

**Q: Why pass `%s` arguments to a logger instead of an f-string?**
> Two reasons. The f-string is evaluated before the call, so you pay the formatting cost even when
> that level is disabled — real overhead for a debug log in a hot loop. And the message template stays
> constant, which is what log aggregators group on: with an f-string every line is unique and you
> can't count occurrences of an event. The related rule is `logger.exception` inside an `except`
> block, because `logger.error(str(e))` records the message and throws away the traceback, which was
> the only evidence of where it came from.

**Q: What's wrong with `subprocess.run(cmd, shell=True)`?**
> It runs the string through a shell, so any user-controlled part becomes shell syntax — a semicolon
> or a backtick and you're executing arbitrary commands. Passing a list means no shell is involved:
> the arguments go straight to `execve`, so there's nothing to parse and nothing to inject. It's
> exactly the same principle as parameterised SQL and template autoescaping — separate the code from
> the data instead of trying to sanitise. I'd also always pass `check=True` and a `timeout`, because
> without them a failed command is silent and a hung child hangs the caller forever.

**Q: What is ReDoS?**
> A regular expression whose backtracking is exponential on certain inputs — nested quantifiers like
> `(a+)+b` are the classic shape. Applied to attacker-supplied input, one request can burn CPU for
> minutes, and on an event loop that freezes the whole worker, which is Day 072's failure arriving
> through a regex. The defences are to avoid nested quantifiers, never to build a pattern from user
> input, and to prefer a parser when the thing being parsed is actually structured.

**Q: How do you write a file safely?**
> Write to a temporary file in the same directory and then `replace()` it onto the destination. The
> rename is atomic on the same filesystem, so a reader sees either the complete old file or the
> complete new one — never a partial write from a process that crashed halfway. Writing directly to
> the destination leaves a truncated file that looks valid, and nothing downstream can tell.

## 🎙️ Articulation drill

Record two minutes: **"A user in Sydney says their scheduled report arrives an hour late twice a
year."**

⭐ Name the cause immediately: **daylight saving, and a system that stored an offset or did arithmetic
in local time.** ⭐ Then the two specific bugs it could be: **a stored `+11:00` instead of
`Australia/Sydney`, which is simply wrong for half the year; or scheduling by adding
`timedelta(days=1)`, which is exactly 24 hours and therefore 23 or 25 local hours across a
transition.**

⭐ Then the fix as a rule: **store and compute in UTC, store the zone *name* alongside anything the
user chose, convert only for display — and when the requirement is "9am local", do the arithmetic in
local time and convert to UTC afterwards, rather than adding seconds.**

⭐⭐ **Then the adjacent one worth volunteering, because it is the same class of mistake:** *"and I'd
check what clock the scheduler uses for its intervals. A timeout or a delay computed with
`time.time()` can be moved by NTP — the interval can come out negative, so it fires immediately or
never. Durations use a monotonic clock; wall-clock time is only for saying when something happened.
Both bugs come from treating a timestamp and a duration as the same kind of number."*
