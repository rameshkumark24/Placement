# Part 2 — The four solutions, and the recognition cue

```python
# ⭐ P1 — MONOTONIC STACK.
# ⭐⭐ CUE: "NEXT GREATER / SMALLER ELEMENT" IN ONE PASS.
def daily_temperatures(temps: list[int]) -> list[int]:
    out = [0] * len(temps)
    stack = []                          # ⭐ indices, decreasing temp
    for i, t in enumerate(temps):
        # ⭐⭐ EVERY POP IS A QUESTION FINALLY ANSWERED.
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            out[j] = i - j
        stack.append(i)
    return out
# ⭐ O(n) — each index is pushed once and popped once.
# ⭐⭐ DEFEND THAT: the nested while LOOKS quadratic and isn't.
```

```python
# ⭐ P2 — DP. Day 474's step ① then ③, unchanged.
from functools import cache

def word_break(s: str, words: list[str]) -> bool:
    vocab = set(words)                  # ⭐ O(1) membership
    @cache
    def can(i: int) -> bool:            # ⭐⭐ INDEX, NOT SLICE
        if i == len(s):
            return True
        # ⭐ THE CHOICE: where does the next word end?
        return any(s[i:j] in vocab and can(j)
                   for j in range(i + 1, len(s) + 1))
    return can(0)
# ⭐ O(n²) states×work, ⭐⭐ AND NOTE THE SLICE IS UNAVOIDABLE
# HERE BECAUSE THE LOOKUP NEEDS THE SUBSTRING — say so.
```

```python
# ⭐⭐ P3 — THE TWO-VALUE TRICK. The one people fail.
def max_path_sum(root) -> int:
    best = float("-inf")

    def gain(node) -> int:
        # ⭐⭐ RETURNS: the best DOWNWARD path through this node.
        # ⭐⭐ UPDATES: the best path ANYWHERE, which may bend here.
        # ⭐ Those are two different quantities and conflating
        # them is exactly why this problem is hard.
        nonlocal best
        if not node:
            return 0
        left  = max(gain(node.left), 0)   # ⭐ negative ⇒ take none
        right = max(gain(node.right), 0)
        best = max(best, node.val + left + right)   # ⭐ bends here
        return node.val + max(left, right)          # ⭐ goes up
    gain(root)
    return best
```

```python
# ⭐ P4 — the array/dict pair. O(1) remove via swap-with-last.
import random

class RandomisedSet:
    def __init__(self):
        self.items: list[int] = []
        self.index: dict[int, int] = {}

    def insert(self, x: int) -> bool:
        if x in self.index:
            return False
        self.index[x] = len(self.items)
        self.items.append(x)
        return True

    def remove(self, x: int) -> bool:
        if x not in self.index:
            return False
        # ⭐⭐ THE TRICK: SWAP WITH THE LAST, THEN POP.
        # ⭐ Deleting from the middle of a list is O(n); this is O(1).
        i, last = self.index[x], self.items[-1]
        self.items[i] = last
        self.index[last] = i
        self.items.pop()
        del self.index[x]
        return True

    def get_random(self) -> int:
        return random.choice(self.items)   # ⭐ O(1) on a list
```

# 💬 Interview

**1. "How do you prepare for coding interviews?"**

⭐ By diagnosing rather than by volume. ⭐⭐ I ran five timed mocks and scored each against a rubric, and
the useful output wasn't the pass rate — it was which rubric row failed in three or more of them. ⭐ For
me the recurring one was stating complexity before coding; I'd start typing and only analyse afterwards,
which meant the interviewer was watching me implement something we hadn't agreed on. ⭐⭐ That's a
communication fix, not an algorithms fix, and no amount of extra problems would have touched it. ⭐ Four
of the five failure modes aren't solved by more practice, and "grind more LeetCode" is the default
self-prescription for all of them.

**2. "Daily temperatures — walk me through it."**

⭐ The cue is "next greater element", which means a monotonic stack. ⭐⭐ I keep a stack of indices whose
answers are still pending, with decreasing temperatures. When a warmer day arrives, it answers every
pending index colder than it — so every pop is a question finally getting resolved. ⭐ It's O(n), and
that's worth defending because the nested `while` looks quadratic: each index is pushed exactly once and
popped at most once, so the total inner work is bounded by n. ⭐⭐ I'd say that out loud, because "it's
O(n), trust me" invites exactly the follow-up I'd rather pre-empt.

**3. "Maximum path sum in a binary tree — why do people fail this?"**

⭐ Because there are two different quantities and it's tempting to conflate them. ⭐⭐ What the recursion
*returns* is the best downward path through a node — a path that continues upward, so it can use only
one child. What it *updates* is the best path anywhere, which may bend at this node and use both
children. ⭐ Once you separate "what I return" from "what I record", it's six lines. ⭐⭐ The other detail
is clamping negative child gains to zero, which encodes "if that subtree hurts, take none of it" — and
that's cleaner than branching on sign.

**4. "How do you recognise a pattern you haven't seen before?"**

⭐ I organise by cue rather than by topic, because a topic list helps me revise and a cue list helps me
in the room. ⭐⭐ Fifteen phrases map to fifteen approaches: "have I seen this" means a hash map, "next
greater" means a monotonic stack, "longest subarray such that" means a sliding window, "is there a valid
order" means a topological sort. ⭐ The skill I train is matching the phrase in the problem to the row in
under thirty seconds. ⭐⭐ And in my last mock I wrote down what I *thought* the pattern was in the first
thirty seconds, before solving — comparing that against what it turned out to be is the most useful data
I've collected.

**5. "What if you don't recognise it at all?"**

⭐ I say so and start from brute force out loud, because a brute force is always available and it usually
contains the insight. ⭐⭐ "I don't immediately see the trick. The obvious approach is to try every
subarray, which is O(n²) — let me write that down and look for what's repeated." ⭐ Most optimisations
are visible as redundant work in a brute force. ⭐⭐ And it keeps the interviewer with me instead of
watching silence, which matters more than the eventual solution — a stuck candidate producing no signal
is a no, and a stuck candidate reasoning aloud usually gets a hint.

**6. "When are you ready?"**

⭐ My calibration is: a medium in twenty-five minutes *while talking through it*. ⭐⭐ Twenty minutes with
one follow-up handled means the harder companies too. ⭐ Speed beyond that buys very little, and I'd
rather spend the time on the project deep dive, which is scored by a human with far more discretion.
⭐⭐ The maintenance is forty-five minutes a day, not four hours: one timed problem out loud, re-solving
failures a week later rather than the same day, and one mock with an actual human per week.
