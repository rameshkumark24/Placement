# Part 1 — ⭐ The tour

```python
from fastapi import FastAPI, Depends, HTTPException, status
from pydantic import BaseModel, Field

app = FastAPI(title="Orders API", version="1.0.0")

class OrderIn(BaseModel):
    qty: int = Field(gt=0, le=100)
    sku: str = Field(min_length=1, max_length=64)

class OrderOut(BaseModel):
    id: int
    qty: int
    sku: str
    total: str                                       # ⭐⭐ money as a string (Days 041, 126)

@app.post("/orders", response_model=OrderOut, status_code=201)      # ⭐⭐ Day 119's output schema
async def create_order(payload: OrderIn, user: User = Depends(current_user)):
    order = await service.place(user, payload.sku, payload.qty)
    return order
```

```
⭐⭐ COUNT WHAT THAT ONE FUNCTION GOT FOR FREE, AND MAP EACH TO A DAY YOU BUILT:
⭐   · routing + path/method dispatch            ⇒ Day 107
⭐   · body parsed, VALIDATED, coerced           ⇒ Day 119 (and 422 on failure)
⭐   · `user` injected by signature inspection   ⇒ ⭐⭐ Day 112's `Depends`
⭐   · the response FILTERED through OrderOut    ⇒ ⭐⭐ Day 119's security control
⭐   · status 201                                ⇒ Day 102
⭐   · ⭐ an OpenAPI schema, generated, truthful  ⇒ Day 126
⭐   · interactive docs at /docs                 ⇒ Day 126
⭐ ⇒ ⭐⭐ SEVEN THINGS, FROM TYPE ANNOTATIONS. That is the whole product, and it
⭐     is why FastAPI reads as magic to people who have not written a router.
⭐     ⭐ You have. So it should read as inevitable instead.
```

# Part 2 — ⭐⭐ What it is made of

```

⭐   YOU WHERE TO LOOK WHEN SOMETHING BREAKS:
⭐
⭐   ┌──────────────────────────────────────────────┐
⭐   │ FASTAPI   ⭐ signature inspection, DI,         │
⭐   │           validation wiring, OpenAPI          │
⭐   ├──────────────────────────────────────────────┤
⭐   │ ⭐⭐ STARLETTE  routing, middleware, Request/  │  ⇒ ⭐ Days 107, 108
⭐   │           Response, WebSockets, TestClient,   │
⭐   │           background tasks, the ASGI app      │
⭐   ├──────────────────────────────────────────────┤
⭐   │ ⭐⭐ PYDANTIC   validation, serialisation,     │  ⇒ ⭐ Days 119, 131
⭐   │           JSON Schema                          │
⭐   ├──────────────────────────────────────────────┤
⭐   │ ⭐ ASGI       the protocol                     │  ⇒ ⭐ Day 110
⭐   │ ⭐ UVICORN    the server                       │  ⇒ ⭐ Day 111
⭐   └──────────────────────────────────────────────┘
⭐
⭐ ⇒ ⭐⭐ SO: A ROUTING OR MIDDLEWARE QUESTION IS A STARLETTE QUESTION. A
⭐     VALIDATION OR SERIALISATION QUESTION IS A PYDANTIC QUESTION. ⭐ Searching
⭐     the right repository is half of debugging this stack, and people lose
⭐     hours reading FastAPI's source for behaviour that lives one layer down.
```

⭐ **`app` is an ASGI application** (Day 110) — `uvicorn main:app` calls it with `scope`, `receive`,
`send`. ⭐⭐ **`FastAPI.__call__` is a handful of lines**, and reading it is a genuinely useful twenty
minutes: you will find the lifespan branch and the delegation to Starlette's router exactly where you
would have put them.

# Part 3 — ⭐ Parameters, and how it decides

```python
@app.get("/orders/{order_id}")
async def get_order(
    order_id: int,                                   # ⭐ in the path template ⇒ PATH param
    include_items: bool = False,                     # ⭐ a scalar, not in the path ⇒ QUERY param
    x_request_id: str = Header(default=None),        # ⭐ explicit HEADER
    payload: OrderPatch | None = None,               # ⭐⭐ a BaseModel ⇒ the BODY
    db: AsyncSession = Depends(get_db),              # ⭐ a Depends ⇒ a DEPENDENCY
): ...
```

```
⭐⭐ THE RULES IT APPLIES, IN ORDER — WORTH KNOWING BECAUSE THEY EXPLAIN EVERY
⭐   "WHY IS THIS A QUERY PARAMETER" CONFUSION:
⭐   1. the name appears in the path template     ⇒ ⭐ PATH
⭐   2. the default is `Depends(...)`             ⇒ ⭐ DEPENDENCY
⭐   3. the annotation is a Pydantic model        ⇒ ⭐⭐ BODY
⭐   4. an explicit marker: Query/Header/Cookie/Form/File/Body
⭐   5. otherwise, a scalar type                  ⇒ ⭐ QUERY
⭐ ⇒ ⭐⭐ RULE 3 IS THE ONE THAT SURPRISES PEOPLE: a bare `dict` or `list`
⭐     annotation is ALSO treated as a body — ⭐ and it documents nothing
⭐     (Day 126), so it is worth banning in review.
⭐ ⇒ ⭐ prefer the `Annotated` form in new code:
⭐        q: Annotated[str | None, Query(max_length=50)] = None
⭐     ⭐⭐ because it separates the TYPE from the METADATA, so the same annotated
⭐     alias can be reused across routes — which is how you stop repeating
⭐     `Depends(get_db)` in forty signatures.
```

```python
from typing import Annotated
DB = Annotated[AsyncSession, Depends(get_db)]        # ⭐⭐ declare once
CurrentUser = Annotated[User, Depends(current_user)]

async def get_order(order_id: int, db: DB, user: CurrentUser): ...   # ⭐ reads cleanly
```

# Part 4 — ⭐⭐ Errors, and the exception handler

```python
class InsufficientStock(Exception):                  # ⭐ your domain exception (Day 120)
    def __init__(self, sku: str): self.sku = sku

@app.exception_handler(InsufficientStock)            # ⭐⭐ Day 112's registry — same idea
async def handle_stock(request: Request, exc: InsufficientStock):
    return JSONResponse(status_code=409, content={
        "code": "insufficient_stock", "detail": f"{exc.sku} is out of stock",
        "request_id": request.state.request_id,      # ⭐ Day 099A
    })

@app.exception_handler(RequestValidationError)       # ⭐⭐ override the DEFAULT 422 shape
async def handle_validation(request, exc):
    return JSONResponse(status_code=422, content={
        "code": "validation_error",
        "errors": [{"field": ".".join(map(str, e["loc"][1:])), "code": e["type"],
                    "message": e["msg"]} for e in exc.errors()],   # ⭐ Day 119's shape
    })
```

```
⭐⭐ TWO THINGS WORTH DOING ON DAY ONE OF ANY FASTAPI PROJECT:
⭐  1. ⭐⭐ OVERRIDE `RequestValidationError`. The default 422 body is FastAPI's
⭐       shape, not yours — ⭐ so your API has two error formats (Day 120's exact
⭐       complaint) and clients must parse both.
⭐  2. ⭐ REGISTER DOMAIN EXCEPTIONS rather than raising `HTTPException` deep in
⭐       a service. ⭐⭐ `HTTPException` IN A SERVICE FUNCTION DRAGS HTTP INTO
⭐       YOUR DOMAIN LAYER (Day 090) — the service now cannot be called from a
⭐       worker, a CLI or a test without importing a web framework.
⭐   ⇒ ⭐ raise `InsufficientStock` in the domain; translate it at the edge.
```

⚠️ ⭐⭐ **The default 500 handler re-raises in debug and returns a bare `Internal Server Error`
otherwise** — ⭐ which is correct (Day 105) but gives you no request id. **Add a handler for
`Exception` that logs once and returns your shape.**

# Part 5 — ⭐ Middleware, background tasks, and what is *not* there

```python
@app.middleware("http")                              # ⭐ Starlette middleware (Day 108)
async def add_request_id(request: Request, call_next):
    request.state.request_id = request.headers.get("x-request-id") or uuid4().hex
    response = await call_next(request)
    response.headers["x-request-id"] = request.state.request_id
    return response
```

⚠️ ⭐⭐ **Middleware order is reversed relative to registration in Starlette** — the *last* added is
outermost. ⭐ Day 108's rules still hold (error handling outermost, CORS outside auth); **only the
direction of the list changes**, and getting it backwards is a real bug with a confusing symptom.

```python
@app.post("/orders")
async def create(payload: OrderIn, background: BackgroundTasks):
    order = await service.place(payload)
    background.add_task(send_confirmation_email, order.id)   # ⭐ runs AFTER the response
    return order
```

```
⚠️⚠️ ⭐⭐ `BackgroundTasks` RUNS IN THE SAME PROCESS, AFTER THE RESPONSE IS SENT.
⭐    ⇒ ⭐ IT IS NOT A QUEUE. If the worker restarts (a deploy — Day 081), THE
⭐         TASK IS SILENTLY LOST. There is no retry, no persistence, no visibility.
⭐    ⇒ ⭐⭐ USE IT FOR: something you would not mind losing — a metrics ping, a
⭐         cache warm, a best-effort log.
⭐    ⇒ ⭐⭐ USE CELERY FOR: anything a user would notice missing — an email, a
⭐         webhook, a payment reconciliation (Stage 4's later days).
⭐    ⇒ ⭐ and it blocks the worker if it is slow, because it runs before the
⭐         connection is freed for the next request.
```

```
⭐⭐ WHAT FASTAPI DOES **NOT** GIVE YOU, AND EXPECTING IT TO IS THE COMMONEST
⭐   NEW-USER MISTAKE:
⭐   ✘ ⭐⭐ AN ORM, MIGRATIONS, OR A DATABASE SESSION ⇒ SQLAlchemy + Alembic,
⭐       and YOU wire the session lifecycle (Days 135-137)
⭐   ✘ ⭐ AUTH — `OAuth2PasswordBearer` extracts a token and validates NOTHING.
⭐       ⭐⭐ Days 114-118 are still entirely your job.
⭐   ✘ an admin interface, forms, templates as a first-class concern ⇒ ⭐ Django
⭐   ✘ ⭐ a project structure ⇒ ⭐⭐ which is why so many FastAPI projects are one
⭐       2,000-line `main.py` (Day 133 fixes this)
⭐   ⇒ ⭐⭐ FASTAPI IS A GOOD HTTP LAYER, NOT A FRAMEWORK IN DJANGO'S SENSE. ⭐ It
⭐        gives you the edge and leaves the application to you — which is freedom
⭐        if you know Days 089-091, and a mess if you do not.
```

## Common mistakes

| Mistake | Correction |
|---|---|
| ⭐ Treating it as magic | ⭐⭐ Starlette + Pydantic + signature inspection. Search the right repo. |
| ⭐ A bare `dict` body annotation | ⭐ It validates nothing and documents nothing. |
| Repeating `Depends(get_db)` everywhere | ⭐ An `Annotated` alias, declared once. |
| ⭐⭐ **Not overriding `RequestValidationError`** | ⭐⭐ Two error formats in one API. |
| ⭐ `HTTPException` inside a service | ⭐⭐ Drags HTTP into the domain; the service is now unusable from a worker. |
| No handler for `Exception` | ⭐ A 500 with no request id. |
| ⭐ Assuming middleware order matches registration | ⭐⭐ Starlette reverses it — last added is outermost. |
| ⭐⭐ **`BackgroundTasks` for an email** | ⭐⭐ Same process, lost on restart, no retry. Use a queue. |
| Expecting an ORM or auth to be included | ⭐ It is an HTTP layer. |
| One 2,000-line `main.py` | ⭐ Day 133. |

## Interview questions

**Q: What is FastAPI, architecturally?**
> A thin layer over Starlette and Pydantic. Starlette does routing, middleware, request and response
> objects, WebSockets and the ASGI plumbing; Pydantic does validation, serialisation and JSON Schema.
> FastAPI's own contribution is one idea taken a long way: read the handler's type annotations and
> derive everything from them — which parameters come from the path, query, headers or body, what to
> validate, what to serialise, and what the OpenAPI schema says. Knowing the split is practically
> useful, because a routing question is a Starlette question and a validation question is a Pydantic
> one, and people lose hours reading the wrong repository.

**Q: How does it know a parameter is a query parameter rather than a body?**
> A fixed set of rules in order: if the name is in the path template it's a path parameter; if the
> default is `Depends` it's a dependency; if the annotation is a Pydantic model it's the body; if
> there's an explicit marker like `Query` or `Header` that wins; otherwise a scalar type is a query
> parameter. The rule that surprises people is the model one — a bare `dict` or `list` annotation is
> also treated as a body, and it validates nothing and documents nothing, so I'd flag it in review.

**Q: Would you raise `HTTPException` in a service function?**
> No — that drags HTTP into the domain layer. The moment a service raises `HTTPException`, it can't be
> called from a Celery worker, a CLI or a test without importing a web framework, and the status code
> is now decided by business logic. I'd raise a domain exception like `InsufficientStock` and register
> an exception handler that translates it at the edge. That keeps the layering honest and keeps the
> status-code decision where the HTTP contract lives.

**Q: What's wrong with `BackgroundTasks` for sending an email?**
> It runs in the same process after the response is sent, so it isn't a queue — there's no
> persistence, no retry and no visibility. A deploy restarts the worker and the task is silently lost,
> which for a confirmation email means a customer who never hears from you and no record that anything
> failed. It also occupies the worker before the connection is freed. I'd use it for things I wouldn't
> mind losing — a metrics ping, a cache warm — and Celery for anything a user would notice missing.

**Q: What doesn't FastAPI give you?**
> An ORM, migrations, session management, authentication, an admin, or a project structure.
> `OAuth2PasswordBearer` extracts a token and validates nothing — all the password hashing, session
> and token work is still yours. That's a reasonable design: it's a good HTTP layer rather than a
> framework in Django's sense. But it means the application architecture is entirely your
> responsibility, which is freedom if you have opinions about layering and a 2,000-line `main.py` if
> you don't.

## 🎙️ Articulation drill

Record two minutes: **"Why FastAPI?"**

⭐ **Answer architecturally rather than with adjectives:** **"it's a thin layer over Starlette for the
HTTP side and Pydantic for the data side, and its own contribution is one idea taken a long way: read
the handler's annotations and derive everything from them — routing, validation, dependency injection,
serialisation and the OpenAPI schema."**

⭐⭐ **Then the property that actually matters, not the speed claim:** *"the thing I'd sell isn't
performance, it's that the validation model and the documentation model are the same object. The
schema can't drift from the code because it's generated from what actually runs. And the response
model is a security control as much as a documentation one — without it, someone adds a column next
month and your public endpoint starts returning it with no code change and no failing test."*

⭐⭐ **Then be honest about the boundary, because that's what shows judgement:** *"but it's an HTTP
layer, not a framework in Django's sense. No ORM, no migrations, no auth — `OAuth2PasswordBearer`
extracts a token and validates nothing — no admin, and no project structure. That's freedom if you have
opinions about layering, and it's why so many FastAPI projects are a single 2,000-line `main.py`. I'd
pick Django when I want the batteries and the admin, and FastAPI when I want a clean async API and I'm
happy to make the architectural decisions myself."*

⭐ **Close on a specific practice:** *"and two things I'd do on day one of any FastAPI project:
override the default validation-error handler, so the API has one error shape rather than two, and
keep `HTTPException` out of service functions — raise domain exceptions and translate them at the edge,
so the domain stays callable from a worker or a test."*
