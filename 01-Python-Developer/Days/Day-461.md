# Part 1 — ⭐⭐ The ten shapes

```
⭐⭐ ① ***EVERYTHING FOLLOWS FROM NEXT-TOKEN PREDICTION.***
⭐   ⭐ No memory, no lookup, no truth-checking step. ⭐ Latency
⭐     linear in ***output***. ⭐⭐ FLUENCY AND ACCURACY COME FROM
⭐     THE SAME MECHANISM, WHICH IS WHY A CONFIDENT FABRICATION
⭐     IS THE MODEL SUCCEEDING, NOT FAILING. (D414/449)

⭐⭐ ② ***THE TOKEN IS THE UNIT OF EVERYTHING*** — ⭐ cost,
⭐   latency, context, rate limits, capacity. ⭐⭐ SO "ADD MORE
⭐   CHUNKS" IS SIMULTANEOUSLY A QUALITY, COST, LATENCY AND
⭐   THROUGHPUT DECISION. (D415/416/457/458)

⭐⭐ ③ ***A CHANGE YOU CANNOT MEASURE IS A CHANGE YOU CANNOT
⭐   MAKE.*** ⭐ Evals are not a quality practice, they are the
⭐   precondition for every optimisation in the stage.
⭐   ⭐⭐ AND THE EVAL SET BUILT FROM PRODUCTION FAILURES IS THE
⭐     ASSET; THE PROMPT IS COPYABLE IN A MINUTE. (D425/435/459)

⭐⭐ ④ ***CHUNKING IS THE CEILING, AND THE FREE FIXES BEAT THE
⭐   PAID ONES.*** ⭐ Nothing downstream recovers information no
⭐   chunk contains. ⭐⭐ TWO-THIRDS OF THE TOTAL GAIN ARRIVES
⭐   BEFORE YOU SPEND A PENNY — ⭐ and ordering the work
⭐   correctly ***is*** the skill. (D430/433/436)

⭐⭐ ⑤ ***MAKE ABSTENTION POSSIBLE OR YOU MANUFACTURE
⭐   FABRICATION.*** ⭐ A required field on an absent value
⭐   ***forces*** an invention — ⭐⭐ AND YOU CAUSED IT WITH A
⭐   TYPE ANNOTATION. ⭐ Retrieval must be able to return
⭐   nothing; the schema must permit null. (D422/424/433/449)

⭐⭐ ⑥ ***CONSTRAIN AT THE SAMPLER, VALIDATE IN ORDINARY
⭐   PYTHON.*** ⭐ A prompt is a request; constrained decoding is
⭐   a guarantee. ⭐⭐ AND SCHEMA-VALID IS NOT CORRECT AND NOT
⭐   SAFE — ⭐ the business rules and the authorisation check are
⭐   where the safety lives, and both are boring code.
⭐   (D418/424/447)

⭐⭐ ⑦ ***THE PERMISSION FILTER IS A CORRECTNESS INVARIANT AND
⭐   ITS FAILURE IS SILENT.*** ⭐ Generation launders leaked data
⭐   into fluent prose, so row counts, error rates and latency
⭐   all stay normal. ⭐⭐ TENANT FROM THE SESSION NEVER THE
⭐   MODEL; FILTER INSIDE THE QUERY NEVER AFTER IT; RLS
⭐   UNDERNEATH; A CANARY IN CI; DOC IDS LOGGED. (D434/446/454)

⭐⭐ ⑧ ***INSTRUCTIONS AND DATA SHARE ONE CHANNEL, AND THERE IS
⭐   NO PREPARED STATEMENT.*** ⭐ A role label is a hint with a
⭐   good track record, not a boundary. ⭐⭐ SO YOU MANAGE THE
⭐   RISK ARCHITECTURALLY: BREAK THE TRIFECTA, BOUND THE
⭐   AUTHORITY, GATE THE IRREVERSIBLE. (D446/447/448)

⭐⭐ ⑨ ***A CHECK IS NOT A BOUNDARY.*** ⭐ Classifiers have
⭐   false-negative rates and a false negative is a bypass.
⭐   ⭐⭐ BOUNDARIES FIRST — AUTHZ, RATE LIMITS, SCHEMAS,
⭐   ALLOWLISTS, HUMAN GATES — CHECKS ON TOP FOR RATE REDUCTION
⭐   AND TELEMETRY. (D440/448/456)

⭐⭐ ⑩ ***THE MODEL IS NON-DETERMINISTIC, SO RETRY NO LONGER
⭐   REPLAYS.*** ⭐ Idempotency keys come from the caller at the
⭐   point of intent; resume replays the log rather than
⭐   re-deciding; compensation is computed from the log, never by
⭐   asking the model. ⭐⭐ AND EVERYTHING RETURNS 200 WHILE
⭐   BROKEN, SO YOU MONITOR DISTRIBUTIONS AND USER BEHAVIOUR
⭐   RATHER THAN ERRORS. (D439/444/455)
```

```
⭐ ① ***THE LADDER.*** ⭐ "0.62 dense → 0.75 prefix, free →
⭐   0.82 hybrid, 15ms → 0.91 rerank, 150ms."
⭐ ② ***THE CEILING.*** ⭐ "Recall@8 is 0.91, so 9% is
⭐   unreachable by any prompt. ⭐⭐ WE STOPPED TUNING WHEN WE
⭐   MEASURED THAT."
⭐ ③ ***THE LEAK, CAUGHT TWICE.*** ⭐ "Deleted the tenant
⭐   predicate: canary red in 40 seconds. ⭐⭐ REPEATED IT WITH
⭐   RLS ON AND IT DID NOT LEAK AT ALL."
⭐ ④ ***ABSTENTION.*** ⭐ "0.15 → 0.85 on twenty unanswerable
⭐   questions, ⭐⭐ USING ONLY FREE FIXES."
⭐ ⑤ ***THE ROUTING.*** ⭐ "A third of real questions were
⭐   aggregations. ⭐⭐ THOSE GO TO VALIDATED SQL AND WE SHOW THE
⭐   QUERY."
⭐ ⑥ ***THE DELETION.*** ⭐ "HyDE measured flat; we removed it.
⭐   ⭐⭐ SEMANTIC CACHING HAD A 4% FALSE-HIT RATE SO IT SERVES

⭐   both mid-step windows: ⭐⭐ EXACTLY ONE EMAIL, EVERY TIME."

⭐   alias swap, ⭐⭐ SO ROLLBACK IS ONE CONFIG VALUE AND THAT
```

## 🎙️ Articulation drill

⭐⭐ **Three minutes, out loud: "what did you learn building AI systems?"**

Open with the frame, because it reframes the interviewer's expectations of the whole conversation.
**That an LLM application is a distributed system with a non-deterministic, expensive, untrusted
component in the middle — and that everything I added for it is a consequence of those three adjectives.
Most of what I built wasn't AI. The ingestion pipeline is a job with retries and idempotency. The vector
index is derived state that has to be rebuildable, and you don't own derived state until you've rebuilt
it with a stopwatch. The agent run is a durable workflow, not a loop. Serving is concurrency,
backpressure and load shedding. SSRF and path traversal are exactly themselves.**

Then what's genuinely new. **Non-determinism broke my retry model: retrying a step means asking the
model again, so it can emit different arguments, which means a content-derived idempotency key is
derived from a coin flip. Keys come from the caller at the point of intent, resume replays the log
rather than re-deciding, and compensation is computed from the log — never by asking the model, because
that's the last place I want sampling. Cost is consumed rather than provisioned and it's
user-controlled, so a per-tenant budget is a correctness control, not a finance one. And untrusted means
instructions and data share one channel with no prepared statement available, so a role label is a hint
with a good track record, not a boundary.**

Then the two things I'd want them to take away. **First: a change you can't measure is a change you
can't make. Evals aren't a quality practice, they're the precondition for every optimisation — you can't
move to a cheaper model, change a prompt or change chunking without one, because you can't see the
effect. And the eval set built from production failures is the asset; the prompt is copyable in a
minute. Second: the failures here are silent. A retrieval permission leak returns a fluent, well-cited
paragraph built from another customer's data with no exception, no error-rate change and no latency
change, because generation launders it into original prose. So I monitor distributions and user
behaviour rather than errors, and the single most valuable signal I instrument is the user asking the
same thing again in different words.**

Close on proof and on limits. **Concretely: recall went 0.62 to 0.91, and two-thirds of that gain was
free. Abstention on unanswerable questions went 0.15 to 0.85 using only free fixes. A third of real
questions turned out not to be retrieval questions at all, so they route to validated SQL. I deleted
HyDE because it measured flat. I killed the process at every step index and proved exactly one email
every time. And what it can't do: nine percent of questions are unreachable by any prompt, revocation
takes thirty seconds, full rebuild is thirty-eight minutes, and I can't pretrain a model — that's a
different job, and saying so is what makes the rest of it believable.**
