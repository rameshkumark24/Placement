# Day 449 👻

**P-449** · 👻 **Hallucination mechanics** — ⭐⭐ the model is working correctly

**Time:** 3 hrs · **Mode:** NEW

> ⭐⭐ **The sentence to own: there is no truth-checking step anywhere in the architecture — fluency and
> accuracy are produced by the same mechanism, so a confident fabrication is not the model
> malfunctioning, it is the model succeeding at the only task it has, and every mitigation is something
> you bolt on from outside.**

# Part 1 — ⭐⭐ Why it is not a bug

```
⭐ ***THE MECHANISM, RESTATED FROM DAY 414:*** ⭐ predict the
⭐   most probable next token given everything so far.
⭐   ⭐⭐ THERE IS NO LOOKUP. NO DATABASE. NO CONFIDENCE
⭐     THRESHOLD. NO STEP AT WHICH THE MODEL CONSULTS ANYTHING.

⭐ ⇒ ***"THE CAPITAL OF FRANCE IS ___"*** and ***"THE CEO OF
⭐   NORTHBRIDGE LOGISTICS IS ___"*** ⭐⭐ ARE THE SAME OPERATION.
⭐   ⭐ One has overwhelming training support and one has none —
⭐     ⭐⭐ AND ***NOTHING IN THE FORWARD PASS MARKS THE
⭐     DIFFERENCE FOR THE USER***. ⭐ Both produce fluent text.

⭐ ***THREE REASONS IT CANNOT NATURALLY SAY "I DON'T KNOW":***
⭐   ⭐ ① ***THE TRAINING DATA BARELY CONTAINS IT.*** ⭐ Text on
⭐     the internet answers questions; ⭐⭐ IT RARELY CONTAINS A
⭐     WELL-FORMED QUESTION FOLLOWED BY "NOBODY KNOWS".
⭐   ⭐ ② ***POST-TRAINING REWARDS HELPFULNESS*** (Day 417).
⭐     ⭐⭐ HUMAN RATERS PREFER AN ANSWER TO A REFUSAL, SO
⭐     PREFERENCE TUNING ***ACTIVELY SELECTS AGAINST***
⭐     ABSTENTION.
⭐   ⭐ ③ ⭐⭐ THERE IS NO INTERNAL SIGNAL SEPARATING RECALL FROM
⭐     CONSTRUCTION. ⭐ The model is not withholding a doubt it
⭐     has. ⭐ It does not have one.

⭐⭐ ⇒ SO EVERY MITIGATION IN THIS DAY IS ***EXTERNAL***: ⭐ give
⭐   it the facts, make abstention possible, or check the answer
⭐   afterwards. ⭐⭐ NONE OF THEM MAKE THE MODEL MORE HONEST,
⭐   BECAUSE HONESTY IS NOT A DIAL IT HAS.
```

# Part 3 — The plausibility gradient

```
⭐ ***HALLUCINATION RATE IS NOT UNIFORM. IT TRACKS TWO THINGS:
⭐   HOW ***SPECIFIC*** THE CLAIM IS, AND HOW ***RARE*** THE FACT
⭐   IS.***

⭐   ⭐ SAFEST → ⭐ general explanations, well-known concepts,
⭐     common code idioms;
⭐   ⭐ RISKY → ⭐ dates, quantities, versions;
⭐   ⭐ ⭐⭐ WORST → ⭐⭐ NAMES, IDENTIFIERS, CITATIONS, URLS,
⭐     PACKAGE NAMES, STATUTE SECTIONS, PRICES.

⭐ ***WHY:*** ⭐ these are exactly the tokens with ***no strong
⭐   distributional support*** — ⭐⭐ THE MODEL KNOWS THE
⭐   ***FORM*** OF A CASE CITATION PERFECTLY AND HAS NO
⭐   PARTICULAR SUPPORT FOR ANY SPECIFIC ONE, ⭐ so it generates
⭐   a well-formed one. ⭐⭐ THE FORMAT IS LEARNED; THE CONTENT IS
⭐   SAMPLED.

⭐ ***THE THREE DOMAIN KILLERS:***
⭐   ⭐ ⭐⭐ CODE — INVENTED APIS AND ***INVENTED PACKAGE NAMES***.
⭐     ⭐ The second is a supply-chain attack surface:
⭐       ⭐⭐ ATTACKERS REGISTER THE PACKAGE NAMES MODELS
⭐       COMMONLY INVENT AND WAIT. ⭐ ⇒ resolve every import
⭐       against the real index before trusting it.
⭐   ⭐ ***LEGAL*** — invented citations that are formatted
⭐     perfectly. ⭐⭐ PEOPLE HAVE BEEN SANCTIONED FOR FILING
⭐     THEM.
⭐   ⭐ ***MEDICAL / FINANCE*** — invented dosages, rates and
⭐     thresholds, ⭐ which are numerically plausible by
⭐     construction.

⭐⭐ ⇒ PRACTICAL RULE: ***ANY FIELD IN YOUR SCHEMA THAT IS A
⭐   NAME, NUMBER, IDENTIFIER OR CITATION NEEDS A VERIFICATION
⭐   PATH.*** ⭐ Prose can be judged; identifiers must be checked.
```

# Part 4 — ⭐⭐ Confidence signals, ranked by how much they are worth

```
⭐ ① ❌ ***VERBALISED CONFIDENCE*** — "I'm 90% confident."
⭐   ⭐⭐ NEARLY WORTHLESS. ⭐ It is generating the ***text of a
⭐     confidence estimate***, which is itself a prediction with
⭐     no privileged access to anything. ⭐⭐ AND IT IS BADLY
⭐     CALIBRATED IN A SPECIFIC DIRECTION: PREFERENCE TUNING
⭐     MAKES IT CONFIDENT-SOUNDING (D417).

⭐ ② ⚠️ ***TOKEN LOG-PROBABILITIES*** (Day 418). ⭐ Weakly
⭐   useful. ⭐ Low probability on the ***specific tokens*** of a
⭐   name or number is a genuine signal. ⭐⭐ BUT A MODEL CAN BE
⭐   CONFIDENTLY WRONG — HIGH PROBABILITY MEANS "CONSISTENT WITH
⭐   TRAINING", NOT "TRUE". ⭐ Best as a ***flag for review***,
⭐   never as a gate.

⭐ ③ ✅ ***SELF-CONSISTENCY.*** ⭐ Sample the same question n
⭐   times at temperature > 0 and compare. ⭐⭐ IF THE MODEL
⭐   RETURNS A DIFFERENT COMPANY NAME EACH TIME, IT IS
⭐   FABRICATING; IF IT RETURNS THE SAME ONE FIVE TIMES, IT AT
⭐   LEAST HAS SUPPORT. ⭐ Costs n×, so reserve it for
⭐   high-stakes fields. ⭐⭐ THE BEST ***CHEAP*** SIGNAL THERE IS.

⭐ ④ ⭐⭐ ***VERIFICATION AGAINST A SOURCE. THE ONLY REAL ONE.***
⭐   ⭐ the quote-in-source check (Day 424) — ⭐ free, exact,
⭐     catches invented numbers and names outright;
⭐   ⭐ ***existence checks*** — ⭐⭐ DOES THIS PACKAGE EXIST ON
⭐     PyPI? DOES THIS METHOD EXIST IN THE INSTALLED VERSION?
⭐     DOES THIS URL RETURN 200? DOES THIS ORDER ID EXIST IN THE
⭐     DATABASE? ⭐ Boring, deterministic, decisive.
⭐   ⭐ cross-model agreement — ⭐ expensive, useful for one-off
⭐     high-value checks, ⭐⭐ AND CORRELATED ERRORS ARE REAL
⭐     BECAUSE MODELS SHARE TRAINING DATA.
```

# Part 6 — Measuring it, so the conversation is about numbers

```
⭐ ***THREE NUMBERS. GET THEM ALL.***
⭐   ⭐ ① ⭐⭐ ***ABSTENTION RATE ON THE UNANSWERABLE SET***
⭐     (Day 435) — ⭐ the headline. ⭐ Baselines are commonly
⭐     0.1–0.3; ⭐⭐ 0.85+ IS ACHIEVABLE WITH ONLY FREE FIXES.
⭐   ⭐ ② ***GROUNDEDNESS*** — the fraction of claims with a
⭐     verified quote in the context. ⭐ Programmatic.
⭐   ⭐ ③ ***IDENTIFIER VALIDITY*** — ⭐⭐ THE FRACTION OF
⭐     GENERATED IDS, PACKAGES, URLS AND CITATIONS THAT ACTUALLY
⭐     RESOLVE. ⭐ Almost nobody measures this and it is trivially
⭐     measurable.

⭐ ***AND THE PRODUCT SIDE, WHICH IS HALF THE MITIGATION:***
⭐   ⭐ ⭐⭐ SHOW THE SOURCE NEXT TO THE CLAIM, NOT AT THE BOTTOM
⭐     — ⭐ verification cost falls and people actually check;
⭐   ⭐ make abstention a ***good*** experience: "I couldn't find
⭐     this — here are the three closest documents";
⭐   ⭐ ⭐⭐ NEVER PRESENT AN UNVERIFIED IDENTIFIER AS CLICKABLE.
⭐     ⭐ A live link is a claim your product is making.
```

# 💬 Interview

**1. "Why do models hallucinate?"**

⭐ Because there's no truth-checking step in the architecture. ⭐⭐ The model predicts the most probable
next token; "the capital of France is" and "the CEO of Northbridge Logistics is" are the same operation,
one with overwhelming training support and one with none, and nothing in the forward pass marks the
difference for the user. ⭐ Fluency and accuracy come from the same mechanism, so a confident fabrication
isn't a malfunction — it's the model succeeding at its only task. ⭐⭐ And it can't naturally abstain for
three reasons: training text rarely contains a well-formed question followed by "nobody knows",
preference tuning actively selects against refusals because raters prefer answers, and there's no
internal signal separating recall from construction. ⭐ It isn't withholding a doubt. It doesn't have
one.

**2. "How do you reduce it?"**

⭐ I'd separate the types first, because they have different fixes. ⭐⭐ If the fact was never in
training, that's retrieval. If it's stale, retrieval with timestamps in the context. If retrieval found
nothing and the model answered anyway, that's a rerank floor so retrieval can return nothing plus an
abstention path in the prompt *and* the schema. If the answer was in the context and the model used its
prior instead, that's fewer chunks, best-first ordering and an explicit instruction that the documents
override what it knows. ⭐ And if the shape is right but the details are invented, that's an existence
check. ⭐⭐ The useful part is that recall-versus-faithfulness in my eval tells me *which* type I have,
so I'm not guessing which fix to apply.

**3. "What's the most dangerous kind?"**

⭐ Confabulated specifics — where the format is perfect and the content is sampled. ⭐⭐ The model knows
the shape of a case citation or an API signature or a package name flawlessly and has no particular
support for any specific one, so it produces a well-formed invention. ⭐ In code that's a supply-chain
issue: attackers register package names that models commonly invent and wait, so every generated import
gets resolved against the real index. ⭐⭐ In legal, people have been sanctioned for filing fabricated
citations. ⭐ The practical rule I use is that any schema field which is a name, number, identifier or
citation needs a verification path — prose can be judged, identifiers must be checked.

**4. "Can you use the model's confidence?"**

⭐ Only carefully, and there's a ranking. ⭐⭐ Verbalised confidence — "I'm 90% sure" — is nearly
worthless, because it's generating the *text* of a confidence estimate with no privileged access to
anything, and preference tuning biases it toward sounding confident. ⭐ Token log-probabilities are
weakly useful: low probability on the specific tokens of a name or number is a real signal, but high
probability means "consistent with training", not "true", so it's a flag for review rather than a gate.
⭐⭐ Self-consistency is the best cheap signal — sample five times and see whether you get the same
company name or five different ones — and it costs five times, so I reserve it for high-stakes fields.
⭐ The only real signal is verification against a source.

**5. "What actually moved the number for you?"**

⭐ Four free things, and they beat every paid one. ⭐⭐ Retrieval with good recall was the largest single
effect. Then an abstention path in both the prompt and the schema — our abstention rate on unanswerable
questions went from 0.15 to 0.85. Then a required verbatim supporting quote that we check
programmatically against the source, which kills invented numbers and names outright. And making
possibly-absent fields nullable, because a required field on an absent value *forces* an invention.
⭐ A stronger model was moderate and expensive by comparison. ⭐⭐ What did nothing measurable was "do
not hallucinate" in the prompt, which is what almost everyone tries first — it describes an outcome, and
there's no mechanism in the model that corresponds to it.

**6. "How do you measure hallucination?"**

⭐ Three numbers. ⭐⭐ Abstention rate on a set of questions the corpus genuinely can't answer, which is
the headline. Groundedness — the fraction of claims carrying a quote we verify against the context,
which is programmatic and free. ⭐ And identifier validity: the fraction of generated ids, packages,
URLs and citations that actually resolve. ⭐⭐ Almost nobody measures that third one and it's trivially
measurable. ⭐ Then there's the product half — sources shown next to the claim rather than at the
bottom, abstention made a good experience, and never rendering an unverified identifier as a clickable
link, because a live link is a claim my product is making.
