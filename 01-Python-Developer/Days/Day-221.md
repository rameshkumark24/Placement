# Day 221 📦

**P-221** · 📦 **npm and the dependency surface** — ⭐⭐ 900 packages you did not choose

**Time:** 3 hrs · **Mode:** NEW

> ⭐⭐ **The sentence to own: `npm install` for a normal React app pulls in several hundred packages
> from several hundred maintainers you have never heard of, all of which run arbitrary code on your
> machine at install time and some of which ship to your users — and the only controls that work are
> boring ones you apply before the problem, not after.**
>
> Today: the lockfile, ⭐ the transitive explosion, ⭐⭐ the four real attacks, and the rules.

---

# Part 1 — The files, and which one matters

| File | ⭐ What it is |
|---|---|
| `package.json` | Your **intent**. Ranges: `^18.2.0` = "18.x, any minor/patch". |
| ⭐⭐ `package-lock.json` | **What you actually got** — exact versions, integrity hashes, the full tree. **Commit it. Always.** |
| `node_modules/` | The installed tree. Never commit. |

```
⭐⭐ THE COMMANDS, AND THE ONE YOU WANT IN CI

⭐   npm install    ⇒ ⭐ MAY UPDATE THE LOCKFILE to satisfy ranges.
⭐                     Fine locally. ⭐⭐ WRONG IN CI — your build is
⭐                     no longer reproducible and "works on my machine"
⭐                     becomes literally true.

⭐   npm ci         ⇒ ⭐⭐ INSTALLS EXACTLY THE LOCKFILE. Fails if
⭐                     package.json and the lock disagree. Deletes
⭐                     node_modules first. ⭐ USE THIS IN CI, ALWAYS.

⭐   ⇒ ⭐⭐ SAME DISTINCTION AS `uv sync` VS `pip install` (Day 075).
⭐     A lockfile you do not install from is decoration.
```

| ⭐ Range | Allows |
|---|---|
| `^1.2.3` | 1.x.x — ⭐ minor + patch. The npm default, and the widest one people use. |
| `~1.2.3` | 1.2.x — patch only |
| `1.2.3` | ⭐⭐ exactly that. Pinning **your** deps is defensible; it does nothing about transitive ones. |

# Part 2 — ⭐⭐ Why there are 900 of them

```
⭐⭐ YOU ADD 12 PACKAGES. YOU GET ~900.

⭐   react, react-dom, vite, typescript, eslint, tailwind, zod, ...
⭐   ⇒ each has deps, which have deps, which have deps.
⭐   ⇒ ⭐ npm ls --all | wc -l   ⇒ run it. The number is the point.

⭐⭐ WHY WORSE THAN PyPI?
⭐   · ⭐ CULTURE OF TINY PACKAGES — is-odd, left-pad. A stdlib gap
⭐     that never closed, so trivial things became dependencies.
⭐   · ⭐⭐ NESTED RESOLUTION — npm can install FIVE COPIES of five
⭐     different versions of the same package. Python cannot; it has
⭐     one site-packages and a conflict is an error you must resolve.
⭐   · ⭐ BUILD TOOLING IS ITSELF JAVASCRIPT — your bundler,
⭐     linter and test runner are all npm packages too.
```

| ⭐ Which of them can hurt you | |
|---|---|
| **`dependencies`** | ⭐⭐ Ship to users. An XSS or an exfiltrator here reaches every visitor. |
| **`devDependencies`** | ⭐⭐ Do **not** ship — but they **run on your machine and in CI**, where your npm token, cloud creds and source live. **Often the more valuable target.** |
| **Transitive, either kind** | ⭐ You never chose them and you will not recognise the name in an advisory. |

# Part 3 — ⭐⭐ The four attacks

| Attack | ⭐ How it works | ⭐⭐ What stops it |
|---|---|---|
| **Typosquatting** | `reakt`, `lodahs`, `crossenv`. ⭐ Also **AI-invented names** — Day 449: a model hallucinates a plausible package, an attacker registers it. | ⭐⭐ Read the name character by character. Check downloads and repo before adding. |
| **Maintainer compromise** | A real, popular package gets a malicious version — stolen credentials or a handed-over repo. | ⭐⭐ **Delay adoption**: `npm config set save-exact true` + update deliberately, not automatically. A malicious version is usually pulled within hours. |
| **Install scripts** | ⭐⭐ `postinstall` runs **arbitrary code** on `npm install` — before you have run a single line of your own. | ⭐ `npm ci --ignore-scripts` where feasible; audit which packages need scripts. |
| **Dependency confusion** | An internal package name published publicly at a higher version; your resolver prefers it. | ⭐ Scope internal packages (`@yourco/x`) and configure the registry per scope. |

```
⭐⭐ THE CONTROLS THAT ACTUALLY WORK, IN ORDER OF VALUE

⭐   ① ⭐⭐ ADD FEWER PACKAGES. The only control with no ongoing cost.
⭐      "Can I write this in 20 lines?" — for a debounce, a clsx,
⭐      a date format: yes, and then you own it forever for free.
⭐   ② COMMIT THE LOCKFILE, BUILD WITH `npm ci`.
⭐   ③ npm audit --omit=dev  in CI, and ⭐ FAIL THE BUILD on high.
⭐   ④ Dependabot/Renovate ⇒ ⭐ updates as REVIEWABLE PRs, not silent drift.
⭐   ⑤ ⭐⭐ CHECK EVERY PACKAGE AN AI SUGGESTS EXISTS AND IS THE RIGHT
⭐      ONE. This is rule 5 in the repo README and it is not theoretical.
```

> ⭐ **The honest limit of `npm audit`.** It reports *known* advisories, it is noisy with unreachable
> dev-only findings, and it says nothing about a package that is malicious *today* and undiscovered.
> It is a floor, not a ceiling — useful, and not a security programme.

# Part 4 — Reading a package before you add it

```
⭐⭐ THE 60-SECOND CHECK, before `npm i anything`

⭐   ① ⭐ WEEKLY DOWNLOADS — 40 is not the same risk as 4,000,000
⭐   ② ⭐⭐ LAST PUBLISH — unmaintained is a vulnerability with a delay
⭐   ③ ⭐ OPEN ISSUES / does the repo link actually resolve?
⭐   ④ ⭐⭐ ITS OWN DEPENDENCY COUNT — a 0-dep package is a different
⭐      proposition from one that drags in 40
⭐   ⑤ ⭐ BUNDLE SIZE (bundlephobia) — 300 KB for a date helper is
⭐      a user-visible cost you are choosing (Day 241)
⭐   ⑥ ⭐⭐ LICENCE — AGPL in a commercial product is a real problem
```

| ⭐ Package | Ask first |
|---|---|
| `moment` (300 KB) | ⭐ `Intl.DateTimeFormat` is built in and free |
| `lodash` (whole) | ⭐ Import the one function, or write it |
| `axios` | ⭐⭐ `fetch` + your Day 217 wrapper is ~40 lines and you already wrote it |
| `left-pad`-shaped | ⭐⭐ `String.prototype.padStart` exists |

> ⭐⭐ **`npm ls <pkg>` tells you *why* something is installed** — the chain that pulled it in. When an
> advisory names a package you have never heard of, that is the command that answers "is this even
> reachable from my code?"

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "how do you manage frontend dependency risk?"**

Establish the scale, because most people underestimate it. **A normal React app is around nine hundred
packages from hundreds of maintainers. All of them run install scripts on my machine, and the
production ones ship to users. It's worse than PyPI for two structural reasons: a culture of tiny
packages, and nested resolution — npm will happily install five versions of the same thing, where
Python has one site-packages and a conflict is an error you have to resolve.**

Then the control that actually matters. **The highest-value control is adding fewer packages, because
it's the only one with no ongoing cost. Before adding anything I ask whether it's twenty lines I could
own — a debounce, a class-name joiner, a date format. I dropped axios because fetch plus my own wrapper
was forty lines I'd already written.**

Then the boring machinery. **Lockfile committed, `npm ci` in CI so the build is reproducible, audit
failing the build on high, and updates arriving as reviewable PRs instead of silent drift. And
deliberately not auto-updating to brand-new versions — a compromised release is usually pulled within
hours, so a short delay is free protection.**

Close on the AI angle, which is current and specific. **Every package an agent suggests gets checked
that it exists and is the right one. Models invent plausible package names, and attackers register
them — that's a supply-chain attack that works because the suggestion looks reasonable.**
