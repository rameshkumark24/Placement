# Part 1 — The three image mistakes

```
⭐⭐ ① SERVING A 4000px PHOTO INTO A 400px BOX
⭐   ⭐ 3.2 MB downloaded, decoded, and thrown away by the browser.
⭐   ⭐⭐ IT IS THE SINGLE MOST COMMON PERFORMANCE BUG ON THE WEB,
⭐     and it is invisible on a desktop with fast wifi.

⭐⭐ ② WRONG FORMAT
⭐   PNG photo ⇒ 2.1 MB  ·  JPEG ⇒ 340 KB  ·  ⭐ WebP ⇒ 180 KB
⭐   ⭐⭐ AVIF ⇒ 120 KB. Same picture. ⭐ 17× FOR ONE ENCODER CHOICE.
⭐   ⇒ ⭐ PNG only for transparency or sharp-edged graphics.
⭐     ⭐⭐ SVG for icons and logos — it is text, it gzips, it scales.

⭐⭐ ③ NO width/height ⇒ ⭐ LAYOUT SHIFT (CLS, Day 241).
⭐   ⭐⭐ ALWAYS SET THEM, EVEN WITH CSS SIZING — they give the
⭐     browser the ASPECT RATIO so it can reserve the space.
```

```html
<!-- ⭐⭐ the correct shape: right format, right size, no shift -->
<picture>
  <source srcset="/hero.avif" type="image/avif">
  <source srcset="/hero.webp" type="image/webp">
  <img src="/hero.jpg" width="1200" height="600" alt="..."
       fetchpriority="high">     <!-- ⭐ it is the LCP element -->
</picture>

<!-- ⭐ responsive: let the browser pick -->
<img srcset="/p-400.webp 400w, /p-800.webp 800w, /p-1600.webp 1600w"
     sizes="(max-width: 600px) 100vw, 50vw"
     src="/p-800.webp" width="800" height="600" alt="">
```

| ⭐ Attribute | Does |
|---|---|
| `srcset` + `sizes` | ⭐⭐ The browser downloads **one** file, chosen for the device and layout |
| `loading="lazy"` | ⭐ Below-the-fold images do not load until near the viewport |
| ⭐⭐ `fetchpriority="high"` | On the LCP image — **jumps the queue.** Often the single biggest LCP win |
| `decoding="async"` | ⭐ Decode off the main thread |

```
⭐⭐ THE EXCEPTION THAT COSTS PEOPLE THEIR LCP:
⭐   ❌ loading="lazy" ON THE HERO IMAGE.
⭐   ⇒ ⭐ THE BROWSER DELAYS THE ONE IMAGE THAT DEFINES YOUR LCP,
⭐     ⭐⭐ MAKING THE METRIC WORSE WHILE YOU BELIEVE YOU OPTIMISED IT.
⭐   ⇒ ⭐ LAZY-LOAD BELOW THE FOLD. EAGER + fetchpriority ABOVE IT.
```

# Part 2 — ⭐⭐ Fonts, and the flash

```
⭐⭐ THE PROBLEM: A CUSTOM FONT IS A RENDER-BLOCKING DEPENDENCY
⭐   DISCOVERED **LATE** — the browser must parse CSS, find the
⭐   @font-face, then fetch the file. ⭐ Meanwhile:

⭐   FOIT (Flash of Invisible Text) ⇒ ⭐⭐ TEXT IS **INVISIBLE** FOR
⭐     UP TO 3 SECONDS. The content arrived and the user cannot read
⭐     it. ⭐ THIS IS THE DEFAULT BEHAVIOUR.
⭐   FOUT (Flash of Unstyled Text) ⇒ ⭐ fallback shows, then swaps.
⭐     A visible reflow, but ⭐⭐ THE USER CAN READ THE WHOLE TIME.

⭐   ⇒ ⭐⭐ font-display: swap  ⇒ CHOOSE FOUT. ⭐ ONE LINE.
⭐     Readable text beats perfect text, every time.
```

```css
@font-face {
  font-family: "Inter";
  src: url("/inter.woff2") format("woff2");   /* ⭐ woff2 ONLY — it is
                                                 universally supported */
  font-display: swap;                          /* ⭐⭐ THE LINE */
  unicode-range: U+0000-00FF;                  /* ⭐ subset: latin only */
  size-adjust: 107%;                           /* ⭐⭐ match the fallback's
                                                 metrics ⇒ NO layout shift
                                                 when it swaps */
}
```

| ⭐ Rule | Why |
|---|---|
| **`woff2` only** | ⭐ ~30% smaller than woff, supported everywhere. Shipping ttf/eot is pure waste. |
| **⭐⭐ Self-host** | Google Fonts costs a **separate DNS + TLS + fetch** to another origin. Self-hosted is one fewer connection — and it is a third party in your critical path and your privacy story. |
| **Preload the one you need** | ⭐ `<link rel="preload" as="font" type="font/woff2" crossorigin>` — moves discovery to the start |
| **Two weights, not seven** | ⭐⭐ 400 + 600 covers almost everything. Each weight is a separate file. |
| **⭐ Subset** | Latin-only can be a third of the size |
| **`size-adjust`** | ⭐⭐ Removes the layout shift the swap would otherwise cause — **this is how you get FOUT without CLS** |

> ⭐ **The strongest option remains a system font stack** — zero bytes, zero requests, instant text.
> `font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. **If you cannot articulate
> what your custom font buys, this is the better engineering decision.**

# Part 3 — Serving them

| ⭐ Control | Value |
|---|---|
| **Hashed filename + `immutable`** | ⭐⭐ `Cache-Control: public, max-age=31536000, immutable` — a year, safely, because the name changes on change (Day 222) |
| **CDN** | ⭐ Serve from an edge near the user; the origin round trip is pure latency |
| **`Accept` negotiation** | ⭐ Serve AVIF to browsers that advertise it, JPEG otherwise |
| **⭐⭐ Never resize in the browser** | Resizing a 4000px image with CSS still downloads and decodes 4000px |
| **An image CDN** | ⭐ `?w=400&fm=webp` — one URL, every variant, no build step |

```
⭐⭐ USER-UPLOADED IMAGES ARE A SEPARATE PROBLEM — and a security one
⭐   · ⭐ RESIZE ON UPLOAD. Never serve the original.
⭐   · ⭐⭐ VALIDATE THE **CONTENT**, NOT THE EXTENSION. A file named
⭐     .jpg can be anything; check the magic bytes.
⭐   · ⭐⭐ STRIP EXIF — PHOTOS CARRY GPS COORDINATES. Serving an
⭐     uploaded photo unmodified can publish a user's home address.
⭐   · ⭐ SERVE FROM A SEPARATE ORIGIN so an uploaded SVG containing
⭐     script cannot run as your origin (Day 243).
```

## Today's build

1. ⭐⭐ **Audit your bytes.** Sort the Network tab by size. **What fraction is images and fonts?** Usually the answer is uncomfortable.
2. Convert your largest image to WebP and AVIF. ⭐ Record all three sizes.
3. ⭐ Add `srcset`/`sizes`. Resize the window and watch the browser choose a different file.
4. ⭐⭐ **Remove `font-display: swap` and throttle to slow 3G.** Watch your text be invisible. Put it back.
5. ⭐ Add `size-adjust` and confirm the swap no longer shifts layout.
6. ⭐⭐ Lazy-load your hero image and watch LCP get **worse.** Undo it.
7. ⭐ Upload a photo from a phone to your own app and read its EXIF. Strip it.

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "how do you optimise images and fonts?"**

Establish why it is worth the time. **They're usually the majority of what I ship and almost none of
what anyone optimises — and unlike JavaScript, they can be fixed without touching application code. It's
the best ratio of improvement to risk available.**

Then the image answer, concretely. **The most common bug on the web is serving a four-thousand-pixel
photo into a four-hundred-pixel box — megabytes downloaded and thrown away, and completely invisible on
a developer's machine with fast wifi. So: `srcset` and `sizes` so the browser picks one file for the
device, AVIF or WebP instead of PNG for photos, and always explicit width and height so the space is
reserved and there's no layout shift. And `fetchpriority="high"` on the LCP image, which is often the
single biggest win.**

Add the trap, because it shows you measured. **Lazy loading the hero image makes LCP worse while you
believe you optimised it. Lazy below the fold, eager and prioritised above it.**

Then fonts. **The default is a flash of invisible text — the content has arrived and the user can't read
it for up to three seconds. `font-display: swap` chooses a flash of unstyled text instead, so it's
readable the whole time, and `size-adjust` matches the fallback's metrics so the swap doesn't shift
anything. That's one line each. I self-host in woff2, subset to the characters I need, and ship two
weights rather than seven.**

Close with the honest option. **If I can't say what a custom font buys, a system font stack is the
better engineering decision — zero bytes, zero requests, instant text.**
