# Day 383 🕸️

**P-383** · 🕸️ **VPC I** — CIDR, subnets, route tables, ⭐⭐ and what actually makes a subnet public

**Time:** 3 hrs · **Mode:** NEW

> ⭐⭐ **The sentence to own: a subnet is public if and only if its route table sends `0.0.0.0/0` to an
> internet gateway — nothing else about it differs — and almost every "why can't this reach the
> internet" question is answered by reading one route table and one route.**

---

# Part 1 — CIDR arithmetic you must do without a calculator

```
⭐⭐ THE FOUR NUMBERS TO KNOW COLD:
⭐   /16 → 65,536   ⭐ (a whole VPC)
⭐   /20 →  4,096   ⭐ (a comfortable subnet)
⭐   /24 →    256   ⭐ (the one everyone reaches for)
⭐   /28 →     16   ⭐ (the smallest AWS allows)
⭐ ⭐ Each step of 1 in the prefix ***halves*** the space.
⭐   ⭐ /17 = 32,768, /18 = 16,384, /19 = 8,192, /21 = 2,048.
⭐ ⭐ The mask is "how many bits are fixed", ⭐ so a ***bigger***
⭐   number is a ***smaller*** network. ⭐⭐ SAY THAT OUT LOUD
⭐   UNTIL IT STOPS FEELING BACKWARDS.

⭐⭐ AND THE AWS-SPECIFIC DETAIL: ***FIVE ADDRESSES PER SUBNET
⭐   ARE RESERVED.***
⭐   ⭐ .0 network · ⭐ .1 VPC router · ⭐⭐ .2 DNS RESOLVER
⭐   ⭐ .3 reserved · ⭐ .255 broadcast
⭐   ⭐⭐ ⇒ A /28 GIVES YOU ***11*** USABLE, NOT 16 — ⭐ and a /28
⭐   subnet for a Fargate service is how you discover this,
⭐   ⭐⭐ BECAUSE EACH TASK TAKES AN ENI AND THEREFORE AN IP.

⭐⭐ THE SIZING RULE, AND THE REASON FOR IT:
⭐   ⭐ VPC: a /16. ⭐ Subnets: /20 each (4,091 usable).
⭐   ⭐ That is 16 subnets per VPC, ⭐ which is 5 AZs × 3 tiers
⭐     with room left.
⭐   ⭐⭐ AND THE REASON TO BE GENEROUS IS NOT COST — ***IP SPACE
⭐   INSIDE A VPC IS FREE.*** ⭐ It is that ⭐⭐ ***YOU CANNOT
⭐   RESIZE A SUBNET. EVER.*** ⭐ You can add a secondary CIDR to
⭐   the VPC and create new subnets, ⭐ then migrate everything
⭐   into them — ⭐⭐ WHICH IS A PROJECT, NOT A CHANGE.

⭐⭐ AND THE OTHER RULE THAT ONLY HURTS LATER: ***DO NOT USE
⭐   10.0.0.0/16 FOR EVERYTHING.*** ⭐ Every default tutorial
⭐   does. ⭐⭐ THEN YOU PEER TWO VPCs, OR CONNECT TO A CORPORATE
⭐   NETWORK, AND OVERLAPPING CIDRs MAKE PEERING FLATLY
⭐   IMPOSSIBLE — ⭐ routing cannot disambiguate identical
⭐   ranges. ⭐ Allocate from a plan: 10.10/16 dev, 10.20/16
⭐   staging, 10.30/16 prod. ⭐⭐ FIVE MINUTES NOW, A MIGRATION
⭐   AVOIDED LATER.
```

# Part 2 — The objects, and how they nest

```
⭐ VPC ....... ⭐ a region-scoped private network. ⭐ Its CIDR is
⭐             fixed at creation (secondaries can be added).
⭐ SUBNET .... ⭐⭐ LIVES IN ***EXACTLY ONE AZ.*** ⭐ This single
⭐             fact is why "multi-AZ" always means "one subnet
⭐             per AZ per tier" in every diagram you will draw.
⭐ ROUTE TABLE ⭐⭐ ***THE THING THAT DECIDES EVERYTHING.***
⭐             ⭐ Associated with subnets; one main table is the
⭐             default for any subnet you forget to associate —
⭐             ⭐⭐ AND THAT DEFAULT IS A CLASSIC SURPRISE.
⭐ IGW ....... ⭐ internet gateway: one per VPC, horizontally
⭐             scaled, ⭐⭐ FREE, AND IT DOES NOTHING UNTIL A ROUTE
⭐             POINTS AT IT.
⭐ NAT GW .... ⭐ outbound-only translation for private subnets.
⭐             ⭐⭐ LIVES IN A ***PUBLIC*** SUBNET. ⭐ Not free.
⭐ ENI ....... ⭐ the actual network interface. ⭐⭐ SECURITY GROUPS
⭐             ATTACH HERE, NOT TO INSTANCES (DAY 384).

⭐⭐ ROUTE MATCHING IS ***LONGEST PREFIX WINS***, ⭐ which is why
⭐   a `0.0.0.0/0` route never shadows the VPC-local route: ⭐ the
⭐   implicit `10.0.0.0/16 → local` entry is more specific,
⭐   ⭐⭐ CANNOT BE DELETED, AND IS WHY EVERYTHING INSIDE A VPC CAN
⭐   ALREADY TALK TO EVERYTHING ELSE AT THE ROUTING LAYER.
⭐   ⭐⭐ ⇒ SO ISOLATION ***INSIDE*** A VPC IS A SECURITY-GROUP
⭐   JOB, NOT A ROUTING JOB. ⭐ Tomorrow.
```

# Part 3 — ⭐⭐ Public vs private, derived from first principles

```
⭐⭐ THERE IS NO "PUBLIC" CHECKBOX ON A SUBNET. ⭐ The word is
⭐   shorthand for exactly one property:

⭐   ⭐⭐ ***THE SUBNET'S ROUTE TABLE HAS `0.0.0.0/0 → igw-xxx`.***

⭐ FOR AN INSTANCE TO BE REACHABLE ***FROM*** THE INTERNET, ALL
⭐ FOUR MUST HOLD — ⭐ and they are checked in this order by the
⭐ packet, so debug in this order too:
⭐   ① ⭐ the subnet routes 0.0.0.0/0 to an IGW
⭐   ② ⭐⭐ THE INSTANCE HAS A ***PUBLIC OR ELASTIC IP***
⭐   ③ ⭐ the security group allows the inbound port
⭐   ④ ⭐ the NACL allows in ***and*** out (Day 384)

⭐⭐ ⇒ AND THE SINGLE MOST COMMON CONFUSION IN ALL OF VPC:
⭐   ⭐⭐ ***A PUBLIC IP WITHOUT AN IGW ROUTE DOES NOTHING.***
⭐   ⭐ The address is assigned, the console shows it, ⭐ `curl`
⭐   times out, ⭐⭐ AND PEOPLE SPEND AN HOUR ON SECURITY GROUPS.
⭐   ⭐ Equally: ⭐⭐ AN IGW ROUTE WITHOUT A PUBLIC IP DOES
⭐   NOTHING EITHER — ⭐ the IGW performs 1:1 NAT between the
⭐   public IP and the private one, ⭐⭐ SO WITH NO PUBLIC IP THERE
⭐   IS NOTHING FOR IT TO TRANSLATE.

⭐ FOR ***OUTBOUND ONLY*** (the normal case for an app server):
⭐   ⭐ private subnet + `0.0.0.0/0 → nat-xxx`
⭐   ⭐⭐ AND NO PUBLIC IP, WHICH IS THE POINT: NOTHING ON THE
⭐   INTERNET CAN INITIATE A CONNECTION TO IT AT ALL, ⭐ which is
⭐   a stronger guarantee than any firewall rule, ⭐⭐ BECAUSE IT
⭐   DOES NOT DEPEND ON A RULE BEING CORRECT.
```

# Part 4 — ⭐⭐ NAT gateways, and why they appear on the bill

```
⭐⭐ THE ARITHMETIC, DONE ONCE, REMEMBERED FOREVER:
⭐   ⭐ $0.045 / hour  → ⭐ ~$33 / month, ***per NAT gateway***
⭐   ⭐ $0.045 / GB processed
⭐   ⭐⭐ ONE PER AZ × 3 AZs = ~$100/MONTH ***BEFORE A SINGLE BYTE
⭐     MOVES***, ⭐ and this is routinely the third-largest line
⭐     on a small AWS bill — ⭐⭐ BIGGER THAN THE COMPUTE IT
⭐     SERVES.

⭐⭐ AND THE PYTHON-SHAPED SURPRISE INSIDE IT: ⭐ every byte of
⭐   the following crosses NAT and is charged at $0.045/GB —
⭐   ⭐ `pip install` in a container build or at boot
⭐   ⭐ `docker pull` of your own image ⭐⭐ FROM ECR
⭐   ⭐⭐ ***EVERY S3 GET AND PUT YOUR APP MAKES***
⭐   ⭐ every CloudWatch metric and log line
⭐   ⭐⭐ ⇒ A DATA JOB READING 2 TB FROM S3 THROUGH NAT PAYS $90
⭐     FOR TRAFFIC THAT NEVER LEFT AWS. ⭐ Tomorrow's gateway
⭐     endpoint makes that ***zero***, ⭐⭐ AND IS THE SINGLE
⭐     HIGHEST-RETURN TEN MINUTES IN THIS WHOLE STAGE.

⭐ ONE NAT OR THREE?
⭐   ⭐ ONE: ~$33/mo, ⭐⭐ BUT CROSS-AZ DATA CHARGES ON TOP AND —
⭐     THE REAL ISSUE — ⭐⭐ LOSING THAT AZ TAKES OUTBOUND AWAY
⭐     FROM ***EVERY*** AZ. ⭐ A single-AZ dependency hiding
⭐     inside a multi-AZ design (Day 380).
⭐   ⭐ THREE: ~$100/mo, no cross-AZ charge, ⭐⭐ AND AZ FAILURE
⭐     STAYS INSIDE THAT AZ.
⭐   ⭐⭐ ⇒ HONEST ANSWER: ***ONE IN DEV, THREE IN PROD*** — ⭐ and
⭐     be able to say why, because "we used one to save $66 and
⭐     accepted a single-AZ outbound dependency" is a fine
⭐     answer ⭐⭐ AND NOT KNOWING IS NOT.

⭐ ⭐ NAT instance (a Linux box doing it) is cheaper and is a
⭐   ***you-maintain-it*** decision. ⭐⭐ IT IS ALSO A SINGLE
⭐   INSTANCE WITH A BANDWIDTH CEILING AND NO HA. ⭐ Fine for a
⭐   sandbox; ⭐ do not put it under production.
```

# Part 5 — The layout that is simply the default answer

```
⭐ PER AZ (×2 minimum, ×3 preferred):

⭐ ┌─ PUBLIC /24 ───────────────────────────────────────┐
⭐ │ ⭐⭐ ONLY THE LOAD BALANCER AND THE NAT GATEWAY.     │
⭐ │ route: 0.0.0.0/0 → igw                             │
⭐ └────────────────────────────────────────────────────┘
⭐ ┌─ PRIVATE /20 ──────────────────────────────────────┐
⭐ │ ⭐ App containers / instances. ⭐⭐ NO PUBLIC IP.     │
⭐ │ route: 0.0.0.0/0 → nat  ·  s3 → gateway endpoint   │
⭐ └────────────────────────────────────────────────────┘
⭐ ┌─ ISOLATED /24 ─────────────────────────────────────┐
⭐ │ ⭐⭐ RDS AND ELASTICACHE. ***NO 0.0.0.0/0 ROUTE AT
⭐ │ ALL*** — ⭐ local routes only.                       │
⭐ └────────────────────────────────────────────────────┘

⭐⭐ WHY THE THIRD TIER EARNS ITS EXISTENCE: ⭐ the app tier can
⭐   reach the internet, so a compromised app can exfiltrate.
⭐   ⭐⭐ THE DATABASE TIER HAS NO ROUTE OFF THE NETWORK, SO EVEN
⭐   FULL CONTROL OF THE DATABASE HOST CANNOT SEND YOUR DATA
⭐   ANYWHERE. ⭐ That is a routing guarantee, ⭐⭐ NOT A RULE THAT
⭐   SOMEONE MIGHT MISCONFIGURE.

⭐⭐ AND THE HONEST CAVEAT, BECAUSE THIS COURSE DOES NOT SELL
⭐   CEREMONY: ⭐ for one small service with no sensitive data, a
⭐   public subnet plus a tight security group is ***not a sin***
⭐   — ⭐ it is $33/month cheaper and one fewer thing to debug.
⭐   ⭐⭐ THE THREE-TIER LAYOUT EARNS ITS COST THE MOMENT YOU HAVE
⭐   A DATABASE WORTH ISOLATING OR AN AUDITOR WORTH ANSWERING.
⭐   ⭐ Know which situation you are in, ⭐⭐ AND SAY SO.
```

# Part 6 — DNS inside a VPC

```
⭐ TWO VPC ATTRIBUTES, BOTH EASY TO GET WRONG ONCE:
⭐   ⭐ `enableDnsSupport` — ⭐⭐ THE RESOLVER AT ***base+2***
⭐     EXISTS. ⭐ Off ⇒ nothing resolves at all, including
⭐     `s3.amazonaws.com`.
⭐   ⭐ `enableDnsHostnames` — instances get DNS names.
⭐   ⭐⭐ AND THE COMBINATION THAT MATTERS: ***PRIVATELINK PRIVATE
⭐     DNS AND RDS ENDPOINTS NEED BOTH ON*** (DAY 384, 387).

⭐ ROUTE 53 PRIVATE HOSTED ZONES: ⭐ internal names resolvable
⭐   only inside associated VPCs. ⭐⭐ USE THEM SO YOUR CONFIG
⭐   SAYS `db.internal` RATHER THAN AN RDS ENDPOINT STRING —
⭐   ⭐ then a failover or a migration is a DNS change, ⭐⭐ NOT A
⭐   CONFIG DEPLOY ACROSS SIX SERVICES.

⭐ ⭐⭐ AND THE PYTHON FOOTNOTE THAT BECOMES DAY 387's WHOLE
⭐   PROBLEM: ⭐ CPython does ***not*** cache DNS itself — ⭐ but
⭐   your connection ***pool*** does something worse: ⭐⭐ IT HOLDS
⭐   AN ALREADY-OPEN SOCKET TO THE OLD IP, SO RE-RESOLVING
⭐   CHANGES NOTHING UNTIL THE CONNECTION IS RECYCLED. ⭐ Park
⭐   that; it is the failover trap in four days' time.
```

# 💬 Interview

**1. ⭐⭐ "What makes a subnet public?"**
> ⭐ Exactly one thing: ⭐⭐ **its route table has a route for `0.0.0.0/0` pointing at an internet
> gateway.** ⭐ There's no flag; "public subnet" is shorthand for that route. ⭐ And two corollaries
> that account for most confusion: ⭐⭐ **a public IP with no IGW route does nothing, and an IGW route
> with no public IP does nothing either** — the gateway does 1:1 NAT between the public and private
> address, so with no public IP there's nothing to translate. ⭐ For inbound reachability you need all
> four: the route, the public IP, the security group, and the NACL both ways.

**2. "How would you size a VPC?"**
> ⭐ A /16 for the VPC, /20 subnets, three AZs, three tiers. ⭐⭐ **And I'd be generous, not because IP
> space costs anything — it's free inside a VPC — but because you cannot resize a subnet, ever.**
> ⭐ Growing means adding a secondary CIDR, creating new subnets and migrating everything, which is a
> project rather than a change. ⭐⭐ **The other thing I'd do up front is allocate non-overlapping
> ranges per environment** — 10.10, 10.20, 10.30 — ⭐ because the day you peer two VPCs or connect a
> corporate network, identical CIDRs make peering flatly impossible.

**3. ⭐⭐ "Why is the NAT gateway on my bill?"**
> ⭐ Because it's $0.045 an hour each plus $0.045 per gigabyte processed, ⭐⭐ **so three of them for
> multi-AZ is about $100 a month before a byte moves** — often larger than the compute it serves.
> ⭐ And the traffic is more than people think: pip installs, ECR image pulls, CloudWatch, ⭐⭐ **and
> every S3 request the app makes, which is data that never leaves AWS and is still charged at
> $0.045/GB.** ⭐ An S3 gateway endpoint is free and makes that portion zero — it's the highest-return
> ten minutes on the bill. ⭐ On count: one NAT in dev, three in prod, ⭐⭐ **and the reason for three
> isn't the cross-AZ charge, it's that a single NAT means losing one AZ removes outbound for every
> AZ — a single-AZ dependency hidden inside a multi-AZ design.**

**4. "Walk me through your standard VPC layout and justify the third tier."**
> ⭐ Public subnets holding only the load balancer and NAT; private subnets for the app with no public
> IP; isolated subnets for RDS and ElastiCache with no `0.0.0.0/0` route at all. ⭐ Per AZ.
> ⭐⭐ **The third tier earns its place because the app tier can reach the internet, so a compromised
> app can exfiltrate — while the database tier has no route off the network, so even total control of
> that host can't send data anywhere.** ⭐ That's a routing guarantee rather than a rule someone might
> misconfigure. ⭐ For one small service with nothing sensitive, ⭐⭐ **a public subnet with a tight
> security group is a defensible choice and $33 cheaper** — I'd just want to know which situation
> we're in.

**5. "Why can everything in a VPC already talk to everything else?"**
> ⭐ Because every route table has an undeletable local route for the VPC CIDR, and routing is
> longest-prefix-wins, so it always beats `0.0.0.0/0`. ⭐⭐ **Which means isolation inside a VPC is a
> security-group problem, not a routing problem** — you cannot express "these two subnets can't talk"
> with route tables.

**6. "What are the two VPC DNS attributes and when do they bite?"**
> ⭐ `enableDnsSupport` turns on the resolver at the VPC base address plus two — with it off, nothing
> resolves at all, including AWS endpoints. ⭐ `enableDnsHostnames` gives instances DNS names.
> ⭐⭐ **Both must be on for PrivateLink private DNS and for RDS endpoints to resolve the way you
> expect**, and that combination is a common half-hour of confusion when someone copies a minimal
> VPC module.
