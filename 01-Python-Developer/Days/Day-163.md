# Day 163

**L-163** · 🏗 **Capstone II — the walking skeleton** — ⭐⭐ deployed on day one, with one endpoint that does nothing

**Time:** 3 hrs · **Mode:** BUILD

> ⭐⭐ **The sentence to own: build the thinnest possible slice that goes all the way through — commit,
> CI, image, deploy, request, response, log, metric — before building any feature, because every
> problem you will hit in deployment is cheaper to solve when the application is empty.**
>
> ⭐ The alternative is three weeks of features followed by a week of discovering that your image
> won't build, your migrations race, your logs are empty and nothing has a health check. ⭐⭐ **Ship
> nothing, but ship it properly.**

```

⭐   DEPENDENCY DIRECTION:

⭐   src/ticketed/

⭐   ⇒ ⭐⭐ WHY IT MATTERS HERE SPECIFICALLY: on Day 166 the SAME service
⭐        functions will be called from a Celery worker where there is no

⭐        ⭐ If the rule held, that is free. If it did not, it is a refactor.
```

```python
# ⭐ src/ticketed/core/config.py — Day 150, all of it
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="TICKETED_", extra="forbid", frozen=True)
    environment: Literal["local", "ci", "staging", "production"]      # ⭐ required
    database_url: PostgresDsn
    redis_url: RedisDsn
    jwt_secret: SecretStr
    version: str = "dev"                                              # ⭐⭐ from CI
    log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR"] = "INFO"

    @model_validator(mode="after")
    def _prod_is_strict(self) -> "Settings":
        if self.environment == "production" and self.log_level == "DEBUG":
            raise ValueError("DEBUG logging leaks data in production")
        return self
```

```python
# ⭐ src/ticketed/main.py — the factory + lifespan (Day 133)
@asynccontextmanager
async def lifespan(app: FastAPI):
    s = get_settings()
    app.state.engine = create_engine(str(s.database_url), pool_pre_ping=True)  # ⭐ after fork
    app.state.redis = redis.from_url(str(s.redis_url), socket_timeout=1)      # ⭐⭐ Day 152
    app.state.ready = True
    yield
    app.state.ready = False                    # ⭐⭐ Day 149 — drain flag first
    app.state.engine.dispose()

def create_app() -> FastAPI:
    configure_logging()                        # ⭐ Day 146, before anything logs
    app = FastAPI(lifespan=lifespan, title="ticketed", version=get_settings().version)
    app.add_middleware(RequestContextMiddleware)   # ⭐ request id — outermost but one
    app.add_middleware(MetricsMiddleware)
    register_error_handlers(app)               # ⭐⭐ Day 120 — one error shape
    app.include_router(health.router)
    app.include_router(events.router, prefix="/v1")
    return app
```

> ⭐⭐ **Middleware order is a correctness property (Day 110).** Error handling outermost so *every*
> failure gets your shape; then the request id, so every log line inside is tagged — ⭐ including the
> logs written by the error handler.

# Part 3 — ⭐⭐ CI green before the second commit

```yaml
# ⭐ the pipeline from Day 154, minimally
jobs:
  static:
    steps: [checkout, "uv sync --frozen", "ruff check .", "ruff format --check .", "mypy src"]
  test:
    services: {postgres: {image: postgres:16}, redis: {image: redis:7}}
    steps: [checkout, "uv sync --frozen", "pytest -q --cov --cov-fail-under=70"]
  migrations:                                   # ⭐⭐ the job people add too late
    steps:
      - "alembic upgrade head"                  # ⭐ on an EMPTY database
      - "alembic check"                         # ⭐⭐ autogenerate diff MUST be empty
  build:
    needs: [static, test, migrations]
    steps:
      - "docker build -t $REG/ticketed:$SHA ."  # ⭐⭐ tagged by sha, never :latest
      - "docker push $REG/ticketed:$SHA"
```

```
⭐⭐ THREE THINGS TO GET RIGHT NOW BECAUSE THEY ARE PAINFUL LATER:
⭐  1. ⭐⭐ THE `alembic check` JOB. ⭐ Today it passes trivially. ⭐⭐ On Day 164
⭐       it will catch the first "changed a model, forgot the migration",
⭐       which is the most common team failure with Alembic (Day 141).
⭐  2. ⭐ `--cov-fail-under` SET LOW (70) AND RATCHETED UP. ⭐⭐ A high
⭐       threshold on an empty project gets lowered the first time it is
⭐       inconvenient, and a threshold that gets lowered is not a threshold.
⭐  3. ⭐⭐ THE VERSION LABEL. Pass the git sha into the image and into
⭐       `Settings.version`, and put it on every log line and every metric
⭐       (Days 146, 147). ⭐ Without it, "did the deploy cause this?" has no
⭐       answer — ⭐⭐ and you will want that answer on Day 168.
```

# Part 4 — ⭐⭐ Observability wired before features

```python
# ⭐ core/logging.py — Day 146
def configure_logging() -> None:
    structlog.configure(processors=[
        structlog.contextvars.merge_contextvars,
        redact_sensitive,                        # ⭐⭐ a control, not a convention
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso", utc=True),
        structlog.processors.format_exc_info,
        structlog.processors.JSONRenderer(),
    ])

class RequestContextMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        rid = safe_request_id(request.headers.get("x-request-id"))   # ⭐ validated
        structlog.contextvars.clear_contextvars()                    # ⭐⭐ or it leaks
        span = trace.get_current_span().get_span_context()
        structlog.contextvars.bind_contextvars(
            request_id=rid,
            trace_id=format(span.trace_id, "032x"),                  # ⭐⭐ THE JOIN KEY
            version=get_settings().version,
            path=request.url.path, method=request.method,
        )
        start = time.perf_counter()
        try:
            response = await call_next(request)
        except Exception:
            log.exception("request.failed",
                          duration_ms=round((time.perf_counter()-start)*1000, 2))
            raise
        log.info("request.completed", status=response.status_code,
                 duration_ms=round((time.perf_counter()-start)*1000, 2))
        response.headers["x-request-id"] = rid                        # ⭐ give it back
        return response
```

```
⭐⭐ THE THREE PROBES, WITH THE Day 149 RULES BAKED IN:
⭐   ⭐ `/healthz`  → `{"status":"ok"}`. ⭐⭐ CHECKS NOTHING. If it ever grows a
⭐        database call, you have built the fleet-wide restart loop.
⭐   ⭐ `/readyz`   → 503 if `app.state.ready` is False; else `SELECT 1` with
⭐        a 1-second timeout and a 3-second cached result.
⭐   ⭐ `/metrics`  → ⭐⭐ bound to an internal port or behind auth (Day 147).
⭐
⭐ ⭐⭐ AND ONE ASSERTION TO WRITE TODAY: A TEST THAT WALKS `app.routes` AND
⭐   FAILS IF A ROUTE IS NEITHER PROTECTED NOR ON AN EXPLICIT PUBLIC LIST
⭐   (Day 140). ⭐ Today the list is `/healthz`, `/readyz`, `/v1/events`.
⭐   ⭐⭐ Writing it now means every endpoint you add for the rest of the
⭐   capstone is protected by default, by CI. ⭐ Writing it later means
⭐   auditing forty endpoints by hand.
```

# Part 5 — ⭐ The first endpoint, and the first test

```python
# ⭐ api/events.py — deliberately trivial, but the SHAPE is final
@router.get("/events", response_model=Page[EventOut])       # ⭐ Day 121 keyset
def list_events(
    after: int | None = None,
    limit: int = Query(default=20, le=100),                 # ⭐⭐ bounded, always
    db: Session = Depends(get_db),
) -> Page[EventOut]:
    rows = EventRepository(db).list_public(after_id=after, limit=limit)
    return Page(items=[EventOut.model_validate(r) for r in rows],
                next=rows[-1].id if len(rows) == limit else None)
```

## Common mistakes

| Mistake | Correction |
|---|---|
| Building features before deploying anything | Every deployment problem is cheapest to solve on an empty app. |
| The layered folders without an enforced rule | Put `grep -r fastapi services/` in CI. Day 166 depends on it. |
| Shell-form `CMD` | `/bin/sh` becomes PID 1 and swallows SIGTERM. |
| `COPY . .` before installing dependencies | Every code change reinstalls everything. |
| No `alembic check` job | The first forgotten migration ships. |
| A high coverage threshold on an empty project | It gets lowered the first time it's inconvenient, and then it isn't a threshold. |
| No version label from the git sha | "Did the deploy cause this?" has no answer. |
| A database check in `/healthz` | You've built the fleet-wide restart loop before writing a feature. |
| `/metrics` publicly exposed | Leaks routes, versions and volumes. |
| No `clear_contextvars` | One request's fields appear on the next and look like a data leak. |
| No `trace_id` bound into logs | The three pillars can't join, and you'll want them on Day 168. |
| Adding the route-protection test later | Then you audit forty endpoints by hand instead of one. |
| Unbounded `limit` on a list endpoint | A client asks for a million rows and you comply. |
| Adding query-count ceilings after the N+1 exists | The ceiling gets set to whatever the bug produces. |
| Patching `get_db` instead of overriding | Guessing an import path instead of using the supported seam. |

## Interview questions

**Q: What's a walking skeleton and why start there?**

> The thinnest slice that goes all the way through — commit, CI, image build, deploy, a request that
> returns an empty list, a structured log line, a metric, a trace, and working health probes — with
> no business logic at all. The argument is that every problem in that path is dramatically cheaper
> to solve on an empty application: the image won't build, the migrations race at startup, the logs
> are buffered and empty, the health check restarts the fleet. If you build three weeks of features
> first, you hit all of those at once, under time pressure, with a codebase big enough that you can't
> tell which part is at fault. Once the skeleton works, every later problem is a business-logic
> problem, which is an enormous simplification. It also builds the habit that you never have
> undeployed work.

**Q: What do you enforce mechanically on day one?**

> Four things. That services never import FastAPI, as a grep in CI — because on the day I add a
> Celery worker, the same service functions get called where there's no request, no `Depends` and
> nowhere for an `HTTPException` to go, and if the rule held that's free. A route-table test that
> fails if any endpoint is neither protected nor on an explicit public list, because writing it now
> means everything I add for the rest of the project is protected by default, and writing it later
> means auditing forty endpoints by hand. `alembic check`, so the first forgotten migration fails CI
> rather than shipping. And a query-count fixture, even with nothing to count yet — because a ceiling
> added after an N+1 exists just gets set to whatever the bug produces.

**Q: Why is `/healthz` allowed to check nothing?**

> Because failing liveness means "kill and restart this container", so it must only fail for things a
> restart can fix. If it checks the database, a thirty-second database blip fails every pod
> simultaneously — they share the dependency — so the orchestrator kills the whole fleet, they come
> back cold with empty caches and stampede a database that's already sick, and a thirty-second blip
> becomes a ten-minute outage I caused. Dependency checks go in readiness, which just stops traffic
> and is recoverable, and even there only for what every request needs, shallow, with a short timeout
> and a cached result.

**Q: Why set the coverage threshold low?**

> Because a threshold that gets lowered isn't a threshold. If I set ninety percent on an empty
> project, the first time it's inconvenient — a hard-to-test integration, a deadline — someone lowers
> it, and once it's been lowered once it's negotiable forever. Setting it at seventy and ratcheting
> it up as the project grows means it only ever moves in one direction, which is what makes it a
> constraint rather than a suggestion.

## 🎙️ Articulation drill

**Two minutes: "How do you start a new service?"**

Lead with the walking skeleton and the reason — every problem in the deploy path is cheapest to solve
when the app is empty — then list what the slice includes, all the way from commit to a trace. Then
the four things you enforce mechanically on day one and why each is cheaper now than later, with the
route-protection test as the clearest example: one endpoint to check now versus forty to audit at the
end. Mention `/healthz` checking nothing and give the restart-loop reason, because it shows you've
thought about failure rather than copied a template. Close on the habit rather than the artefact:
**you never have undeployed work, so "it works on my machine" stops being a sentence anyone in the
team can say.**
