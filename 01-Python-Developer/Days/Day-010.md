# Part 1 — ⭐ The message, byte for byte

```http
POST /api/v1/users?verbose=true HTTP/1.1        ⭐ request line: METHOD SP TARGET SP VERSION
Host: api.example.com                           ⭐⭐ MANDATORY in 1.1 — one IP, many sites
Content-Type: application/json                  ⭐ what the body IS
Content-Length: 27                              ⭐⭐ how the receiver knows where the body ENDS
Authorization: Bearer eyJhbGciOi...             ⭐ who you are
Accept: application/json                        ⭐ what you want back
                                                ⭐⭐ ← ONE BLANK LINE. Headers end here.
{"name":"Ada","age":36}
```

```http
HTTP/1.1 201 Created                            ⭐ status line: VERSION SP CODE SP REASON
Content-Type: application/json
Content-Length: 42
Location: /api/v1/users/1138                    ⭐⭐ where the thing you created now lives
Cache-Control: no-store

{"id":1138,"name":"Ada","age":36}
```

⭐⭐ **Three things carry all the weight:** the blank line (structure), `Content-Length` or
`Transfer-Encoding: chunked` (framing — because TCP is a byte stream, Day 005), and `Host` (routing
— it is why one IP serves ten thousand sites).

# Part 2 — ⭐⭐ Methods, and the two properties that matter

| Method | ⭐ Safe? | ⭐⭐ Idempotent? | Body? | Meaning |
|---|---|---|---|---|
| `GET` | ⭐ **yes** | yes | no | retrieve. ⭐⭐ **must not change state** |
| `HEAD` | yes | yes | no | headers only |
| `POST` | no | ⭐⭐ **NO** | yes | create / "do a thing" |
| `PUT` | no | ⭐⭐ **yes** | yes | replace the whole resource at this URL |
| `PATCH` | no | ⭐ not necessarily | yes | partial update |
| `DELETE` | no | ⭐⭐ **yes** | rarely | remove |
| `OPTIONS` | yes | yes | no | ⭐ what may I do here (**CORS preflight**, Day 020) |

```
⭐⭐ SAFE       = does not change server state.  ⇒ ⭐ crawlers, prefetchers and proxies WILL call it.
⭐⭐ IDEMPOTENT = doing it N times == doing it once. ⇒ ⭐⭐ THEREFORE IT CAN BE RETRIED SAFELY.

⭐⭐ THE CONSEQUENCE, and it is a Stage 12 idea arriving on Day 10:
⭐   ⇒ ⭐⭐ IDEMPOTENCE IS WHAT MAKES RETRIES SAFE.
⭐   ⇒ POST is not idempotent ⇒ a retried POST double-charges the customer
⭐   ⇒ ⭐⭐ FIX: an Idempotency-Key header + a table of keys you have already processed.
```

⚠️ ⭐⭐ **`GET /users/5/delete` is one of the most expensive mistakes on this page.** Google's crawler
finds the link, follows it — it is a `GET`, it is supposed to be safe — and deletes your data. This
has really happened, to real companies, more than once.

⭐ `PUT` replaces, `PATCH` modifies. **`PUT` with a partial body means the fields you omitted should
be erased**, and an API that silently keeps them is lying about its own method.

# Part 3 — ⭐⭐ Status codes — the families, then the ones you must get right

```
⭐ 1xx informational   — 101 Switching Protocols ⭐ (WebSockets, Day 017)
⭐ 2xx SUCCESS         — it worked
⭐ 3xx REDIRECTION     — look elsewhere
⭐⭐ 4xx YOUR fault     — the CLIENT sent something wrong. ⭐⭐ Do not retry unchanged.
⭐⭐ 5xx MY fault       — the SERVER failed. ⭐⭐ Retrying may work.
```

⭐⭐ **The 4xx/5xx split is not cosmetic — it is the instruction to every retry policy, alert and
dashboard in the system.** Returning `500` for bad user input creates a pager alert for a typo;
returning `200` with `{"error": ...}` makes every client parse a body to discover failure and blinds
every monitor you own.

| ⭐ Code | ⭐ Use it when |
|---|---|
| `200 OK` | it worked and there is a body |
| ⭐ `201 Created` | you created something — ⭐ **include `Location`** |
| `202 Accepted` | ⭐⭐ accepted, **not yet done** — the async/queue answer (Stage 12) |
| `204 No Content` | worked, nothing to return (a `DELETE`) |
| ⭐ `301` / `308` | moved **permanently** — ⚠️ browsers cache this ~forever |
| ⭐ `302` / `307` | moved **temporarily** |
| `304 Not Modified` | ⭐ your cached copy is still good — ⭐⭐ **no body sent** |
| ⭐⭐ `400 Bad Request` | malformed / failed validation |
| ⭐⭐ `401 Unauthorized` | ⭐⭐ **you are not authenticated** — misnamed; means *unauthenticated* |
| ⭐⭐ `403 Forbidden` | ⭐⭐ **authenticated, but not allowed** |
| `404 Not Found` | ⭐ also the right answer for "exists but you may not know that" |
| `409 Conflict` | ⭐ concurrent modification, duplicate unique key |
| `422` | semantically invalid — ⭐ **FastAPI returns this for validation failures** |
| ⭐ `429 Too Many Requests` | rate limited — ⭐⭐ **send `Retry-After`** |
| ⭐⭐ `500` | ⭐⭐ **an unhandled exception. Your bug.** |
| ⭐ `502 Bad Gateway` | ⭐⭐ the proxy got garbage from upstream — *upstream died* |
| ⭐⭐ `503 Service Unavailable` | overloaded / shedding — ⭐ **the honest answer under load** |
| ⭐ `504 Gateway Timeout` | ⭐⭐ upstream too slow — *upstream is alive but hanging* |

⭐⭐ **502 vs 503 vs 504 is a real diagnostic, not trivia:** 502 = the upstream answered with
nonsense or died mid-response; 503 = nothing was available to send it to; 504 = it was there and
never replied in time. **Day 011 and Stage 11's idle-timeout 502 both build directly on this.**

# Part 4 — ⭐ Headers worth memorising

| Header | ⭐ Why |
|---|---|
| ⭐⭐ `Host` | mandatory; virtual hosting |
| ⭐ `Content-Type` | ⭐⭐ `application/json`, `application/x-www-form-urlencoded`, `multipart/form-data` |
| ⭐⭐ `Content-Length` / `Transfer-Encoding: chunked` | ⭐⭐ **framing** — where the body ends |
| ⭐ `Authorization` | `Bearer <token>` |
| ⭐⭐ `Cache-Control` | `no-store`, `max-age=3600`, `private` — ⭐ Stage 9 leans on this |
| ⭐ `ETag` + `If-None-Match` | conditional GET ⇒ `304` |
| ⭐ `Accept` / `Content-Encoding` | negotiation; `gzip` |
| ⭐⭐ `X-Forwarded-For` / `-Proto` | ⭐⭐ real client IP/scheme behind a proxy (Day 009) |
| ⭐ `Set-Cookie` | Day 019 |
| ⭐ `Connection: keep-alive` | Day 011 |

⚠️ ⭐⭐ **Never trust `X-Forwarded-For` unless a proxy you control set it.** A client can send any
header it likes; rate limiting or IP allow-listing on a forgeable header is not a control.

## ⭐ Two Python-specific notes you will need in Stage 3

```python
# ⭐ Headers are case-insensitive (RFC), so real HTTP libraries use a case-insensitive mapping.
resp.headers["content-type"] == resp.headers["Content-Type"]      # ⭐ True in httpx/requests

# ⭐⭐ A header can legally appear MULTIPLE times. A plain dict LOSES the duplicates.
#     That is why Starlette/FastAPI use a multi-dict for headers and query params.
#     ⚠️ request.query_params["tag"] gives you ONE tag; getlist() gives you all of them.
```

# Part 5 — C-07 · ⭐ UDP: what you gain and what you lose

| | ⭐ TCP | ⭐ UDP |
|---|---|---|
| Connection | handshake first | ⭐ none — just send |
| Reliability | retransmits | ⭐⭐ **none** |
| Ordering | guaranteed | ⭐⭐ **none** |
| Congestion control | yes | ⭐⭐ **none — you must build it** |
| Header | 20 bytes | ⭐ **8 bytes** |
| Head-of-line blocking | ⭐⭐ **yes** | ⭐ no |

```
⭐⭐ UDP IS NOT "UNRELIABLE TCP". It is the raw IP service with ports added.
⭐   Everything TCP gives you, UDP leaves to you — which is exactly the point
⭐   when you want DIFFERENT reliability, not NO reliability.
```

| ⭐ Choose UDP when | Why |
|---|---|
| Late data is **worthless** | ⭐ voice/video — a retransmitted frame is already off-screen |
| ⭐⭐ You will implement your own reliability | ⭐⭐ **QUIC does exactly this** (Day 011) |
| One small request, one small reply | ⭐ DNS — a handshake would double the cost |
| Broadcast / multicast | TCP cannot |
| ⭐ Metrics you can afford to lose | ⭐ StatsD is UDP **on purpose** — never block the app to record a metric |

```python
# ⭐ UDP in Python — note what is missing: no connect, no accept, no streams.
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)      # ⭐ DGRAM, not STREAM
s.sendto(b"metric:1|c", ("127.0.0.1", 8125))              # ⭐⭐ may never arrive. That is fine here.

srv = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
srv.bind(("0.0.0.0", 8125))
data, addr = srv.recvfrom(4096)   # ⭐⭐ ONE datagram, whole. Message boundaries ARE preserved.
```

⭐⭐ **Note the contrast with Day 005:** TCP gave you a byte stream with no message boundaries, so you
wrote a framing loop. UDP preserves boundaries — one `sendto` is one `recvfrom` — but may lose,
duplicate or reorder them. **You always give something up.**

## Common mistakes

| Mistake | Correction |
|---|---|
| ⭐⭐ **`GET` that mutates state** | ⭐⭐ Crawlers and prefetchers will call it. Safe means safe. |
| ⭐⭐ **`200` with `{"error": ...}`** | ⭐⭐ Blinds every monitor and retry policy. Use the right code. |
| ⭐ `500` for invalid input | ⭐⭐ That is a `400`/`422`. `5xx` means *you* broke. |
| Confusing `401` and `403` | ⭐ 401 = who are you; 403 = I know, and no. |
| Retrying a `POST` blindly | ⭐⭐ Not idempotent — needs an idempotency key. |
| `PUT` used for partial updates | ⭐ That is `PATCH`. `PUT` replaces. |
| Omitting `Content-Length` | ⭐⭐ The receiver cannot tell where the body ends. |
| Trusting `X-Forwarded-For` | ⚠️ Forgeable unless your proxy set it. |
| ⭐ Reading headers from a plain dict | ⭐ Case-insensitive, and legally repeatable. |
| "UDP is unreliable TCP" | ⭐ It is IP + ports. You choose what to add back. |
| `301` while testing | ⚠️ ⭐⭐ Browsers cache it hard. Use `302` until you are sure. |

## Interview questions

**Q: What makes a method idempotent, and why does it matter?**
> Performing it N times has the same effect as performing it once. It matters because it is the
> property that makes retries safe — and everything in a distributed system retries: clients,
> proxies, load balancers, queues. `GET`, `PUT` and `DELETE` are idempotent; `POST` is not, which is
> why a retried payment double-charges unless the client sends an idempotency key that the server
> records and de-duplicates against.

**Q: Difference between 502, 503 and 504?**
> All three come from something in front of my application. 502 means the proxy reached upstream and
> got an invalid or truncated response — often the process died mid-request. 503 means there was
> nothing healthy to send it to, or the service is deliberately shedding load. 504 means upstream was
> reachable but did not answer within the timeout. So 502 is "it broke", 503 is "it isn't there", 504
> is "it's too slow" — three different investigations.

**Q: When would you return 202?**
> When I have accepted the work but not done it — the request went onto a queue. It is the honest
> status for anything asynchronous, and it should come with a way to check progress, usually a
> `Location` pointing at a status resource. The alternative — holding the connection open until the
> work finishes — turns every slow dependency into my own latency.

**Q: 401 or 403?**
> 401 means unauthenticated: no credentials, or invalid ones — and it should carry a
> `WWW-Authenticate` header. 403 means authenticated and identified, but not permitted. The name of
> 401 is historically wrong, which is why people mix them up. Sometimes 404 is the better answer than
> 403, when even confirming the resource exists leaks information.

**Q: Why is `Host` mandatory in HTTP/1.1?**
> Because one IP address serves many domains. The TCP connection only tells the server which address
> it arrived at; `Host` tells it which *site* was asked for. That is virtual hosting, and it is why
> HTTP/1.0 could not share an IP. It is the same information TLS carries in SNI, one layer down.

**Q: Give me a case where UDP is the right choice for a backend service.**
> Metrics. StatsD is UDP deliberately: if the metrics collector is down or slow, I want my
> application to keep serving traffic, not to block on a socket write to observe itself. Losing a few
> counter increments is acceptable; adding latency to every request to record them is not.

## 🎙️ Articulation drill

Record two minutes: **"Design the status codes and methods for a 'transfer money' endpoint."**

⭐ `POST /transfers` — it is not idempotent, so ⭐⭐ **require an `Idempotency-Key` header and store
processed keys**, returning the original result on a repeat. ⭐ `202 Accepted` with a `Location` if
settlement is asynchronous, `201 Created` if synchronous. `400`/`422` for a malformed amount, `403`
for an account you do not own, `409` for insufficient funds *or* a conflicting concurrent transfer,
`429` with `Retry-After` when rate limited, and ⭐⭐ **`503` when the downstream ledger is unavailable
— because that is the code that tells the caller to back off and try again, and `500` is not.**
