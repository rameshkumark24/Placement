# Part 4 — Executing generated code, honestly

```
⭐ ***THINGS THAT ARE NOT SANDBOXES:***
⭐   ⭐ `exec(code, {"__builtins__": {}})` — ⭐⭐ ESCAPABLE VIA
⭐     `().__class__.__bases__[0].__subclasses__()`. ⭐ It has
⭐     been escaped a thousand times; ⭐⭐ IT IS A SPEED BUMP
⭐     THAT LOOKS LIKE A WALL.
⭐   ⭐ a Docker container with default settings and network —
⭐     ⭐ better, ⭐⭐ AND IT CAN STILL REACH YOUR VPC AND YOUR
⭐     METADATA ENDPOINT.
⭐   ⭐ "we reviewed the prompt so it only writes safe code."

⭐ ***WHAT A REAL ONE NEEDS — ALL SIX:***
⭐   ⭐ ① ***NO NETWORK*** by default (or an egress allowlist);
⭐   ⭐ ② read-only filesystem + a small tmpfs;
⭐   ⭐ ③ memory, CPU and ***PID*** limits (fork bombs);
⭐   ⭐ ④ a hard wall-clock timeout, enforced outside;
⭐   ⭐ ⑤ ⭐⭐ NO CREDENTIALS IN THE ENVIRONMENT — ⭐ and IMDS
⭐     unreachable;
⭐   ⭐ ⑥ ***a kernel boundary***: gVisor, Firecracker, or a
⭐     separate VM. ⭐⭐ NOT NAMESPACES ALONE.

⭐ ⭐⭐ AND THE DESIGN THAT AVOIDS THE QUESTION: ⭐ have the model
⭐   emit ***parameters***, not code. ⭐ A chart spec instead of
⭐   matplotlib; a filter expression from a closed grammar
⭐   instead of pandas. ⭐⭐ IT IS LESS IMPRESSIVE AND VASTLY MORE
⭐   DEFENSIBLE, AND IT IS THE RIGHT ANSWER FOR MOST PRODUCTS.
```

# Part 5 — The safe URL fetcher, as a worked example

```python
import ipaddress, socket
from urllib.parse import urlparse

ALLOWED_HOSTS = {"docs.example.com", "api.example.com"}

def assert_fetchable(url: str) -> str:
    u = urlparse(url)
    if u.scheme != "https":                       # ⭐ no http, file, gopher
        raise Unsafe("https only")
    if u.hostname not in ALLOWED_HOSTS:           # ⭐⭐ ALLOWLIST, NOT DENYLIST
        raise Unsafe(f"host not allowed: {u.hostname}")

    # ⭐⭐ RESOLVE AND CHECK THE *IP*. A permitted hostname can
    # resolve to 169.254.169.254 — that is DNS rebinding, and an
    # allowlist alone does not stop it.
    for *_, sa in socket.getaddrinfo(u.hostname, 443):
        ip = ipaddress.ip_address(sa[0])
        if (ip.is_private or ip.is_loopback or ip.is_link_local
                or ip.is_reserved):
            raise Unsafe(f"resolves to internal address {ip}")
    return url

# ⭐⭐ AND AT THE CALL SITE:
#   allow_redirects=False   ← a 302 to the metadata endpoint
#                             bypasses every check above
#   timeout=(3, 10)         ← Day 439's deadline
#   stream + size cap       ← a 2GB response is a DoS on you
```

```
⭐⭐ FOUR THINGS THAT FUNCTION GETS RIGHT THAT MOST DO NOT:
⭐   ⭐ allowlist rather than denylist — ⭐ you cannot enumerate
⭐     every bad host;
⭐   ⭐ ⭐⭐ CHECKS THE RESOLVED IP, NOT THE STRING;
⭐   ⭐ redirects disabled, ⭐⭐ BECAUSE A 302 IS A LEGAL WAY TO
⭐     LAUNDER A BLOCKED DESTINATION;
⭐   ⭐ a response size cap, because the DoS runs both ways.
```

⭐     and ⭐⭐ SHOW THE FULL URL;
⭐   ⭐ strip zero-width and unicode tag characters ***on the way
⭐     out***, not only on the way in.

# 💬 Interview

**1. "Why treat model output as untrusted?"**

⭐ Because after prompt injection it may literally be an attacker's text laundered through my own model.
⭐⭐ The trap is psychological: I wrote the prompt and chose the model, so the output *feels* like it came
from my code — but it came from a function whose inputs include arbitrary third-party content. ⭐ So the
rule is that every validator, escaper and authorisation check I'd apply to a form field from the public
internet applies unchanged to model output. ⭐⭐ Including "it's just displaying text", which is where
this usually gets waved through.

**2. "You're generating SQL. How is that safe?"**

⭐ It isn't, by default — the model is writing my WHERE clause. ⭐⭐ So I parse the statement with sqlglot
before executing: single statement, SELECT only, no CTE writes, mandatory LIMIT, and a required tenant
predicate. ⭐ It runs as a read-only role on a replica with a statement timeout, against a curated view
rather than my real schema, so there are no PII columns to select in the first place. ⭐⭐ And row-level
security underneath, so validation failing isn't fatal — that's the difference between a check and a
boundary. ⭐ I also show the user the generated SQL, which is both the only citation an aggregate answer
can have and a second pair of eyes.

**3. "The agent can fetch URLs. What's the risk?"**

⭐⭐ A model-chosen URL is an SSRF primitive. ⭐ The specific target is the cloud metadata endpoint at
169.254.169.254 — that's credentials, and it's reachable from inside any VM by default. ⭐ Then
localhost, private ranges and `.internal` names. ⭐⭐ So: an allowlist rather than a denylist, because
you can't enumerate every bad host; resolve the hostname and check the **IP**, since an allowed name can
resolve to a link-local address; disable redirects, because a 302 is a legal way to launder a blocked
destination past every check you just made; a timeout and a response size cap. ⭐ And IMDSv2 with hop
limit 1 on the instance, so even a successful SSRF gets nothing.

**4. "Structured output guarantees a schema. Isn't that enough?"**

⭐ It guarantees parsing, and nothing about safety. ⭐⭐ `{"url": "http://169.254.169.254/"}` is
schema-valid. So is `{"path": "../../etc/passwd"}`, `{"recipient": "attacker@evil.com"}` and
`{"amount_cents": 999999999}`. ⭐ So there are three layers and they aren't interchangeable: syntactic,
which the schema gives me free; semantic, which is ordinary business rules — is this amount within
policy, is this recipient a known contact of *this* user; and authorisation, which is may **this
session** do **this**, checked in my code every time even when the arguments look fine. ⭐⭐ All the
safety is in the second and third, and both are completely ordinary Python.

**5. "You need to run model-generated code."**

⭐ First I'd try not to. ⭐⭐ Having the model emit parameters rather than code — a chart spec instead of
matplotlib, a filter expression from a closed grammar instead of pandas — is less impressive and vastly
more defensible, and it's the right answer for most products. ⭐ If I genuinely need execution, then a
real sandbox: no network by default, read-only filesystem, memory, CPU and PID limits, a hard timeout
enforced from outside, no credentials in the environment with IMDS unreachable, and a **kernel**
boundary — gVisor or Firecracker, not namespaces alone. ⭐⭐ What isn't a sandbox is `exec` with an empty
builtins dict; that's escapable through `__subclasses__` and has been a thousand times. ⭐ It's a speed
bump that looks like a wall.

**6. "What's the risk in just rendering the answer?"**

⭐ Rendering is execution. ⭐⭐ Markdown-to-HTML gives you remote images, which fire a silent GET with
data in the query string — that's the exfiltration channel even when the agent has no send tool. ⭐ It
gives you links, which is phishing wearing my own product's UI and far more convincing than an email.
⭐ Raw HTML if I allow it is ordinary XSS with the user's session, plus `javascript:` and `data:` URLs.
⭐⭐ And hidden text — white-on-white or zero-width — which the *next* model reads if the user copies the
answer back in or if I store it. ⭐ So: sanitise with a tiny allowlist, never raw HTML, CSP on `img-src`
and `connect-src`, show full URLs, and strip zero-width characters on the way **out** as well as in.

## 🎙️ Articulation drill

⭐⭐ **Two minutes, out loud: "how do you handle model output safely?"**

Open with the composition, because it's the argument. **Prompt injection means an attacker can put text
into the model's context. Model output flows into my systems. Compose those and an attacker's text can
reach my database, my shell, my HTTP client and my browser — with my own model as the laundering step.
So model output gets treated exactly like a string posted by an anonymous stranger: same escaping, same
validation, same authorisation. The trap is that it *feels* like it came from my code, because I wrote
the prompt — but it came from a function whose inputs include arbitrary third-party content.**

Then the two destinations worth naming specifically. **A model-chosen URL is an SSRF primitive, and the
target is the cloud metadata endpoint — that's credentials. So it's an allowlist rather than a denylist,
I resolve the hostname and check the IP because an allowed name can resolve link-local, and redirects
are disabled because a 302 is a legal way to launder a blocked destination past every check I just made.
And generated SQL means the model is writing my WHERE clause, so it's parsed before execution —
SELECT-only, single statement, mandatory limit, required tenant predicate — on a read-only replica role
against a curated view, with row-level security underneath so validation isn't the only control.**

Then correct the thing people over-trust. **Structured output solved parsing and nothing about safety.
A URL pointing at the metadata endpoint is schema-valid. So is a path traversal, an attacker's email
address, and a nine-figure amount. There are three layers: syntactic from the schema, semantic business
rules, and authorisation — may this session do this, checked every time even when the arguments look
fine. All the safety is in the last two, and both are completely ordinary Python.**

Close on the one people skip. **And rendering is execution. Markdown-to-HTML gives you remote images
that fire a silent GET with data in the query string, which is how a system with no send tool still
exfiltrates. It gives you links, which is phishing wearing my own UI. Raw HTML is XSS with the user's

stored or pasted back. So: sanitise with a tiny allowlist, no raw HTML, CSP on image and connect
sources, full URLs shown, and zero-width characters stripped on the way out as well as in.**
