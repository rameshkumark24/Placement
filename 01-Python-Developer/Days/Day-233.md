> query that lives in `useState` instead is a feature you have quietly deleted.**

# Part 1 — Routes and nested layouts

```
⭐⭐ FILE-BASED ROUTING — the URL mirrors the folder tree

⭐   app/
⭐     layout.tsx          ⇒ wraps EVERYTHING  (nav, providers)
⭐     page.tsx            ⇒ /
⭐     orders/
⭐       layout.tsx        ⇒ wraps /orders/*   ⭐ persists across children
⭐       page.tsx          ⇒ /orders
⭐       [id]/page.tsx     ⇒ /orders/:id       ⭐ dynamic segment
⭐       loading.tsx       ⇒ ⭐ shown while this route's data loads
⭐       error.tsx         ⇒ ⭐⭐ CATCHES ERRORS IN THIS SUBTREE ONLY
```

| ⭐ Why nested layouts matter | |
|---|---|
| **State survives navigation** | ⭐⭐ Navigating `/orders/1` → `/orders/2` **keeps the layout mounted** — the sidebar does not re-fetch, the scroll position holds, an open panel stays open. |
| **Per-route error boundaries** | ⭐ One broken widget takes out its subtree, not the whole page (Day 240) |
| **Per-route loading** | ⭐ The shell renders immediately; only the changing part shows a skeleton |

# Part 2 — ⭐⭐ The URL is state

```
⭐⭐ WHAT BELONGS IN THE URL — the test is one question:
⭐   ⭐ "IF THE USER SENT THIS LINK TO A COLLEAGUE, SHOULD THEY SEE
⭐     THE SAME THING?"  ⇒ IF YES, IT GOES IN THE URL.

⭐   ✅ ⭐ filters, sort, page number, search query, the active tab,
⭐      the selected record, an open modal that is a "place"
⭐   ❌ ⭐ a dropdown's open/closed, an unsent form draft, hover state
⭐   ❌ ⭐⭐ ANYTHING SENSITIVE. The URL is logged by your server, your
⭐      CDN, the browser history, and pasted into chat windows.
⭐      ⭐⭐ A TOKEN IN A QUERY STRING IS A LEAKED TOKEN (Day 235).
```

```jsx
const [params, setParams] = useSearchParams();
const status = params.get("status") ?? "all";     // ⭐ ?? not || (Day 215)

function setStatus(next) {
  setParams(p => { p.set("status", next); p.delete("page"); return p; });
  //                              ⭐⭐ RESET PAGE — otherwise the user
  //                              lands on page 7 of a 2-page result set
}
```

| ⭐ What you get free | |
|---|---|
| **Refresh survives** | ⭐ The filtered view is still there |
| **Shareable** | ⭐⭐ "Here's the list of failed orders" is a link, not instructions |
| **Back/forward works** | ⭐ Users expect back to undo a filter, and are annoyed when it exits the page |
| **Server-renderable** | ⭐ The server can read the params and render with data (Day 234) |

> ⭐ **`replace` vs `push`.** Typing in a search box should `replace` — otherwise every keystroke is a
> history entry and Back requires eleven presses. Changing a *filter* should `push`. Getting this
> wrong is a small thing users feel immediately.

# Part 3 — ⭐⭐ Loaders kill the waterfall

```
⭐⭐ WITHOUT A LOADER — the Day 227 staircase
⭐   click link → download route chunk → mount component
⭐              → useEffect fires → fetch → render
⭐   ⇒ ⭐ THE FETCH CANNOT START UNTIL THE CODE HAS ARRIVED.

⭐⭐ WITH A LOADER — both start at the click
⭐   click link → ⭐⭐ FETCH **AND** CHUNK DOWNLOAD, IN PARALLEL
⭐              → render with data already present
⭐   ⇒ ⭐ ONE ROUND TRIP SAVED ON EVERY NAVIGATION, and no
⭐     loading flash for fast responses.
```

```jsx
// ⭐ React Router style
export async function loader({ params, request }) {
  return { order: await api(`/orders/${params.id}`, { signal: request.signal }) };
}

// ⭐⭐ or a server component — the fetch happens where the data is
export default async function Page({ params }) {
  const order = await getOrder(params.id);     // ⭐ no round trip at all
  return <OrderView order={order} />;
}
```

> ⭐⭐ **This is the single biggest navigation-speed win available**, and it is architectural rather
> than an optimisation. It is also why "where does the fetch live" (Day 227, Part 4) was worth a whole
> section.

# Part 4 — Code splitting and prefetch

```jsx
const Reports = lazy(() => import("./Reports"));   // ⭐ its own chunk

<Suspense fallback={<Skeleton />}>
  <Reports />
</Suspense>
```

| ⭐ Split on | Not on |
|---|---|
| ⭐⭐ **Route boundaries** — the natural seam | ⭐ Every component (hundreds of tiny chunks is slower) |
| Heavy, rarely used deps — a chart lib, a rich-text editor, a PDF viewer | ⭐ Anything above the fold |
| Admin-only sections | |

```
⭐⭐ PREFETCH ON INTENT — the trick that makes navigation feel instant
⭐   onMouseEnter / onFocus on a link ⇒ start downloading its chunk.
⭐   ⭐ The user takes ~200–300 ms to actually click. That is enough
⭐     time to have the chunk ready.
⭐   ⇒ ⭐⭐ MOST ROUTERS DO THIS FOR YOU. Know that it is happening,
⭐     and that it costs bandwidth on mobile — bound it.
```

> ⭐ **Splitting the login route away from the dashboard is the highest-value split in most apps** —
> the first page a logged-out user sees should not ship the code for a page they cannot reach.

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "how do you decide what goes in the URL?"**

Give the test, because it is memorable and it is genuinely how you decide. **One question: if the user
sent this link to a colleague, should they see the same thing? If yes, it belongs in the URL. Filters,
sort, page number, search query, the active tab. Those in `useState` instead are features I've quietly
deleted — refresh loses them, they can't be shared, and Back does the wrong thing.**

Add the exclusion, since it is a security point. **Nothing sensitive. The URL is logged by my server,
my CDN and the browser history, and it gets pasted into chat windows. A token in a query string is a
leaked token.**

Then the architectural win. **Fetching in a route loader instead of a component removes a round trip
per navigation. Without it, the click downloads the route's code chunk, the component mounts, and only
then does the effect fire and the fetch start — the fetch can't begin until the code arrives. With a
loader they run in parallel. That's the biggest navigation-speed win available and it's structural, not
an optimisation.**

Close on a small thing that shows you have used this with real users. **Nested layouts matter because
state survives navigation — moving between two orders keeps the sidebar mounted and the scroll position
held. And a search box has to `replace` rather than `push`, or every keystroke becomes a history entry
and Back takes eleven presses to escape.**
