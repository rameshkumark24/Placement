# Part 2 — The client, set up properly

```python
# ⭐⭐ ONE MODULE-LEVEL CLIENT. Constructing it per request costs
# ⭐   real milliseconds and leaks connections (Day 382).
import httpx
from openai import AsyncOpenAI

_client = AsyncOpenAI(
    timeout=httpx.Timeout(
        connect=5.0,        # ⭐ fail fast on a network problem
        read=120.0,         # ⭐⭐ GENERATION IS GENUINELY SLOW —
                            # ⭐   a reasoning model needs this
        write=10.0, pool=5.0,
    ),
    max_retries=0,          # ⭐⭐ OWN YOUR RETRIES (PART 4)
    http_client=httpx.AsyncClient(
        limits=httpx.Limits(
            max_connections=100,            # ⭐⭐ MATCH YOUR REAL
            max_keepalive_connections=20,   # ⭐   CONCURRENCY —
        ),                                  # ⭐ Day 386's lesson
    ),
)
```

```
⭐⭐ ***ASYNC IS THE RIGHT DEFAULT HERE, AND THIS IS THE ONE
⭐   PLACE IN PYTHON WHERE THE ARGUMENT IS UNARGUABLE*** (DAYS
⭐   070–072):
⭐   ⭐ An LLM call is 2–60 seconds of ***pure waiting***. ⭐ Zero
⭐     CPU. ⭐⭐ THE GIL IS RELEASED THE ENTIRE TIME.
⭐   ⭐ Sync + gunicorn: ⭐⭐ 4 WORKERS = 4 CONCURRENT CALLS, ⭐ and
⭐     a 30-second generation holds a worker for 30 seconds
⭐     (Day 389).
⭐   ⭐⭐ ASYNC: HUNDREDS OF CONCURRENT CALLS PER PROCESS, BECAUSE
⭐     THEY ARE ALL JUST WAITING ON SOCKETS.
⭐   ⭐⭐ ⇒ FOR AN LLM-BACKED SERVICE, SYNC WORKERS ARE NOT A
⭐     STYLE CHOICE — THEY ARE A 50× CAPACITY DIFFERENCE.
⭐ ⭐ And the fan-out primitive you will use constantly:
⭐   `asyncio.gather` ⭐⭐ INSIDE AN `asyncio.timeout` (DAY 398),
⭐   ⭐ with a `Semaphore` to respect the provider's rate limit
⭐   (Day 415).
```

# Part 3 — ⭐⭐ The call function

```python
from dataclasses import dataclass
import time, uuid

@dataclass(frozen=True, slots=True)
class LLMResult:
    text: str
    model: str
    prompt_tokens: int
    completion_tokens: int
    cost_usd: float          # ⭐⭐ COMPUTED HERE, ONCE
    latency_ms: float
    cached: bool
    request_id: str          # ⭐ correlate with the provider

async def complete(
    *,
    task: str,                       # ⭐⭐ "invoice_extract" —
        # ⭐ THE DIMENSION EVERY METRIC AND LOG IS GROUPED BY.
        # ⭐⭐ WITHOUT IT YOU CAN NEVER ANSWER "WHICH FEATURE COSTS
        # ⭐   THE MOST" (DAY 396).
    messages: list[dict],
    model: str = "gpt-4o-mini",
    max_tokens: int = 1024,          # ⭐⭐ NEVER UNBOUNDED
    temperature: float = 0.0,
    prompt_version: str | None = None,   # ⭐ Day 427
    timeout_s: float = 60.0,
) -> LLMResult:
    t0 = time.perf_counter()
    with tracer.start_as_current_span("llm.complete") as span:
        span.set_attribute("llm.task", task)
        span.set_attribute("llm.model", model)
        span.set_attribute("llm.prompt_version", prompt_version or "")
        # ⭐⭐ THE PROMPT ITSELF GOES IN A SPAN ***EVENT***, NOT AN
        # ⭐   ATTRIBUTE — attributes have length limits and are
        # ⭐   indexed; a 40 KB prompt as an attribute will be
        # ⭐   silently truncated or will blow up your bill
        # ⭐   (Day 394).
        span.add_event("prompt", {"body": _redact(messages)})

        async with _sem:                       # ⭐ rate limit
            resp = await _client.chat.completions.create(
                model=model, messages=messages,
                max_tokens=max_tokens, temperature=temperature,
                timeout=timeout_s,
            )

        u = resp.usage
        cost = price(model, u.prompt_tokens, u.completion_tokens)
        span.set_attribute("llm.prompt_tokens", u.prompt_tokens)
        span.set_attribute("llm.completion_tokens", u.completion_tokens)
        span.set_attribute("llm.cost_usd", cost)
        LLM_COST.labels(task=task, model=model).inc(cost)   # ⭐⭐ EMF
        LLM_TOKENS.labels(task=task, model=model,           # ⭐ or
                          kind="completion").inc(u.completion_tokens)

        return LLMResult(
            text=resp.choices[0].message.content or "",
            model=resp.model,        # ⭐⭐ THE ***RESOLVED*** MODEL —
                # ⭐ "gpt-4o" resolves to a dated snapshot, and
                # ⭐⭐ THAT SNAPSHOT IS WHAT CHANGED UNDER YOU WHEN
                # ⭐   QUALITY MOVED OVERNIGHT (DAY 459).
            prompt_tokens=u.prompt_tokens,
            completion_tokens=u.completion_tokens,
            cost_usd=cost, cached=False,
            latency_ms=(time.perf_counter() - t0) * 1000,
            request_id=resp.id,
        )
```

```
⭐⭐ THE FIVE DECISIONS IN THAT FUNCTION THAT ARE NOT DECORATION:
⭐ ① ⭐⭐ `task` IS MANDATORY AND KEYWORD-ONLY. ⭐ It is the
⭐    low-cardinality dimension everything is grouped by
⭐    (Day 394). ⭐⭐ MAKE IT IMPOSSIBLE TO CALL WITHOUT ONE.
⭐ ② ⭐⭐ COST IS COMPUTED ***AT THE CALL***, ⭐ not reconstructed
⭐    later from a bill you cannot attribute.
⭐ ③ ⭐⭐ THE ***RESOLVED*** MODEL IS RECORDED. ⭐ Aliases move.
⭐ ④ ⭐ The prompt goes in a span ***event***, redacted.
⭐ ⑤ ⭐ `max_tokens` has a default rather than being optional —
⭐    ⭐⭐ SO THE UNBOUNDED CASE CANNOT HAPPEN BY OMISSION.
```

# Part 4 — ⭐⭐ Retries: which errors, and which absolutely not

```
⭐ ✅ ***RETRY:***
⭐   ⭐ `RateLimitError` (429) — ⭐⭐ WITH BACKOFF AND `Retry-After`
⭐   ⭐ `APIConnectionError`, `APITimeoutError`
⭐   ⭐ 500 / 502 / 503 / 529 — provider-side
⭐ ❌ ***NEVER RETRY:***
⭐   ⭐ 400 (bad request), 401, 403, 404 — ⭐⭐ THE ANSWER WILL NOT
⭐     CHANGE
⭐   ⭐ `context_length_exceeded` — ⭐⭐ FIX THE PROMPT, DO NOT
⭐     RESEND IT
⭐   ⭐ a content-filter refusal
⭐ ⚠️ ***THE INTERESTING ONE:*** ⭐ a ***timeout*** is Day 398's
⭐   unknown outcome. ⭐⭐ THE MODEL MAY HAVE GENERATED THE WHOLE
⭐   ANSWER AND YOU MAY HAVE BEEN BILLED FOR IT. ⭐ Retrying costs
⭐   you twice. ⭐⭐ THAT IS USUALLY ACCEPTABLE FOR A READ-ONLY
⭐   GENERATION AND ***NOT*** ACCEPTABLE IF THE CALL TRIGGERS A
⭐   TOOL WITH A SIDE EFFECT (DAY 444).
```

```python
from tenacity import (retry, stop_after_attempt, wait_exponential_jitter,
                      retry_if_exception_type)

@retry(
    retry=retry_if_exception_type(
        (RateLimitError, APIConnectionError, APITimeoutError, InternalServerError)),
    wait=wait_exponential_jitter(initial=1, max=30),   # ⭐⭐ JITTER
        # ⭐ OR EVERY CLIENT RETRIES IN LOCKSTEP AFTER AN OUTAGE
        # ⭐   AND YOU DDoS THE RECOVERY (DAY 336)
    stop=stop_after_attempt(3),
    reraise=True,
)
async def _call_with_retry(**kw): ...
```

```
⭐⭐ AND THE PART tenacity DOES NOT GIVE YOU: ***A RETRY
⭐   BUDGET*** (DAY 336). ⭐ Three attempts per call is fine;
⭐   ⭐⭐ THREE ATTEMPTS × EVERY CALL DURING A PROVIDER BROWNOUT IS
⭐   3× LOAD ON A SYSTEM THAT IS ALREADY FAILING. ⭐ Track the
⭐   fleet-wide retry ratio and ⭐⭐ STOP RETRYING ABOVE ~10%.
```

# Part 5 — Structured output, the honest version

```
⭐ THREE MECHANISMS, IN ASCENDING RELIABILITY:
⭐ ① ⭐ ***"RETURN JSON" IN THE PROMPT.*** ⭐⭐ IT WILL EVENTUALLY
⭐    RETURN ```json FENCES, A PREAMBLE, OR A TRAILING COMMA.
⭐    ⭐ Do not rely on it.
⭐ ② ⭐ ***JSON MODE*** — ⭐ guarantees ***syntactically valid***
⭐    JSON. ⭐⭐ IT DOES ***NOT*** GUARANTEE YOUR SCHEMA. ⭐ You can
⭐    get `{"result": "sorry, I cannot help"}`.
⭐ ③ ⭐⭐ ***CONSTRAINED DECODING / STRUCTURED OUTPUTS*** — ⭐ the
⭐    provider masks the token distribution so only tokens that
⭐    keep the JSON schema-valid are sampled.
⭐    ⭐⭐ THIS IS A ***GUARANTEE***, NOT A REQUEST, ⭐ because it is
⭐    enforced at the sampler (Day 418), not in the prompt.
⭐    ⭐ Use it wherever it exists.
```

```python

class Invoice(BaseModel):
    number: str
    total_cents: int = Field(ge=0)      # ⭐⭐ MONEY AS AN INTEGER
    currency: Literal["GBP", "EUR", "INR"]
    line_items: list[str] = []

resp = await _client.beta.chat.completions.parse(
    model=MODEL, messages=msgs, response_format=Invoice,

invoice = resp.choices[0].message.parsed     # ⭐⭐ ALREADY TYPED
```

```
⭐⭐ AND THE THREE THINGS STILL TRUE EVEN WITH A GUARANTEE:
⭐ ① ⭐⭐ ***SCHEMA-VALID IS NOT ***CORRECT***.*** ⭐ `total_cents`
⭐    will be an integer ≥ 0. ⭐⭐ IT MAY STILL BE THE WRONG
⭐    NUMBER. ⭐ Structured output solves parsing, ⭐⭐ NOT ACCURACY
⭐    — AND CONFLATING THE TWO IS THE COMMONEST FALSE COMFORT IN
⭐    THIS FIELD.
⭐ ② ⭐ Deeply nested or very permissive schemas degrade quality;
⭐    ⭐⭐ KEEP THEM FLAT AND CONSTRAINED. ⭐ `Literal` and `Enum`
⭐    beat free-text fields.
⭐ ③ ⭐⭐ GIVE THE MODEL AN ***ESCAPE HATCH***: ⭐ an
⭐    `Optional[str] = None` or a `confidence` field, ⭐⭐ OR A
⭐    SCHEMA THAT ***FORBIDS*** SAYING "I DON'T KNOW" FORCES IT TO
⭐    INVENT (DAY 449). ⭐ The schema itself can cause
⭐    hallucination, which surprises people.
```

# Part 6 — Provider differences that leak

```
⭐ ⭐⭐ THE APIs LOOK SIMILAR AND DIFFER IN WAYS THAT BREAK CODE:
⭐   ⭐ ***SYSTEM PROMPT***: OpenAI takes a `system` ***message***;
⭐     Anthropic takes a top-level `system` ***parameter***.
⭐   ⭐ ***MULTI-TURN***: Anthropic requires strictly alternating
⭐     user/assistant; ⭐⭐ OPENAI IS PERMISSIVE. ⭐ A history that
⭐     works on one 400s on the other.
⭐   ⭐ ***TOOL CALLING***: different field names and different
⭐     result formats (Day 438).
⭐   ⭐ ***TOKENISERS DIFFER***, so counts are not portable
⭐     (Day 415).
⭐   ⭐ ***STOP REASONS***: `stop` / `length` / `end_turn` /
⭐     `max_tokens` — ⭐⭐ AND YOU ***MUST*** CHECK THIS. ⭐ A
⭐     truncated answer is not an error; ⭐⭐ IT ARRIVES AS A 200
⭐     WITH A SHORTER STRING, AND CODE THAT IGNORES THE FINISH
⭐     REASON WILL PARSE HALF AN INVOICE AND CARRY ON.

⭐ ⭐ Options: ⭐ write the thin adapter yourself (⭐⭐ TWO HOURS,
⭐   ZERO DEPENDENCIES, AND YOU UNDERSTAND IT), ⭐ or use
⭐   LiteLLM / the OpenAI-compatible endpoints most providers
⭐   now expose.
⭐ ⭐⭐ AND THE DISCIPLINE THAT MAKES A SWAP REAL: ***A PROVIDER
⭐   SWAP IS NOT A CONFIG CHANGE — IT IS A CONFIG CHANGE PLUS AN
⭐   EVAL RUN*** (DAY 425), ⭐ because prompts are not portable
⭐   (Day 417).

# 💬 Interview

**1. ⭐⭐ "Would you call the OpenAI SDK directly from your handlers?"**
> ⭐ No — one thin layer in front. ⭐⭐ **Eight things have to happen on every model call: cost
> accounting per feature, a real timeout, retries on the right errors with a budget, a trace span,
> caching, model routing and fallback, prompt version tagging, and output validation.** ⭐ Eight
> cross-cutting concerns times forty call sites is the definition of something belonging in one place.
> ⭐⭐ **And the test for whether the wrapper is right is: can you add provider failover in one file? If
> not it's too thin. Can you still pass a provider-specific parameter through? If not it's too thick,
> and someone will bypass it within a month.**

**2. ⭐⭐ "Sync or async for an LLM-backed service?"**
> ⭐ Async, and this is the one place in Python where the argument is unarguable. ⭐⭐ **An LLM call is 2
> to 60 seconds of pure waiting with zero CPU — the GIL is released the entire time. Sync with four
> gunicorn workers means four concurrent calls, and a 30-second generation holds a worker for 30
> seconds. Async gives you hundreds per process because they're all just waiting on sockets.** ⭐ So it
> isn't a style choice, ⭐⭐ **it's roughly a 50× capacity difference** — with a semaphore to respect the
> provider's rate limit and an `asyncio.timeout` around any fan-out.

**3. "Which errors do you retry?"**
> ⭐ 429s with backoff and `Retry-After`, connection errors, timeouts, and provider 5xx. ⭐ Never 400,
> 401, 403, 404 or context-length-exceeded — ⭐⭐ **the answer won't change, and resending an oversized
> prompt just wastes another round trip.** ⭐ The interesting one is a timeout: ⭐⭐ **it's the unknown
> outcome — the model may have generated the whole answer and you may already have been billed, so
> retrying costs you twice. That's acceptable for a read-only generation and not acceptable if the
> call triggers a tool with a side effect.** ⭐ And I'd add what `tenacity` doesn't give you: ⭐⭐ **a
> retry budget, because three attempts per call is fine but three attempts on every call during a
> provider brownout is 3× load on something already failing.**

**4. ⭐⭐ "How do you get structured output reliably?"**
> ⭐ Three mechanisms in ascending reliability. ⭐ Asking for JSON in the prompt eventually returns
> fences or a preamble. ⭐ JSON mode guarantees syntactically valid JSON ⭐⭐ **but not your schema — you
> can get `{"result": "sorry, I cannot help"}`.** ⭐⭐ **Constrained decoding is the real answer: the
> provider masks the token distribution so only tokens keeping the schema valid can be sampled — that's
> a guarantee rather than a request, because it's enforced at the sampler rather than in the prompt.**
> ⭐ Then three things still true: ⭐⭐ **schema-valid is not correct — the integer will be an integer and
> may still be the wrong number, and conflating parsing with accuracy is the commonest false comfort
> in this field.** ⭐ Keep schemas flat and use `Literal` over free text. ⭐⭐ **And give the model an
> escape hatch, because a schema that forbids saying "I don't know" forces it to invent — the schema
> itself can cause hallucination.**

**5. ⭐⭐ "What breaks when you swap providers?"**
> ⭐ More than people expect. ⭐⭐ **OpenAI takes the system prompt as a message and Anthropic as a
> top-level parameter; Anthropic requires strictly alternating user/assistant turns while OpenAI is
> permissive, so a history that works on one 400s on the other; tool-calling field names differ;
> tokenisers differ so counts aren't portable; and stop reasons are named differently.** ⭐ That last one
> matters most: ⭐⭐ **a truncated answer isn't an error — it arrives as a 200 with a shorter string, so
> code that ignores the finish reason will parse half an invoice and carry on.** ⭐ And the discipline:
> ⭐⭐ **a provider swap is a config change plus an eval run, because prompts aren't portable between
> models.**

**6. "What do you log on every call?"**
> ⭐ A mandatory low-cardinality `task` label, the **resolved** model rather than the alias I asked for
> — ⭐⭐ **because "gpt-4o" resolves to a dated snapshot, and that snapshot is what changed under you
> when quality moved overnight** — prompt and completion tokens, the cost computed at the call rather
> than reconstructed from a bill, latency, the provider request id, and the prompt version. ⭐⭐ **The
> prompt body goes in a span event rather than an attribute, because attributes are indexed and
> length-limited, so a 40 KB prompt gets silently truncated or blows up the observability bill.**
