# Part 1 — What a second agent actually buys

```
⭐ ***FOUR REAL BENEFITS. NAME THEM OR YOU ARE CARGO-CULTING.***

⭐ ① ⭐⭐ ***A SEPARATE CONTEXT WINDOW.*** ⭐ This is the big one.
⭐   ⭐ A sub-agent researching 40 documents fills ***its own***
⭐     window and returns 300 tokens of findings.
⭐   ⭐⭐ THE ORCHESTRATOR NEVER SEES THE 40 DOCUMENTS — ⭐ so the
⭐     main transcript stays small, cheap and un-distracted
⭐     (Day 439's quadratic term never grows).

⭐ ② ***A SEPARATE TOOL SET.*** ⭐ Day 438: selection degrades
⭐   past ~20 tools. ⭐⭐ FIVE AGENTS WITH SIX TOOLS EACH BEATS
⭐   ONE AGENT WITH THIRTY, ⭐ measurably.

⭐ ③ ***A SEPARATE MODEL.*** ⭐ The cascade from Day 421, made
⭐   structural: ⭐⭐ A CHEAP MODEL FOR EXTRACTION SUB-TASKS, AN
⭐   EXPENSIVE ONE FOR THE PLAN.

⭐ ④ ***A SEPARATE EVAL.*** ⭐ Each agent has one job, so each
⭐   gets its own eval set and its own gate (Day 425).
⭐   ⭐⭐ THIS IS THE MOST UNDER-RATED REASON AND OFTEN THE BEST
⭐     ONE.

⭐⭐ AND THE BENEFIT THAT IS ***NOT*** ON THE LIST: ⭐ "the agents
⭐   collaborate and reach better conclusions." ⭐⭐ THEY ARE THE
⭐   SAME MODEL WITH DIFFERENT SYSTEM PROMPTS. ⭐ There is no
⭐   second opinion — ⭐⭐ THERE IS THE SAME DISTRIBUTION SAMPLED
⭐   AGAIN UNDER A DIFFERENT CONDITION. ⭐ Sometimes useful,
⭐   never a "team".
```

# Part 2 — ⭐⭐ The handoff is an RPC you designed badly

```
⭐ ***WHAT ACTUALLY CROSSES THE BOUNDARY:*** ⭐ a string.
⭐   ⭐ The sub-agent does ***not*** have the conversation, the
⭐     user's earlier corrections, or the constraint mentioned
⭐     four turns ago. ⭐⭐ IT HAS WHAT YOU SERIALISED.

⭐ ⇒ ***THIS IS A NETWORK BOUNDARY WITH ALL OF STAGE 12'S
⭐   PROPERTIES*** (Day 398):
⭐   ⭐ ⭐⭐ THE INTERFACE IS UNTYPED PROSE — ⭐ the exact thing
⭐     Day 402 spent a day arguing against;
⭐   ⭐ information is lost, ***silently***;
⭐   ⭐ the sub-agent can fail, hang, or return nonsense;
⭐   ⭐ ⭐⭐ THE THIRD OUTCOME IS BACK: DID IT DO THE WORK AND FAIL
⭐     TO REPORT, OR NOT DO IT? (DAY 398)
⭐   ⭐ and there is ***no transaction*** across agents (Day 411).

⭐ ***SO GIVE THE HANDOFF A SCHEMA.*** ⭐⭐ IF IT IS WORTH BEING
⭐   A SEPARATE AGENT, IT IS WORTH A TYPED CONTRACT.
```

```python
class ResearchTask(BaseModel):
    """⭐⭐ THE WIRE FORMAT. Explicit beats 'the orchestrator
    will write a good prompt'."""
    question: str
    must_cover: list[str] = []
    exclude_sources: list[str] = []
    already_tried: list[str] = []      # ⭐⭐ STOPS CROSS-AGENT DOOM LOOPS
    max_findings: int = 5
    budget: Budget                     # ⭐ Day 439 — deadlines propagate

class ResearchResult(BaseModel):
    findings: list[Finding]            # ⭐ each with a source + quote
    coverage: Literal["complete", "partial", "none"]   # ⭐⭐ ABSTENTION
    unresolved: list[str]              # ⭐ what it could NOT answer
    steps_used: int
    cost_usd: float
```

```
⭐⭐ NOTE `coverage` AND `unresolved`. ⭐ Without them the
⭐   orchestrator cannot distinguish ***"there is nothing"*** from
⭐   ***"I gave up"***, ⭐⭐ AND IT WILL CONFIDENTLY SYNTHESISE AN
⭐   ANSWER FROM AN EMPTY RESULT. ⭐ Day 422's abstention, moved
⭐   to a service boundary.
```

# Part 3 — The topologies, ranked by how often they are right

```
⭐ ① ⭐⭐ ***ONE AGENT, GOOD TOOLS.*** ⭐ The correct answer far
⭐   more often than the literature suggests. ⭐ Try this first
⭐   and make it fail before adding anything.

⭐ ② ⭐⭐ ***DETERMINISTIC PIPELINE.*** ⭐ extract → validate →
⭐   enrich → summarise, as ***ordinary function calls***.
⭐   ⭐⭐ THIS IS A PROGRAM, NOT A MULTI-AGENT SYSTEM, AND THAT IS
⭐     THE POINT: ⭐ it is testable, debuggable, cheap and it
⭐     cannot loop. ⭐⭐ MOST "CREWS" SHOULD BE THIS.

⭐ ③ ***ROUTER / DISPATCHER.*** ⭐ One cheap classification call
⭐   picks a specialist path, then a single agent runs.
⭐   ⭐⭐ THE CLASSIFICATION IS ONE CALL WITH AN ENUM OUTPUT —
⭐     ⭐ constrained, cheap, and separately evaluable.

⭐ ④ ⭐⭐ ***ORCHESTRATOR + PARALLEL WORKERS.*** ⭐ The genuinely
⭐   strong case, and the ***only*** topology that improves
⭐   latency: ⭐ N independent read-only sub-tasks fan out with
⭐   `asyncio.gather`, ⭐⭐ SO WALL-CLOCK IS ONE SUB-AGENT, NOT N.
⭐   ⭐ Requires the sub-tasks to be genuinely independent —
⭐     ⭐⭐ IF WORKER B NEEDS WORKER A'S OUTPUT YOU HAVE A
⭐     PIPELINE, NOT A FAN-OUT, AND YOU JUST PAID FOR
⭐     COORDINATION YOU DID NOT USE.

⭐ ⑤ ***REFLECTION / CRITIC.*** ⭐ A second pass that critiques
⭐   the first. ⭐ Real gains on writing and code; ⭐⭐ ~2× THE
⭐   COST AND LATENCY, AND IT PLATEAUS AFTER ***ONE*** ROUND.
⭐   ⭐ Measure it — on extraction tasks it usually does nothing.

⭐ ⑥ ⭐⭐ ***AUTONOMOUS PEER-TO-PEER "TEAMS".*** ⭐ Agents freely
⭐   messaging each other until they agree. ⭐⭐ NON-TERMINATING
⭐   BY CONSTRUCTION, COST UNBOUNDED, TRAJECTORY UNDEBUGGABLE,
⭐   AND NO EVAL CAN ATTRIBUTE A FAILURE. ⭐ Demos beautifully.
⭐   ⭐ ⭐⭐ DO NOT SHIP IT.

⭐⭐ THE RULE UNDER ALL SIX: ⭐ ***USE THE MODEL FOR DECISIONS,
⭐   NOT FOR PLUMBING.*** ⭐ Every arrow you can make
⭐   deterministic, make deterministic — ⭐⭐ IT IS CHEAPER,
⭐   FASTER, TESTABLE, AND IT CANNOT HALLUCINATE A ROUTE.
```

# Part 4 — The cost, which multiplies quietly

```
⭐ ***EACH AGENT CARRIES ITS OWN BASE COST EVERY STEP:***
⭐   ⭐ its system prompt (~800 tokens)
⭐   ⭐ its tool schemas (~1,200 tokens)
⭐   ⭐ its own growing transcript (Day 439's quadratic term)

⭐ ***A 3-AGENT RUN, 5 STEPS EACH:***
⭐   ⭐ 3 × (5 steps × ~2,000 base) = 30,000 tokens of ***pure
⭐     overhead***, before a single useful token.
⭐   ⭐ plus the orchestrator's own loop,
⭐   ⭐ plus ⭐⭐ EVERY HANDOFF IS WRITTEN BY ONE MODEL AND READ
⭐     BY ANOTHER — ⭐ you pay output tokens ***and*** input
⭐     tokens for the same words.

⭐⭐ RULE OF THUMB: ⭐ ***MULTI-AGENT IS 3–10× THE COST OF A
⭐   SINGLE AGENT FOR THE SAME TASK.*** ⭐ It is worth it when
⭐   ① the context isolation is load-bearing, or ④ the fan-out
⭐   is real. ⭐⭐ IT IS NEVER WORTH IT BECAUSE THE DIAGRAM LOOKS
⭐   BETTER.

⭐ ***THE ONE COST THAT GOES DOWN:*** ⭐ prompt caching works
⭐   ***per agent*** — each has a stable prefix — ⭐⭐ SO A
⭐   LONG-LIVED SUB-AGENT WITH A FIXED SYSTEM PROMPT AND TOOLS
⭐   CACHES EXTREMELY WELL. ⭐ Design for stable prefixes and the
⭐   multiplier drops sharply.
```

# Part 5 — Failure, which is now distributed

```
⭐⭐ EVERY STAGE 12 FAILURE MODE IS BACK, WITH WORSE
⭐   OBSERVABILITY.

⭐ ① ***PARTIAL FAILURE.*** ⭐ Worker 2 of 4 failed. ⭐ Does the
⭐   orchestrator proceed with three findings ⭐⭐ AND
⭐   CONFIDENTLY PRESENT AN INCOMPLETE ANSWER AS COMPLETE?
⭐   ⭐ ⇒ `coverage` on every result, and ⭐⭐ THE ORCHESTRATOR
⭐     MUST BE ***REQUIRED*** TO REPORT PARTIALITY (D440).

⭐ ② ***TIMEOUT PROPAGATION.*** ⭐ The orchestrator has 45s; a
⭐   worker must get ***less*** (Day 401). ⭐⭐ A WORKER THAT
⭐   OUTLIVES ITS ORCHESTRATOR IS SPENDING MONEY ON AN ANSWER
⭐   NOBODY WILL READ.

⭐ ③ ***THE CROSS-AGENT DOOM LOOP.*** ⭐ Worker A fails, the
⭐   orchestrator re-dispatches ***the same task*** to worker B.
⭐   ⭐⭐ DAY 440'S REPEAT DETECTION MUST WORK ACROSS AGENTS, ⭐
⭐   which is what `already_tried` is for.

⭐ ④ ***ERROR AMPLIFICATION.*** ⭐ Worker 1's hallucination
⭐   becomes worker 2's ***premise***. ⭐⭐ NOTHING DOWNSTREAM
⭐   QUESTIONS IT, BECAUSE IT ARRIVED AS ESTABLISHED CONTEXT.
⭐   ⭐ ⇒ findings carry ***sources and verbatim quotes***
⭐     (Day 424), so the final synthesis can be checked against
⭐     documents rather than against another model's prose.

⭐ ⑤ ⭐⭐ ***THE TRAJECTORY IS NOW A TREE.*** ⭐ "Why did it say
⭐   that?" spans four transcripts. ⭐⭐ ONE TRACE ID, PROPAGATED
⭐   THROUGH EVERY AGENT, OR YOU CANNOT DEBUG IT AT ALL (D 455).
```

# 💬 Interview

**1. "When do you use multiple agents?"**

⭐ When I'm buying one of four specific things, and I make myself name which. ⭐⭐ A separate context
window is the big one — a sub-agent can read forty documents, fill its own window, and hand back three
hundred tokens, so the orchestrator's transcript never grows and never gets distracted. ⭐ A separate
tool set, because selection degrades past about twenty tools, so five agents with six tools each
measurably beats one with thirty. ⭐ A separate model, which makes the cost cascade structural. ⭐ And a
separate eval, which is the most under-rated reason. ⭐⭐ What I'm explicitly *not* buying is
"collaboration" — they're the same model with different system prompts, so there's no second opinion,
just the same distribution sampled again under a different condition.

**2. "What does a handoff actually cost you?"**

⭐ It's an RPC with a hand-written wire format and no schema. ⭐⭐ The sub-agent doesn't have the
conversation, the user's correction from four turns ago, or the constraint that was mentioned in
passing — it has whatever I serialised into a string, and what's lost is lost silently. ⭐ So it inherits
every property of a network boundary: it can fail, hang, or return nonsense, there's no transaction
across it, and the third outcome is back — did it do the work and fail to report, or not do it? ⭐⭐ So
if it's worth being a separate agent it's worth a typed contract. ⭐ Mine carries `already_tried` so
doom loops don't cross agents, and `coverage` plus `unresolved`, because otherwise the orchestrator
can't tell "there is nothing" from "I gave up" and will confidently synthesise an answer from an empty
result.

**3. "Which topology do you actually use?"**

⭐ Usually one agent with six good tools, wrapped in a deterministic pipeline. ⭐⭐ Most things people
build as a crew of role-played agents should be ordinary function calls: extract, validate, enrich,
summarise. ⭐ That's a program — testable, debuggable, cheap, and structurally incapable of looping.
⭐ The one topology I reach for deliberately is orchestrator with parallel workers, because it's the only
one that *improves* latency: independent read-only sub-tasks fan out and wall-clock is one sub-agent
rather than N. ⭐⭐ The one I won't ship is autonomous peer-to-peer teams — non-terminating by
construction, unbounded cost, and no eval can attribute a failure. ⭐ It demos beautifully.

**4. "What does multi-agent cost?"**

⭐ Three to ten times a single agent for the same task. ⭐⭐ Each agent carries its own system prompt and
tool schemas on every step of its own loop, so a three-agent run with five steps each is around thirty
thousand tokens of pure overhead before a single useful token. ⭐ And every handoff is written by one
model and read by another, so you pay output tokens and input tokens for the same words. ⭐⭐ The one
thing that goes the other way is caching — each agent has a stable prefix, so a long-lived sub-agent
with fixed tools caches extremely well, and designing for stable prefixes drops the multiplier sharply.

**5. "How does failure differ from a single agent?"**

⭐ It's distributed failure with worse observability. ⭐ Partial failure is the main one: worker two of
four failed, and if the orchestrator just proceeds it presents an incomplete answer as complete — which
is why coverage is a required field and reporting partiality is enforced in my code, not requested in a
prompt. ⭐⭐ Then error amplification: worker one's hallucination becomes worker two's *premise*, and
nothing downstream questions it because it arrived as established context. ⭐ That's why findings carry
sources and verbatim quotes, so the final synthesis is checkable against documents rather than against
another model's prose. ⭐⭐ And the trajectory is now a tree, so "why did it say that" spans four
transcripts — one trace id propagated through every agent, or it's undebuggable.

**6. "Someone proposes a researcher, a writer and a critic. What do you say?"**

⭐ I'd ask what the researcher's context isolation is buying, and whether we've measured the single-agent
version it's replacing. ⭐⭐ Usually the honest answer is that it's three prompts and a for-loop with
job titles, at three times the cost. ⭐ The critic is the one piece I'd keep if it measures well —
reflection genuinely helps on writing and code, roughly doubles cost and latency, and plateaus after one
round, so it's a measurable trade rather than a philosophy. ⭐ On extraction tasks it usually does
nothing at all. ⭐⭐ The general rule I'd offer is: use the model for decisions, not for plumbing — every
arrow you can make deterministic is cheaper, faster, testable, and can't hallucinate a route.
