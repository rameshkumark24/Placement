# Part 1 — Why there is a build

Python ships source. The browser ships whatever you give it, so a build stage earns its place.

| ⭐ Job | Why |
|---|---|
| **Transform** | TS → JS, JSX → function calls. ⭐ The browser knows neither. |
| **Bundle** | ⭐ 400 modules = 400 requests without it. HTTP/2 helps and does not eliminate the cost. |
| **⭐⭐ Tree-shake** | Delete code nobody imports. **The main size lever.** |
| **Minify** | Shorten names, strip whitespace/comments. ⭐ ~40% before gzip. |
| **Hash filenames** | ⭐⭐ `app.9f2c1a.js` → cache **forever**, and a deploy invalidates by *changing the name*. Day 245. |
| **Split** | ⭐ Per-route chunks so the login page does not ship the dashboard. |

```
⭐⭐ DEV VS PROD ARE DIFFERENT PROGRAMS

⭐   dev   ⇒ no bundling (native ESM), source as written, HMR,
⭐           ⭐ fast start, huge and slow to load — irrelevant locally
⭐   prod  ⇒ bundled, tree-shaken, minified, hashed, split
⭐   ⇒ ⭐⭐ NEVER MEASURE PERFORMANCE IN DEV MODE. React alone is
⭐     several times slower there, and every "React is slow" claim
⭐     traces back to someone profiling a dev build.
```

# Part 2 — Modules and tree-shaking

```javascript
// ⭐ named exports — tree-shakeable
export function a() {}
export function b() {}
import { a } from "./x";        // ⭐⭐ b is DELETED from the bundle

// ⭐ default export — one per file
export default function Thing() {}
import Thing from "./Thing";
```

```
⭐⭐ THE THREE THINGS THAT DEFEAT TREE-SHAKING

⭐ ① import * as _ from "lodash"    ⇒ ⭐⭐ THE WHOLE LIBRARY SHIPS.
⭐    ✅ import debounce from "lodash/debounce"  (or write it)

⭐ ② ⭐ CommonJS deps (require/module.exports). ⭐⭐ CJS IS DYNAMIC,
⭐    so the bundler CANNOT PROVE an export is unused. It keeps it.
⭐    ⇒ prefer packages that ship ESM ("module"/"exports" in pkg.json)

⭐ ③ ⭐⭐ SIDE EFFECTS. If importing a module DOES something —
⭐    registers a polyfill, mutates a prototype — removing it would
⭐    change behaviour, so the bundler keeps it.
⭐    ⇒ "sideEffects": false in package.json is you PROMISING
⭐      it is safe to drop. ⭐ Lying there causes very confusing bugs.
```

> ⭐ **`import type { User } from "./types"`** — the `type` keyword guarantees the import vanishes at
> compile time and cannot accidentally pull a runtime module into the bundle.

# Part 3 — ⭐⭐ The leaked secret

```
⭐⭐ THIS IS THE ONE PEOPLE ACTUALLY SHIP.

⭐   .env
⭐     VITE_API_URL=https://api.example.com     ⭐ fine — public anyway
⭐     VITE_STRIPE_SECRET=sk_live_abc123        ⭐⭐ NOW PUBLIC. FOREVER.

⭐   ⇒ the bundler INLINES it as a literal string in app.js
⭐   ⇒ ⭐⭐ ANYONE CAN VIEW-SOURCE, Ctrl-F "sk_live", AND BILL YOU.
⭐   ⇒ ⭐ AND IT IS IN THE GIT HISTORY, AND IN EVERY CDN CACHE,
⭐     AND IN THE INTERNET ARCHIVE. ROTATION IS THE ONLY FIX.
```

| ⭐ Rule | |
|---|---|
| **The prefix is a warning, not a guard** | ⭐⭐ `VITE_` / `NEXT_PUBLIC_` exists to make you *say* "this is public". It does not protect anything — it **exposes**. |
| **A frontend has no secrets** | ⭐ Publishable keys yes (`pk_live_`), secret keys never. If it must stay secret, **the call belongs on your server** (Day 236). |
| **Minification ≠ security** | ⭐⭐ Renaming variables is not encryption. Anyone can prettify your bundle in one click. |
| **Grep before deploy** | ⭐ `grep -rE "sk_live|secret|BEGIN PRIVATE" dist/` in CI. It costs nothing and it has caught real incidents. |

```javascript
// ❌ the shape that leaks
const res = await fetch("https://api.openai.com/v1/...", {
  headers: { Authorization: `Bearer ${import.meta.env.VITE_OPENAI_KEY}` }
});   // ⭐⭐ your key, in the browser, on every visitor's machine

// ✅ your own server holds the key and enforces the limits
const res = await api("/ai/summarise", { method: "POST", body: { text } });
//    ⭐ and THAT endpoint checks auth, rate-limits, and caps spend (Day 458)
```

> ⭐⭐ **This is the "huge surprise bill" failure from the repo README, in its exact form.** A key in a
> bundle is scraped by bots within hours. **The fix is architectural, not a config flag: the browser
> calls *your* API, and your API holds the credential.**

# Part 4 — Source maps, and the debugging trade

| ⭐ Option | Effect |
|---|---|
| **No source maps** | Stack traces read `a.js:1:48211`. ⭐ Undebuggable in production. |
| **⭐⭐ Public source maps** | Readable traces for you *and* readable source for everyone. **Fine for most apps** — your bundle was already readable. |
| **⭐ Upload to Sentry, don't serve** | Best of both: readable traces in your tooling, no `.map` files on the CDN. **The default you want** (Day 279). |

> ⭐ **Source maps do not leak secrets that were not already leaked.** The bundle contains everything;
> the map only makes it pleasant to read. **If a source map would expose something, you had already
> exposed it.** Worth saying, because "we can't ship source maps, security" is a common confusion that
> costs teams their production debugging.

```
⭐⭐ THE BUNDLE BUDGET — set it before you need it
⭐   initial JS  < 150–200 KB gzipped   ⭐ beyond this, mobile hurts
⭐   ⇒ ⭐ CI FAILS THE BUILD when the budget is exceeded, so growth
⭐     is a decision someone made rather than a slow drift nobody saw.
```

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "what actually ships in your frontend build, and what can't?"**

Start with the rule, because it reframes the whole question. **Everything in the build is public. The
bundle is downloadable by anyone, minification isn't obfuscation and obfuscation isn't secrecy — so any
value that reaches the build is a value I've published. The only question is whether I meant to.**

Make it concrete with the failure. **The one people actually ship is a secret key in an env var. The
bundler inlines it as a literal string, so it's view-source and Ctrl-F away, and it's simultaneously in
git history, every CDN cache and probably an archive — rotation is the only fix, there's no unpublish.
The `VITE_` prefix isn't a guard, it's a warning label that means "this will be exposed."**

Then the architectural fix, which is the part that shows seniority. **A frontend has no secrets.
Publishable keys yes, secret keys never. If a call needs a credential, the browser calls my API and my
API holds it — which also gives me the place to enforce auth, rate limits and a spend cap. That's the
same fix as the surprise-bill failure.**

Close on the thing people get backwards. **Source maps. They don't leak anything the bundle didn't
already contain — they just make it readable. Teams give up production debugging over that
misunderstanding. I upload them to Sentry rather than serving them, which gets readable traces without
putting map files on the CDN.**
