# Part 1 — ⭐⭐ The six answers

⭐ **Record each of these. Two minutes. No notes. Play them back.** The exit gate is not "do you
know this" — it is **"can you say it under mild pressure without hedging."**

```
⭐⭐ 1. "EXPLAIN THE GIL."                                        (Day 065)
⭐   · one mutex per interpreter; a thread must hold it to run bytecode
⭐   · ⭐⭐ WHY: reference counting is not atomic; making it atomic costs ~2× single-threaded
⭐   · ⭐⭐ correct BOTH misconceptions unprompted: threads are excellent for I/O because
⭐     it is released during syscalls; and it does NOT make your code thread-safe,
⭐     because it guarantees one BYTECODE, not one statement
⭐   · ⇒ processes for CPU, threads or asyncio for waiting

⭐⭐ 2. "WHAT IS THE DATA MODEL?"                                  (Days 031, 032)
⭐   · syntax is dispatch to dunders — len(), [], +, with, for, and attribute access
⭐   · ⇒ ⭐⭐ you IMPLEMENT protocols, you do not INHERIT to be list-like
⭐   · ⭐ attribute access is itself a protocol ⇒ an innocuous-looking read can run SQL

⭐⭐ 3. "WHAT IS THE EVENT LOOP?"                                  (Days 070, 072)
⭐   · one thread, a ready queue, and a blocking select() call
⭐   · ⭐⭐ await is a SUSPENSION POINT, not a wait — and does NOT create concurrency;
⭐     gather/create_task/TaskGroup do
⭐   · ⇒ ⭐⭐ a blocking call is a FULL STOP for every connection the worker owns

⭐⭐ 4. "WHY IS PYTHON SLOW, AND DOES IT MATTER?"                   (Days 023, 028, 073)
⭐   · a per-operation tax: dispatch, type lookup, allocation, refcounting, pointer chasing
⭐   · ⇒ do FEWER operations, do not make each faster
⭐   · ⭐⭐ and the honest part: in every backend you profile, the time is in a query,
⭐     an N+1, or a round trip — not the interpreter

⭐⭐ 5. "HOW DO YOU HANDLE ERRORS?"                                (Days 059, 060)
⭐   · expected errors are domain facts with a defined response; unexpected ones are bugs
⭐     that must crash, log with a traceback, and alert
⭐   · ⭐ one handler per entry point; translate at layer boundaries with `from`
⭐   · ⭐⭐ log once, at the boundary; every network call has a timeout

⭐⭐ 6. "WHERE DOES VALIDATION BELONG?"                            (Days 057, 062)
⭐   · ⭐⭐ Pydantic at the edge, dataclasses inside; validate once, trust afterwards
⭐   · ⭐ mypy checks your BELIEFS about incoming data, never the data
⭐   · ⇒ types inside, validation at the boundary, tests for the logic
```
