# Part 3 — The three patterns in this mock

```
⭐ ① ⭐⭐ ***HASHING — TRADE SPACE FOR TIME.***
⭐   ⭐ The trigger: ⭐⭐ "HAVE I SEEN…?" INSIDE A LOOP.
⭐   ⭐ Two-sum, group anagrams, longest consecutive sequence,
⭐     subarray-sum-equals-k (⭐ prefix sums in a dict).
⭐   ⭐ ⭐⭐ THE INSIGHT IS ALWAYS THE SAME: ⭐ an inner scan
⭐     becomes a lookup, so n² becomes n.

⭐ ② ⭐⭐ ***TWO POINTERS — EXPLOIT ORDER.***
⭐   ⭐ The trigger: ⭐⭐ THE INPUT IS SORTED, OR SORTING IS FREE
⭐     BECAUSE YOU ARE ALREADY PAYING n log n.
⭐   ⭐ Opposite ends (two-sum-sorted, container with most water,
⭐     ⭐ 3-sum) · same direction (remove duplicates, ⭐ Dutch
⭐     national flag).
⭐   ⭐ ⭐⭐ THE PROOF OBLIGATION: ⭐ why is it safe to move a
⭐     pointer? ⭐⭐ "MOVING THE SMALLER ONE CANNOT LOSE A BETTER
⭐     ANSWER, BECAUSE…" ⭐ Say that sentence — it is the
⭐     difference between remembering and understanding.

⭐ ③ ⭐⭐ ***SLIDING WINDOW — A CONTIGUOUS RANGE WITH A
⭐   CONSTRAINT.***
⭐   ⭐ The trigger: ***"longest/shortest subarray such that…"***
⭐   ⭐ ⭐⭐ THE TEMPLATE IS ALWAYS: ⭐ expand right, ⭐ shrink left
⭐     ***while*** the window is invalid, ⭐ record.
⭐   ⭐ ⭐⭐ THE ONLY HARD PART IS WHAT "INVALID" MEANS ⭐ and what
⭐     state you carry — a count, a `Counter`, a max.
```

# Part 4 — The mock: four problems, 45 minutes

```
⭐ ⭐⭐ RUN THESE UNDER TIMER, IN ORDER, WITHOUT LOOKING AHEAD.
⭐   ⭐ P1 and P2 are the round; P3 and P4 are the follow-ups an
⭐     interviewer adds if you finish early.

⭐ ***P1 (10 min) — GROUP ANAGRAMS.*** ⭐ Given a list of strings,
⭐   group the anagrams.
⭐ ***P2 (20 min) — LONGEST SUBSTRING WITHOUT REPEATING
⭐   CHARACTERS.*** ⭐ Then: ⭐⭐ "NOW ALLOW AT MOST k REPEATS."
⭐ ***P3 (10 min) — SUBARRAY SUM EQUALS K.*** ⭐ Count subarrays
⭐   summing to k. ⭐⭐ NEGATIVES ALLOWED — WHICH KILLS THE
⭐   SLIDING WINDOW AND IS THE WHOLE POINT.
⭐ ***P4 (5 min) — LONGEST CONSECUTIVE SEQUENCE*** in O(n).
```

```python
# ⭐ P1 — the whole solution is choosing the key.
from collections import defaultdict

def group_anagrams(words: list[str]) -> list[list[str]]:
    groups = defaultdict(list)
    for w in words:
        # ⭐ sorted() → O(k log k) per word. Fine, and obvious.
        # ⭐⭐ THE ALTERNATIVE WORTH MENTIONING: a 26-tuple of
        # counts is O(k) per word and a better key for long
        # strings — say this out loud even if you use sorted().
        groups["".join(sorted(w))].append(w)
    return list(groups.values())
# ⭐ O(n·k log k) time, O(n·k) space.
```

```python
# ⭐ P2 — the sliding-window template, in its purest form.
def longest_unique(s: str) -> int:
    last = {}          # ⭐ char -> most recent index
    best = left = 0
    for right, ch in enumerate(s):
        # ⭐⭐ THE SUBTLETY: only move left FORWARD. `max` is not
        # decoration — without it a stale index drags left back
        # and the window becomes invalid. This is the bug.
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best
# ⭐ O(n) time, O(min(n, alphabet)) space.

# ⭐⭐ THE FOLLOW-UP — "at most k repeats" — CHANGES THE STATE,
# NOT THE TEMPLATE. That is the point of the template.
from collections import Counter

def longest_with_k_repeats(s: str, k: int) -> int:
    count = Counter()
    best = left = 0
    for right, ch in enumerate(s):
        count[ch] += 1
        while count[ch] > k:            # ⭐ window invalid
            count[s[left]] -= 1
            left += 1
        best = max(best, right - left + 1)
    return best
```

```python
# ⭐⭐ P3 — THE ONE THAT SEPARATES PEOPLE.
def subarray_sum(nums: list[int], k: int) -> int:
    # ⭐⭐ WHY NOT A SLIDING WINDOW? Negatives. Extending the
    # window can DECREASE the sum, so "too big → shrink" is not
    # a valid rule. SAY THIS OUT LOUD — it is the insight.
    # ⭐ Instead: sum(i..j) == prefix[j] - prefix[i-1], so we
    # need prefix[i-1] == prefix[j] - k. That is a LOOKUP.
    seen = {0: 1}                       # ⭐ empty prefix, once
    total = running = 0
    for x in nums:
        running += x
        total += seen.get(running - k, 0)
        seen[running] = seen.get(running, 0) + 1
    return total
# ⭐ O(n) / O(n). ⭐⭐ SAME SHAPE AS TWO-SUM: "have I seen…?"
```

```python
# ⭐ P4 — the O(n) trick is knowing where to START a run.
def longest_consecutive(nums: list[int]) -> int:
    s = set(nums)
    best = 0
    for x in s:
        if x - 1 in s:      # ⭐⭐ NOT A SEQUENCE START — SKIP.
            continue        # ⭐ This line is what makes it O(n):
                            # each element is walked at most once.
        length = 1
        while x + length in s:
            length += 1
        best = max(best, length)
    return best
# ⭐ O(n) — and be ready to DEFEND that, because it looks
# ⭐⭐ QUADRATIC UNTIL YOU EXPLAIN THE `continue`.
```

# 💬 Interview

**1. "Walk me through your approach before you code."**

⭐ For the longest-unique-substring: the brute force is every substring checked for duplicates, which is
O(n³) or O(n²) with a set — ⭐⭐ I'd name that and not write it. ⭐ The observation is that when I hit a
repeat, the window's left edge can jump straight past the previous occurrence rather than sliding one at
a time. ⭐⭐ So one pass, a dict from character to its most recent index, and it's O(n) time with space
bounded by the alphabet. ⭐ One subtlety I'd flag before coding: `left` must only ever move forward, so
it's `max(left, last[ch] + 1)` — otherwise a stale index drags the window backwards and it silently
becomes invalid. ⭐⭐ That's the bug in this problem, and saying it up front is cheaper than finding it
in testing.

**2. "Why doesn't a sliding window work for subarray-sum-equals-k?"**

⭐ Negatives. ⭐⭐ A sliding window needs the invariant that extending the window is monotone — that
adding an element can only increase the sum, so "too big, shrink from the left" is a valid rule. ⭐ With
negative numbers, extending can *decrease* the sum, so shrinking is no longer justified and you can miss
answers. ⭐⭐ The right frame is prefix sums: the sum from i to j is `prefix[j] - prefix[i-1]`, so I need
`prefix[i-1] == prefix[j] - k`, which is a lookup. ⭐ That makes it the same shape as two-sum — "have I
seen this value?" — and it's O(n) with a dict.

**3. "Your longest-consecutive solution looks O(n²)."**

⭐ It looks it, and it isn't, because of one line. ⭐⭐ I only start walking a run when `x - 1` is not in
the set — so each element is only ever visited as part of exactly one run, and the total inner work
across all iterations is bounded by n. ⭐ Without that `continue`, walking from every element would
genuinely be quadratic. ⭐⭐ It's worth being able to defend that out loud, because "it's O(n), trust me"
is not an argument and an interviewer will push on it.

**4. "What Python-specific mistakes do you watch for?"**

⭐ Four, and all four change complexity or correctness silently. ⭐⭐ Slicing copies, so `arr[i:j]` is
O(k) and a slice inside a loop is a hidden O(n²). ⭐ String concatenation in a loop is O(n²) because
strings are immutable — build a list and join. ⭐ `list.pop(0)` is O(n), which is the most common
accidental quadratic in Python interviews, so it's `deque` for a queue. ⭐⭐ And `[[0] * n] * m` creates
m references to one row, so writing to one cell writes to every row — that one has probably cost more
interviews than any algorithm. ⭐ It's `[[0] * n for _ in range(m)]`.

**5. "You finished early. Make it harder."**

⭐ Good — I'd rather they extend it than move on. ⭐⭐ For longest-unique, the natural extension is "at
most k repeats", and the useful thing is that it changes the *state*, not the template: expand right,
shrink left while invalid, record. ⭐ The window state goes from a last-seen dict to a `Counter`, and
"invalid" goes from "seen before" to "count exceeds k". ⭐⭐ That's the point of having a template —
follow-ups stop being new problems and become a question about what invariant I'm maintaining.

## 🎙️ Articulation drill

⭐⭐ **Two minutes, out loud: the first five minutes of a problem, done properly.**

Restate, then clarify with questions that matter. **"So: given a string, find the length of the longest
substring with no repeated characters. Before I start — is the alphabet bounded, ASCII or full Unicode?
Can I assume it fits in memory? And should I return the length or the substring itself?"** Three
questions, all of which change something.

Then work an example aloud. **"Take 'abcabcbb'. At index 3 I hit 'a' again, and the window was 'abc'.
The new window should start just after the previous 'a', so 'bca'. That tells me I need the *index* of
the last occurrence, not just whether I've seen it."** That's the insight, discovered on a concrete case
rather than asserted.

Then state the approach and complexity before touching the keyboard. **"Brute force is every substring
checked for duplicates — O(n²) with a set, and I won't write it. Instead: one pass, a dict from
character to last index, and when I see a repeat I jump the left edge past it. O(n) time, O(min(n,
alphabet)) space. One thing I want to flag before I code it: the left edge must only move forward, so
it's a max against the current left — otherwise a stale index drags the window backwards. That's the bug
in this problem."** Then pause and let them nod.

Close by naming what you'd do at the end. **"When I've got it working I'll walk it by hand on
'abcabcbb', then check empty string, single character, and all-identical — those are the three that
break window code."**
