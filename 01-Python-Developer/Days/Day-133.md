# Day 133

**L-133** · **Application structure** — `APIRouter`, settings, lifespan, and ⭐⭐ escaping the 2,000-line `main.py`

**Time:** 3 hrs · **Mode:** NEW

> ⭐⭐ **The sentence to own: FastAPI gives you no structure, so the structure is your decision — and
> the one that matters is not the folder layout, it is that the domain layer never imports FastAPI,
> because that single rule is what keeps your business rules testable, reusable and portable.**
>
> ⭐ Day 090 gave you layering in the abstract. **Today is what it looks like in a real FastAPI
> project**, including the three things that are always tangled: settings, the app object, and the
> database session.

# Part 1 — ⭐ The layout

```
src/myapp/
├── main.py                 ⭐ ~30 lines: create the app, mount routers, done
├── config.py               ⭐⭐ Settings, built ONCE
├── api/
│   ├── deps.py             ⭐ shared dependencies + Annotated aliases (Day 132)
│   ├── errors.py           ⭐ exception handlers, one error shape (Day 120)
│   └── v1/
│       ├── orders.py       ⭐ APIRouter — routes ONLY
│       └── users.py
├── schemas/orders.py       ⭐ Pydantic in/out models (Day 131)
├── services/orders.py      ⭐⭐ the DOMAIN — no FastAPI import, ever
├── repositories/orders.py  ⭐ SQLAlchemy lives here and nowhere else
├── models/orders.py        ⭐ ORM models
└── core/                   ⭐ security, logging, clock
tests/
alembic/
```

```
⭐⭐ THE ONE RULE THAT MAKES THE LAYOUT WORTH HAVING (Day 090):
⭐        api/ ──▶ services/ ──▶ repositories/ ──▶ models/
⭐   ⇒ ⭐⭐ ARROWS POINT ONE WAY. `services/` MUST NOT IMPORT `fastapi`, AND
⭐        MUST NOT IMPORT ANYTHING FROM `api/`.
⭐   ⇒ ⭐ THE TEST IS MECHANICAL AND WORTH AUTOMATING:
⭐        `grep -r "^from fastapi" src/myapp/services/` should return NOTHING,
⭐        and ⭐⭐ ruff's banned-api or import-linter (Day 090) makes it a CI
⭐        failure rather than a convention.
⭐   ⇒ ⭐⭐ WHY IT PAYS, CONCRETELY: the same `place_order` runs from an HTTP
⭐        route, a Celery task, a management command and a test — ⭐ and the
⭐        domain tests need no client, no session fixture and no event loop.
```

⭐ **By feature or by type?** ⭐⭐ The layout above is by type, which is honest below ten modules
(Day 090). **Past that, `orders/` containing `router.py`, `service.py`, `repo.py` and `schemas.py`
scales better** — because "add a field to an order" then touches one directory rather than four piles.

# Part 2 — ⭐⭐ Settings, built once

```python
# config.py
from pydantic_settings import BaseSettings, SettingsConfigDict
from functools import lru_cache

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_",
                                      extra="forbid")          # ⭐⭐ typo in .env ⇒ boot failure

    database_url: PostgresDsn
    redis_url: RedisDsn
    secret_key: SecretStr                                       # ⭐⭐ repr is '**********'
    jwt_algorithm: str = "HS256"
    access_token_ttl: int = 900
    environment: Literal["dev", "staging", "prod"] = "dev"      # ⭐ a closed set (Day 058)

@lru_cache                                                       # ⭐ built once per process
def get_settings() -> Settings:
    return Settings()                                            # ⭐⭐ raises if anything is missing
```

```
⭐⭐ FOUR THINGS THIS BUYS OVER `os.environ` (Day 090):
⭐  1. ⭐⭐ IT FAILS AT STARTUP. A missing `APP_DATABASE_URL` raises when the app
⭐       is created — ⭐ not at 3 a.m. on the one endpoint that uses it.
⭐  2. ⭐ TYPES. `access_token_ttl` is an `int`, not the string `"900"`, so
⭐       nobody writes `int(os.environ[...])` in five places.
⭐  3. ⭐⭐ `SecretStr` KEEPS SECRETS OUT OF REPRS AND TRACEBACKS (Days 099A, 120)
⭐       — ⭐ you must call `.get_secret_value()` deliberately, which is also a
⭐       greppable audit point.
⭐  4. ⭐⭐ `extra="forbid"` MAKES A TYPO IN `.env` A BOOT FAILURE rather than a
⭐       silently-ignored line and a default nobody noticed.
⭐
⭐ ⚠️ ⭐⭐ AND THE ONE TO GET RIGHT: MAKE `get_settings` A **DEPENDENCY**, NOT A
⭐    MODULE-LEVEL `settings = Settings()`.
⭐    ⇒ ⭐ a module-level instance is constructed at IMPORT time ⇒ ⭐⭐ your test
⭐         suite cannot even COLLECT without a full environment (Day 074), and
⭐         you cannot override it per test (Day 132).
```

# Part 3 — ⭐ Routers, and the app factory

```python
# api/v1/orders.py — ROUTES ONLY
router = APIRouter(prefix="/orders", tags=["orders"],
                   dependencies=[Depends(require("orders:read"))])   # ⭐ Day 132

@router.post("", response_model=OrderOut, status_code=201)
async def create_order(payload: OrderCreate, db: DB, user: CurrentUser):
    order = await services.orders.place(db, user, payload.sku, payload.qty)   # ⭐⭐ plain args
    return order
```

```python
# main.py — thirty lines
def create_app(settings: Settings | None = None) -> FastAPI:     # ⭐⭐ AN APP FACTORY
    settings = settings or get_settings()
    app = FastAPI(title="Orders API", lifespan=lifespan,
                  docs_url="/docs" if settings.environment != "prod" else None)
    register_error_handlers(app)                                  # ⭐ Day 120
    app.add_middleware(RequestIdMiddleware)                        # ⭐ Day 099A
    app.include_router(v1_router, prefix="/v1")                    # ⭐ Day 125
    return app

app = create_app()
```

```
⭐⭐ WHY A FACTORY RATHER THAN A MODULE-LEVEL `app = FastAPI()`:
⭐   · ⭐⭐ TESTS CAN BUILD AN APP WITH TEST SETTINGS, and build a FRESH one per
⭐        test module — ⭐ no shared mutable app object accumulating overrides
⭐        (Day 132's leak).
⭐   · ⭐ you can run two configurations in one process (a worker app, an
⭐        admin app).
⭐   · ⭐⭐ NOTHING HAPPENS AT IMPORT TIME, which is Day 074's rule: importing a
⭐        module should not open connections or read the environment.
⭐   ⇒ ⭐ note `docs_url=None` in production — ⭐⭐ not a security control on its
⭐        own (the endpoints are still there), but there is no reason to publish
⭐        a browsable map of your API to the internet.
```

⭐ **The route handler is three lines**: resolve dependencies, call the service, return. ⭐⭐ **If a
handler is thirty lines, business logic has leaked into the HTTP layer** — and that logic is now
untestable without a client and unusable from a worker.

# Part 4 — ⭐⭐ Lifespan

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    settings = get_settings()
    app.state.engine = create_async_engine(str(settings.database_url),
                                           pool_size=10, max_overflow=5)
    app.state.redis = await redis.from_url(str(settings.redis_url))
    await check_migrations_current(app.state.engine)          # ⭐⭐ fail fast — see below
    yield                                                      # ⭐⭐ the app serves here
    await app.state.redis.aclose()
    await app.state.engine.dispose()                           # ⭐ drain (Day 081)
```

```
⭐⭐ THIS IS DAY 110'S LIFESPAN SCOPE, AND IT MATTERS FOR THREE REASONS:
⭐  1. ⭐⭐ POOLS ARE CREATED **PER WORKER, AFTER THE FORK** (Day 111). A pool
⭐       built at import time under `--preload` is SHARED BY EVERY WORKER, which
⭐       gives interleaved protocol traffic on one socket and corrupt results.
⭐       ⭐ Lifespan is per-worker by construction, which is why it is the clean
⭐       answer.
⭐  2. ⭐⭐ FAIL FAST. A bad `DATABASE_URL`, or a schema older than the code,
⭐       kills STARTUP — ⭐ so a broken deploy never becomes ready and the
⭐       rollout halts, instead of serving 500s (Day 111's readiness).
⭐  3. ⭐ GRACEFUL SHUTDOWN has somewhere to attach (Day 081): on SIGTERM,
⭐       uvicorn stops accepting, drains in-flight requests, then runs the code
⭐       after `yield`.
⭐
⭐ ⚠️ ⭐ AND THE POOL ARITHMETIC FROM DAY 111, WHICH BITES HERE:
⭐    `pool_size × workers × pods` must stay under Postgres's `max_connections`.
⭐    ⭐⭐ 10 × 4 × 5 = 200 connections from one service, and the default limit
⭐    is 100. ⭐ That failure presents as "the database is down".
```

# Part 5 — ⭐ The seams worth having

```python
# api/deps.py — ⭐ every Annotated alias, in one place
Settings_ = Annotated[Settings, Depends(get_settings)]
DB        = Annotated[AsyncSession, Depends(get_db)]
CurrentUser = Annotated[User, Depends(current_user)]
Clock     = Annotated[Callable[[], datetime], Depends(get_clock)]     # ⭐⭐ Day 096
```

```
⭐⭐ MAKE THESE FOUR THINGS DEPENDENCIES FROM DAY ONE, BECAUSE RETROFITTING THEM
⭐   MEANS TOUCHING EVERY CALL SITE:
⭐   · ⭐ THE DATABASE SESSION  ⇒ overridable in tests (Day 132)
⭐   · ⭐⭐ THE CLOCK           ⇒ ⭐⭐ Day 096's whole lesson. `datetime.now()`
⭐        called directly anywhere is a test you will have to freeze.
⭐   · ⭐ ANY OUTBOUND CLIENT   ⇒ the payment gateway, the mailer, the queue
⭐        (Day 095: mock the adapter you own, never their client)
⭐   · ⭐ SETTINGS              ⇒ per-test configuration without patching
⭐   ⇒ ⭐⭐ EACH ONE IS A SEAM, AND A SEAM YOU DID NOT BUILD ON DAY ONE IS A
⭐        REFACTOR LATER — ⭐ which in practice means it never happens and the
⭐        tests use `freezegun` and `patch` forever.
```

```
⭐ THE STARTUP CHECKLIST — every line is a day (Days 090, 099, 111, 112, 118):
⭐   □ ⭐ settings load, or the process dies with a clear message
⭐   □ ⭐⭐ every route declares a permission (PUBLIC explicitly)   ⇒ Day 118
⭐   □ ⭐ no route is unreachable behind another                    ⇒ Day 112
⭐   □ ⭐⭐ the database schema matches the code's expected revision ⇒ Part 4
⭐   □ ⭐ `docs_url` off in production; debug off                   ⇒ Day 128
⭐   □ ⭐ log the version, the git SHA and the settings — ⭐⭐ REDACTED
⭐   ⇒ ⭐⭐ ALL OF THESE ARE CHEAP, AND EACH CONVERTS A 3 A.M. MYSTERY INTO A
⭐        BOOT FAILURE. ⭐ That is the whole argument for startup validation.
```

## Common mistakes

| Mistake | Correction |
|---|---|
| ⭐⭐ **Everything in `main.py`** | ⭐ Routers by resource; `main.py` is thirty lines. |
| ⭐⭐ **`services/` importing `fastapi`** | ⭐⭐ The domain is now unusable from a worker or a test. Enforce in CI. |
| A thirty-line route handler | ⭐ Business logic has leaked into the HTTP layer. |
| ⭐ `settings = Settings()` at module level | ⭐⭐ Constructed at import ⇒ tests cannot collect, and cannot override. |
| ⭐ `os.environ` in a function | ⭐ Untestable, invisible, fails at request time (Day 090). |
| ⭐ Plain `str` for a secret | ⭐⭐ `SecretStr` — it appears in reprs and tracebacks otherwise. |
| No `extra="forbid"` on settings | ⭐ A typo in `.env` is silently ignored. |
| ⭐⭐ **A pool created at import time** | ⭐⭐ Shared across forked workers ⇒ corrupt results. Use lifespan. |
| Ignoring `pool × workers × pods` | ⭐ Presents as "the database is down". |
| ⭐ `datetime.now()` called directly | ⭐⭐ A seam you did not build; now every test needs freezing. |
| ⭐ `docs` exposed in production | ⭐ A browsable map of your API. |
| No app factory | ⭐ Shared mutable app across tests; overrides leak. |

## Interview questions

**Q: How do you structure a FastAPI project?**
> Routers by resource under `api/`, Pydantic schemas separate from ORM models, a services layer for
> the domain, repositories for persistence, and a `main.py` of about thirty lines that creates the app
> and mounts routers. But the folder layout is the least interesting part — the rule that matters is
> that `services/` never imports FastAPI and never imports from `api/`. That one constraint is what
> lets the same `place_order` run from an HTTP route, a Celery task, a management command and a test,
> and it means the domain tests need no client and no event loop. I'd enforce it in CI with
> import-linter rather than leave it as a convention, because a convention lasts until the first
> deadline.

**Q: How do you handle configuration?**
> `pydantic-settings`, built once, exposed as a dependency rather than a module-level instance. It
> gives me four things over `os.environ`: it fails at startup rather than at 3 a.m. on the one endpoint
> that needs the missing variable; the values are typed, so nobody writes `int(os.environ[...])` in
> five places; `SecretStr` keeps secrets out of reprs and tracebacks; and `extra="forbid"` makes a typo
> in `.env` a boot failure instead of a silently-ignored line. A dependency rather than a module-level
> instance because a module-level one is constructed at import time, so the test suite can't collect
> without a full environment and you can't override it per test.

**Q: Why an app factory?**
> So tests can build a fresh app with test settings per module rather than sharing one mutable object
> that accumulates dependency overrides. It also means nothing happens at import time — importing a
> module shouldn't open connections or read the environment — and you can run two configurations in
> one process if you need a separate admin or worker app.

**Q: Why does the connection pool belong in lifespan?**
> Three reasons. It's per-worker by construction, which matters because a pool created at import time
> under `--preload` is shared by every forked worker, and several processes writing to one socket gives
> you interleaved protocol traffic and corrupt results. It fails fast — a bad database URL or a schema
> older than the code kills startup, so a broken deploy never becomes ready and the rollout halts
> instead of serving 500s. And it gives graceful shutdown somewhere to attach, so on SIGTERM the
> connections drain rather than being severed.

**Q: What would you make a dependency on day one?**
> The database session, the clock, any outbound client, and settings. Each is a seam, and a seam you
> don't build on day one is a refactor later — which in practice means it never happens and the tests
> end up full of `freezegun` and `patch` forever. The clock is the one people skip: `datetime.now()`
> called directly anywhere is a test you'll have to freeze, whereas an injected clock makes the same
> test a variable you advance.

## 🎙️ Articulation drill

Record two minutes: **"How would you structure a FastAPI service?"**

than one rule: the services layer never imports FastAPI. Routes are thin — resolve dependencies, call
a service, return — and everything below takes ordinary arguments."**
