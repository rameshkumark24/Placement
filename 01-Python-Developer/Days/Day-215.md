# Part 1 — The subset

You are not learning all of JavaScript. You are learning the ~15% that appears in a React codebase.

```
⭐⭐ WRITE THESE, EVERY DAY
⭐   const / let ....... never var. const by default.
⭐   arrow functions ... x => x * 2
⭐   destructuring ..... const { id, name } = user
⭐   spread ............ { ...user, name: "new" }   [...items, x]
⭐   template literals . `Hello ${name}`
⭐   map/filter/reduce . the comprehension you already think in
⭐   optional chaining . user?.profile?.email
⭐   nullish coalescing  count ?? 0     ⭐⭐ NOT || — see Part 3
⭐   async / await ..... Day 216
⭐   modules ........... import / export

⭐⭐ REFUSE THESE, ALWAYS
⭐   var ............... function-scoped, hoisted, a bug generator
⭐   == ................ ⭐⭐ USE === . ALWAYS. NO EXCEPTIONS.
⭐   this in callbacks . arrow functions make it a non-issue
⭐   prototype fiddling  you are not writing a framework
⭐   with, eval ........ dead
```

| Python | JavaScript | ⭐ Note |
|---|---|---|
| `[x*2 for x in xs]` | `xs.map(x => x * 2)` | ⭐ Chained methods, not a comprehension. Reads worse nested — extract a named function. |
| `[x for x in xs if p(x)]` | `xs.filter(p)` | |
| `dict` | object literal or `Map` | ⭐⭐ Object keys are **strings only**. `Map` if keys are objects or you need real ordering/size. |
| `None` | `null` **and** `undefined` | ⭐⭐ Two of them. See Part 3 — this is the real one. |
| `f"{a}"` | `` `${a}` `` | |
| `def f(a, b=1)` | `function f(a, b = 1)` | ⭐ Defaults evaluate **per call** here — the Python mutable-default trap does *not* exist in JS. |
| `*args` / `**kwargs` | `...rest` / options object | ⭐ There are no keyword arguments. An options object is the idiom. |
| `import x from y` | `import { x } from "y"` | Named vs default exports — Day 222. |
| `class` | `class` | ⭐ Rarely used in React. Functions and closures dominate. |

# Part 2 — ⭐⭐ `null` vs `undefined`, which is the one that matters

Python has one absence. JavaScript has two, and your API is about to produce both.

```
⭐⭐ THE DISTINCTION, PRACTICALLY

⭐   undefined = ⭐ "this was never set"
⭐               a missing object property, a missing argument,
⭐               a function with no return
⭐   null      = ⭐ "this was deliberately set to nothing"
⭐               ⭐⭐ AND IT IS WHAT YOUR JSON API SENDS.

⭐   JSON.parse('{"a": null}').a    // null       ⭐ from the wire
⭐   JSON.parse('{}').a             // undefined  ⭐ absent key

⭐⭐ ⇒ A NULLABLE COLUMN IN POSTGRES ARRIVES AS null.
⭐   AN OMITTED FIELD ARRIVES AS undefined.
⭐   ⭐⭐ THESE ARE DIFFERENT BUGS AND YOUR UI RENDERS THEM DIFFERENTLY.
```

| ⭐ Check | Catches | Use when |
|---|---|---|
| `x == null` | ⭐⭐ **both** `null` and `undefined` | The **one** place `==` is correct. Idiomatic, deliberate. |
| `x === null` | only `null` | You care that the server explicitly sent null. |
| `x === undefined` | only `undefined` | You care that a key was absent. |
| `x ?? fallback` | ⭐⭐ both, and **only** both | Defaults. **This is the one you want.** |
| `x \|\| fallback` | ⭐ also `0`, `""`, `false`, `NaN` | ⚠️ Almost always a bug — see below. |

```python
# ⭐ Your FastAPI model
class Item(BaseModel):
    name: str
    count: int | None = None     # ⭐⭐ null on the wire
    note: str = ""               # ⭐ empty string, NOT null
```

```javascript
// ❌ THE BUG — a real one, and it ships constantly
const count = item.count || 1;      // ⭐⭐ count of 0 BECOMES 1

// ✅ correct
const count = item.count ?? 1;      // only null/undefined fall back
```

> ⭐⭐ **`||` treats `0` and `""` as absent.** Every "the quantity resets to 1" and "the empty note
> shows the placeholder forever" bug is this line. **Default with `??`, always.** The only reason to
> use `||` is when you genuinely want *falsy*, which is rarer than it looks.

# Part 3 — The three traps that survive every style guide

### ⭐⭐ ① Equality

```
⭐   0 == "0"        // true      ⭐⭐ COERCION
⭐   0 == ""         // true
⭐   null == undefined  // true   ⭐ the one useful case
⭐   NaN === NaN     // false     ⭐⭐ NOTHING equals NaN
⭐   [] == false     // true      ⭐ do not think about this

⭐⭐ RULE: === EVERYWHERE. == ONLY AS `x == null`.
⭐   Use Number.isNaN(x), never x === NaN.
```

### ⭐⭐ ② Objects and arrays compare by identity

```javascript
{ a: 1 } === { a: 1 }        // ⭐⭐ false. Always.
[1,2] === [1,2]              // false
```

> ⭐⭐ **This is not trivia — it is the engine of React's re-render behaviour (Day 232) and of the
> dependency-array bug on Day 226.** A new object literal every render is a *different* object, so
> anything comparing by identity sees a change that isn't one. Hold onto this.

### ⭐ ③ Mutation is everywhere and React hates it

```javascript
// ❌ mutates — React may not re-render, because the reference is unchanged
items.push(newItem);
user.name = "new";

// ✅ new reference every time
const next = [...items, newItem];
const updated = { ...user, name: "new" };
```

| ⭐ Mutates (avoid on state) | ✅ Returns new |
|---|---|
| `push`, `pop`, `splice`, `sort`, `reverse` | `[...arr, x]`, `slice`, `toSorted`, `toReversed`, `map`, `filter` |

> ⭐ `sort()` **and** `reverse()` mutate in place *and* return the array, which is how they sneak into
> "pure" code. `arr.sort()` on state is a genuine React bug. Use `toSorted()`, or `[...arr].sort()`.

# Part 4 — Equality of *shape*, and why `reduce` is usually wrong

```javascript
// ⭐ the four you actually use
const names   = users.map(u => u.name);
const active  = users.filter(u => u.isActive);
const found   = users.find(u => u.id === id);        // ⭐ first match or undefined
const anyLeft = users.some(u => u.isActive);         // ⭐ .every() for "all"

// ⭐⭐ grouping — reach for this instead of reduce
const byRole = Object.groupBy(users, u => u.role);
```

> ⭐ **`reduce` is legitimate for a running total and almost nothing else.** A `reduce` that builds an
> object is a `for...of` loop that has been made harder to read and impossible to debug with a
> breakpoint. Interviewers notice both ways: using it well, and using it to look clever.

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "you came from Python — what actually bit you in JavaScript?"**

Do not say "the weird equality stuff", which is what everyone says and demonstrates nothing. Lead with
the one that shipped a bug. **Two kinds of absence. A nullable Postgres column arrives as `null` and a
missing key arrives as `undefined`, and they're different bugs with different renders. I defaulted with
`||` like I would with `or` in Python, and a count of zero silently became one — `??` only falls back on
null and undefined, and it's the correct default operator.**

Then the one that explains a whole framework. **Objects compare by identity, so `{a:1} === {a:1}` is
false. That's not trivia — it's the engine of React's re-render behaviour and of the dependency-array
bug, and once I understood it, the framework stopped looking arbitrary.**

Close on discipline rather than cleverness. **Most of the language's reputation is features you can
just refuse to use — `var`, `==`, prototypes. The subset I write is small and boring on purpose. The
part I can't refuse is mutation: `sort` and `reverse` mutate in place and still return the array, so
they sneak into code that looks pure, and on React state that's a real bug.**
