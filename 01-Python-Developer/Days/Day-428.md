# Part 3 — ⭐⭐ The five proofs

> Day 379's rule, in a new domain: **demonstrations, not claims.** Each produces a number you can say
> out loud.

```
⭐⭐ ① ***THE EVAL SCORE, WITH ITS VARIANCE AND ITS DATE.***
⭐    ⭐ "87% on 42 cases, ±2% over three runs, measured
⭐      yesterday."
⭐    ⭐⭐ NOT "IT WORKS WELL". ⭐ And the variance matters: ⭐⭐ IT IS
⭐      WHAT MAKES THE NEXT COMPARISON MEANINGFUL.

⭐⭐ ② ***THE CHEAPER-MODEL NUMBER.*** ⭐ Run the same eval on a
⭐    model one tier down. ⭐⭐ THE PROOF IS TWO SCORES AND TWO
⭐    COSTS. ⭐ Either you save 10–30× (Day 421), ⭐ or you have
⭐    evidence that you genuinely need the expensive one —
⭐    ⭐⭐ AND BOTH OUTCOMES ARE A WIN, BECAUSE BOTH REPLACE A
⭐    GUESS.

⭐⭐ ③ ***THE HALLUCINATION RATE.*** ⭐ Percentage of outputs whose
⭐    supporting quote is not present in the source (Day 424).
⭐    ⭐⭐ A NUMBER, MEASURED DETERMINISTICALLY, WHERE MOST TEAMS
⭐    HAVE A FEELING.

⭐⭐ ④ ***THE ABSTENTION PROOF.*** ⭐ Feed it an input where the
⭐    answer genuinely is not present. ⭐⭐ SHOW IT ABSTAINS RATHER
⭐    THAN INVENTING. ⭐ Then remove the abstention path from the
⭐    schema and show it ***does*** invent (Day 424).
⭐    ⭐⭐ TWO RUNS, AND THE SECOND ONE IS THE ONE THAT TEACHES THE
⭐    TEAM.

⭐⭐ ⑤ ***THE REGRESSION PROOF.*** ⭐ Deliberately degrade the
⭐    prompt — delete a constraint — ⭐⭐ AND SHOW CI CATCHES IT.
⭐    ⭐ If your gate does not go red, ⭐⭐ YOUR GATE IS DECORATION
⭐    AND YOU HAVE JUST FOUND THAT OUT CHEAPLY.
```

## 🎙️ Articulation drill — the 13B close

**Three minutes.** Open with the framing that organises everything so far: **an LLM app is a
distributed system with a non-deterministic, expensive, untrusted component in the middle — so Stages
9 to 12 apply unchanged, plus four new problems: you can't unit-test it, instructions and data share a
channel, cost is per-request and user-controlled, and confidence tells you nothing.**

Then the seven shapes. **Everything follows from next-token prediction** — no memory, no lookup,
latency linear in output, fluency uncorrelated with correctness. **The token is the unit of
everything**, so you architect in tokens rather than documents. **Constrain at the sampler, not in the
prompt** — a prompt is a request, constrained decoding is a guarantee. **Make abstention possible or
you manufacture fabrication** — a required field on an absent value *forces* an invention, and you
caused it with a type annotation. **Schema-valid is not correct** — parsing is solved, truth isn't, and
the value is in business rules and the quote-in-source check, which are ordinary Python. **Split it
before you reword it** — a failing prompt doing five things becomes five separately testable, separately
modelled, separately cacheable prompts. **And a change you cannot measure is a change you cannot make**
— evals aren't a quality practice, they're the precondition for every optimisation in this stage.

Close on proof rather than claim: **86% against 88% at a twentieth of the cost, so we run the cheap
model on evidence. A measured hallucination rate of 0.4% because every value carries a quote we check
against the source. We removed the abstention path and watched it start inventing invoice numbers. And
we deleted a constraint and watched CI go red, which is how we know the gate isn't decoration.** Then
the honest summary: **none of that is prompting skill. It's that we built the feedback loop, which is
the only thing that makes the next six months of improvement possible.**
