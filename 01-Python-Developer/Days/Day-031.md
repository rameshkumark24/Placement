# Day 031

**L-031** · ⭐⭐ **The data model** — dunder methods as the whole language's interface

**Time:** 3 hrs · **Mode:** NEW

> ⭐⭐ **The sentence to own: Python's syntax is a dispatch table. Every operator, every built-in
> function and every statement form is defined as "call this dunder method on the object."**
>
> ⭐ Once you see that, the language stops being a list of features and becomes **one rule applied
> consistently** — and "make my class behave like a built-in" becomes a matter of implementing the
> right protocol rather than inheriting from anything.

---

# Part 1 — ⭐⭐ Syntax is dispatch

| ⭐ You write | ⭐⭐ Python calls |
|---|---|
| `len(x)` | `x.__len__()` |
| `x[k]` | `x.__getitem__(k)` |
| `x[k] = v` | `x.__setitem__(k, v)` |
| `del x[k]` | `x.__delitem__(k)` |
| `k in x` | `x.__contains__(k)` — ⭐ or falls back to iterating |
| `x + y` | `x.__add__(y)`, then ⭐ `y.__radd__(x)` |
| `x += y` | ⭐ `x.__iadd__(y)` if present, else `x = x + y` |
| `-x`, `abs(x)` | `__neg__`, `__abs__` |
| `x == y`, `x < y` | `__eq__`, `__lt__` (Day 029) |
| `str(x)`, `repr(x)` | `__str__`, `__repr__` |
| `f"{x:>10.2f}"` | ⭐ `x.__format__(">10.2f")` |
| `x()` | ⭐ `x.__call__()` |
| `for i in x` | ⭐⭐ `iter(x)` ⇒ `x.__iter__()`, then `__next__` |
| `with x:` | ⭐⭐ `x.__enter__()` / `x.__exit__(...)` |
| `x.y` | `__getattribute__`, then `__getattr__` (Day 032) |
| `bool(x)` | `__bool__`, else `__len__` |
| `hash(x)` | `__hash__` |
| `async with`, `async for` | ⭐ `__aenter__`/`__aexit__`, `__aiter__`/`__anext__` |

```
⭐⭐ THE CONSEQUENCE, AND IT IS THE WHOLE POINT OF THE DAY:
⭐   ⭐⭐ You do not INHERIT to be sequence-like. You IMPLEMENT the protocol.
⭐   ⇒ nothing checks isinstance(x, Sequence) before doing x[0] —
⭐     it just calls __getitem__ and works or raises.
⭐   ⇒ ⭐⭐ THIS IS DUCK TYPING GIVEN TEETH: the protocols are named, documented,
⭐        and every built-in and every library respects them.
```

# Part 2 — ⭐ `__repr__` vs `__str__` — the one to get right today

```python
class Point:
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self): return f"Point(x={self.x!r}, y={self.y!r})"   # ⭐⭐ for DEVELOPERS
    def __str__(self):  return f"({self.x}, {self.y})"                # ⭐ for USERS
```

```
⭐⭐ THE RULES:
⭐   __repr__ ⇒ UNAMBIGUOUS. Ideally valid Python that would recreate the object.
⭐             ⇒ ⭐⭐ used by the REPL, by the DEBUGGER, and INSIDE CONTAINERS
⭐   __str__  ⇒ readable. Used by print() and str(). ⭐ Falls back to __repr__ if absent.
⭐
⭐ ⇒ ⭐⭐ IF YOU IMPLEMENT ONLY ONE, IMPLEMENT __repr__ — you get both.
```

⚠️ ⭐⭐ **This is the highest-value-per-character method in Python.** `print(my_list)` calls
`__repr__` on the *elements*, not `__str__` — so a list of your objects prints as
`[<app.Point object at 0x7f...>, ...]` unless you defined it. **Every log line, every debugger
window, every test failure message is worse without it**, and `@dataclass` gives you a good one for
free.

⭐ **`!r` inside an f-string calls `repr`** — use it in log messages so `""` and `None` and `"None"`
are distinguishable.

# Part 3 — ⭐⭐ Building a class that behaves like a built-in

```python
class Vector:
    __slots__ = ("x", "y")                     # ⭐ Day 028
    def __init__(self, x, y): self.x, self.y = x, y

    def __repr__(self):  return f"Vector({self.x}, {self.y})"
    def __eq__(self, o): return isinstance(o, Vector) and (self.x, self.y) == (o.x, o.y)
    def __hash__(self):  return hash((self.x, self.y))          # ⭐⭐ Day 029's contract

    def __add__(self, o):  return Vector(self.x + o.x, self.y + o.y)
    def __mul__(self, k):  return Vector(self.x * k, self.y * k)     # ⭐ v * 3
    def __rmul__(self, k): return self * k                           # ⭐⭐ 3 * v — see below
    def __neg__(self):     return Vector(-self.x, -self.y)
    def __abs__(self):     return (self.x**2 + self.y**2) ** 0.5     # ⭐ abs(v) = length

    def __len__(self):     return 2
    def __iter__(self):    yield self.x; yield self.y   # ⭐⭐ now `x, y = v` UNPACKING WORKS
    def __getitem__(self, i): return (self.x, self.y)[i]
    def __bool__(self):    return bool(self.x or self.y)
    def __format__(self, spec): return f"({self.x:{spec}}, {self.y:{spec}})"
```

```python
v = Vector(1, 2)
v + Vector(3, 4)     # Vector(4, 6)
3 * v                # ⭐⭐ Vector(3, 6) — via __rmul__
x, y = v             # ⭐⭐ 1, 2 — because __iter__ exists
sorted({v, Vector(1,2)})    # ⭐ one element — __eq__ + __hash__ agree
f"{v:.2f}"           # (1.00, 2.00)
```

```
⭐⭐ REFLECTED OPERATORS — the bit people miss:
⭐   `3 * v`: Python first tries int.__mul__(3, v) ⇒ ⭐ NotImplemented (int knows nothing of Vector)
⭐   ⇒ ⭐⭐ THEN it tries v.__rmul__(3). That is why __rmul__ exists.
⭐   ⇒ ⭐ Return NotImplemented (not raise!) from __add__ for unknown types —
⭐     it tells Python to try the other side, and to raise a good TypeError if that fails too.
```

⭐ **`__iter__` earns its place twice:** it makes `for`, unpacking, `list()`, `tuple()`, `min`, `max`,
`sum` and `*args` splatting all work. **One method, a dozen behaviours** — that is what "protocol"
means in practice.

# Part 4 — ⭐⭐ Context managers and callables

```python
class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                     # ⭐⭐ THIS is what `as t` receives
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.t0
        # ⭐⭐ return True to SUPPRESS the exception; ⭐ return None/False to let it propagate
        return False

with Timer() as t: work()
print(t.elapsed)
```

```
⭐⭐ __exit__ RUNS ON EVERY PATH — normal return, exception, break, or an early return.
⭐   ⇒ ⭐⭐ which is exactly why `with` is the answer to Day 026's __del__ problem
⭐        and Day 008's CLOSE_WAIT.
⭐   ⇒ ⚠️ ⭐ returning a TRUTHY value from __exit__ SWALLOWS the exception —
⭐        an easy accident if you end __exit__ with something that returns a value.
```

```python
# ⭐ The generator form — usually the one you should write:
from contextlib import contextmanager
@contextmanager
def timer():
    t0 = time.perf_counter()
    try:
        yield                          # ⭐⭐ everything before yield is __enter__,
    finally:                           #     everything after is __exit__
        print(time.perf_counter() - t0)
# ⚠️ ⭐⭐ the `finally` is not optional — without it an exception skips your cleanup entirely.
```

```python
# ⭐ __call__ — an object that behaves like a function
class RateLimiter:
    def __init__(self, per_sec): self.per_sec = per_sec; self.last = 0
    def __call__(self, fn):                    # ⭐⭐ so the instance can be used as a DECORATOR
        ...
```

⭐⭐ **`__call__` is why "callable" is a protocol and not a type** — functions, classes, methods,
`functools.partial` objects and your own instances are all callable, and `callable(x)` just checks
for the method.

## Common mistakes

| Mistake | Correction |
|---|---|
| ⭐⭐ **No `__repr__`** | ⭐⭐ Every log, debugger and test failure gets worse. Define it. |
| Defining `__str__` only | ⭐ Containers and the REPL use `__repr__`. |
| Raising `TypeError` in `__add__` | ⭐⭐ Return `NotImplemented` so the reflected op gets a turn. |
| Forgetting `__rmul__` | ⭐ `3 * v` fails while `v * 3` works. |
| Returning something truthy from `__exit__` | ⭐⭐ Silently swallows exceptions. |
| `@contextmanager` without `try/finally` | ⭐⭐ Cleanup is skipped on exception. |
| Forgetting `__enter__` must `return self` | ⭐ `as x` binds `None`. |
| `__eq__` without `__hash__` | ⭐ Day 029 — the class becomes unhashable. |
| Inheriting from `list`/`dict` to customise | ⭐ Usually implement the protocol, or use `UserDict`. |
| Implementing every dunder | ⭐ Implement what your object genuinely *is*. |

## Interview questions

**Q: What is the Python data model?**
> The set of special methods that define what the language's syntax means for an object. `len(x)`
> calls `__len__`, `x[k]` calls `__getitem__`, `x + y` calls `__add__` then `y.__radd__`, `with`
> calls `__enter__` and `__exit__`, and iteration calls `__iter__` and `__next__`. The consequence is
> that being sequence-like or context-manager-like is about implementing a protocol, not inheriting
> from a base class — nothing checks the type before dispatching, so my objects can be first-class
> citizens of the syntax.

**Q: `__repr__` or `__str__`?**
> `__repr__` is for developers and should be unambiguous — ideally something that could recreate the
> object. `__str__` is for end users and falls back to `__repr__` if it's missing. If I implement
> only one it's `__repr__`, because that's what the REPL, the debugger, and containers use — printing
> a list of my objects calls `repr` on each element, so without it every log line and test failure
> shows memory addresses.

**Q: Why does `__radd__` exist?**
> For the case where the left operand doesn't know about my type. `3 * v` first tries
> `int.__mul__(3, v)`, which returns `NotImplemented` because `int` has never heard of `Vector`;
> Python then tries `v.__rmul__(3)`. That's also why my operators should return `NotImplemented`
> rather than raising — returning it gives the other operand a chance and lets Python raise a good
> `TypeError` if neither side can handle it.

**Q: What does a context manager guarantee?**
> That `__exit__` runs on every exit path — normal completion, an exception, a `break`, an early
> `return`. That's why it's the only reliable cleanup mechanism in Python, unlike `__del__`, and
> why leaked sockets and file handles are a design problem solved by `with` rather than by
> discipline. One subtlety: returning a truthy value from `__exit__` suppresses the exception, so an
> accidental return value silently swallows errors.

**Q: How would you make a class support `for`, unpacking and `sum()`?**
> One method: `__iter__`, yielding the elements. That single protocol gives me `for`, tuple
> unpacking, `list()`, `min`, `max`, `sum`, `in` if `__contains__` is absent, and splatting into a
> function call. It's the clearest example of why Python is protocol-oriented rather than
> inheritance-oriented — one method, a dozen behaviours, no base class involved.
