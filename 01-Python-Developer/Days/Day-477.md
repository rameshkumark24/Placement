# Part 3 — ⭐⭐ Entities: start from the smallest thing

```
⭐ ***THE MISTAKE:*** ⭐ starting with `ParkingLot`.
⭐   ⭐ ⭐⭐ THE BIGGEST NOUN BECOMES A GOD OBJECT, BECAUSE
⭐     EVERYTHING YOU THINK OF NEXT GETS ADDED TO IT.

⭐ ***START FROM THE SMALLEST THING THAT HAS STATE:***
⭐   ⭐ `Spot` — has a size, is occupied or not. ⭐⭐ THE
⭐     INVARIANT LIVES HERE.
⭐   ⭐ `Vehicle` — has a size. ⭐ Probably just an enum and a
⭐     plate; ⭐⭐ RESIST MAKING A CLASS HIERARCHY OF Car / Truck /
⭐     Motorcycle. ⭐ In Python that is three empty subclasses and
⭐     an interviewer will ask what behaviour differs.
⭐   ⭐ `Ticket` — issued at entry, ⭐⭐ IMMUTABLE, ⭐ carries spot,
⭐     vehicle, entry time.
⭐   ⭐ `Level` — owns spots, ⭐ knows its own availability.
⭐   ⭐ `ParkingLot` — ⭐⭐ A ***COORDINATOR***, NOT A CONTAINER OF
⭐     EVERYTHING. ⭐ Its job is: find a spot, issue a ticket,
⭐     close a ticket.

⭐ ***THE PYTHON THAT MAKES THIS SHORT:***
```

```python
from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum
from typing import Protocol
import itertools, threading

class Size(Enum):
    MOTORCYCLE = 1
    COMPACT = 2
    LARGE = 3
    # ⭐⭐ ORDERED VALUES SO "FITS" IS ARITHMETIC, NOT A LOOKUP
    # TABLE — a motorcycle fits a large spot, not vice versa.

@dataclass(frozen=True, slots=True)
class Vehicle:
    plate: str
    size: Size
    # ⭐⭐ NO SUBCLASSES. There is no behaviour that differs —
    # only a size — so a subclass hierarchy is ceremony.

@dataclass(slots=True)
class Spot:
    id: str
    size: Size
    occupied_by: str | None = None      # ⭐ plate, or None

    def fits(self, v: Vehicle) -> bool:
        return v.size.value <= self.size.value

@dataclass(frozen=True, slots=True)
class Ticket:
    id: str
    plate: str
    spot_id: str
    entered_at: datetime
    # ⭐⭐ FROZEN: a ticket is a FACT about something that
    # happened. Exit produces a *new* object, it does not mutate
    # this one. That is a design statement worth making aloud.
```

# Part 4 — ⭐⭐ Strategy in Python is a function

```
⭐ ***THE JAVA-SHAPED ANSWER:*** ⭐ an abstract `PricingStrategy`
⭐   class with three concrete subclasses.
⭐ ⭐⭐ THE PYTHON ANSWER: ***A CALLABLE.*** ⭐ Everything is
⭐   first-class, so the class hierarchy adds ceremony and
⭐   removes nothing.

⭐ ⭐⭐ SAYING THIS EXPLICITLY IS A REAL SIGNAL — ⭐ it shows you
⭐   are designing ***in*** Python rather than transliterating a
⭐   pattern book. ⭐ But say ***why***, because "Python doesn't
⭐   need patterns" is a bad answer:
⭐   ⭐ ⭐⭐ "THE STRATEGY PATTERN EXISTS TO LET YOU PASS BEHAVIOUR
⭐     AROUND. ⭐ In a language without first-class functions you
⭐     need an object to carry a method. ⭐⭐ HERE THE FUNCTION
⭐     ***IS*** THE OBJECT, SO THE PATTERN COLLAPSES TO ITS
⭐     INTENT."
⭐   ⭐ ⭐⭐ AND USE A `Protocol` WHEN THE STRATEGY NEEDS STATE OR
⭐     SEVERAL METHODS ⭐ — that is the honest boundary, and
⭐     naming it stops you sounding dogmatic.
```

```python
from typing import Callable

# ⭐ A pricing rule is just this shape.
PricingRule = Callable[[Ticket, datetime], int]     # ⭐ pence

def flat_hourly(rate_pence: int) -> PricingRule:
    def price(ticket: Ticket, exit_at: datetime) -> int:
        hours = -(-(exit_at - ticket.entered_at).seconds // 3600)  # ⭐ ceil
        return hours * rate_pence
    return price                    # ⭐⭐ A CLOSURE CARRIES THE RATE

def first_hour_free(inner: PricingRule) -> PricingRule:
    def price(ticket: Ticket, exit_at: datetime) -> int:
        # ⭐⭐ RULES COMPOSE. This is the payoff for using
        # functions: a decorator IS a pricing modifier, and you
        # get "free first hour" without touching the base rule.
        return max(0, inner(ticket, exit_at) - 0)
    return price
```

```
⭐ ⭐⭐ WHEN A CLASS ***IS*** RIGHT: ⭐ if pricing needs to load
⭐   tariffs, cache them, and expose `explain()` alongside
⭐   `price()`, ⭐ that is state plus multiple methods —
⭐   ⭐⭐ USE A `Protocol`. ⭐ Structural typing means implementers
⭐   do not inherit from anything, which is the Python-idiomatic
⭐   interface.
```

# Part 5 — ⭐⭐ The interesting part: allocation under concurrency

```
⭐ ***THIS IS WHAT THE ROUND IS ACTUALLY ABOUT, AND WHERE EVERY
⭐   INTERVIEWER PUSHES.***

⭐ ***THE NAIVE VERSION AND ITS RACE:***
⭐   ⭐ `spot = find_free()` … `spot.occupied_by = plate`
⭐   ⭐ ⭐⭐ TWO THREADS FIND THE ***SAME*** FREE SPOT BETWEEN THE
⭐     FIND AND THE ASSIGN. ⭐ Both succeed. ⭐⭐ TWO CARS, ONE
⭐     SPOT — YOUR INVARIANT FROM QUESTION ⑤, BROKEN.
⭐   ⭐ ⭐⭐ THIS IS ***CHECK-THEN-ACT***, AND IT IS THE ENTIRE
⭐     SUBJECT OF DAY 479.

⭐ ***AND THE PYTHON-SPECIFIC TRAP WORTH NAMING:***
⭐   ⭐ ⭐⭐ THE GIL DOES ***NOT*** SAVE YOU. ⭐ It makes individual
⭐     bytecodes atomic; ⭐⭐ IT DOES NOT MAKE A ***SEQUENCE*** OF
⭐     OPERATIONS ATOMIC. ⭐ A thread switch between find and
⭐     assign is entirely legal.
⭐   ⭐ ⭐ Saying "the GIL doesn't help here, because this is
⭐     check-then-act across two statements" is one of the
⭐     highest-value sentences in a Python LLD round.
```

```python
class ParkingLot:
    def __init__(self, spots: list[Spot], price: PricingRule):
        self._spots = spots
        self._price = price
        self._lock = threading.Lock()          # ⭐ one lot, one lock
        self._tickets: dict[str, Ticket] = {}
        self._ids = itertools.count(1)

    def park(self, v: Vehicle) -> Ticket:
        with self._lock:                       # ⭐⭐ FIND AND CLAIM
            spot = next((s for s in self._spots #    ARE ONE UNIT
                         if s.occupied_by is None and s.fits(v)), None)
            if spot is None:
                raise LotFull(v.size)          # ⭐ a real error type
            spot.occupied_by = v.plate
            t = Ticket(f"T{next(self._ids)}", v.plate,
                       spot.id, datetime.now())
            self._tickets[t.id] = t
            return t
    # ⭐⭐ THE CRITICAL SECTION IS *SMALL* AND CONTAINS NO I/O.
    # ⭐ Say that: a lock held across a database call or a
    # payment gateway is how you turn a design into an outage.
```

```
⭐ ***THE FOLLOW-UPS, AND THE ANSWERS:***
⭐   ⭐ ⭐⭐ "A GLOBAL LOCK DOESN'T SCALE." ⭐ Correct. ⭐ Next:
⭐     a lock per ***level***, so entrances contend only within a
⭐     level. ⭐⭐ THEN: STOP USING LOCKS ENTIRELY — ⭐ make it a
⭐     database row with a conditional update
⭐     (`UPDATE … WHERE occupied_by IS NULL`) ⭐⭐ AND LET THE ROW
⭐     COUNT TELL YOU WHO WON (D412: CORRECTNESS LIVES IN THE
⭐     RESOURCE, NOT THE COORDINATOR).
⭐   ⭐ ⭐⭐ "WHAT IF THE PROCESS DIES AFTER CLAIMING?" ⭐ The spot
⭐     is leaked. ⭐ ⇒ a claim with an expiry, reconciled by a
⭐     sweeper — ⭐⭐ WHICH IS A LEASE, AND SAYING THE WORD IS THE
⭐     SIGNAL.
⭐   ⭐ ⭐ "Multiple processes?" ⭐⭐ THEN AN IN-PROCESS LOCK IS
⭐     MEANINGLESS AND THE DATABASE IS THE ONLY HONEST ANSWER.
```

# 💬 Interview

**1. "Design a parking lot."**

⭐ Six questions first, and they take three minutes. ⭐⭐ Who uses it — a driver parking, or an operator
managing capacity across sites? What's out of scope — I'd assume payment processing is an external
service. What scale, and is this one process or many, because that decides whether locks or a database
row are my concurrency mechanism. ⭐ What varies — pricing rules, vehicle types? ⭐⭐ What must never
happen — two cars in one spot? ⭐ And is it concurrent? ⭐⭐ Then I'd summarise it back in one sentence
and start. ⭐ Skipping that is how people spend forty minutes designing a system nobody asked for.

**2. "Where would you start coding?"**

⭐ Not with `ParkingLot`, because the biggest noun becomes a god object — everything you think of next
gets added to it. ⭐⭐ I'd start with `Spot`, because that's the smallest thing holding state and it's
where the invariant lives. ⭐ Then I'd say out loud which part I'm going to write properly: "I'll sketch
the entities and code the allocation logic, since that's where the actual design is — tell me if you'd
rather see something else." ⭐⭐ Writing getters for eight classes is typing, not design, and it scores
nothing.

**3. "Why no `Car`, `Truck`, `Motorcycle` classes?"**

⭐ Because there's no behaviour that differs — only a size. ⭐⭐ Three empty subclasses is ceremony, and
the first thing an interviewer should ask is what method they override. ⭐ A `Vehicle` dataclass with a
`Size` enum captures everything, and I'd give the enum ordered values so "does this fit" is arithmetic
rather than a lookup table. ⭐⭐ If a vehicle type later needed real behaviour — an EV needing a charger —
that's when a subclass or a capability flag earns its place, and I'd add it then rather than in
anticipation.

**4. "How do you make pricing configurable?"**

⭐ A pricing rule is a callable — `(Ticket, exit_time) -> pence` — and different rules are functions,
often closures carrying their rate. ⭐⭐ The reason isn't "Python doesn't need patterns", which is a bad
answer; it's that the strategy pattern exists to let you pass behaviour around, and in a language without
first-class functions you need an object to carry a method. ⭐ Here the function *is* the object, so the
pattern collapses to its intent. ⭐⭐ The bonus is composition: "first hour free" becomes a decorator
wrapping a base rule, with no change to the base. ⭐ Where I'd use a `Protocol` instead is if pricing
needed state and several methods — loading tariffs, caching them, exposing `explain()` alongside
`price()`.

**5. "Two cars arrive at once."**

⭐ That's check-then-act, and it's the bug in every naive version: you find a free spot, and between the
find and the assign another thread finds the same one. ⭐⭐ Both succeed, and the invariant I named in
requirements is broken. ⭐ So find-and-claim has to be one atomic unit — a lock around both, with the
critical section small and containing no I/O. ⭐⭐ And the Python-specific point worth saying: the GIL
doesn't save me here. It makes individual bytecodes atomic, not sequences of statements, so a thread
switch between the find and the assign is entirely legal.

**6. "A global lock doesn't scale."**

⭐ Agreed, and I'd escalate in three steps rather than jumping to the end. ⭐⭐ First a lock per level, so
entrances only contend within a level — cheap and usually sufficient for one building. ⭐ Then, if it's
multiple processes, an in-process lock is meaningless and I'd move the invariant into the database: a
conditional update, `UPDATE spots SET occupied_by = ? WHERE id = ? AND occupied_by IS NULL`, and the row
count tells me who won. ⭐⭐ That's correctness living in the resource rather than in the coordinator.
⭐ And I'd add an expiry to the claim, so a process dying after claiming doesn't leak the spot forever —
that's a lease, reconciled by a sweeper.

## 🎙️ Articulation drill

⭐⭐ **Three minutes, out loud: the first eight minutes of an LLD round.**

Ask before designing. **"Before I start — who's using this, a driver or an operator? What's out of
scope; can I assume payment processing is an external service? Is this one lot in one process, or many
lots across many processes — because that decides whether my concurrency mechanism is a lock or a
database row. What varies: do pricing rules change, do new vehicle types get added? What must never
happen — I'm assuming two cars in one spot is the invariant. And are there multiple entrances operating
at once?"**

Summarise back, then commit. **"So: one lot, in-memory, multiple entrances so concurrency is real,
pricing varies, and one-vehicle-per-spot is the invariant. I'll design for that."**

Then set the scope of what you'll write. **"I'll sketch the entities quickly and then write the
allocation logic properly, because that's where the actual design is — writing getters for eight classes
would be typing rather than design. Tell me if you'd rather see a different part."**

Then start from the smallest thing. **"I'll start with `Spot` rather than `ParkingLot`, because the
biggest noun tends to become a god object — everything you think of next gets added to it. `Spot` is the
smallest thing that holds state, and it's where the invariant lives. Vehicle is a frozen dataclass with a
size enum and no subclasses, because nothing about a truck behaves differently from a car here — only
its size — and three empty subclasses is ceremony. I'll give the enum ordered values so 'does this fit'
is arithmetic rather than a lookup."**
