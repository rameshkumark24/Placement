# L-042 · Modern Java data modelling

## Records

**A transparent carrier for immutable data.**

```java
public record Point(int x, int y) { }
```

That single line generates:

```java
public final class Point {
    private final int x;
    private final int y;
    public Point(int x, int y) { this.x = x; this.y = y; }   // canonical constructor
    public int x() { return x; }                              // accessors — NOT getX()
    public int y() { return y; }
    @Override public boolean equals(Object o) { ... }         // all components
    @Override public int hashCode() { ... }                   // all components
    @Override public String toString() { ... }                // "Point[x=1, y=2]"
}
```

**What you get, for free and correctly:**

| Feature | Note |
|---|---|
| `final` class | Cannot be subclassed |
| `private final` fields | One per component |
| Canonical constructor | Parameters in declaration order |
| Accessors | `x()`, not `getX()` |
| `equals` / `hashCode` | **All components. Correct by construction** — Day 040 |
| `toString` | Day 041 |

**That's the argument for records in one line: they eliminate the entire `equals`/`hashCode` bug
class** that Day 040 was about.

### The compact constructor

```java
public record Range(int low, int high) {
    public Range {                                        // no parameter list, no assignments
        if (low > high) throw new IllegalArgumentException("low > high");
        low = Math.max(low, 0);                            // you may REASSIGN parameters
    }
}
```

**The compact constructor runs before the fields are assigned**, and assignments to the parameters
are what the canonical constructor then stores. That's the idiom for validation and normalisation.

**And for defensive copying** — Day 034A's point, restated because it's the most-missed thing about
records:

```java
public record Team(String name, List<String> members) {
    public Team {
        members = List.copyOf(members);      // ✅ records do NOT copy for you
    }
}
```

**Records are shallowly immutable.** A record holding a mutable object shares it with whoever passed
it in.

### What records can and can't do

```java
public record Point(int x, int y) implements Comparable<Point> {
    public static final Point ORIGIN = new Point(0, 0);   // ✅ static fields
    public double distance() { return Math.sqrt(x*x + y*y); }   // ✅ instance methods
    public static Point of(int x, int y) { return new Point(x, y); }  // ✅ static factories
    @Override public int compareTo(Point o) { ... }        // ✅ implement interfaces

    // ❌ instance fields beyond the components
    // ❌ extends anything (they implicitly extend Record)
    // ❌ non-final — always final
}
```

**When to use a record:** DTOs, value objects, API request and response types, map keys, tuples,
domain values, events. **Anything that is data.**

**When not to:** entities with identity and lifecycle, anything needing mutable state, JPA entities
(Hibernate needs a no-arg constructor and non-final fields — Day 035).

## Sealed classes

**A closed hierarchy: you control exactly who may extend or implement.**

```java
public sealed interface Shape permits Circle, Square, Triangle { }

public record Circle(double radius)          implements Shape { }
public record Square(double side)            implements Shape { }
public record Triangle(double b, double h)   implements Shape { }
```

**Every permitted subtype must be `final`, `sealed`, or `non-sealed`:**

```java
public sealed class Animal permits Dog, Cat, Bird { }

public final class Dog extends Animal { }           // closed
public sealed class Cat extends Animal permits Persian { }   // continues the seal
public non-sealed class Bird extends Animal { }     // deliberately reopened
```

**Why it exists:** before sealed types, an interface was either fully open — anyone can implement,
so you can never exhaustively handle all cases — or `final`, so nobody can. There was no way to say
"exactly these three".

**The payoff is exhaustiveness.** The compiler *knows* the complete set:

```java
double area(Shape s) {
    return switch (s) {                    // no `default` needed!
        case Circle c   -> Math.PI * c.radius() * c.radius();
        case Square sq  -> sq.side() * sq.side();
        case Triangle t -> 0.5 * t.b() * t.h();
    };
}
```

**Add a fourth shape and every switch over `Shape` fails to compile** until you handle it. That turns
"we forgot a case" from a production bug into a build error — which is the same argument as Day 030's
switch exhaustiveness, now extended to type hierarchies.

**Sealed types + records = algebraic data types**, the same modelling power as Kotlin's sealed
classes, Rust's enums, or a Haskell sum type. That's the real significance.

## Pattern matching

### `instanceof` patterns (Java 16)

```java
// Before
if (o instanceof String) {
    String s = (String) o;                 // test, then cast, then use
    if (s.length() > 5) { ... }
}

// After
if (o instanceof String s && s.length() > 5) { ... }
```

The variable `s` is **bound and scoped correctly** — available where the test is known true, including
in the `&&` and in the `if` body, and not in the `else`.

### Pattern matching for `switch` (Java 21)

```java
String describe(Object o) {
    return switch (o) {
        case null            -> "null";                 // explicit null case — legal here
        case Integer i when i < 0 -> "negative int: " + i;   // GUARDED pattern
        case Integer i       -> "int: " + i;
        case String s        -> "string of length " + s.length();
        case int[] arr       -> "int array of " + arr.length;
        default              -> "something else";
    };
}
```

**Three things worth noting:**
- `case null` is allowed — a switch on a reference no longer NPEs automatically, if you handle it
- **`when` guards** add a condition to a pattern
- **Order matters** — patterns are tested top to bottom, so put more specific ones first. The compiler
  rejects an unreachable case.

### Record patterns (Java 21) — deconstruction

```java
record Point(int x, int y) { }
record Line(Point start, Point end) { }

String describe(Object o) {
    return switch (o) {
        case Line(Point(var x1, var y1), Point(var x2, var y2)) ->
                "line from (%d,%d) to (%d,%d)".formatted(x1, y1, x2, y2);
        case Point(var x, var y) when x == y -> "on the diagonal";
        case Point p -> "point " + p;
        default -> "?";
    };
}
```

**Nested deconstruction in one pattern.** No accessor calls, no casts. This is where the three
features combine — records give you the shape, sealed types give you exhaustiveness, patterns give
you the destructuring.

## The combination — a worked example

```java
sealed interface Result<T> permits Success, Failure { }
record Success<T>(T value)              implements Result<T> { }
record Failure<T>(String error, int code) implements Result<T> { }

String handle(Result<String> r) {
    return switch (r) {                                    // exhaustive — no default
        case Success(var value)                 -> "ok: " + value;
        case Failure(var error, int code) when code >= 500 -> "server error: " + error;
        case Failure(var error, var code)       -> "client error " + code + ": " + error;
    };
}
```

**Compare that with the traditional version:** an abstract class, two subclasses with boilerplate
constructors, `equals`, `hashCode`, `toString`, an `instanceof` chain with casts, and a `default`
branch that throws because the compiler can't prove the chain is complete.

**This is the modern-Java answer to modelling a closed set of outcomes**, and it's a strong thing to
be able to write fluently in an LLD round (Stage 8).

## Type this yourself

```java
import java.util.*;

public class ModernJavaDemo {

    // ---- sealed hierarchy of records ----
    sealed interface Shape permits Circle, Square, Rectangle { }
    record Circle(double radius)             implements Shape { }
    record Square(double side)               implements Shape { }
    record Rectangle(double w, double h)     implements Shape { }

    static double area(Shape s) {
        return switch (s) {                        // exhaustive, no default
            case Circle c    -> Math.PI * c.radius() * c.radius();
            case Square sq   -> sq.side() * sq.side();
            case Rectangle r -> r.w() * r.h();
        };
    }

    // ---- record patterns, nested ----
    record Point(int x, int y) { }
    record Line(Point start, Point end) { }

    static String describe(Object o) {
        return switch (o) {
            case null -> "null";
            case Line(Point(var x1, var y1), Point(var x2, var y2)) when x1 == x2 ->
                    "vertical line at x=" + x1;
            case Line(Point p1, Point p2) -> "line " + p1 + " → " + p2;
            case Point(var x, var y) when x == y -> "diagonal point (" + x + "," + y + ")";
            case Point p -> "point " + p;
            case Integer i when i < 0 -> "negative " + i;
            case Integer i -> "int " + i;
            case String s -> "string of length " + s.length();
            default -> "unknown: " + o.getClass().getSimpleName();
        };
    }

    // ---- compact constructor: validation + defensive copy ----
    record Team(String name, List<String> members) {
        Team {
            Objects.requireNonNull(name);
            if (name.isBlank()) throw new IllegalArgumentException("name required");
            members = List.copyOf(members);            // records do NOT copy for you
        }
        Team(String name) { this(name, List.of()); }   // extra constructor delegating to canonical
    }

    // ---- Result modelling ----
    sealed interface Result permits Ok, Err { }
    record Ok(String value)              implements Result { }
    record Err(String message, int code) implements Result { }

    static String handle(Result r) {
        return switch (r) {
            case Ok(var v) -> "ok: " + v;
            case Err(var m, int c) when c >= 500 -> "server error (" + c + "): " + m;
            case Err(var m, var c) -> "client error (" + c + "): " + m;
        };
    }

    public static void main(String[] args) {
        System.out.println("--- records: equals/hashCode/toString for free ---");
        Point a = new Point(1, 2), b = new Point(1, 2);
        System.out.println("   " + a);
        System.out.println("   a.equals(b) = " + a.equals(b));
        System.out.println("   same hash   = " + (a.hashCode() == b.hashCode()));
        System.out.println("   HashSet size of {a,b} = " + new HashSet<>(List.of(a, b)).size());

        System.out.println("\n--- sealed + exhaustive switch ---");
        for (Shape s : List.of(new Circle(1), new Square(2), new Rectangle(2, 3)))
            System.out.printf("   %-28s area = %.2f%n", s, area(s));

        System.out.println("\n--- pattern matching ---");
        for (Object o : Arrays.asList(
                new Line(new Point(1, 0), new Point(1, 5)),
                new Line(new Point(0, 0), new Point(3, 4)),
                new Point(3, 3), new Point(1, 2),
                -7, 42, "hello", null, 3.14))
            System.out.println("   " + describe(o));

        System.out.println("\n--- compact constructor ---");
        List<String> mutable = new ArrayList<>(List.of("alice"));
        Team t = new Team("Platform", mutable);
        mutable.add("bob");                                  // try to corrupt it
        System.out.println("   " + t + "   ← unaffected");
        try { t.members().add("carol"); }
        catch (UnsupportedOperationException e) { System.out.println("   members() is immutable"); }
        try { new Team("  ", List.of()); }
        catch (IllegalArgumentException e) { System.out.println("   validation: " + e.getMessage()); }

        System.out.println("\n--- Result ---");
        for (Result r : List.of(new Ok("done"), new Err("not found", 404), new Err("boom", 503)))
            System.out.println("   " + handle(r));
    }
}
```

**Two experiments that prove the value:**

1. **Add `record Triangle(double b, double h) implements Shape { }` to the `permits` clause** and
   recompile. **`area()` fails to compile** with "the switch expression does not cover all possible
   input values". That's the whole point of sealed types — a missed case is a build failure.

2. **Remove `members = List.copyOf(members)`** from the compact constructor and re-run. The record is
   now corruptible from outside. **Records don't defensively copy** (Day 034A).

## Common mistakes

| Mistake | Correction |
|---|---|
| Assuming records are deeply immutable | Shallow. Use `List.copyOf` in the compact constructor. |
| Expecting `getX()` accessors | Records generate `x()`. |
| Using records for JPA entities | Hibernate needs a no-arg constructor and non-final fields. |
| Assigning to `this.x` in a compact constructor | Assign to the *parameter*; the canonical constructor stores it. |
| Forgetting subtypes must be final/sealed/non-sealed | Compile error. |
| Adding a `default` to an exhaustive sealed switch | Defeats the exhaustiveness check — you lose the compile error when a case is added. |
| Ordering patterns from general to specific | Later specific cases become unreachable; the compiler rejects it. |

## Interview questions

**Q: What is a record and what does it generate?**
> A transparent carrier for immutable data. The compiler generates a final class with private final
> fields, a canonical constructor, accessors named after the components, and `equals`, `hashCode` and
> `toString` derived from all components. Its main practical value is eliminating the
> `equals`/`hashCode` bug class entirely for value types.

**Q: Are records immutable?**
> Shallowly. The class is final, fields are final and there are no setters, but records perform no
> defensive copying — a record holding a `List` shares that list with whoever constructed it. The fix
> is `List.copyOf` in the compact constructor, assigning to the parameter.

**Q: What problem do sealed classes solve?**
> They let you define a closed hierarchy. Previously a type was either open, so you could never
> exhaustively handle every subtype, or final, so nobody could extend it. Sealed types name exactly
> which subtypes are permitted, which lets the compiler verify a switch covers all of them — so adding
> a subtype and forgetting to handle it becomes a compile error rather than a runtime bug.

**Q: What are record patterns?**
> Patterns that deconstruct a record into its components inside a `switch` or `instanceof`, including
> nested records in a single pattern. Combined with sealed types this gives Java algebraic data types
> — the same modelling as a Kotlin sealed class or a Rust enum — with exhaustiveness checked at
> compile time.

**Q: When would you not use a record?**
> When the type has identity and a lifecycle rather than being a value — JPA entities need a no-arg
> constructor and mutable non-final fields, so they can't be records. Also anything requiring mutable
> state or inheritance.
