# Part 1 — The flow, in full

```
⭐⭐ THE SEVEN STEPS. MOST DEMOS IMPLEMENT THREE.

⭐   ① POST /auth/login ⇒ ⭐ Spring sets an HttpOnly cookie (Day 235)
⭐   ② ⭐ CLIENT FETCHES /auth/me ⇒ the user object.
⭐      ⭐⭐ IT NEVER DECODES A TOKEN. It cannot read the cookie, and
⭐        it should not want to — ⭐ the server is the authority on
⭐        who you are.
⭐   ③ that user lives in Context (Day 231) — ⭐ wide and slow ✅
⭐   ④ ⭐ PROTECTED ROUTES check it before rendering
⭐   ⑤ ⭐⭐ 401 ⇒ single-flight refresh ⇒ retry once (Day 235)
⭐   ⑥ ⭐⭐ REFRESH FAILS ⇒ **preserve, then redirect** (Part 3)
⭐   ⑦ logout ⇒ ⭐ server revokes, client clears the cache
```

```jsx
function AuthProvider({ children }) {
  const { data: user, isPending } = useQuery({
    queryKey: keys.users.me(),
    queryFn: () => client.GET("/auth/me"),
    retry: false,              // ⭐⭐ a 401 here is an ANSWER, not a failure
    staleTime: 5 * 60_000,
  });
  if (isPending) return <FullPageSkeleton />;   // ⭐ not a redirect — you
  return <AuthCtx.Provider value={user ?? null}>{children}</AuthCtx.Provider>;
}                                              //   don't know yet
```

> ⭐⭐ **The bug this avoids: redirecting to login while the `/auth/me` call is still in flight.** The
> user is logged in, and you bounced them out because you treated "unknown" as "unauthenticated". ⭐ It
> is the three-state problem again — loading, authenticated, anonymous — collapsed into a boolean.

# Part 2 — Protected routes

```jsx
function RequireAuth({ children }) {
  const user = useAuth();
  const location = useLocation();
  if (!user) {
    return <Navigate to="/login" replace           // ⭐⭐ replace, not push
             state={{ from: location }} />;        // ⭐ so you can return
  }
  return children;
}
```

| ⭐ Detail | Why |
|---|---|
| **`replace`** | ⭐⭐ Otherwise Back goes to the protected page, which bounces to login — an infinite loop the user experiences as a broken Back button |
| **`state.from`** | ⭐ After login, return them **where they were going** |
| **⭐⭐ Role checks use server data** | `user.permissions`, never a decoded token (Day 236) |
| **⭐ It is not security** | Day 236. This is routing. `@PreAuthorize` is the boundary. |

# Part 3 — ⭐⭐ The expiry that preserves work

```
⭐⭐ THE MOMENT THAT SEPARATES A REAL APP FROM A DEMO

⭐   A user has typed 400 words. The access token expires.
⭐   They press Save.

⭐   ❌ THE DEMO: 401 ⇒ redirect to /login ⇒ ⭐⭐ THE FORM UNMOUNTS ⇒
⭐      **400 WORDS GONE**. They do not come back to your product.
⭐   ✅ THE REAL APP:
⭐      ① ⭐ transport tries single-flight refresh (Day 235)
⭐      ② succeeds ⇒ ⭐⭐ RETRY THE SAVE. THE USER NEVER KNOWS.
⭐      ③ ⭐ fails ⇒ **DO NOT NAVIGATE**. Show a modal over the page:
⭐         "Your session expired. Sign in to continue."
⭐         ⇒ ⭐⭐ THE FORM IS STILL MOUNTED. THE TEXT IS STILL THERE.
⭐      ④ they log in IN THE MODAL ⇒ ⭐ close it ⇒ retry the save.
```

| ⭐ Belt and braces | |
|---|---|
| **Draft to `localStorage`** | ⭐ Debounced, keyed by form + record id. ⭐⭐ **Not for anything sensitive** — it is readable by any script (Day 235) |
| **The unsaved-changes guard** | ⭐ Day 229 |
| **`aria-live` on the modal** | ⭐⭐ Otherwise a screen reader user has no idea it appeared |

> ⭐⭐ **"What happens when the session expires mid-edit?" is a question interviewers ask** precisely
> because most candidates have never thought about it. **Having an answer with a demo behind it is
> disproportionately convincing.**

# Part 4 — Logout, and the cross-user leak

```jsx
async function logout() {
  await client.POST("/auth/logout");   // ⭐⭐ SERVER REVOKES. Do this FIRST.
  queryClient.clear();                 // ⭐⭐ THE LINE PEOPLE FORGET
  localStorage.removeItem("draft:*");  // ⭐ any cached drafts
  navigate("/login", { replace: true });
}
```

```
⭐⭐ WHY queryClient.clear() IS A SECURITY LINE, NOT HOUSEKEEPING

⭐   ⭐ User A logs out. User B logs in ON THE SAME MACHINE.
⭐   ⭐⭐ WITHOUT THE CLEAR, THE CACHE STILL HOLDS A's ORDERS —
⭐     AND THEY RENDER INSTANTLY FROM CACHE BEFORE ANY REFETCH.
⭐   ⇒ ⭐⭐ B SEES A's DATA. Briefly, but it is on screen, and it is
⭐     a real cross-user leak on any shared machine.
⭐   ⇒ ⭐ AND ACROSS TABS: a `storage` event, or tab 2 keeps
⭐     showing a logged-in UI over an invalid session.
```

| ⭐ The honest limit | |
|---|---|
| **A stateless access token stays valid** | ⭐⭐ Until it expires. **Say the window out loud** — "up to 15 minutes". ⭐ That is the price of statelessness, and naming it is the senior answer (Day 235). |
| **A denylist buys revocation** | ⭐ At the cost of a lookup per request. **A real trade, not a fix.** |

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "walk me through auth in your app."**

Cover the flow briskly, then spend your time on the interesting part. **The server sets an HttpOnly
cookie and the client fetches `/auth/me` for the user object — it never decodes a token, because it
can't read the cookie and shouldn't want to. The server is the authority on who you are. That user
sits in Context, which is the right use: wide and slow.**

Name a bug you fixed, since it shows you built rather than followed a tutorial. **The one I hit was
redirecting to login while `/auth/me` was still in flight — the user was logged in and I bounced them
out, because I'd collapsed three states into a boolean. Loading isn't unauthenticated.**

Then the part that matters. **What happens when the session expires mid-edit. In a demo, a 401
redirects to login, the form unmounts, and four hundred words are gone. In mine the transport tries a
single-flight refresh and retries the request, so usually the user never knows. If the refresh fails I
don't navigate — I show a modal over the page, so the form is still mounted and the text is still
there. They sign in inside the modal and the save retries.**

Close on logout, and be honest about the limit. **Logout revokes server-side first, then clears the
query cache — which is a security line, not housekeeping: without it the next user on that machine sees
the previous user's data render instantly from cache. And I'm clear that a stateless access token stays
valid until it expires, up to fifteen minutes. A denylist buys revocation at the cost of a lookup per
request — that's a trade, not a fix.**
