# Part 1 — The three image mistakes

```
⭐⭐ ① SERVING A 4000px PHOTO INTO A 400px BOX
⭐   ⭐ 3.2 MB downloaded, decoded, and thrown away.
⭐   ⭐⭐ THE MOST COMMON PERFORMANCE BUG ON THE WEB, and invisible
⭐     on a desktop with fast wifi.

⭐⭐ ② WRONG FORMAT
⭐   PNG photo ⇒ 2.1 MB  ·  JPEG ⇒ 340 KB  ·  ⭐ WebP ⇒ 180 KB
⭐   ⭐⭐ AVIF ⇒ 120 KB. Same picture. ⭐ 17× FOR ONE ENCODER CHOICE.
⭐   ⇒ ⭐ PNG only for transparency or sharp-edged graphics.
⭐     ⭐⭐ SVG for icons and logos — it is text, it gzips, it scales.

⭐⭐ ③ NO width/height ⇒ ⭐ LAYOUT SHIFT (CLS, Day 241).
⭐   ⭐⭐ ALWAYS SET THEM, EVEN WITH CSS SIZING — they give the
⭐     browser the ASPECT RATIO so it can reserve the space.
```

```html
<!-- ⭐⭐ the correct shape -->
<picture>
  <source srcset="/hero.avif" type="image/avif">
  <source srcset="/hero.webp" type="image/webp">
  <img src="/hero.jpg" width="1200" height="600" alt="..."
       fetchpriority="high">     <!-- ⭐ it is the LCP element -->
</picture>

<img srcset="/p-400.webp 400w, /p-800.webp 800w, /p-1600.webp 1600w"
     sizes="(max-width: 600px) 100vw, 50vw"
     src="/p-800.webp" width="800" height="600" alt="">
```

| ⭐ Attribute | Does |
|---|---|
| `srcset` + `sizes` | ⭐⭐ The browser downloads **one** file, chosen for the device |
| `loading="lazy"` | ⭐ Below-the-fold images load near the viewport |
| ⭐⭐ `fetchpriority="high"` | On the LCP image — **often the single biggest LCP win** |

```
⭐⭐ THE EXCEPTION THAT COSTS PEOPLE THEIR LCP:
⭐   ❌ loading="lazy" ON THE HERO IMAGE.
⭐   ⇒ ⭐⭐ THE BROWSER DELAYS THE ONE IMAGE THAT DEFINES YOUR LCP,
⭐     MAKING THE METRIC WORSE WHILE YOU BELIEVE YOU OPTIMISED IT.
⭐   ⇒ ⭐ LAZY BELOW THE FOLD. EAGER + fetchpriority ABOVE IT.
```

# Part 2 — ⭐⭐ Fonts, and the flash

```
⭐⭐ A CUSTOM FONT IS A RENDER-BLOCKING DEPENDENCY DISCOVERED LATE
⭐   — the browser must parse CSS, find the @font-face, then fetch.
⭐   ⭐ Meanwhile:

⭐   FOIT (Flash of Invisible Text) ⇒ ⭐⭐ TEXT IS **INVISIBLE** FOR
⭐     UP TO 3 SECONDS. The content arrived and the user cannot read
⭐     it. ⭐ THIS IS THE DEFAULT BEHAVIOUR.
⭐   FOUT (Flash of Unstyled Text) ⇒ ⭐ fallback shows, then swaps.
⭐     A visible reflow, but ⭐⭐ READABLE THE WHOLE TIME.

⭐   ⇒ ⭐⭐ font-display: swap  ⇒ CHOOSE FOUT. ⭐ ONE LINE.
```

```css
@font-face {
  font-family: "Inter";
  src: url("/inter.woff2") format("woff2");   /* ⭐ woff2 ONLY */
  font-display: swap;                          /* ⭐⭐ THE LINE */
  unicode-range: U+0000-00FF;                  /* ⭐ subset: latin only */
  size-adjust: 107%;                           /* ⭐⭐ match the fallback's
                                                 metrics ⇒ NO layout shift */
}
```

| ⭐ Rule | Why |
|---|---|
| **`woff2` only** | ⭐ ~30% smaller than woff, supported everywhere |
| **⭐⭐ Self-host** | Google Fonts costs a **separate DNS + TLS + fetch** to another origin — and it is a third party in your critical path and your privacy story |
| **Preload the one you need** | ⭐ Moves discovery to the start |
| **Two weights, not seven** | ⭐⭐ Each weight is a separate file |
| **`size-adjust`** | ⭐⭐ **How you get FOUT without CLS** |

> ⭐ **The strongest option remains a system font stack** — zero bytes, zero requests, instant text.
> **If you cannot articulate what your custom font buys, this is the better engineering decision.**

# Part 3 — Serving them

| ⭐ Control | Value |
|---|---|
| **Hashed filename + `immutable`** | ⭐⭐ `Cache-Control: public, max-age=31536000, immutable` — a year, safely (Day 222) |
| **CDN** | ⭐ Serve from an edge near the user |
| **⭐⭐ Never resize in the browser** | Resizing a 4000px image with CSS still downloads and decodes 4000px |
| **An image CDN** | ⭐ `?w=400&fm=webp` — every variant, no build step |

```
⭐⭐ USER-UPLOADED IMAGES ARE A SEPARATE PROBLEM — and a security one
⭐   · ⭐ RESIZE ON UPLOAD. Never serve the original.
⭐   · ⭐⭐ VALIDATE THE **CONTENT**, NOT THE EXTENSION. A file named
⭐     .jpg can be anything; check the magic bytes.
⭐     ⭐ MultipartFile.getContentType() IS CLIENT-SUPPLIED. Do not
⭐       trust it — it is a request header, like any other.
⭐   · ⭐⭐ STRIP EXIF — PHOTOS CARRY GPS COORDINATES. Serving an
⭐     uploaded photo unmodified can publish a user's home address.
⭐   · ⭐ SERVE FROM A SEPARATE ORIGIN so an uploaded SVG containing
⭐     script cannot run as your origin (Day 243).
```

## Today's build

1. ⭐⭐ **Audit your bytes.** Sort the Network tab by size. **What fraction is images and fonts?**
2. Convert your largest image to WebP and AVIF. ⭐ Record all three sizes.
3. ⭐ Add `srcset`/`sizes`. Resize the window and watch the browser choose a different file.
4. ⭐⭐ **Remove `font-display: swap` and throttle to slow 3G.** Watch your text be invisible. Put it back.
5. ⭐ Add `size-adjust` and confirm the swap no longer shifts layout.
6. ⭐⭐ Lazy-load your hero image and watch LCP get **worse.** Undo it.
7. ⭐ Upload a phone photo to your own app and read its EXIF. Strip it. ⭐⭐ Then confirm you are not trusting `getContentType()`.

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "how do you optimise images and fonts?"**

Establish why it is worth the time. **They're usually the majority of what I ship and almost none of
what anyone optimises — and unlike JavaScript, they can be fixed without touching application code.
Best ratio of improvement to risk available.**

Then images. **The most common bug on the web is serving a four-thousand-pixel photo into a
four-hundred-pixel box — megabytes downloaded and thrown away, completely invisible on a developer's
machine. So `srcset` and `sizes` so the browser picks one file, AVIF or WebP instead of PNG for photos,
explicit width and height so space is reserved, and `fetchpriority="high"` on the LCP image. And the
trap: lazy-loading the hero makes LCP worse while you believe you fixed it.**

Then fonts. **The default is a flash of invisible text — the content has arrived and the user can't read
it for up to three seconds. `font-display: swap` chooses unstyled text instead so it's readable
throughout, and `size-adjust` matches the fallback's metrics so the swap doesn't shift anything. One
line each. I self-host in woff2, subset, and ship two weights rather than seven.**

Close on the upload path, because it is a security answer. **User uploads get resized on the server and
validated by magic bytes, not by extension — `getContentType()` on a multipart file is a client-supplied
header and I don't trust it any more than any other header. And EXIF gets stripped, because phone photos
carry GPS coordinates and serving one unmodified can publish someone's home address.**
