# L-045 · The collections framework

## The hierarchy

```
                    Iterable<E>
                        │
                   Collection<E>
        ┌───────────────┼───────────────┐
        │               │               │
     List<E>         Set<E>          Queue<E>
        │               │               │
   ArrayList       HashSet          ArrayDeque
   LinkedList      LinkedHashSet     PriorityQueue
   Vector (legacy) TreeSet ─────┐    LinkedList
   CopyOnWriteAL   EnumSet      │         │
                                │      Deque<E>
                          SortedSet<E>    ArrayDeque
                                │         LinkedList
                          NavigableSet<E>


   Map<K,V>            ← NOT a Collection!
        │
   HashMap
   LinkedHashMap
   TreeMap ──── SortedMap<K,V> ──── NavigableMap<K,V>
   Hashtable (legacy)
   EnumMap
   ConcurrentHashMap
```

**`Map` is not a `Collection`.** A `Collection` holds elements; a `Map` holds *mappings*. It's the
first thing to say if asked about the hierarchy, and it's the detail people most often get wrong.

You reach the collection views explicitly:

```java
map.keySet()      // Set<K>
map.values()      // Collection<V>   — not a Set: values may repeat
map.entrySet()    // Set<Map.Entry<K,V>>
```

**These are *views*, not copies.** Modifying the view modifies the map, and vice versa:

```java
map.keySet().remove("a");        // removes the ENTRY from the map
for (Map.Entry<K,V> e : map.entrySet()) e.setValue(newValue);   // updates the map
```

## The four contracts

| Interface | Guarantees | Allows duplicates | Ordered |
|---|---|---|---|
| **`List`** | Indexed, positional access | ✅ | ✅ insertion order |
| **`Set`** | No duplicates (by `equals`) | ❌ | Depends on implementation |
| **`Queue`** | Ordering for processing — usually FIFO | ✅ | By the queue's policy |
| **`Map`** | Key → value, unique keys | Values yes, keys no | Depends |

**"Ordered" and "sorted" are different words:**

- **Ordered** — there is a defined iteration order (insertion order for `ArrayList` and
  `LinkedHashMap`)
- **Sorted** — iteration follows a comparison order (`TreeMap`, `TreeSet`)
- **Unordered** — no guarantee at all (`HashMap`, `HashSet`)

**`HashSet` iteration order is not random — it's just not guaranteed**, and it changes with capacity.
Relying on it is a bug that appears when the set grows.

| A queue | **`ArrayDeque`** | |

## Complexity — the table you must know cold

| Operation | `ArrayList` | `LinkedList` | `HashMap`/`HashSet` | `TreeMap`/`TreeSet` | `ArrayDeque` |
|---|---|---|---|---|---|
| `get(index)` | **O(1)** | O(n) | — | — | — |
| `get(key)` | — | — | **O(1)** avg | O(log n) | — |
| `add` (end) | **O(1)** amortised | O(1) | O(1) avg | O(log n) | O(1) amortised |
| `add` (index) | O(n) | O(n) to find + O(1) to link | — | — | — |
| `add` (front) | **O(n)** | **O(1)** | — | — | **O(1)** |
| `remove` (index) | O(n) | O(n) | — | — | — |
| `contains` | **O(n)** | O(n) | **O(1)** avg | O(log n) | O(n) |
| Memory per element | Low | **High** (2 pointers + node) | Moderate | Moderate | Low |

**Two rows that decide most real choices:**

- **`contains` is O(n) on a `List` and O(1) on a `HashSet`.** Using `list.contains()` inside a loop is
  an accidental O(n²) — one of the most common performance bugs in real code.
- **`LinkedList` is O(1) to insert *once you have the node*, but O(n) to find it.** That caveat
  destroys almost every argument for using it (Day 047).

## Legacy — recognise and avoid

| Legacy | Use instead | Why |
|---|---|---|
| `Vector` | `ArrayList` | Synchronizes every method, uselessly |
| `Hashtable` | `HashMap` / `ConcurrentHashMap` | Same, and rejects nulls |
| `Stack` | `ArrayDeque` | Extends `Vector` — you can index into the middle of a "stack" (Day 037) |
| `Enumeration` | `Iterator` | |

**They all synchronize every method**, which is both slow and insufficient — a compound operation
like check-then-put still isn't atomic (Day 040's B-06). **Per-method synchronization gives you the
cost of thread safety without the benefit.**

## Null handling — inconsistent, and it catches people

| Collection | Null key | Null value |
|---|---|---|
| `HashMap` | ✅ one | ✅ |
| `LinkedHashMap` | ✅ one | ✅ |
| `TreeMap` | ❌ NPE (needs to compare) | ✅ |
| **`ConcurrentHashMap`** | ❌ **NPE** | ❌ **NPE** |
| `Hashtable` | ❌ | ❌ |
| `ArrayList` | — | ✅ |
| `List.of(...)` | — | ❌ **NPE** |

**Why `ConcurrentHashMap` forbids nulls** — a genuinely good interview answer:

```java
map.get(key)     // returns null
```

In a single-threaded `HashMap` you disambiguate with `containsKey`. In a concurrent map that's
useless — the mapping could be added or removed between the two calls. **The ambiguity is
unresolvable, so nulls are banned.**

**And `List.of()` rejects nulls** while `Arrays.asList()` permits them — a real difference between
two things that look interchangeable.

## Immutable collections

```java
List.of("a", "b")                    // Java 9+ — truly immutable, rejects nulls
Set.of(1, 2, 3)
Map.of("k", 1, "k2", 2)
Map.ofEntries(entry("k", 1), ...)    // for more than 10 pairs

List.copyOf(existing)                // immutable COPY (Day 034A)
Collections.unmodifiableList(l)      // a VIEW — the backing list can still change!
```

Day 034A covered the `unmodifiableList` trap. **`List.of` and `copyOf` are the right defaults.**

## Iteration and removal

```java
// 💀 ConcurrentModificationException
for (String s : list) if (s.isEmpty()) list.remove(s);

// ✅ Iterator.remove
Iterator<String> it = list.iterator();
while (it.hasNext()) if (it.next().isEmpty()) it.remove();

// ✅ best
list.removeIf(String::isEmpty);
```

Day 052 covers the mechanism. **`removeIf` is the modern answer**, and it's a default method — one of
the ones default methods were invented to add (Day 039).

## Type this yourself

```java
import java.util.*;

public class HierarchyDemo {
    public static void main(String[] args) {

        // ---- Map views are LIVE ----
        Map<String, Integer> map = new HashMap<>(Map.of("a", 1, "b", 2, "c", 3));
        System.out.println("--- map views are live ---");
        Set<String> keys = map.keySet();
        keys.remove("a");                                    // removes the ENTRY
        System.out.println("   after keySet().remove(\"a\"): " + map);
        for (Map.Entry<String, Integer> e : map.entrySet()) e.setValue(e.getValue() * 10);
        System.out.println("   after entry.setValue: " + map);

        // ---- ordered vs sorted vs unordered ----
        System.out.println("\n--- iteration order ---");
        List<String> input = List.of("banana", "apple", "cherry", "date");
        System.out.println("   HashSet:       " + new HashSet<>(input));
        System.out.println("   LinkedHashSet: " + new LinkedHashSet<>(input));
        System.out.println("   TreeSet:       " + new TreeSet<>(input));

        // ---- contains: O(n) vs O(1) — MEASURE IT ----
        int n = 40_000;
        List<Integer> list = new ArrayList<>();
        Set<Integer> set = new HashSet<>();
        for (int i = 0; i < n; i++) { list.add(i); set.add(i); }

        long start = System.currentTimeMillis();
        int found = 0;
        for (int i = 0; i < n; i++) if (list.contains(i)) found++;
        long listTime = System.currentTimeMillis() - start;

        start = System.currentTimeMillis();
        for (int i = 0; i < n; i++) if (set.contains(i)) found++;
        long setTime = System.currentTimeMillis() - start;

        System.out.printf("%n--- contains() on %,d elements ---%n", n);
        System.out.printf("   List (O(n) each → O(n²)): %,5d ms%n", listTime);
        System.out.printf("   Set  (O(1) each → O(n)):  %,5d ms%n", setTime);
        System.out.printf("   ratio: %.0f×   (found=%d)%n",
                (double) listTime / Math.max(setTime, 1), found);

        // ---- null handling ----
        System.out.println("\n--- nulls ---");
        Map<String, String> hash = new HashMap<>();
        hash.put(null, "ok");
        System.out.println("   HashMap null key:            allowed → " + hash.get(null));
        try { new TreeMap<String,String>().put(null, "x"); }
        catch (NullPointerException e) { System.out.println("   TreeMap null key:            NPE"); }
        try { new java.util.concurrent.ConcurrentHashMap<String,String>().put("k", null); }
        catch (NullPointerException e) { System.out.println("   ConcurrentHashMap null value: NPE"); }
        try { List.of("a", null); }
        catch (NullPointerException e) { System.out.println("   List.of with null:            NPE"); }

        // ---- removal during iteration ----
        System.out.println("\n--- removal ---");
        List<String> items = new ArrayList<>(List.of("a", "", "b", "", "c"));
        try {
            for (String s : items) if (s.isEmpty()) items.remove(s);
        } catch (ConcurrentModificationException e) {
            System.out.println("   for-each + remove: ConcurrentModificationException");
        }
        items = new ArrayList<>(List.of("a", "", "b", "", "c"));
        items.removeIf(String::isEmpty);
        System.out.println("   removeIf:          " + items);
    }
}
```

**Record the `contains` ratio.** At 40,000 elements it's typically hundreds of times. That single
measurement is the practical reason the hierarchy matters — **`list.contains()` in a loop is the most
common accidental O(n²) in Java code.**

## Interview questions

**Q: Why isn't `Map` part of the `Collection` hierarchy?**
> A `Collection` is a group of individual elements with a single-element `add` and an iterator over
> elements. A `Map` holds key-value mappings, so those operations don't apply. It exposes collection
> views instead — `keySet`, `values` and `entrySet` — which are live views backed by the map, not
> copies.

**Q: `List`, `Set`, `Queue`, `Map` — what does each guarantee?**
> `List` is an ordered, indexed sequence permitting duplicates. `Set` forbids duplicates as defined by
> `equals`. `Queue` defines an ordering for processing, usually FIFO. `Map` associates unique keys
> with values.

**Q: What's the difference between ordered and sorted?**
> Ordered means there's a defined iteration order, such as insertion order in `ArrayList` or
> `LinkedHashMap`. Sorted means iteration follows a comparison order, as in `TreeMap`. `HashMap` is
> neither — its iteration order isn't guaranteed and changes as the table resizes.

**Q: Why does `ConcurrentHashMap` forbid null values?**
> Because `get` returning null would be ambiguous — absent key, or key mapped to null? In a
> single-threaded `HashMap` you disambiguate with `containsKey`, but in a concurrent map the mapping
> can change between the two calls, so the ambiguity is unresolvable. Banning nulls removes it.

**Q: Why avoid `Vector`, `Hashtable` and `Stack`?**
> They synchronize every method, which costs on every call and still doesn't make compound operations
> atomic — a check-then-act sequence remains racy. `Stack` also extends `Vector`, so you can index
> into the middle of a stack, which breaks the abstraction. Use `ArrayList`, `ConcurrentHashMap` and
> `ArrayDeque`.
