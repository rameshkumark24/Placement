# L-031 · Arrays

## What an array is

**A fixed-size, contiguous block of memory holding elements of one type.**

Three properties, each with consequences:

| Property | Consequence |
|---|---|
| **Fixed size** | Set at creation, never changes. Growth = allocate + copy. |
| **Contiguous** | O(1) indexing by address arithmetic; excellent cache locality *(Day 001)* |
| **Homogeneous** | One element type, checked at runtime for reference arrays |

```java
int[] nums = new int[5];              // [0, 0, 0, 0, 0]  — zero-initialised
int[] nums = {1, 2, 3, 4, 5};         // literal
int[] nums = new int[]{1, 2, 3};      // explicit form (needed when not a declaration)

String[] names = new String[3];        // [null, null, null]
boolean[] flags = new boolean[3];      // [false, false, false]
```

**Arrays are objects** — they live on the heap (Day 025), have a `length` field, and inherit from
`Object`. But `length` is a *field*, not a method:

```java
array.length      // field — no parentheses
string.length()   // method
list.size()       // method
```

Three different spellings for the same concept. It catches everyone at least once.

## Why indexing is O(1)

```
   int[] arr = {10, 20, 30, 40};

   base address: 0x1000
   ┌────────┬────────┬────────┬────────┐
   │   10   │   20   │   30   │   40   │
   └────────┴────────┴────────┴────────┘
    0x1000   0x1004   0x1008   0x100C

   arr[2]  →  0x1000 + (2 × 4)  =  0x1008
```

**One multiply, one add.** No traversal. That's the entire reason arrays are the base of every
performant data structure.

**And it's why array iteration beats linked-list traversal** even at equal element counts — Day 001's
cache-line experiment. One cache line brings in 16 `int`s; the prefetcher predicts the pattern.
Linked-list nodes are scattered, so nearly every step is a cache miss. Day 047 revisits this with
`ArrayList` vs `LinkedList`.

## Bounds checking

```java
int[] a = new int[3];
a[3] = 1;      // ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
a[-1] = 1;     // same
```

**Every array access is bounds-checked at runtime.** That's memory safety (Day 023) — a C program
would happily write past the end and corrupt whatever is there.

**Does it cost?** Barely. The JIT eliminates most checks it can prove safe — in a `for (int i = 0;
i < a.length; i++)` loop it proves `i` is in range and removes the check entirely. **Bounds-check
elimination** is one of C2's standard optimisations (Day 023).

## 2D arrays — arrays of arrays

**Java has no true 2D arrays.** A `int[][]` is an array of references to `int[]` objects.

```java
int[][] grid = new int[3][4];

   grid ──▶ ┌───┬───┬───┐
            │ • │ • │ • │        an int[3] of REFERENCES
            └─┬─┴─┬─┴─┬─┘
              │   │   └──▶ [0,0,0,0]     separate int[4] objects,
              │   └──────▶ [0,0,0,0]     NOT necessarily adjacent in memory
              └──────────▶ [0,0,0,0]
```

**Consequences:**

```java
int[][] jagged = new int[3][];         // rows unallocated
jagged[0] = new int[5];                // rows can have DIFFERENT lengths
jagged[1] = new int[2];

grid.length        // number of rows
grid[0].length     // length of row 0 — may differ from grid[1].length
```

**Row-major traversal is much faster than column-major**, because each row is contiguous:

```java
for (int i = 0; i < rows; i++)
    for (int j = 0; j < cols; j++)
        sum += grid[i][j];              // ✅ walks each row contiguously

for (int j = 0; j < cols; j++)
    for (int i = 0; i < rows; i++)
        sum += grid[i][j];              // 💀 jumps between rows — cache miss each step
```

**You will measure this today.** On large grids the difference is often 3–10×, from nothing but loop
order.

## Copying — and the shallow-copy trap

```java
int[] a = {1, 2, 3};
int[] b = a;                            // ❌ NOT a copy — same array, two references
b[0] = 99;                              // a[0] is now 99 too

int[] c = a.clone();                            // ✅ copy
int[] d = Arrays.copyOf(a, a.length);           // ✅ copy, can resize
int[] e = Arrays.copyOfRange(a, 1, 3);          // ✅ [1, 3)
System.arraycopy(a, 0, dest, 0, a.length);      // ✅ fastest — native intrinsic
```

**`System.arraycopy` is a JVM intrinsic** — the JIT replaces it with an optimised native memory move,
often SIMD. It's what `ArrayList.add` and `Arrays.copyOf` use internally (Day 046).

### Shallow vs deep

```java
int[][] original = {{1, 2}, {3, 4}};
int[][] shallow = original.clone();       // copies the ROW REFERENCES only
shallow[0][0] = 99;
// original[0][0] is now 99 — the rows are shared!

int[][] deep = new int[original.length][];
for (int i = 0; i < original.length; i++)
    deep[i] = original[i].clone();        // ✅ actually independent
```

**`clone()` on any array of references is shallow.** This is the same problem as defensive copying
(Day 034A) — and it's why `Arrays.deepToString` and `Arrays.deepEquals` exist as separate methods.

## The `Arrays` utility class

```java
Arrays.sort(a);                          // dual-pivot quicksort for primitives
Arrays.sort(objs, comparator);           // TimSort for objects — STABLE
Arrays.binarySearch(a, key);             // requires a SORTED array
Arrays.fill(a, 7);
Arrays.equals(a, b);                     // element-wise, 1D
Arrays.deepEquals(a2d, b2d);             // recursive, for nested
Arrays.toString(a);                      // "[1, 2, 3]"
Arrays.deepToString(a2d);                // "[[1, 2], [3, 4]]"
Arrays.stream(a).sum();
Arrays.asList(a);                        // ⚠️ see below
```

**Why two sort algorithms?**

| Array of | Algorithm | Stable? | Why |
|---|---|---|---|
| **Primitives** | Dual-pivot quicksort | No | Stability is meaningless — equal ints are indistinguishable. Quicksort has better cache behaviour. |
| **Objects** | TimSort (merge sort) | **Yes** | Equal objects may differ in other fields, so preserving input order matters. Also fast on partly-sorted data. |

**That's a genuinely good interview answer**, and most people don't know Java uses different
algorithms for the two.

### The `Arrays.asList` traps

```java
List<String> list = Arrays.asList("a", "b", "c");
list.set(0, "z");        // ✅ allowed — writes through to the backing array
list.add("d");           // 💥 UnsupportedOperationException — FIXED SIZE
```

It returns a **fixed-size view**, not a real `ArrayList`. And with primitives:

```java
int[] nums = {1, 2, 3};
List<int[]> wrong = Arrays.asList(nums);          // a list of ONE int[] !
List<Integer> right = Arrays.stream(nums).boxed().toList();
```

**Because generics can't hold primitives** (Day 028), `Arrays.asList(int[])` treats the whole array
as a single element. Classic bug.

Modern alternatives: `List.of(...)` — truly immutable, and `new ArrayList<>(Arrays.asList(...))` when
you need a mutable list.

## Array covariance — a design flaw

```java
Object[] objects = new String[3];        // ✅ compiles! Arrays are COVARIANT
objects[0] = 42;                          // 💥 ArrayStoreException at RUNTIME
```

**Arrays are covariant**: `String[]` is a subtype of `Object[]`. This is unsound, so the JVM
checks every store at runtime and throws `ArrayStoreException`.

**Generics fixed this by being invariant** — `List<String>` is *not* a `List<Object>`, and the error
is caught at compile time instead. That's Day 054–056, and this is the motivation for it.

## Type this yourself

```java
import java.util.*;

public class ArrayDemo {
    public static void main(String[] args) {

        // ---- 1. Reference vs copy ----
        int[] a = {1, 2, 3};
        int[] alias = a;
        int[] copy  = a.clone();
        alias[0] = 99;
        System.out.println("a after alias write: " + Arrays.toString(a));      // [99,2,3]
        System.out.println("copy unaffected:     " + Arrays.toString(copy));   // [1,2,3]

        // ---- 2. Shallow clone of a 2D array ----
        int[][] orig = {{1, 2}, {3, 4}};
        int[][] shallow = orig.clone();
        shallow[0][0] = 99;
        System.out.println("\nShallow clone leaked: " + Arrays.deepToString(orig));

        int[][] deep = new int[orig.length][];
        for (int i = 0; i < orig.length; i++) deep[i] = orig[i].clone();
        deep[1][0] = 77;
        System.out.println("Deep copy safe:      " + Arrays.deepToString(orig));

        // ---- 3. Row-major vs column-major — MEASURE IT ----
        int n = 4000;
        int[][] grid = new int[n][n];

        long start = System.currentTimeMillis();
        long sum1 = 0;
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++) sum1 += grid[i][j];      // contiguous
        long rowMajor = System.currentTimeMillis() - start;

        start = System.currentTimeMillis();
        long sum2 = 0;
        for (int j = 0; j < n; j++)
            for (int i = 0; i < n; i++) sum2 += grid[i][j];      // cache-hostile
        long colMajor = System.currentTimeMillis() - start;

        System.out.printf("%nRow-major:    %,5d ms%n", rowMajor);
        System.out.printf("Column-major: %,5d ms%n", colMajor);
        System.out.printf("Same work, %.1f× slower from LOOP ORDER alone%n",
                (double) colMajor / Math.max(rowMajor, 1));

        // ---- 4. Copy methods, timed ----
        int[] big = new int[10_000_000];
        int[] dest = new int[10_000_000];

        start = System.nanoTime();
        for (int i = 0; i < big.length; i++) dest[i] = big[i];
        System.out.printf("%nManual loop:      %,4d ms%n", (System.nanoTime() - start) / 1_000_000);

        start = System.nanoTime();
        System.arraycopy(big, 0, dest, 0, big.length);
        System.out.printf("System.arraycopy: %,4d ms  (native intrinsic)%n",
                (System.nanoTime() - start) / 1_000_000);

        // ---- 5. Arrays.asList traps ----
        List<String> fixed = Arrays.asList("a", "b");
        try { fixed.add("c"); }
        catch (UnsupportedOperationException e) {
            System.out.println("\nArrays.asList is FIXED SIZE — add() throws");
        }

        int[] prims = {1, 2, 3};
        System.out.println("Arrays.asList(int[]).size() = " + Arrays.asList(prims).size()
                         + "   ← ONE element, the whole array!");
        System.out.println("Correct: " + Arrays.stream(prims).boxed().toList());

        // ---- 6. Covariance ----
        Object[] objs = new String[2];
        try { objs[0] = 42; }
        catch (ArrayStoreException e) {
            System.out.println("\nArrayStoreException — arrays are covariant, so this is a RUNTIME error");
        }
    }
}
```

**Record the row-major vs column-major numbers.** Identical arithmetic, identical element count —
and often 3–10× different. That gap is pure memory locality, and it's the same phenomenon you
measured on Day 001.

## Common mistakes

| Mistake | Correction |
|---|---|
| `array.length()` | It's a field: `array.length`. |
| `b = a` as a copy | That aliases. Use `clone()`, `Arrays.copyOf` or `System.arraycopy`. |
| `clone()` on a 2D array | Shallow — rows are shared. Copy each row. |
| Column-major iteration | Destroys cache locality. Iterate row-major. |
| `Arrays.asList(intArray)` | Gives a list of one array. Use `Arrays.stream(a).boxed()`. |
| `add()` on `Arrays.asList` | Fixed-size view. Wrap in `new ArrayList<>(...)`. |
| Expecting compile-time safety from array covariance | It's checked at runtime — `ArrayStoreException`. |
| `binarySearch` on an unsorted array | Undefined result. Sort first. |

## Interview questions

**Q: Why is array access O(1)?**
> Elements are contiguous and of uniform size, so the address is base plus index times element size —
> one multiply and one add, no traversal. Contiguity also gives excellent cache locality, which is why
> array iteration outperforms pointer-chasing structures with the same element count.

**Q: Are 2D arrays contiguous in Java?**
> No. A `int[][]` is an array of references to separate `int[]` objects, so rows can have different
> lengths and aren't necessarily adjacent in memory. That's why row-major traversal is substantially
> faster than column-major — each row is contiguous but the rows themselves may be scattered.

**Q: Why does Java use different sorting algorithms for primitives and objects?**
> Primitives use dual-pivot quicksort, which isn't stable — but stability is meaningless for
> primitives since equal values are indistinguishable, and quicksort has better cache behaviour.
> Objects use TimSort, which is stable, because equal-comparing objects may differ in other fields and
> preserving input order matters. TimSort is also very fast on partially sorted input.

**Q: What's wrong with array covariance?**
> `String[]` is a subtype of `Object[]`, which is unsound — you can assign a `String[]` to an
> `Object[]` reference and attempt to store an `Integer`. The JVM has to check every store at runtime
> and throw `ArrayStoreException`. Generics are invariant precisely to move that error to compile time.

**Q: What does `Arrays.asList` return?**
> A fixed-size list view backed by the original array. You can set elements, which writes through, but
> not add or remove. With a primitive array it treats the whole array as a single element, because
> generics can't hold primitives.
