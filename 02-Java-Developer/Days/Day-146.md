# Part 1 — A controller that reflects Day 103's decisions

```java
@RestController
@RequestMapping("/api/orders")                       // ⭐ class-level prefix, one place to change
class OrderController {

    private final OrderService orders;                // Day 131 — constructor injection

    OrderController(OrderService orders) { this.orders = orders; }

    @GetMapping("/{id}")
    OrderResponse get(@PathVariable UUID id) {
        return orders.find(id).orElseThrow(() -> new OrderNotFoundException(id));
    }

    @GetMapping
    Page<OrderResponse> list(@RequestParam(required = false) OrderStatus status,
                             Pageable pageable) { ... }          // Day 152

    @PostMapping
    ResponseEntity<OrderResponse> create(@Valid @RequestBody CreateOrderRequest req,
                                         UriComponentsBuilder uri) {
        OrderResponse created = orders.place(req);
        return ResponseEntity
                .created(uri.path("/api/orders/{id}").buildAndExpand(created.id()).toUri())  // ⭐ 201 + Location
                .body(created);
    }

    @PutMapping("/{id}/status")
    OrderResponse updateStatus(@PathVariable UUID id,
                               @Valid @RequestBody UpdateStatusRequest req) { ... }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)                        // ⭐ 204, not 200
    void cancel(@PathVariable UUID id) { orders.cancel(id); }
}
```

Everything notable there is a Stage 3 decision, not a Spring one:

| Line | The decision it encodes | Built on |
|---|---|---|
| `/api/orders` plural noun | resources are nouns; collections are plural | Day 103 |
| `201` + `Location` | a creation tells the client where the thing now lives | Day 102 |
| `204` on delete | no body means no body; do not return `{"success":true}` | Day 102 |
| `PUT /{id}/status` | a state transition is a sub-resource, not a verb in the path | Day 103 |
| `@Valid` at the boundary | validate at the trust boundary, once | Day 105 |
| `OrderResponse` not `Order` | never expose the entity | Day 147 |

## `UriComponentsBuilder` rather than string concatenation

Injecting `UriComponentsBuilder` gives you a builder **pre-populated with the current request's scheme,
host and port**, so the `Location` header is correct behind a load balancer and in tests, and
`buildAndExpand` URL-encodes the segment. Hand-built `"/api/orders/" + id` breaks the first time an id
contains a slash or the service moves behind a path prefix.

Behind a proxy this needs one more thing — Day 155's `server.forward-headers-strategy: framework`,
without which `Location` claims `http://localhost:8080` and clients follow it into nowhere.

# Part 2 — The mapping behaviours that surprise people

## ⭐ Ambiguity is a startup failure, and that is a feature

```java
@GetMapping("/{id}")      OrderResponse get(@PathVariable String id) { }
@GetMapping("/{orderId}") OrderResponse get2(@PathVariable String orderId) { }
```

```
IllegalStateException: Ambiguous mapping. Cannot map 'orderController' method ...
There is already 'orderController' bean method ... mapped.
```

**The application refuses to start.** Compare with the alternative, which is a coin-flip at runtime
depending on scan order. Day 133's principle again — a failure at startup is a rolled-back deploy;
the same failure at request time is an incident.

## ⭐ Static wins over variable, but only when it is genuinely more specific

```java
@GetMapping("/{id}")      // /api/orders/search would match this…
@GetMapping("/search")    // …but this wins: literal beats template
```

The precedence is literal > single-segment template `{x}` > multi-segment `**`. Rely on it and it
works — but **do not rely on it for security**, because the resolution is subtle and a refactor can
change it. A `/search` collection endpoint that only accidentally avoids the `{id}` handler is
fragile design.

## `PathPattern` and the Boot 3 trailing-slash change

**Boot 3 stopped matching trailing slashes.** `/api/orders` no longer matches `/api/orders/`, and the
result is a 404 for clients that had always sent the slash. This broke a lot of upgrades quietly,
because it only shows up for the subset of callers with the trailing slash habit.

```java
// If you must restore it — deprecated, and a migration crutch, not a fix
@Configuration
class WebConfig implements WebMvcConfigurer {
    @Override public void configurePathMatch(PathMatchConfigurer c) {
        c.setUseTrailingSlashMatch(true);
    }
}
```

The correct answer is to fix the clients or 301-redirect at the ingress, because the Spring option is
deprecated and will go.

## `@RequestParam` defaults, and the difference that produces a 400

```java
@RequestParam String q                              // required → 400 if absent
@RequestParam(required = false) String q            // null if absent
@RequestParam(defaultValue = "10") int size         // ⭐ implies required=false
@RequestParam Optional<String> q                    // ⭐ clearer than nullable
@RequestParam Map<String,String> all                // everything — usually a smell
@RequestParam List<String> tags                     // ?tags=a&tags=b  or  ?tags=a,b
```

**`@RequestParam(required = false) int size` is a 500 waiting to happen** — absent means `null`, and
`null` cannot be unboxed into `int`. Either use `Integer` or give it a `defaultValue`. This is
Day 034's autoboxing NPE, arriving via HTTP.

## `consumes` and `produces` are mapping *conditions*, not documentation

```java
@PostMapping(consumes = APPLICATION_JSON_VALUE, produces = APPLICATION_JSON_VALUE)
```

They participate in matching. Wrong `Content-Type` → **415**. Unsatisfiable `Accept` → **406**. Both
are mapping outcomes decided at Day 145's step 1 and step 6 respectively, which is why neither is a
bug in your handler.

## Enums and dates — the two conversions people fight

```java
@GetMapping
List<OrderResponse> list(@RequestParam(required = false) OrderStatus status,
                         @RequestParam @DateTimeFormat(iso = ISO.DATE) LocalDate from) { }
```

`?status=shipped` fails by default: enum conversion is **case-sensitive**. `?status=SHIPPED` works. If
you want lenient parsing, that is a `Converter`, registered once:

```java
@Component
class StringToOrderStatusConverter implements Converter<String, OrderStatus> {
    @Override public OrderStatus convert(String s) {
        return OrderStatus.valueOf(s.trim().toUpperCase(Locale.ROOT));
    }
}
```

Without `@DateTimeFormat`, `LocalDate` binding depends on the default parser and locale, which is the
Day 057-flavoured trap: it works on your machine and fails in a container with a different locale.
**Be explicit about date formats at the boundary, always.**

## `@ResponseStatus` vs `ResponseEntity`

| | Use when |
|---|---|
| `@ResponseStatus(NO_CONTENT)` | the status is fixed for this handler. Cleaner signature |
| `ResponseEntity<T>` | status or headers depend on the outcome — 200 vs 201, `Location`, `ETag`, `Cache-Control` |

Day 102's `ETag`/`If-Match` flow needs `ResponseEntity`, because the header is the point:

```java
@GetMapping("/{id}")
ResponseEntity<OrderResponse> get(@PathVariable UUID id) {
    Order o = orders.get(id);
    return ResponseEntity.ok()
            .eTag("\"" + o.version() + "\"")                    // ⭐ Day 102
            .cacheControl(CacheControl.maxAge(Duration.ofSeconds(30)).cachePrivate())
            .body(OrderResponse.from(o));
}
```

**Do not return `ResponseEntity<Object>` or `ResponseEntity<?>`** — it erases the schema, so
springdoc (Day 153) documents your endpoint as returning "an object", and every consumer generator
produces garbage.

# Part 3 — Keeping the controller thin

**A controller does exactly four things:** bind and validate input, call one service method, map the
result to a response type, and choose the status and headers. Anything else has escaped its layer.

```java
// ❌ business logic in the controller
@PostMapping
ResponseEntity<OrderResponse> create(@RequestBody CreateOrderRequest req) {
    if (req.quantity() > 100 && !customer.isWholesale()) throw new BadRequestException("...");
    BigDecimal total = req.quantity() * price.of(req.productId());
    if (total.compareTo(customer.creditLimit()) > 0) throw new BadRequestException("...");
    ...
}
```

Two rules make the reason concrete rather than stylistic:

1. **Rules in the controller cannot be reused.** The same order placed by a scheduled job, a Kafka
   consumer or an admin CLI silently skips every check. That is not a style preference; it is a
   correctness hole, and it is Day 105's *validate at the boundary, enforce in the domain* split.
2. **Rules in the controller need `MockMvc` and a servlet context to test.** In the service they are
   a plain unit test. Day 097's pyramid, expressed as a package decision.

## `@RestControllerAdvice` for cross-cutting binding

```java
@RestControllerAdvice
class BindingAdvice {
    @InitBinder
    void restrictFields(WebDataBinder binder) {
        binder.setDisallowedFields("id", "createdAt", "customerId");   // ⭐ Day 105, defence in depth
    }
}
```

Day 147 argues the real fix — a request DTO that has no such fields to bind. Keep this as a second
layer, not the primary one.

## Common mistakes

| Mistake | Why it hurts |
|---|---|
| `@RequestParam(required=false) int` | unboxing NPE → 500 |
| Returning 200 with a body on POST create | client cannot learn the new URI; Day 102 |
| 200 + `{"deleted":true}` on DELETE | 204 exists precisely for this |
| Verbs in paths (`/orders/create`) | Day 103 |
| Hand-built `Location` | breaks behind a proxy, and does not encode |
| Relying on literal-beats-template for security | fragile under refactor |
| `ResponseEntity<?>` | destroys the OpenAPI schema |
| Business rules in the controller | unreachable from jobs and consumers; needs MockMvc to test |
| No `@DateTimeFormat` | locale-dependent parsing, container-only failures |
| Assuming trailing slashes still match in Boot 3 | silent 404s after upgrade |

## Interview questions

**Q: POST returns what?**
201 with a `Location` header pointing at the created resource, and usually the representation in the
body so the client avoids a second round trip. Built with `UriComponentsBuilder` so it is correct
behind a proxy.

**Q: `@ResponseStatus` or `ResponseEntity`?**
`@ResponseStatus` when the status is fixed, `ResponseEntity` when status or headers vary — ETag,
Location, Cache-Control. I avoid `ResponseEntity<?>` because it erases the response schema.

**Q: What does an ambiguous mapping do, and is that good?**
It fails at startup. It is good: the alternative is a scan-order-dependent coin flip discovered in
production.

**Q: Where does validation happen and where do business rules go?**
Structural validation at the boundary with `@Valid`; business rules in the service, because the same
operation also arrives from jobs and message consumers that never touch a controller.
