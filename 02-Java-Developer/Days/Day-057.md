# Part 1 — L-057 · Lambdas

## What a lambda is

**An instance of a functional interface, written as an expression.**

```java
Runnable r = () -> System.out.println("hi");
Comparator<String> byLength = (a, b) -> Integer.compare(a.length(), b.length());
Function<String, Integer> len = s -> s.length();
```

**A lambda always has a target type**, inferred from context — the parameter, the variable, the return
type. **There is no "lambda type" in Java.** `() -> {}` alone doesn't compile; the compiler must know
which interface you mean.

## Syntax forms

```java
() -> expr                       // no parameters
x -> expr                        // one parameter, no parens needed
(x, y) -> expr                    // two or more
(String x, int y) -> expr         // explicit types, rarely needed
x -> { statement; return v; }     // block body needs an explicit return
```

## What it compiles to — not an anonymous class

Day 024 showed the bytecode: **`invokedynamic`**, not a class file.

```
   invokedynamic #2, 0   // run:()Ljava/lang/Runnable;
```

**At first execution, `LambdaMetafactory` generates the implementation.** Consequences:

- **No `Outer$1.class` files** — less to load (Day 023), less Metaspace
- **A non-capturing lambda can be reused as a singleton** — it holds no state, so one instance
  suffices for every evaluation
- **A capturing lambda allocates**, because it must hold the captured values

```java
Runnable a = () -> System.out.println("x");
Runnable b = () -> System.out.println("x");
// a and b may or may not be the same object — but evaluating the SAME
// non-capturing lambda expression repeatedly returns a cached instance
```

**And `this` is lexically scoped** — Day 044's key distinction. In a lambda, `this` is the enclosing
instance; in an anonymous class it's the anonymous instance.

## Capture

**Lambdas capture *values*, and only effectively final ones** (Day 034):

```java
int count = 0;
Runnable r = () -> System.out.println(count);
count = 1;                        // ❌ now the lambda won't compile
```

**Why:** the value is copied into the lambda. If the original could change, the lambda would silently
observe a stale copy. Rather than allow that ambiguity, the language forbids it.

**Instance fields are NOT captured** — they're reached through the captured `this`:

```java
class Counter {
    private int count;                        // a field, not a local
    Runnable r = () -> count++;                // ✅ legal — captures `this`, then dereferences
}
```

**That's a real distinction**, and it's why the array-hack workaround exists for locals but not
fields.

## The built-in functional interfaces

**`java.util.function` has 43 of them, but there are only four shapes** plus primitive
specialisations.

| Interface | Method | Takes | Returns | Mnemonic |
|---|---|---|---|---|
| **`Function<T,R>`** | `apply` | T | R | transform |
| **`Predicate<T>`** | `test` | T | `boolean` | test |
| **`Consumer<T>`** | `accept` | T | `void` | consume |
| **`Supplier<T>`** | `get` | — | T | supply |
| `UnaryOperator<T>` | `apply` | T | T | `Function<T,T>` |
| `BinaryOperator<T>` | `apply` | T, T | T | reduce |
| `BiFunction<T,U,R>` | `apply` | T, U | R | |
| `BiConsumer<T,U>` | `accept` | T, U | `void` | `Map.forEach` |
| `BiPredicate<T,U>` | `test` | T, U | `boolean` | |

**Learn the four core ones by their shape** — takes/returns — and the rest are variations.

### Primitive specialisations — and why they exist

```java
IntPredicate, IntFunction<R>, ToIntFunction<T>, IntUnaryOperator,
LongSupplier, DoubleConsumer, ObjIntConsumer<T>, ...
```

**They exist to avoid boxing** (Day 028). `Predicate<Integer>` boxes every value; `IntPredicate`
doesn't.

**That's why `IntStream` exists separately from `Stream<Integer>`** — in a tight loop the boxing cost
is 10–20×.

## Default methods make them composable

**This is the part people underuse.** Every core interface has combinators (Day 039):

```java
Predicate<String> notEmpty = s -> !s.isEmpty();
Predicate<String> shortStr = s -> s.length() < 10;

Predicate<String> valid = notEmpty.and(shortStr);
Predicate<String> invalid = valid.negate();
Predicate<String> either = notEmpty.or(shortStr);
Predicate<String> notNull = Predicate.not(Objects::isNull);      // Java 11 static

Function<String, Integer> length = String::length;
Function<Integer, String> describe = n -> "len=" + n;
Function<String, String> pipeline = length.andThen(describe);     // f then g
Function<String, String> reversed = describe.compose(length);      // g then f — same result

Consumer<String> log = System.out::println;
Consumer<String> both = log.andThen(s -> audit(s));

Comparator<Person> cmp = Comparator.comparing(Person::last)
                                   .thenComparing(Person::first)
                                   .reversed();
```

**`andThen` versus `compose` catches people:** `f.andThen(g)` is `g(f(x))`; `f.compose(g)` is
`f(g(x))`. Reading order versus mathematical order.

## Writing your own

```java
@FunctionalInterface
interface Validator<T> {
    boolean validate(T input);                          // the ONE abstract method

    default Validator<T> and(Validator<T> other) {      // doesn't count
        return t -> this.validate(t) && other.validate(t);
    }
    static <T> Validator<T> alwaysTrue() { return t -> true; }   // doesn't count
}
```

**Use `@FunctionalInterface`** — a compile-time assertion (Day 039). Adding a second abstract method
fails the build instead of breaking every lambda.

**But prefer the built-in interfaces** where they fit. A custom `interface StringTransformer` that's
really a `Function<String,String>` doesn't compose with anything in the JDK.

**Write your own when:** the parameter names carry meaning, you need checked exceptions, or the arity
isn't covered.

### The checked exception problem

```java
list.forEach(s -> Files.readString(Path.of(s)));   // ❌ IOException isn't handled
```

**None of the built-in interfaces declare checked exceptions**, so you can't throw one from a lambda
passed to them.

Options: wrap in an unchecked exception, write your own throwing interface, or use a library
(`vavr`, `jOOλ`). **This is a genuine wart** and a fair thing to mention — it's the most common
friction point with lambdas in real code.

## Type this yourself

```java
import java.util.*;
import java.util.function.*;

public class LambdaDemo {

    @FunctionalInterface
    interface Validator<T> {
        boolean validate(T t);
        default Validator<T> and(Validator<T> other) { return x -> validate(x) && other.validate(x); }
        default Validator<T> negate() { return x -> !validate(x); }
        static <T> Validator<T> notNull() { return Objects::nonNull; }
    }

    record Person(String first, String last, int age) { }

    public static void main(String[] args) {

        // ---- the four shapes ----
        System.out.println("--- the four core interfaces ---");
        Function<String, Integer> length = String::length;
        Predicate<String> isLong = s -> s.length() > 5;
        Consumer<String> print = s -> System.out.println("      " + s);
        Supplier<String> supply = () -> "supplied value";

        System.out.println("   Function: " + length.apply("hello"));
        System.out.println("   Predicate: " + isLong.test("hello"));
        System.out.print("   Consumer: "); print.accept("consumed");
        System.out.println("   Supplier: " + supply.get());

        // ---- composition ----
        System.out.println("\n--- composition ---");
        Predicate<String> notEmpty = s -> !s.isEmpty();
        Predicate<String> shortish = s -> s.length() < 8;
        Predicate<String> valid = notEmpty.and(shortish);
        for (String s : List.of("", "ok", "averylongstring"))
            System.out.printf("   valid(\"%s\") = %b%n", s, valid.test(s));

        Function<String, Integer> len = String::length;
        Function<Integer, String> tag = n -> "[len=" + n + "]";
        System.out.println("   andThen: " + len.andThen(tag).apply("hello"));
        System.out.println("   compose: " + tag.compose(len).apply("hello"));

        // ---- custom functional interface ----
        System.out.println("\n--- custom ---");
        Validator<String> v = Validator.<String>notNull()
                .and(s -> !s.isBlank())
                .and(s -> s.length() <= 10);
        for (String s : Arrays.asList("ok", "", null, "waytoolongvalue"))
            System.out.printf("   validate(%s) = %b%n", s, s == null ? false : v.validate(s));

        // ---- `this` is lexical (Day 044) ----
        new LambdaDemo().thisDemo();

        // ---- capture ----
        System.out.println("\n--- capture ---");
        int captured = 42;
        Runnable r = () -> System.out.println("   captured local = " + captured);
        r.run();
        // captured = 43;      // ← uncomment: the LAMBDA stops compiling

        // ---- boxing cost ----
        int n = 40_000_000;
        Predicate<Integer> boxed = x -> x % 2 == 0;
        IntPredicate primitive = x -> x % 2 == 0;

        long start = System.nanoTime();
        int count = 0;
        for (int i = 0; i < n; i++) if (boxed.test(i)) count++;
        long boxedTime = System.nanoTime() - start;

        start = System.nanoTime();
        for (int i = 0; i < n; i++) if (primitive.test(i)) count++;
        long primTime = System.nanoTime() - start;

        System.out.printf("%n--- boxing (%,d calls) ---%n", n);
        System.out.printf("   Predicate<Integer>: %,5d ms%n", boxedTime / 1_000_000);
        System.out.printf("   IntPredicate:       %,5d ms   ← no boxing%n", primTime / 1_000_000);
        System.out.println("   (count=" + count + ")");

        // ---- comparators ----
        System.out.println("\n--- comparator chains ---");
        List<Person> people = new ArrayList<>(List.of(
                new Person("Ada", "Lovelace", 36),
                new Person("Alan", "Turing", 41),
                new Person("Grace", "Hopper", 41)));
        people.sort(Comparator.comparingInt(Person::age).thenComparing(Person::first));
        people.forEach(p -> System.out.println("   " + p));
    }

    private String field = "OUTER";

    void thisDemo() {
        System.out.println("\n--- `this` in lambda vs anonymous class ---");
        Runnable lambda = () -> System.out.println("   lambda:    " + this.field);
        Runnable anon = new Runnable() {
            @Override public void run() {
                System.out.println("   anonymous: this is " + this.getClass().getSimpleName()
                        + " — must write LambdaDemo.this.field = " + LambdaDemo.this.field);
            }
        };
        lambda.run(); anon.run();
    }
}
```

**Record the boxing comparison** — `IntPredicate` versus `Predicate<Integer>` over 40 million calls.
That gap is why the JDK ships primitive specialisations, and why `IntStream` exists.

# Part 2 — B-11 · Demand paging and replacement

## Demand paging

Day 053's B-10 introduced paging. **Demand paging: don't load a page until it's actually accessed.**

```
   Program starts → almost NO pages loaded
   First instruction → page fault → load that page
   Access a global → page fault → load
   ...only the working set is ever brought in
```

**Why it works:** most programs touch a small fraction of their address space. Loading a 500 MB binary
entirely would waste both time and RAM.

**And it's why a JVM's `-Xms` reservation isn't immediately physical** (Day 053) — address space is
reserved, frames are committed on first touch.

## Copy-on-write

```
   fork() → child shares ALL the parent's pages, marked read-only
   either writes → page fault → copy just THAT page → both proceed
```

**`fork` is cheap because almost nothing is copied** (Day 026, B-02). Only modified pages are
duplicated, and `exec` usually replaces the image anyway.

## Page replacement — the core problem

Memory is full and you need a frame. **Which page do you evict?**

### Optimal (Bélády's algorithm)

**Evict the page that will be used furthest in the future.** Provably optimal — and **impossible**,
since it requires knowing the future.

**Its value is as a benchmark.** You measure real algorithms against it.

### FIFO

Evict the oldest-loaded page. Simple, and it ignores usage — a page loaded early and used constantly
gets evicted.

**Bélády's anomaly:** with FIFO, **adding more frames can increase the number of faults.** That's
deeply counter-intuitive and a favourite exam question. LRU and Optimal are *stack algorithms* and
never exhibit it.

### LRU — Least Recently Used

**Evict the page unused for the longest time.** Good approximation of Optimal, because of locality.

**True LRU is expensive** — you'd update a timestamp or move a list node on *every* memory access,
in hardware.

**So real systems approximate it.** The **clock (second-chance)** algorithm:

```
   Pages in a circular list, each with a REFERENCE bit set by hardware on access.

   Hand moves round:
     reference bit == 1 → clear it, give a second chance, move on
     reference bit == 0 → EVICT this one
```

**One bit per page instead of a timestamp.** Linux uses a two-list refinement (active and inactive
lists) with periodic aging.

### Comparison

| Algorithm | Quality | Cost | Bélády's anomaly |
|---|---|---|---|
| **Optimal** | Best possible | Impossible | No |
| **LRU** | Near-optimal | High (per-access tracking) | No |
| **Clock** | Good | **Low — one bit** | No |
| **FIFO** | Poor | Very low | **Yes** |

## Thrashing

**The system spends more time paging than computing.**

```
   Working set doesn't fit in RAM
        → page fault
        → evict a page that's about to be needed
        → immediate fault on it
        → evict another needed page
        → ...
   CPU utilisation collapses toward zero. Disk saturates.
```

**The signature:** high disk I/O, near-zero CPU utilisation, unresponsive system. Adding more
processes makes it worse, not better.

**The fix:** reduce the degree of multiprogramming — suspend processes — or add RAM. **The
working-set model** sizes each process's allocation to its recent locality.

## Why this matters for the JVM

**This is the mechanism behind Day 027's rule "never let a JVM swap":**

- **GC touches large regions of the heap** in a short window. If pages have been evicted, a collection
  triggers thousands of major faults at ~100 µs each — Day 001's ladder.
- **A pause budgeted at 50 ms becomes seconds**, and G1's pause-time goal becomes meaningless.
- **GC's access pattern defeats LRU.** A full scan touches everything once, evicting exactly the pages
  the application was using — so the app then faults on its own working set.

**Practical consequences you already have on your checklist** (Day 027):

- `-Xms` = `-Xmx` — commit the heap once
- `MaxRAMPercentage` — leave room for Metaspace, thread stacks and direct buffers inside the cgroup
- **Disable swap on JVM hosts** (`vm.swappiness=0`, or none at all in Kubernetes) — better to fail
  fast with an OOM than to degrade into thrashing
- **Huge pages** for large heaps — fewer TLB entries to cover the same memory

## Interview questions

**Q: What is a lambda, and what does it compile to?**
> An instance of a functional interface written as an expression, with the target type inferred from
> context. It compiles to an `invokedynamic` instruction, not an anonymous class — the implementation
> is generated at runtime by `LambdaMetafactory`. That means no extra class files, and a non-capturing
> lambda can be reused rather than allocated each time. Also `this` is lexically scoped, unlike in an
> anonymous class.

**Q: Name the four core functional interfaces.**
> `Function<T,R>` transforms T into R, `Predicate<T>` tests a T and returns boolean, `Consumer<T>`
> takes a T and returns nothing, `Supplier<T>` takes nothing and produces a T. Everything else in
> `java.util.function` is a variation on those shapes — binary versions, unary and binary operators,
> and primitive specialisations that exist to avoid boxing.

**Q: Why does `IntPredicate` exist when `Predicate<Integer>` works?**
> To avoid autoboxing. Every call to `Predicate<Integer>` boxes the argument, allocating and adding GC
> pressure — measurably slower in a tight loop. It's the same reason `IntStream` exists separately
> from `Stream<Integer>`.

**Q: What's the difference between `andThen` and `compose`?**
> `f.andThen(g)` applies f first, then g — reading order. `f.compose(g)` applies g first, then f —
> mathematical composition order.

**Q: What is Bélády's anomaly?**
> With FIFO page replacement, increasing the number of frames can increase the number of page faults —
> which is counter-intuitive since more memory should help. It occurs because FIFO ignores usage. LRU
> and Optimal are stack algorithms and never exhibit it.

**Q: Why is true LRU impractical, and what's used instead?**
> It would require updating usage information on every memory access, in hardware, which is
> prohibitively expensive. Real systems approximate it — the clock algorithm keeps a single reference
> bit per page, set by hardware on access, and a rotating hand evicts pages whose bit is clear while
> giving a second chance to those whose bit is set.

**Q: Why must a JVM never swap?**
> Garbage collection touches large regions of the heap in a short window, so if pages have been evicted
> a collection generates thousands of major page faults at around 100 microseconds each, turning a
> 50-millisecond pause into seconds. GC's scan pattern also defeats LRU by touching everything once,
> evicting exactly the pages the application needs.
