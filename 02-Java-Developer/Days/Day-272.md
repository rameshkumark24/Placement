# Part 1 — ⭐⭐ The eight

```
⭐⭐ THIS IS THE WHOLE SET. BUILD THESE, STOP.

⭐ ① ⭐ Button      — variant × size × state (Day 224: unions, not booleans)
⭐ ② ⭐ Input       — ⭐⭐ WITH label, error text and aria wiring BUILT IN
⭐ ③ ⭐⭐ Card       — the container everything sits in
⭐ ④ ⭐ Badge       — status. ⭐⭐ YOUR DOMAIN'S STATE MACHINE, VISIBLE
⭐ ⑤ ⭐ Skeleton    — the loading shape (Day 240)
⭐ ⑥ ⭐⭐ EmptyState — icon + message + ACTION. ⭐ Twenty minutes, and
⭐                    the most-noticed component you will write
⭐ ⑦ ⭐⭐ ErrorState — message + retry, branched by status
⭐ ⑧ ⭐ Dialog      — ⭐⭐ FROM A LIBRARY. Do NOT hand-roll focus
⭐                    trapping (Day 239)

⭐ ⭐ PLUS THREE LAYOUT PRIMITIVES: Stack, Row, Grid (Day 238)
```

| ⭐ Deliberately absent | Why |
|---|---|
| Table | ⭐ Build the *one* table your app needs, in place. A generic table is a two-week project. |
| Select / Combobox | ⭐⭐ From a library. Keyboard + ARIA + filtering is genuinely hard. |
| Toast | ⭐ From a library, or skip — inline errors are usually better |
| Tabs, Accordion, Tooltip | ⭐ Only if the demo path needs one |

# Part 2 — ⭐⭐ Every component gets its states

```
⭐⭐ THE CHECKLIST. A COMPONENT IS NOT DONE UNTIL ALL FIVE EXIST.

⭐   ① DEFAULT
⭐   ② ⭐ HOVER      ⇒ ⭐⭐ A BUTTON WITH NO HOVER FEELS BROKEN
⭐   ③ ⭐⭐ FOCUS     ⇒ :focus-visible ring. NEVER outline:none (Day 239)
⭐   ④ ⭐ DISABLED   ⇒ ⭐⭐ AND `disabled`, NOT JUST GREY
⭐   ⑤ ⭐⭐ LOADING   ⇒ on anything that triggers a request.
⭐                     ⭐ Keep the WIDTH stable — a button that shrinks
⭐                       to fit a spinner moves everything beside it.
```

```tsx
type ButtonProps = {
  variant?: "primary" | "secondary" | "danger";   // ⭐ unions (Day 224)
  size?: "sm" | "md";
  loading?: boolean;
  children: React.ReactNode;
} & React.ButtonHTMLAttributes<HTMLButtonElement>;

export function Button({ variant = "primary", size = "md",
                         loading, disabled, children, ...rest }: ButtonProps) {
  return (
    <button
      type="button"                           // ⭐⭐ THE DEFAULT THAT MATTERS
      {...rest}
      disabled={disabled || loading}          // ⭐⭐ loading implies disabled
      aria-busy={loading || undefined}
      data-variant={variant} data-size={size}
    >
      {loading ? <Spinner aria-hidden /> : null}
      <span style={{ visibility: loading ? "hidden" : undefined }}>
        {children}                            {/* ⭐⭐ WIDTH HELD — no jump */}
      </span>
    </button>
  );
}
```

> ⭐⭐ **`type="button"` should be your default.** A `<button>` inside a form submits it — which is the
> cause of a great many "the page reloaded when I clicked" bugs, and it will surprise you because it
> is the HTML default rather than React's.

# Part 3 — ⭐⭐ The abstraction trap

```
⭐⭐ THE HOUR YOU ARE ABOUT TO LOSE

⭐   You write <Card>. ⭐ Then you think: "what if someone wants a
⭐   header? a footer? a collapsible variant? a different padding?"
⭐   ⇒ ⭐⭐ YOU ARE BUILDING FOR A CALLER THAT DOES NOT EXIST, AND
⭐     YOU WILL GUESS THE SEAM WRONG, BECAUSE YOU HAVE ONE EXAMPLE
⭐     AND ABSTRACTION NEEDS TWO.

⭐   ⭐⭐ THE RULE: CONCRETE THE FIRST TIME. COPY THE SECOND TIME.
⭐     ⭐ ABSTRACT THE **THIRD** TIME — now you have three real
⭐       examples showing you where the seam is.
```

| ⭐ Smell | ⭐⭐ What it means |
|---|---|
| A prop with exactly one caller passing a non-default | ⭐ You invented a requirement |
| A component with a `variant` used once | ⭐⭐ Inline it |
| `children` **plus** a `content` prop | ⭐ Two ways to do one thing |
| Configuring padding from outside | ⭐⭐ Let the **parent** own spacing (`Stack` gap) |

> ⭐⭐ **Duplication is cheaper than the wrong abstraction.** ⭐ You have felt this in Java: the
> `AbstractBaseService<T, ID>` that three services extend and none of them fits. **Two similar cards
> you can edit independently beat one card with nine props nobody dares change.**

# Part 4 — Domain components

```
⭐⭐ THE COMPONENTS THAT MAKE IT LOOK LIKE A PRODUCT ARE YOURS,
⭐   NOT GENERIC ONES.

⭐   <OrderStatusBadge status={o.status} />
⭐     ⇒ ⭐⭐ ONE PLACE THAT KNOWS YOUR STATE MACHINE'S COLOURS AND
⭐       LABELS. ⭐ Add a value to the enum ⇒ TypeScript's exhaustive
⭐       switch makes you handle it here (Day 218).
⭐   <Money amount={p} currency={c} />
⭐     ⇒ ⭐⭐ ONE PLACE THAT FORMATS MONEY. ⭐ Day 246: BigDecimal does
⭐       NOT survive a JS number, so it arrives as a string or minor
⭐       units — and THIS COMPONENT IS WHERE THAT STOPS LEAKING INTO
⭐       EVERY SCREEN.
⭐   <RelativeTime value={iso} />
⭐     ⇒ ⭐ "3 minutes ago", with a title= holding the exact
⭐       timestamp, and ⭐⭐ TIMEZONE HANDLED ONCE INSTEAD OF NEVER.
```

> ⭐ **These three are worth more than five generic components.** They encode a domain rule in one
> place and are each a concrete answer to *"how do you handle money / time / state?"*

## Today's build

1. Build the eight. ⭐⭐ **Time-box to one session.** Still on Button after an hour means you are designing, not building.
2. ⭐ Build the three layout primitives. Use **only** them for layout from here.
3. ⭐⭐ **Run the five-state checklist on every component.** Most will fail on focus or loading.
4. ⭐ Build `StatusBadge`, `Money` and `RelativeTime` for **your** domain.
5. ⭐⭐ Make the status badge switch exhaustive. Add a value to the enum in Java and watch the frontend build fail.
6. ⭐ Find any prop you added "in case" and delete it. Count them.

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "did you build a design system?"**

Answer with the scope. **For one application, a design system is a token file and about eight
components — button, input, card, badge, skeleton, empty state, error state, and a dialog from a
library because focus trapping is genuinely hard. Plus three layout primitives. The whole skill is
stopping there.**

Then the discipline. **Every component has five states: default, hover, focus, disabled and loading.
Focus and loading are the two everyone skips. My loading state holds the button's width, because a
button that shrinks to fit a spinner moves everything beside it.**

Then the trap, with the analogy your audience knows. **I deliberately didn't generalise. The moment you
write a card you start imagining a caller who wants a header, a footer, a collapsible variant — and
you'll guess the seam wrong, because abstraction needs two examples and you have one. It's the
`AbstractBaseService` that three services extend and none of them fits. Duplication is cheaper than the
wrong abstraction.**

Close on the components that matter. **The ones that make it look like a product are mine — a status
badge owning my state machine's colours and labels, with an exhaustive switch so adding an enum value
in Java fails the frontend build. A money component, because BigDecimal doesn't survive a JS number, so
it arrives as a string or minor units and that fact lives in one place instead of every screen. And a
relative-time component so timezones are handled once rather than never.**
