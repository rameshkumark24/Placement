# L-052 · Iterators and modification

## The `Iterator` contract

```java
public interface Iterator<E> {
    boolean hasNext();
    E next();
    default void remove() { throw new UnsupportedOperationException(); }
}
```

**The enhanced for loop is an iterator**, desugared by the compiler (Day 024):

```java
for (String s : list) { use(s); }

// compiles to:
Iterator<String> it = list.iterator();
while (it.hasNext()) { String s = it.next(); use(s); }
```

**That's why you cannot access the index in an enhanced for loop** — there isn't one. And it's why
modifying the collection inside one throws.

## `ConcurrentModificationException` — what actually happens

```java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {
    if (s.equals("b")) list.remove(s);        // 💥 ConcurrentModificationException
}
```

### The mechanism: `modCount`

```java
public class ArrayList<E> {
    protected transient int modCount = 0;      // incremented by every STRUCTURAL change

    private class Itr implements Iterator<E> {
        int expectedModCount = modCount;       // snapshot taken at iterator creation

        public E next() {
            checkForComodification();
            ...
        }
        final void checkForComodification() {
            if (modCount != expectedModCount) throw new ConcurrentModificationException();
        }
    }
}
```

**Every structural modification — `add`, `remove`, `clear` — increments `modCount`.** The iterator
recorded the value at creation. On each `next()` it compares. A mismatch means the collection changed
underneath it, so it fails immediately.

**Structural vs non-structural:**

| Change | Structural? | Throws? |
|---|---|---|
| `add`, `remove`, `clear` | ✅ | Yes |
| `set(i, e)` | ❌ — size unchanged | **No** |
| `map.put(existingKey, newValue)` | ❌ — no new entry | **No** |
| `map.put(newKey, value)` | ✅ | Yes |

**So `set` during iteration is legal.** That surprises people, and it's a good detail.

### The name is wrong

**`ConcurrentModificationException` usually has nothing to do with concurrency.** Single-threaded
code triggers it constantly. It means "modified while iterating", not "modified by another thread".

### The best-effort caveat

```java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {
    if (s.equals("b")) list.remove(s);        // removing the SECOND-TO-LAST element
}
// ← may exit silently WITHOUT throwing!
```

**Why:** `hasNext()` is just `cursor != size`. Removing an element decrements `size`, so after
removing "b", `cursor` is 2 and `size` is 2 — `hasNext()` returns false, the loop exits, and
`checkForComodification` is never reached.

**The JDK documents this explicitly: fail-fast behaviour is "best-effort" and must not be relied
upon for correctness.** You get a silently truncated iteration instead of an exception, which is
worse. **Never write code that depends on the exception being thrown.**

## The four correct approaches

```java
// 1. Iterator.remove — the classic
Iterator<String> it = list.iterator();
while (it.hasNext()) if (it.next().equals("b")) it.remove();

// 2. removeIf — the modern answer
list.removeIf(s -> s.equals("b"));

// 3. Collect, then remove
List<String> toRemove = list.stream().filter(...).toList();
list.removeAll(toRemove);

// 4. Iterate a copy
for (String s : new ArrayList<>(list)) if (cond(s)) list.remove(s);
```

**`removeIf` is best** — one pass, no intermediate collection, and on `ArrayList` it's optimised: it
marks survivors in a bitset and does a single compaction, rather than shifting on every removal. So
it's O(n) where a loop of `remove` would be O(n²).

**For maps:**

```java
map.entrySet().removeIf(e -> e.getValue() < 10);
map.values().removeIf(v -> v == null);

Iterator<Map.Entry<K,V>> it = map.entrySet().iterator();
while (it.hasNext()) { var e = it.next(); if (cond(e)) it.remove(); }
```

## Fail-fast vs fail-safe

| | Fail-fast | Fail-safe (weakly consistent) |
|---|---|---|
| On modification | Throws `ConcurrentModificationException` | Continues |
| Iterates over | The live collection | A snapshot, or a weakly-consistent view |
| Memory | No copy | May copy the whole collection |
| Sees concurrent changes | N/A — it throws | **Maybe** — unspecified |
| Examples | `ArrayList`, `HashMap`, `HashSet`, `TreeMap` | `CopyOnWriteArrayList`, `ConcurrentHashMap` |

**"Fail-safe" is a poor name too** — the JDK calls it **weakly consistent**, which is more honest:
the iterator won't throw, but it makes no guarantee about whether it sees modifications made after it
was created.

```java
// CopyOnWriteArrayList — the iterator holds a snapshot of the array
List<String> cow = new CopyOnWriteArrayList<>(List.of("a", "b", "c"));
for (String s : cow) cow.add("x");         // no exception — but the loop never sees "x"

// ConcurrentHashMap — weakly consistent
for (String k : chm.keySet()) chm.put("new", 1);   // no exception; may or may not see "new"
```

## Other iterator features

### `ListIterator` — bidirectional, and it can add

```java
ListIterator<String> it = list.listIterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("b")) {
        it.set("B");        // replace
        it.add("b2");       // insert AFTER the current position — legally
    }
}
while (it.hasPrevious()) System.out.println(it.previous());
```

**`ListIterator.add` is the only legal way to insert during iteration**, and it's the one case where
`LinkedList` genuinely shines (Day 047).

### Custom iterators

```java
class Range implements Iterable<Integer> {
    private final int from, to;
    Range(int from, int to) { this.from = from; this.to = to; }

    @Override public Iterator<Integer> iterator() {
        return new Iterator<>() {
            int current = from;
            public boolean hasNext() { return current < to; }
            public Integer next() {
                if (!hasNext()) throw new NoSuchElementException();
                return current++;
            }
        };
    }
}

for (int i : new Range(1, 5)) System.out.print(i);      // 1234
```

**Implement `Iterable` and your type works in an enhanced for loop.** Note `next()` must throw
`NoSuchElementException` when exhausted — that's part of the contract.

### `Spliterator`

The parallel-capable iterator behind streams (Day 059), supporting `trySplit()` to divide the source.
You rarely implement one directly; know it exists and that it's what makes `parallelStream()`
possible.

## Type this yourself

```java
import java.util.*;
import java.util.concurrent.*;

public class IteratorDemo {
    public static void main(String[] args) {

        // ---- 1. The classic CME ----
        System.out.println("--- ConcurrentModificationException ---");
        List<String> list = new ArrayList<>(List.of("a", "b", "c", "d"));
        try {
            for (String s : list) if (s.equals("b")) list.remove(s);
        } catch (ConcurrentModificationException e) {
            System.out.println("   removing 'b' from [a,b,c,d]: CME thrown");
        }

        // ---- 2. The best-effort caveat — NO exception ----
        List<String> list2 = new ArrayList<>(List.of("a", "b", "c"));
        for (String s : list2) if (s.equals("b")) list2.remove(s);
        System.out.println("   removing 'b' from [a,b,c]: no exception, result = " + list2);
        System.out.println("   ↑ 'c' was never visited — fail-fast is BEST-EFFORT");

        // ---- 3. set() is not structural ----
        List<String> list3 = new ArrayList<>(List.of("a", "b", "c"));
        for (int i = 0; i < list3.size(); i++) { }
        ListIterator<String> li = list3.listIterator();
        while (li.hasNext()) { String s = li.next(); if (s.equals("b")) li.set("B"); }
        System.out.println("\n   set() during iteration: " + list3 + "   ← legal, no CME");

        // ---- 4. The four correct approaches ----
        System.out.println("\n--- correct removal ---");
        List<String> a = new ArrayList<>(List.of("a", "b", "c", "b"));
        Iterator<String> it = a.iterator();
        while (it.hasNext()) if (it.next().equals("b")) it.remove();
        System.out.println("   Iterator.remove: " + a);

        List<String> b = new ArrayList<>(List.of("a", "b", "c", "b"));
        b.removeIf(s -> s.equals("b"));
        System.out.println("   removeIf:        " + b);

        Map<String,Integer> m = new HashMap<>(Map.of("a",1,"b",20,"c",3));
        m.entrySet().removeIf(e -> e.getValue() < 10);
        System.out.println("   map removeIf:    " + m);

        // ---- 5. removeIf is O(n), a remove loop is O(n²) ----
        int n = 120_000;
        List<Integer> big1 = new ArrayList<>();
        for (int i = 0; i < n; i++) big1.add(i);
        long start = System.currentTimeMillis();
        Iterator<Integer> bi = big1.iterator();
        while (bi.hasNext()) if (bi.next() % 2 == 0) bi.remove();
        long iterTime = System.currentTimeMillis() - start;

        List<Integer> big2 = new ArrayList<>();
        for (int i = 0; i < n; i++) big2.add(i);
        start = System.currentTimeMillis();
        big2.removeIf(x -> x % 2 == 0);
        long removeIfTime = System.currentTimeMillis() - start;

        System.out.printf("%n--- removing half of %,d elements ---%n", n);
        System.out.printf("   Iterator.remove: %,5d ms   ← shifts each time, O(n²)%n", iterTime);
        System.out.printf("   removeIf:        %,5d ms   ← one compaction, O(n)%n", removeIfTime);

        // ---- 6. fail-safe ----
        System.out.println("\n--- fail-safe (weakly consistent) ---");
        List<String> cow = new CopyOnWriteArrayList<>(List.of("a", "b", "c"));
        int seen = 0;
        for (String s : cow) { cow.add("x"); seen++; if (seen > 10) break; }
        System.out.println("   CopyOnWriteArrayList: iterated " + seen
                         + " (snapshot), size now " + cow.size());

        Map<String,Integer> chm = new ConcurrentHashMap<>(Map.of("a",1,"b",2));
        for (String k : chm.keySet()) chm.put("added-" + k, 9);
        System.out.println("   ConcurrentHashMap: no CME, size now " + chm.size());

        // ---- 7. custom Iterable ----
        System.out.println("\n--- custom Iterable ---");
        System.out.print("   Range(1,6): ");
        for (int i : new Range(1, 6)) System.out.print(i + " ");
        System.out.println();
    }

    record Range(int from, int to) implements Iterable<Integer> {
        @Override public Iterator<Integer> iterator() {
            return new Iterator<>() {
                int current = from;
                public boolean hasNext() { return current < to; }
                public Integer next() {
                    if (!hasNext()) throw new NoSuchElementException();
                    return current++;
                }
            };
        }
    }
}
```

**Two results that matter most:**

1. **Removing "b" from `[a,b,c]` throws nothing** and silently skips "c". That's the best-effort
   caveat, and it's more dangerous than the exception.
2. **`removeIf` is dramatically faster** than a remove loop on `ArrayList` — O(n) versus O(n²),
   because it compacts once instead of shifting per removal.

## Common mistakes

| Mistake | Correction |
|---|---|
| Removing inside an enhanced for loop | Use `Iterator.remove` or `removeIf`. |
| Relying on CME being thrown | It's best-effort. You may get a silently truncated iteration. |
| Thinking CME means a threading bug | It usually means single-threaded modification during iteration. |
| `Iterator.remove` in a loop on `ArrayList` | O(n²). `removeIf` is O(n). |
| Assuming fail-safe iterators see updates | They're weakly consistent — it's unspecified. |
| Forgetting `NoSuchElementException` in a custom iterator | Part of the contract. |
| `it.remove()` before `it.next()` | `IllegalStateException` — `remove` operates on the last returned element. |

## Interview questions

**Q: What causes `ConcurrentModificationException`?**
> Structurally modifying a collection while iterating it. The collection maintains a `modCount`
> incremented by every add or remove; the iterator snapshots it at creation and checks it on each
> `next`. A mismatch throws. Despite the name it usually has nothing to do with threads —
> single-threaded code triggers it constantly.

**Q: Is it guaranteed to be thrown?**
> No — the JDK documents fail-fast behaviour as best-effort. If you remove the second-to-last element,
> `hasNext` returns false because the cursor now equals the reduced size, so the loop exits before the
> check runs. You get a silently truncated iteration instead of an exception, which is why you must
> never depend on it being thrown.

**Q: What's the difference between fail-fast and fail-safe iterators?**
> Fail-fast iterators operate on the live collection and throw if it's structurally modified —
> `ArrayList`, `HashMap`. Fail-safe, more accurately called weakly consistent, iterate a snapshot or
> tolerate concurrent change without throwing — `CopyOnWriteArrayList` iterates a fixed array snapshot,
> `ConcurrentHashMap` gives a weakly consistent view that may or may not reflect later modifications.

**Q: What's the correct way to remove during iteration?**
> `removeIf` for a predicate, which is a single-pass O(n) operation on `ArrayList` because it marks
> survivors and compacts once. Otherwise `Iterator.remove`, which is safe because it updates
> `expectedModCount`. A loop of `Iterator.remove` on an `ArrayList` is O(n²) since each removal shifts
> the tail.

**Q: Why can you call `set` during iteration but not `add`?**
> `set` replaces an element without changing the size, so it isn't a structural modification and
> doesn't increment `modCount`. `add` and `remove` change the structure and do.
