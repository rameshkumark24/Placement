# Part 2 — ⭐ Read your own code as a reviewer

**⭐ Open a pull request against `main` containing everything since Day 253. Review it properly.**

### ⭐ Pass 1 — the diff, looking for specific smells

| Look for | Day |
|---|---|
| ⭐ **A service method longer than ~20 lines** | ⭐ 256 — the domain is anaemic |
| ⭐ **A guard you could have made a scoped query** | 259 |
| ⭐ **A `try/catch` inside a transaction** | ⭐ 164 — caught means committed |
| ⭐ **An entity in a service signature** | 147 |
| ⭐ **`Instant.now()` instead of the injected clock** | 183 |
| A `@Transactional` method calling another in the same class | 164 |
| ⭐ **Duplicated business rules** across two callers | 254 |
| A `TODO` older than three days | — |

### ⭐ Pass 2 — the commit history

**⭐ It will be read.** Day 085's rules: small commits, meaningful messages, no secrets, no `wip`.
**Squash the mess now**, while the history is short — an interviewer scrolling a clean history forms
an impression before reading a line of code.

### ⭐ Pass 3 — the README

```
⭐ Can someone clone it and run it in under five minutes?
```

**⭐ Test this literally**: fresh clone, follow your own README, time it. **Missing setup steps are
the most common failure**, and they are also the first impression anyone gets.

**⭐ It must contain:** the one-paragraph pitch (Day 248), how to run it, the architecture in one
diagram, ⭐ **the hard problem and how it is solved**, and a link to the ADRs.

# Part 3 — ⭐ Rehearse the defence, with evidence in hand

**⭐ Record a ten-minute walkthrough.** Not slides — the code, the tests, and the deployed instance.

```
⭐ 1. The problem and the one core flow                     (1 min)
⭐ 2. The architecture in one sentence                       (1 min)
⭐⭐ 3. THE HARD PROBLEM — the race, the fix, ⭐ THE TEST     (3 min)
⭐ 4. Auth: the five validations + reuse detection            (2 min)
⭐ 5. A decision with its trade-off, unprompted               (1 min)
⭐ 6. What breaks at 100×, ⭐ from the load test              (1 min)
⭐ 7. What you would do differently                           (1 min)
```

**⭐ Play it back and check four things:**

| Check | ⭐ Fail signal |
|---|---|
| ⭐ Did you open with the **problem**, not the stack? | ⭐ "Spring Boot, PostgreSQL, Redis…" |
| ⭐ Did you **show a test** for the hard problem? | you described it instead |
| ⭐ Did you name a trade-off **unprompted**? | only benefits |
| ⭐ Did you cite a **number** from the load test? | "it seems fast" |

**⭐ Section 3 is the project.** Three minutes on the race you found, the constraint that makes it
impossible, and the two-thread test that proves it — **with the test on screen.**

## ⭐ The twenty questions, cold

**⭐ Answer every one aloud. Anything you cannot answer is a gap, not a memory lapse — go fix it.**

1. What does it do, in thirty seconds?
2. ⭐ **What was the hardest part?**
3. ⭐ **What happens when two users act simultaneously?**
4. ⭐ **Why is that in the database rather than the service?**
5. Why is your primary key not in the URL?
6. ⭐ **Why 404 rather than 403?**
7. ⭐ **What stops a refresh token being used as an access token?**
8. ⭐ **A refresh token is stolen. What happens?**
9. How do you revoke a JWT? *(honestly)*
10. ⭐ **How do you know there is no N+1?**
11. Why projections instead of entities?
12. ⭐ **Where are your transaction boundaries, and what is deliberately outside?**
13. ⭐ **You call an external service. Walk me through the failure handling.**
14. ⭐ **What happens when Redis is down?**
15. ⭐ **What is in liveness and what is in readiness, and why?**
16. ⭐ **How would you debug "a customer saw an error at 3pm"?**
17. ⭐ **What breaks first at 100× traffic?**
18. ⭐ **What did you deliberately leave out?**
19. ⭐ **Why is this not microservices?**
20. ⭐ **What would you do differently?**

## ⭐ Traps

| Trap | Consequence |
|---|---|
| ⭐ Reviewing to confirm rather than to find | ⭐ the point of the gate is missed entirely |
| Skipping rows in the audit | the ❌ you skipped is the one that matters |
| ⭐ Not fixing what you found | a checklist with no consequence |
| Not recording the walkthrough | you find out in the interview |
| ⭐ Opening with the tech stack | you sound like a CV |
| Describing the hard problem instead of showing the test | ⭐ a claim, not evidence |
| ⭐ No `KNOWN-GAPS.md` | caught out by a question you could have owned |
| Moving on with a red CI | it stays red |
