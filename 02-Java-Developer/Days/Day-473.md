# Part 1 — ⭐⭐ Recognising the graph

| ⭐ Disguise | ⭐ Nodes / edges |
|---|---|
| ⭐⭐ **A grid** | ⭐⭐ cell = node, 4 or 8 neighbours = edges — **the most common disguise** |
| ⭐ Course prerequisites | course = node, "must come before" = directed edge ⇒ **topological sort** |
| ⭐ Word ladder / one-letter changes | word = node, one edit apart = edge ⇒ **BFS for shortest** |
| ⭐ Dependency / build order | ⇒ topological sort + **cycle detection** |
| ⭐ Friend/follower relations | undirected graph ⇒ connected components, union-find |
| ⭐ State transitions (locks, puzzles) | ⭐⭐ **state = node** — the hardest disguise to see |

```
⭐⭐ THE CHOICE, DECIDED BY THE QUESTION AND NOTHING ELSE:
⭐   ⭐⭐ "SHORTEST path / fewest steps", unweighted   ⇒ ⭐⭐ BFS. Always. No exceptions.
⭐   ⭐ "does a path exist" / "explore everything"     ⇒ ⭐ DFS (less code, recursion)
⭐   ⭐⭐ "level by level" / "distance from source"      ⇒ ⭐⭐ BFS with a level loop
⭐   ⭐ "detect a cycle in a DIRECTED graph"           ⇒ ⭐⭐ DFS with 3 colours
⭐   ⭐ "ordering with dependencies"                    ⇒ ⭐⭐ topological sort (Kahn's, or DFS post-order)
⭐   ⭐ shortest path with WEIGHTS                      ⇒ ⭐ Dijkstra (Day 475's heap)
```

⚠️ **The single most common error in this family: using DFS for a shortest-path question.** DFS finds
*a* path, not the *shortest* one, and the bug is invisible on small test cases. **If the word "shortest",
"minimum steps" or "fewest" appears and edges are unweighted, the answer is BFS before you have finished
reading the sentence.**

# Part 2 — ⭐⭐ The problems

## ⭐ Warm-up (target: 15 minutes)

> **Given a 2D grid of `'1'` (land) and `'0'` (water), count the number of islands. An island is land
> connected horizontally or vertically.**

```java
int count = 0;
for (int r = 0; r < grid.length; r++)
    for (int c = 0; c < grid[0].length; c++)
        if (grid[r][c] == '1') { count++; sink(grid, r, c); }
return count;

void sink(char[][] g, int r, int c) {
    if (r < 0 || r >= g.length || c < 0 || c >= g[0].length || g[r][c] != '1') return;  // ⭐ one guard
    g[r][c] = '0';                                    // ⭐⭐ MARK VISITED IMMEDIATELY — before recursing
    sink(g, r+1, c); sink(g, r-1, c); sink(g, r, c+1); sink(g, r, c-1);
}
```

| ⭐ What is tested | |
|---|---|
| ⭐⭐ **Seeing a grid as a graph** | ⭐ and saying so out loud |
| ⭐⭐ **Marking visited before recursing** | ⭐⭐ mark after, and you get infinite recursion |
| ⭐ One combined bounds+value guard | ⭐ cleaner than four separate checks |
| ⭐⭐ **The mutation question** | ⭐⭐ *"I'm sinking the grid to avoid a visited set — is mutating the input acceptable?"* **Ask this.** |
| ⭐ Complexity | O(rows × cols) time; O(rows × cols) worst-case stack |

**⭐ Say aloud:** *"This is a connected-components count on an implicit graph where each cell is a node and
the four orthogonal neighbours are edges. DFS is fine because I only need to explore, not find a shortest
path. I'll mark visited by sinking the land, which avoids a separate visited array — but that mutates the
input, so I'd confirm that's allowed. If not, a boolean array of the same size."*

## ⭐⭐ Main problem (target: 30 minutes)

> **There are `n` courses labelled `0..n-1`. Given a list of prerequisite pairs `[a, b]` meaning you must
> take `b` before `a`, return any valid order in which to take all courses, or an empty array if none
> exists.**

| ⭐ The arc | |
|---|---|
| ⭐ 1. Name it: **topological sort on a directed graph** | ⭐ and the empty case means **a cycle** |
| ⭐⭐ 2. **Build the adjacency list and in-degree array** | ⭐⭐ get the edge direction right — this is where people lose it |
| ⭐ 3. Kahn's algorithm: queue of in-degree 0 | ⭐ or DFS post-order reversed |
| ⭐⭐ 4. **The cycle check** | ⭐⭐ if the output has fewer than `n` entries, there is a cycle |

```java
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
int[] indeg = new int[n];

for (int[] p : prereqs) {          // ⭐⭐ p = [course, prerequisite] ⇒ edge prereq → course
    adj.get(p[1]).add(p[0]);
    indeg[p[0]]++;
}

Deque<Integer> q = new ArrayDeque<>();
for (int i = 0; i < n; i++) if (indeg[i] == 0) q.add(i);

int[] order = new int[n]; int k = 0;
while (!q.isEmpty()) {
    int cur = q.poll();
    order[k++] = cur;
    for (int nxt : adj.get(cur))
        if (--indeg[nxt] == 0) q.add(nxt);           // ⭐⭐ decrement, enqueue only at zero
}
return k == n ? order : new int[0];                  // ⭐⭐ k < n ⇒ CYCLE
```

| ⭐⭐ The four places this goes wrong | |
|---|---|
| ⭐⭐ **Edge direction reversed** | ⭐⭐ produces a valid-looking but wrong order — **state the direction aloud as you build it** |
| ⭐⭐ **Forgetting the `k == n` check** | ⭐⭐ silently returns a partial order on a cyclic graph |
| ⭐ Enqueueing before in-degree hits zero | ⭐ duplicates in the output |
| ⭐ Not handling isolated nodes | ⭐ they have in-degree 0 and belong in the output |

## ⭐ The DFS alternative, and the three colours

```
⭐⭐ Cycle detection in a DIRECTED graph needs THREE states, not two:
⭐   WHITE (0) unvisited · ⭐⭐ GREY (1) IN THE CURRENT RECURSION STACK · BLACK (2) fully done
⭐   ⇒ ⭐⭐ hitting a GREY node = a back edge = A CYCLE
⭐   ⇒ ⭐ hitting a BLACK node = already processed, fine — ⭐⭐ NOT a cycle
⭐ ⇒ ⭐⭐ A simple visited boolean gives FALSE POSITIVES on a diamond-shaped DAG.
⭐   ⭐ This distinction is asked about constantly and answered wrongly just as often.
```

**⭐ In an *undirected* graph, cycle detection is different**: a visited neighbour that is not your parent
means a cycle. **Say which kind of graph you are in before you pick the technique.**

# Part 3 — ⭐ Tree traversal, and the two you must have cold

| ⭐ Traversal | ⭐ Use |
|---|---|
| ⭐⭐ **In-order on a BST** | ⭐⭐ **gives sorted order** — the single most useful tree fact |
| ⭐ Pre-order | serialise, copy a tree |
| ⭐ Post-order | delete, compute heights, anything needing children first |
| ⭐⭐ **Level order (BFS with a level loop)** | ⭐⭐ level-by-level output, minimum depth |

```java
// ⭐⭐ The level loop — the pattern that makes "by level" problems trivial
Deque<Node> q = new ArrayDeque<>();
q.add(root);
while (!q.isEmpty()) {
    int size = q.size();                    // ⭐⭐ SNAPSHOT the size — this is the whole trick
    List<Integer> level = new ArrayList<>();
    for (int i = 0; i < size; i++) {
        Node n = q.poll();
        level.add(n.val);
        if (n.left != null)  q.add(n.left);
        if (n.right != null) q.add(n.right);
    }
    result.add(level);
}
```

| ⭐ Two facts worth having ready | |
|---|---|
| ⭐⭐ **Minimum depth wants BFS, maximum depth wants DFS** | ⭐⭐ BFS can stop at the first leaf; DFS must see all |
| ⭐ Validating a BST needs **min/max bounds**, not parent comparison | ⭐⭐ comparing to the parent only is a classic wrong answer |

## Common mistakes

| Mistake | Why it hurts |
|---|---|
| ⭐⭐ **DFS for a shortest-path question** | ⭐⭐ finds *a* path; invisible on small tests |
| ⭐ Not recognising the grid as a graph | ⭐ you reinvent traversal badly |
| ⭐⭐ **Marking visited after recursing** | ⭐⭐ infinite recursion |
| ⭐ Marking visited on dequeue instead of enqueue in BFS | ⭐⭐ the same node enters the queue many times |
| ⭐⭐ **Reversed edge direction in topological sort** | ⭐⭐ a valid-looking wrong answer |
| ⭐⭐ **No `k == n` cycle check** | ⭐⭐ silently returns a partial order |
| ⭐ A two-state visited for directed cycle detection | ⭐⭐ false positives on a diamond DAG |
| ⭐ Using the directed technique on an undirected graph | ⭐ the parent rule is different |
| ⭐ Forgetting the queue-size snapshot in level order | ⭐ levels merge |
| ⭐ Validating a BST against the parent only | ⭐⭐ a classic wrong answer |
| ⭐ Not mentioning recursion depth on a large grid | stack overflow is a real answer |
| Ignoring disconnected components | half the graph unvisited |

## Interview questions

**Q: BFS or DFS?**
Decided by the question, not by preference. If it asks for the shortest path or fewest steps and the
edges are unweighted, it is BFS, always — DFS finds a path, not the shortest one, and that bug is
invisible on small inputs. If it asks whether a path exists or wants full exploration, DFS is less code.
Level-by-level output or distance from a source is BFS with a size snapshot per level. Cycle detection in
a directed graph is DFS with three colours. And weighted shortest path is Dijkstra, which is BFS with a
priority queue.

**Q: Why does directed cycle detection need three states?**
Because a plain visited flag cannot distinguish "already fully processed" from "currently on the
recursion stack". In a diamond-shaped DAG you reach the same node by two different paths, and a two-state
check reports a cycle that does not exist. Three colours fix it: white unvisited, grey means it is in the
current recursion stack, black means fully finished. Reaching a grey node is a back edge and therefore a
genuine cycle; reaching a black node is fine. In an undirected graph the rule is different again — a
visited neighbour that is not your parent means a cycle.

**Q: How do you detect that a course schedule is impossible?**
With Kahn's algorithm, by counting. You repeatedly remove nodes whose in-degree has reached zero, and if
you finish with fewer than n nodes emitted, the remaining ones are in a cycle and no valid order exists.
The check is one comparison and it is the line people forget — without it you silently return a partial
ordering that looks plausible. The other place this goes wrong is edge direction: the pair means take b
before a, so the edge runs from prerequisite to course, and I say that aloud while building the adjacency
list precisely because reversing it produces a valid-looking wrong answer.

**Q: Minimum depth of a binary tree — BFS or DFS?**
BFS, and this is the cleanest illustration of the choice. BFS reaches the first leaf at the shallowest
level and can stop immediately; DFS has to explore every path to be sure none is shorter. Maximum depth
is the opposite — DFS is natural because you must see everything anyway. It is a small example of the
general rule that shortest questions are breadth questions.

**Q: How do you validate a binary search tree?**
By carrying a minimum and maximum bound down the recursion, not by comparing each node to its parent.
The parent comparison is the classic wrong answer: a node can be greater than its immediate parent and
still violate the ordering with respect to an ancestor further up. Each recursive call narrows the valid
range — going left tightens the upper bound to the current value, going right tightens the lower bound —
and a node outside its range fails.

and it's the line most people forget."**
