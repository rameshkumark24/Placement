# Part 1 — L-083

## The header

```bash
#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'
```

Line by line, because every one of them prevents a specific disaster.

**`#!/usr/bin/env bash`** — finds bash on `PATH` rather than assuming `/bin/bash`. On macOS
`/bin/bash` is version 3.2 from 2007 (no associative arrays); Homebrew's bash 5 is elsewhere. And
never write `#!/bin/sh` if you use bash features — on Debian `sh` is `dash`, and your script will
fail in ways that look like syntax errors.

**`set -e`** — exit immediately if any command fails. Without it:

```bash
cd /opt/myapp        # ← if this fails…
rm -rf ./*           # ← …this runs in the WRONG directory
```

That two-line sequence has destroyed real systems. `set -e` turns it into a stop.

**`set -u`** — error on an unset variable. Without it, `rm -rf "$PREFIX/data"` with `PREFIX` unset
becomes `rm -rf /data`. A typo in a variable name is otherwise an empty string, silently.

**`set -o pipefail`** — Day 079: without it a pipeline's status is only the last command's, so
`build | tee log` succeeds when the build fails.

**`IFS=$'\n\t'`** — remove the space from the field separator so word-splitting happens only on
newlines and tabs. This makes filenames with spaces far less dangerous. It is optional but
worthwhile.

### What `set -e` does *not* catch

Know the exceptions, because relying on `-e` without them is a false sense of safety:

```bash
if failing_command; then ...; fi     # condition context — no exit
failing_command || true              # explicitly tolerated
failing_command && other             # left of && or ||
f() { failing; echo "still runs"; }  # inside a function used in a condition
local x=$(failing)                   # ⚠️ `local` masks the exit status!
```

That last one is subtle and real: `local x=$(cmd)` returns `local`'s status, not `cmd`'s. Declare
and assign separately:

```bash
local x
x=$(cmd)         # now failure is caught
```

## Variables, arrays, and quoting

```bash
name="ram"                       # no spaces around =
readonly MAX_RETRIES=3
declare -i count=0               # integer
declare -A config                # associative array (bash 4+)
config[host]="db.local"
config[port]=5432
echo "${config[host]}:${config[port]}"

files=(a.txt "b c.txt" d.txt)    # indexed array
echo "${files[@]}"               # all, each quoted separately
echo "${#files[@]}"              # length
for f in "${files[@]}"; do echo "[$f]"; done     # ← "${arr[@]}" always
```

**`"${arr[@]}"` with the quotes and the `@`.** `${arr[*]}` joins into one string; unquoted `@`
re-splits on whitespace. The quoted `@` form is the only one that survives filenames with spaces.

Day 079's expansions all apply, especially:

```bash
: "${DATABASE_URL:?DATABASE_URL is required}"     # fail fast with a clear message
readonly ENV="${ENV:-dev}"                        # default
```

## Conditionals

```bash
if [[ -f "$file" ]]; then ...; fi
if [[ -d "$dir" && -r "$dir" ]]; then ...; fi
if [[ "$a" == "$b" ]]; then ...; fi
if [[ "$s" =~ ^[0-9]+$ ]]; then ...; fi          # regex — bash only
if (( count > 5 )); then ...; fi                  # arithmetic
```

**Use `[[ ]]`, not `[ ]`.** `[` is a *command* (`/usr/bin/[`), so unquoted empty variables become
syntax errors; `[[ ]]` is bash syntax with no word-splitting inside, supports `&&`, `||` and `=~`,
and is simply safer. Use `(( ))` for arithmetic.

File tests worth knowing: `-f` regular file, `-d` directory, `-e` exists, `-r/-w/-x` permissions,
`-s` non-empty, `-z` empty string, `-n` non-empty string.

```bash
case "$1" in
    start)   start_app ;;
    stop)    stop_app ;;
    restart) stop_app; start_app ;;
    *)       echo "usage: $0 {start|stop|restart}" >&2; exit 2 ;;
esac
```

Note `>&2` — **usage and errors go to stderr** (Day 079), so piping the script's output does not mix
diagnostics into the data.

## Loops

```bash
for f in *.log; do
    [[ -e "$f" ]] || continue        # ← glob with no matches expands to the literal
    gzip "$f"
done

for i in {1..10}; do echo "$i"; done
for ((i = 0; i < 10; i++)); do echo "$i"; done

while read -r line; do               # -r: do NOT interpret backslashes
    process "$line"
done < input.txt                     # redirect, not a pipe (Day 079's subshell trap)

while IFS=, read -r name age city; do
    echo "$name is $age"
done < data.csv

find . -name "*.log" -print0 | while IFS= read -r -d '' f; do
    echo "$f"                        # NUL-safe: handles any filename
done

until nc -z localhost 5432; do sleep 1; done      # wait for a port
```

Two idioms to memorise: **`read -r`** always (without it, backslashes in the input are eaten), and
the **`-print0` / `read -d ''`** pairing for filenames.

The unmatched-glob guard matters: `for f in *.log` with no `.log` files iterates once with `f`
literally `*.log`. Either guard with `[[ -e "$f" ]]` or `shopt -s nullglob`.

## Functions

```bash
log()  { printf '%s [%s] %s\n' "$(date -Is)" "$1" "${*:2}" >&2; }
info() { log INFO "$@"; }
die()  { log ERROR "$@"; exit 1; }

require() {
    command -v "$1" >/dev/null 2>&1 || die "$1 is required but not installed"
}

retry() {
    local attempts=$1; shift
    local n=1
    until "$@"; do
        (( n >= attempts )) && return 1
        info "attempt $n failed; retrying in $((2 ** n))s"
        sleep $(( 2 ** n ))
        (( n++ ))
    done
}

require curl
retry 3 curl -fsS --max-time 10 "https://api.example.com/health" || die "health check failed"
```

Notes: **functions return exit statuses, not values** — to return data, echo it and capture with
`$(...)`. Variables are global unless declared `local`, which is a frequent source of surprising
bugs in longer scripts. And `"$@"` passes arguments through intact.

That `retry` function is Day 062's retry with backoff, in bash — same rules, and you should add
jitter for the same reason (Day 071).

## `trap` — cleanup that actually runs

```bash
TMPDIR_="$(mktemp -d)"
cleanup() {
    local code=$?
    rm -rf "$TMPDIR_"
    (( code != 0 )) && log ERROR "failed with exit $code"
    exit $code
}
trap cleanup EXIT INT TERM
```

`trap ... EXIT` is bash's `finally` (Day 061). It runs on normal exit, on `set -e` failure, and on
Ctrl-C. **Every script that creates a temp directory, takes a lock, or starts a background process
should have one** — otherwise a failed run leaves debris that makes the next run behave differently.

Use `mktemp -d`, never a fixed `/tmp/mydir`: a predictable path in a world-writable directory is a
symlink-attack vector, and two concurrent runs collide.

## A complete script

```bash
#!/usr/bin/env bash
#
# deploy.sh — deploy the application jar to a target host.
# Usage: deploy.sh -h HOST -v VERSION [-d]
#
set -euo pipefail
IFS=$'\n\t'

readonly SCRIPT_NAME="${0##*/}"
readonly ARTIFACT_DIR="${ARTIFACT_DIR:-./target}"
DRY_RUN=false

log()  { printf '%s [%-5s] %s\n' "$(date -Is)" "$1" "${*:2}" >&2; }
info() { log INFO "$@"; }
die()  { log ERROR "$@"; exit 1; }

usage() {
    sed -n '2,5p' "$0" | sed 's/^# \?//'
    exit "${1:-0}"
}

cleanup() {
    local code=$?
    [[ -n "${TMP:-}" ]] && rm -rf "$TMP"
    (( code != 0 )) && log ERROR "$SCRIPT_NAME failed (exit $code)"
    exit $code
}
trap cleanup EXIT INT TERM

main() {
    local host="" version=""
    while getopts ":h:v:d?" opt; do
        case "$opt" in
            h) host="$OPTARG" ;;
            v) version="$OPTARG" ;;
            d) DRY_RUN=true ;;
            \?|*) usage 2 ;;
        esac
    done

    [[ -n "$host"    ]] || die "-h HOST is required"
    [[ -n "$version" ]] || die "-v VERSION is required"
    [[ "$version" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]] || die "bad version: $version"

    command -v rsync >/dev/null || die "rsync is required"

    local jar="$ARTIFACT_DIR/app-$version.jar"
    [[ -f "$jar" ]] || die "artifact not found: $jar"

    TMP="$(mktemp -d)"
    info "deploying $version to $host (dry-run=$DRY_RUN)"

    if $DRY_RUN; then
        info "would rsync $jar -> $host:/opt/myapp/"
        return 0
    fi

    rsync -az --checksum "$jar" "$host:/opt/myapp/app.jar"
    ssh "$host" 'sudo systemctl restart myapp'

    local n=0
    until curl -fsS --max-time 5 "http://$host:8080/health" >/dev/null; do
        (( ++n >= 12 )) && die "health check never passed"
        info "waiting for health ($n/12)"
        sleep 5
    done

    info "deployed $version to $host"
}

main "$@"
```

Everything in it is deliberate: strict mode, logging to stderr with timestamps, `trap` cleanup,
argument validation before any side effect, a dry-run flag, `command -v` preflight checks, a bounded
health-check wait, and `main "$@"` so the whole script parses before anything executes. **That last
point is not cosmetic** — bash reads scripts incrementally, so editing a running script can change
what executes; wrapping the logic in `main` and calling it on the last line avoids that class of
weirdness.

## `shellcheck` — run it

```bash
shellcheck deploy.sh
```

A static analyser for shell that catches unquoted variables, useless `cat`, wrong test operators,
subshell variable loss, and dozens of real bugs. **Put it in CI.** It is the single cheapest quality
improvement available for shell code, and it will teach you more than any tutorial.

## When not to use bash

> **Rule of thumb: over ~100 lines, or the moment you need data structures, JSON parsing, or real
> error handling — switch to Python.**

Bash is excellent glue for running programs in sequence. It is bad at arithmetic, terrible at
floating point, has no real data structures beyond flat arrays, and its error handling is a
collection of workarounds. A 500-line bash script is a maintenance liability that everyone is afraid
to touch.

## Common mistakes

| Mistake | Consequence |
|---|---|
| No `set -euo pipefail` | Failures pass silently; the script continues into a bad state |
| `local x=$(cmd)` | Masks `cmd`'s exit status from `set -e` |
| `[ ]` instead of `[[ ]]` | Breaks on empty or unquoted values |
| Unquoted `$var` | Word-splitting and glob injection |
| `${arr[*]}` instead of `"${arr[@]}"` | Array collapses into one string |
| `read` without `-r` | Backslashes eaten |
| Piped `while` loop | Variables lost in the subshell |
| No `trap` cleanup | Temp files and locks left behind |
| Fixed `/tmp` path | Collisions and symlink attacks |
| `cd` without checking | Subsequent commands run in the wrong place |
| `#!/bin/sh` with bash syntax | Fails on dash |
| 500-line bash script | Should have been Python 400 lines ago |

## Interview questions

**Q: What does `set -euo pipefail` do?**
`-e` exits on any failing command, `-u` errors on unset variables, `-o pipefail` makes a pipeline
fail if any stage fails. Together they turn silent failure into a loud stop.

**Q: Name two things `set -e` does not catch.**
Commands in a condition context (`if`, `&&`, `||`), and `local x=$(cmd)`, where the assignment's
status masks the command's.

**Q: `[[ ]]` vs `[ ]`?**
`[` is an external command, so unquoted empty variables cause syntax errors; `[[ ]]` is bash syntax
with no word-splitting, plus `&&`, `||` and `=~`.

**Q: How do you clean up reliably?**
`trap cleanup EXIT INT TERM` — bash's `finally`. It runs on success, on failure, and on Ctrl-C.

**Q: How do you safely iterate over filenames?**
`find -print0 | while IFS= read -r -d ''`, quote every expansion, and use `"${arr[@]}"` for arrays.

**Q: When would you stop using bash?**
Around a hundred lines, or as soon as you need data structures, JSON, floating-point arithmetic or
structured error handling.
