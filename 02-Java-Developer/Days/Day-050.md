# Part 1 — L-050 · The `Set` family

## The reveal: every `Set` is a `Map` in disguise

```java
public class HashSet<E> {
    private transient HashMap<E, Object> map;              // ← the actual storage
    private static final Object PRESENT = new Object();    // a shared dummy value

    public boolean add(E e)         { return map.put(e, PRESENT) == null; }
    public boolean contains(Object o){ return map.containsKey(o); }
    public boolean remove(Object o) { return map.remove(o) == PRESENT; }
}
```

**`HashSet` is a `HashMap` where every value is the same dummy object.** Likewise `LinkedHashSet`
wraps `LinkedHashMap`, and `TreeSet` wraps `TreeMap`.

**So everything from Days 048–049 transfers directly** — spreading, bucket indexing, treeification at
8, resize at 0.75, the red-black tree. There is nothing new to learn about set *mechanics*.

**Two consequences worth stating:**

1. **All of Day 040's `equals`/`hashCode` requirements apply**, because the element is the map key.
2. **`PRESENT` costs nothing** — one shared object for the entire set, not one per element.

## Choosing

| Implementation | Backed by | Order | `add`/`contains` | Nulls |
|---|---|---|---|---|
| **`HashSet`** | `HashMap` | None | **O(1)** avg | ✅ one |
| `LinkedHashSet` | `LinkedHashMap` | **Insertion** | O(1) avg | ✅ one |
| `TreeSet` | `TreeMap` | **Sorted** | O(log n) | ❌ NPE |
| **`EnumSet`** | **Bit vector** | Declaration | **O(1), bitwise** | ❌ |
| `CopyOnWriteArraySet` | `CopyOnWriteArrayList` | Insertion | O(n) add | ✅ |

**Default to `HashSet`.** Use `LinkedHashSet` when iteration order must be deterministic — including
for reproducible tests and stable output. Use `TreeSet` for sorted iteration and range queries.

## `TreeSet` — `NavigableSet`

The same range operations as `TreeMap` (Day 049):

```java
TreeSet<Integer> set = new TreeSet<>(List.of(10, 20, 30, 40));

set.first(); set.last();
set.floor(25);        // 20 — greatest ≤ 25
set.ceiling(25);      // 30 — smallest ≥ 25
set.headSet(30);      // [10, 20]
set.tailSet(30);      // [30, 40]
set.subSet(15, 35);   // [20, 30]
set.descendingSet();
set.pollFirst();      // retrieve and remove the smallest
```

**`pollFirst`/`pollLast` make `TreeSet` a usable priority structure** when you also need
membership tests and removal by value — which `PriorityQueue` can't do efficiently (Day 051).

## `EnumSet` — a bit vector

```java
EnumSet<Day> weekend = EnumSet.of(Day.SAT, Day.SUN);
EnumSet<Day> weekdays = EnumSet.complementOf(weekend);
EnumSet<Day> all = EnumSet.allOf(Day.class);
EnumSet<Day> none = EnumSet.noneOf(Day.class);
EnumSet<Day> range = EnumSet.range(Day.MON, Day.WED);
```

**For ≤64 constants it's a single `long`.** Each constant is one bit, indexed by ordinal.

```
   enum Day { MON, TUE, WED, THU, FRI, SAT, SUN }
   EnumSet.of(SAT, SUN)  →  0b1100000
                                ││
                               SUN SAT
```

**Every operation is a bitwise instruction:**

| Operation | Becomes |
|---|---|
| `contains` | `(bits & (1L << ordinal)) != 0` |
| `add` | `bits \|= (1L << ordinal)` |
| `addAll` (union) | `bits \|= other.bits` |
| `retainAll` (intersection) | `bits &= other.bits` |
| `complementOf` | `~bits` masked to the universe |

**One CPU instruction per set operation, and 8 bytes for the whole set.** That's why Day 043 said
using `HashSet<SomeEnum>` leaves free performance on the table — the difference is orders of
magnitude, and the memory difference is roughly 500× for a small set.

## `EnumMap`

```java
Map<Status, Integer> counts = new EnumMap<>(Status.class);
```

**Backed by a plain `Object[]` indexed by ordinal.** No hashing, no collisions, no `Node` objects.

```
   values: [ null │ 42 │ null │ 7 ]
              ACTIVE  INACTIVE  ...
```

- **`get`/`put` are array indexing** — faster than hashing
- **Iterates in declaration order**, always
- Requires the `Class` object at construction so it can size the array

**Use `EnumMap` for every enum-keyed map.** There is no scenario where `HashMap` beats it.

## Set algebra

```java
Set<String> a = new HashSet<>(List.of("x", "y", "z"));
Set<String> b = new HashSet<>(List.of("y", "z", "w"));

Set<String> union = new HashSet<>(a); union.addAll(b);          // x y z w
Set<String> inter = new HashSet<>(a); inter.retainAll(b);       // y z
Set<String> diff  = new HashSet<>(a); diff.removeAll(b);        // x
```

**Always copy first** — `addAll`, `retainAll` and `removeAll` mutate the receiver. Forgetting is a
common bug, and it silently corrupts the original.

# Part 2 — B-09 · Memory allocation

## The problem

The OS must give each process contiguous-looking memory from a finite physical pool, and reclaim it
when freed.

## Contiguous allocation

**Each process gets one contiguous block.** Simple, and it fails badly.

### External fragmentation

```
   Start:  [ P1 ][ P2 ][ P3 ][ P4 ][    free    ]
   P2, P4 exit:
           [ P1 ][ free ][ P3 ][ free ][ free    ]
                   50 KB          30 KB   40 KB

   A 100 KB request FAILS — 120 KB is free, but not contiguously.
```

**Enough total memory, not enough in one piece.** That's external fragmentation.

**Allocation strategies:**

| Strategy | Picks |
|---|---|
| **First fit** | The first hole big enough — fastest |
| **Best fit** | The smallest adequate hole — leaves tiny unusable slivers |
| **Worst fit** | The largest hole — leaves large usable remainders |

**First fit is usually best in practice** — best fit's name is misleading, since it fragments worst by
creating slivers.

**Compaction** — sliding allocations together to merge holes — is expensive and requires relocatable
addressing.

### Internal fragmentation

**Allocating in fixed units wastes the remainder inside a block.** Ask for 33 KB with 4 KB pages and
you get 36 KB — 3 KB wasted *inside* your allocation.

**The trade-off:** larger pages mean less bookkeeping and more internal waste; smaller pages the
reverse.

## Segmentation

**Divide a process by logical region** — code, data, stack, heap — each its own variable-length
segment with a base and a limit.

```
   Logical address: (segment number, offset)
        │
        ├─ look up the base and limit in the segment table
        ├─ if offset ≥ limit → SEGMENTATION FAULT
        └─ physical = base + offset
```

**That's literally where "segfault" comes from** — a good detail to know.

**Advantage:** matches the program's logical structure, and per-segment protection (code read-only,
stack no-execute).
**Disadvantage:** variable sizes, so external fragmentation persists.

## Why paging won

**Paging divides memory into fixed-size pages (typically 4 KB), eliminating external fragmentation
entirely** — any free frame fits any page.

Cost: internal fragmentation (up to one page per allocation) and a page table per process.

**Modern systems use paging, often with segmentation-like protection on top.** Day 053's B-10 covers
paging, the MMU and the TLB properly.

## Where this touches Java

- **The JVM heap is one large contiguous region** requested from the OS. `-Xms` = `-Xmx` (Day 027)
  avoids repeatedly re-requesting it.
- **`ArrayList` growth at 1.5× rather than 2×** is a fragmentation argument (Day 046) — the same
  reasoning as first-fit versus best-fit, one level up.
- **Compacting collectors** (G1, ZGC — Day 026) exist to fix *heap* fragmentation, the same problem
  the OS faces. G1's regions are paging applied to the heap.
- **Humongous objects in G1** — allocations larger than half a region need contiguous regions, and
  can fail even when total free memory is sufficient. **That's external fragmentation inside the
  JVM.**

## Type this yourself

```java
import java.util.*;

public class SetDemo {
    enum Day { MON, TUE, WED, THU, FRI, SAT, SUN }

    public static void main(String[] args) {

        // ---- HashSet IS a HashMap ----
        System.out.println("--- iteration order ---");
        List<String> in = List.of("banana", "apple", "cherry", "date");
        System.out.println("   HashSet:       " + new HashSet<>(in));
        System.out.println("   LinkedHashSet: " + new LinkedHashSet<>(in));
        System.out.println("   TreeSet:       " + new TreeSet<>(in));

        // ---- NavigableSet ----
        System.out.println("\n--- NavigableSet ---");
        TreeSet<Integer> t = new TreeSet<>(List.of(10, 20, 30, 40, 50));
        System.out.println("   floor(25)   = " + t.floor(25));
        System.out.println("   ceiling(25) = " + t.ceiling(25));
        System.out.println("   subSet(15,45) = " + t.subSet(15, 45));
        System.out.println("   descending  = " + t.descendingSet());

        // ---- EnumSet is a bit vector ----
        System.out.println("\n--- EnumSet ---");
        EnumSet<Day> weekend = EnumSet.of(Day.SAT, Day.SUN);
        System.out.println("   weekend      = " + weekend);
        System.out.println("   complement   = " + EnumSet.complementOf(weekend));
        System.out.println("   range MON-WED= " + EnumSet.range(Day.MON, Day.WED));

        // ---- EnumSet vs HashSet: memory and speed ----
        int iterations = 20_000_000;
        Set<Day> enumSet = EnumSet.of(Day.MON, Day.WED, Day.FRI);
        Set<Day> hashSet = new HashSet<>(List.of(Day.MON, Day.WED, Day.FRI));

        long start = System.nanoTime();
        int hits = 0;
        for (int i = 0; i < iterations; i++) if (enumSet.contains(Day.WED)) hits++;
        long enumTime = System.nanoTime() - start;

        start = System.nanoTime();
        for (int i = 0; i < iterations; i++) if (hashSet.contains(Day.WED)) hits++;
        long hashTime = System.nanoTime() - start;

        System.out.printf("%n--- %,d contains() calls ---%n", iterations);
        System.out.printf("   EnumSet: %,5d ms   ← one bitwise AND%n", enumTime / 1_000_000);
        System.out.printf("   HashSet: %,5d ms   ← hash, mask, compare%n", hashTime / 1_000_000);
        System.out.println("   (hits=" + hits + ")");

        // ---- EnumMap iterates in declaration order ----
        System.out.println("\n--- EnumMap ---");
        Map<Day, Integer> em = new EnumMap<>(Day.class);
        em.put(Day.FRI, 5); em.put(Day.MON, 1); em.put(Day.WED, 3);
        System.out.println("   " + em + "   ← inserted FRI,MON,WED");

        // ---- set algebra MUTATES ----
        System.out.println("\n--- set algebra ---");
        Set<String> a = new HashSet<>(List.of("x", "y", "z"));
        Set<String> b = new HashSet<>(List.of("y", "z", "w"));
        Set<String> union = new HashSet<>(a); union.addAll(b);
        Set<String> inter = new HashSet<>(a); inter.retainAll(b);
        Set<String> diff  = new HashSet<>(a); diff.removeAll(b);
        System.out.println("   union        = " + union);
        System.out.println("   intersection = " + inter);
        System.out.println("   difference   = " + diff);
        System.out.println("   a unchanged  = " + a + "   ← because we copied first");

        // ---- equals/hashCode still governs everything ----
        System.out.println("\n--- Day 040 applies ---");
        record Good(int x) { }
        Set<Good> good = new HashSet<>();
        good.add(new Good(1)); good.add(new Good(1));
        System.out.println("   record: size after 2 equal adds = " + good.size());
    }
}
```

**Record the `EnumSet` vs `HashSet` timing.** The gap is the difference between a single bitwise
instruction and a hash-plus-mask-plus-compare — and it's why Day 043 flagged this.

## Interview questions

**Q: How is `HashSet` implemented?**
> It wraps a `HashMap`, storing each element as a key with a shared dummy object as the value. So all
> of `HashMap`'s mechanics apply — hash spreading, power-of-two bucket indexing, treeification at
> eight, resize at load factor 0.75 — and the element must honour the `equals`/`hashCode` contract
> because it's being used as a map key.

**Q: When would you use `LinkedHashSet` over `HashSet`?**
> When iteration order matters — deterministic output, reproducible tests, or preserving the order
> elements were first seen while deduplicating. It costs two extra references per element.

**Q: Why is `EnumSet` so much faster than `HashSet`?**
> It's a bit vector, not a hash table. Each enum constant is one bit indexed by its ordinal, so for up
> to 64 constants the whole set is a single `long`. `contains` is a bitwise AND, union is an OR,
> intersection is an AND — one CPU instruction each, and eight bytes of memory total.

**Q: What is external fragmentation?**
> Enough total free memory exists but not in one contiguous block, so an allocation fails despite
> sufficient capacity. It's what paging eliminates by using fixed-size frames, since any free frame
> can hold any page. The JVM equivalent is G1's humongous object allocation failing when no run of
> contiguous regions is available.

**Q: Where does the term "segmentation fault" come from?**
> Segmented memory management. A logical address is a segment number plus an offset, and the hardware
> checks the offset against that segment's limit. Exceeding it raises a segmentation fault. The name
> survived even though modern systems are paged rather than segmented.
