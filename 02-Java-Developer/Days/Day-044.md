# L-044 · The four kinds of nested class

| Kind | Declared | Holds outer instance? | Use for |
|---|---|---|---|
| **Static nested** | `static class X` inside a class | ❌ | **The default choice** |
| **Inner (non-static)** | `class X` inside a class | ✅ **implicitly** | Rarely — only when you need the outer instance |
| **Local** | Inside a method | ✅ if in an instance method | Rare |
| **Anonymous** | `new Interface() { ... }` | ✅ if in an instance context | Mostly replaced by lambdas |

## Static nested — use this by default

```java
class Outer {
    private static int shared;
    private int instanceField;

    static class Nested {
        void method() {
            shared = 1;              // ✅ can access the outer class's STATIC members
            // instanceField = 1;    // ❌ no enclosing instance
        }
    }
}

new Outer.Nested();                  // no Outer instance required
```

**It's a top-level class that happens to live inside another for namespacing.** No hidden reference,
no lifetime coupling.

**Where you see it:** `Map.Entry`, `HashMap.Node`, builders, and any helper type that logically
belongs to one class.

## Inner (non-static) — the one that leaks

```java
class Outer {
    private int value = 42;
    private byte[] huge = new byte[100_000_000];

    class Inner {
        void method() { System.out.println(value); }    // direct access to outer's INSTANCE fields
    }

    Inner make() { return new Inner(); }
}

Outer.Inner in = new Outer().new Inner();      // the odd syntax — needs an enclosing instance
```

**Decompile it** (Day 024) and you'll find a synthetic field:

```java
class Outer$Inner {
    final Outer this$0;                        // ← the hidden reference
    Outer$Inner(Outer outer) { this.this$0 = outer; }
}
```

**That `this$0` is the whole problem:**

```java
class Outer {
    private byte[] huge = new byte[100_000_000];        // 100 MB

    class Listener implements Runnable {
        public void run() { /* doesn't touch huge at all */ }
    }
}

eventBus.register(new Outer().new Listener());
// The Outer instance — and its 100 MB — is now immortal for as long as the bus holds the listener
```

**The listener doesn't use `huge`, doesn't use anything from `Outer`, and still keeps it alive.**
That's Day 027's leak pattern #5, and it's why long-lived callbacks must be static.

**The fix is one keyword:**

```java
static class Listener implements Runnable { ... }        // no this$0, no leak
```

> **Rule: make every nested class `static` unless it genuinely needs the enclosing instance.** IDEs
> warn about this; the warning is worth listening to.

### Shadowing and the qualified `this`

```java
class Outer {
    private String name = "outer";
    class Inner {
        private String name = "inner";
        void print(String name) {
            System.out.println(name);              // the parameter
            System.out.println(this.name);         // Inner's field
            System.out.println(Outer.this.name);   // Outer's field
        }
    }
}
```

**`Outer.this`** is the syntax for reaching the enclosing instance. Needing it is usually a sign the
naming is poor.

## Local classes

Declared inside a method:

```java
void process(List<String> items) {
    class Validator {                              // scoped to this method only
        boolean isValid(String s) { return s != null && !s.isBlank(); }
    }
    Validator v = new Validator();
    items.removeIf(s -> !v.isValid(s));
}
```

**Can capture effectively final locals** (Day 034), and holds the enclosing instance if declared in an
instance method.

**Rare in practice.** A private method or a lambda is almost always clearer.

## Anonymous classes

```java
Runnable r = new Runnable() {
    @Override public void run() { System.out.println("running"); }
};
```

**A class declaration and instantiation in one expression.** No name, so it can be used exactly once.

### Anonymous class vs lambda — the differences that matter

```java
Runnable anon   = new Runnable() { public void run() { System.out.println(this); } };
Runnable lambda = () -> System.out.println(this);
```

| | Anonymous class | Lambda |
|---|---|---|
| `this` refers to | **The anonymous instance** | **The enclosing instance** |
| Can have state | ✅ fields | ❌ |
| Can implement | Any interface or extend a class | **Functional interfaces only** |
| Compiles to | A **separate `.class` file** | `invokedynamic` (Day 024) |
| Multiple methods | ✅ | ❌ |
| Non-capturing instance | New object each time | **Can be reused as a singleton** |

**The `this` difference is the classic bug:**

```java
class Service {
    void register() {
        bus.subscribe(new Handler() {
            public void handle() {
                this.doSomething();          // 💀 `this` is the Handler, not the Service
                Service.this.doSomething();  // ✅ what you meant
            }
        });
        bus.subscribe(() -> this.doSomething());   // ✅ `this` is the Service, naturally
    }
}
```

**Lambdas are lexically scoped** — `this` means what it means in the surrounding code. Anonymous
classes introduce a new `this`. That's the single most useful distinction between them.

**And there's a real artefact difference:** each anonymous class produces `Outer$1.class`,
`Outer$2.class` and so on. A codebase with hundreds of them has hundreds of extra classes to load
(Day 023) and hold in Metaspace. Lambdas don't generate class files at compile time.

### When you still need an anonymous class

- Implementing an interface with more than one abstract method
- Extending an abstract class
- You need instance fields
- **The reified generic trick:**

```java
new TypeReference<List<User>>() { }        // Jackson — the anonymous subclass PRESERVES the type
```

Generics are erased (Day 055), but a *subclass*'s type argument is recorded in the class file. That's
why Jackson and Spring use this idiom — a lambda cannot do it.

## Type this yourself

```java
import java.util.*;
import java.util.function.*;

public class NestedDemo {

    private String name = "OUTER";
    private final byte[] payload = new byte[10_000_000];    // 10 MB, to make the leak visible

    // ---- static nested: no hidden reference ----
    static class StaticNested {
        void show() { System.out.println("   static nested — no outer instance"); }
    }

    // ---- inner: holds this$0 ----
    class Inner {
        private String name = "INNER";
        void show() {
            System.out.println("   this.name       = " + this.name);
            System.out.println("   NestedDemo.this.name = " + NestedDemo.this.name);
        }
    }

    // ---- `this` in an anonymous class vs a lambda ----
    void thisComparison() {
        Runnable anon = new Runnable() {
            @Override public void run() {
                System.out.println("   anonymous: this is a " + this.getClass().getSimpleName());
            }
        };
        Runnable lambda = () ->
                System.out.println("   lambda:    this is a " + this.getClass().getSimpleName());
        anon.run();
        lambda.run();
    }

    // ---- returning an inner class instance keeps `this` alive ----
    Runnable leakyListener() { return new Inner2(); }          // holds NestedDemo
    Runnable safeListener()  { return new Safe(); }            // holds nothing

    class Inner2 implements Runnable { public void run() { } }         // non-static → leaks
    static class Safe implements Runnable { public void run() { } }    // static → safe

    public static void main(String[] args) throws Exception {
        NestedDemo outer = new NestedDemo();

        System.out.println("--- static nested vs inner ---");
        new StaticNested().show();
        outer.new Inner().show();                              // note the syntax

        System.out.println("\n--- `this` in anonymous vs lambda ---");
        outer.thisComparison();

        System.out.println("\n--- the leak ---");
        List<Runnable> registry = new ArrayList<>();
        for (int i = 0; i < 20; i++) registry.add(new NestedDemo().leakyListener());
        System.gc(); Thread.sleep(100);
        Runtime rt = Runtime.getRuntime();
        System.out.printf("   20 LEAKY listeners retained: %,d MB used%n",
                (rt.totalMemory() - rt.freeMemory()) / 1024 / 1024);

        registry.clear();
        for (int i = 0; i < 20; i++) registry.add(new NestedDemo().safeListener());
        System.gc(); Thread.sleep(100);
        System.out.printf("   20 SAFE  listeners retained: %,d MB used%n",
                (rt.totalMemory() - rt.freeMemory()) / 1024 / 1024);
        System.out.println("   ↑ same listener count, ~200 MB difference from ONE keyword");
    }
}
```

**Then look at the generated class files:**

```bash
javac NestedDemo.java
ls NestedDemo*.class
# NestedDemo.class  NestedDemo$Inner.class  NestedDemo$StaticNested.class  NestedDemo$1.class ...
javap -p NestedDemo\$Inner        # ← find the synthetic  final NestedDemo this$0;  field
```

**Seeing `this$0` in the decompiled output is the moment this lands.** It's not a metaphor — there's
literally a field holding the outer object.

## Common mistakes

| Mistake | Correction |
|---|---|
| Non-static nested class by default | Holds the enclosing instance. Make it `static` unless you need the outer. |
| Returning an inner class instance from a long-lived object | Pins the outer object and everything it references. |
| Assuming `this` in an anonymous class is the enclosing object | It's the anonymous instance. Use `Outer.this`, or a lambda. |
| Anonymous classes where a lambda works | More class files, more Metaspace, confusing `this`. |
| Lambda where you need multiple methods or state | Lambdas only implement functional interfaces. |
| Local classes where a private method would do | Usually less readable. |

## Interview questions

**Q: What's the difference between a static nested class and an inner class?**
> A static nested class is effectively a top-level class namespaced inside another — it has no
> reference to any enclosing instance and can be created independently. A non-static inner class holds
> an implicit reference to the enclosing instance, stored in a synthetic `this$0` field, so it can
> access the outer object's instance members but also keeps that object alive.

**Q: Why can a non-static inner class cause a memory leak?**
> The synthetic reference to the enclosing instance means that as long as the inner instance is
> reachable, so is the outer object and everything it references — even if the inner class never uses
> any of it. Registering a non-static inner listener with a long-lived event bus pins the whole outer
> object indefinitely.

**Q: What's the difference between a lambda and an anonymous class?**
> `this` differs most importantly: in an anonymous class it refers to the anonymous instance, whereas
> a lambda is lexically scoped so `this` is the enclosing instance. Anonymous classes can hold state,
> implement multi-method interfaces and extend classes, and each generates its own class file. Lambdas
> only target functional interfaces, compile to `invokedynamic` rather than a class file, and
> non-capturing ones can be reused as a singleton.

**Q: When do you still need an anonymous class?**
> When implementing an interface with more than one abstract method, extending an abstract class,
> needing instance fields, or capturing a generic type — the `new TypeReference<List<User>>() {}`
> idiom works because a subclass's type argument survives erasure, which a lambda can't do.
