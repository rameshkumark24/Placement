# Part 1 — L-080

## `grep` — find lines

```bash
grep ERROR app.log
grep -i error app.log            # case-insensitive
grep -v DEBUG app.log            # inVert: lines NOT matching
grep -c ERROR app.log            # count matching LINES (not occurrences)
grep -n ERROR app.log            # line numbers
grep -r "TODO" src/              # recursive
grep -l "main(" *.java           # only filenames
grep -w "id" file                # whole word — not "uuid"
grep -A3 -B3 ERROR app.log       # 3 lines after / before
grep -C3 ERROR app.log           # both
grep -o 'order-[0-9]*' app.log   # print only the MATCH, one per line
grep -E 'ERROR|FATAL' app.log    # extended regex (or use egrep)
grep -F 'a.b.c' file             # Fixed string — no regex. Faster and safer
grep -P '(?<=user=)\w+' app.log  # Perl regex: lookbehind
```

Three flags worth internalising:

**`-o`** turns grep from a filter into an extractor. `grep -o` piped into `sort | uniq -c` is the
most common ad-hoc analysis pipeline there is.

**`-F`** when the pattern is literal — it avoids both the regex cost and the bug where a `.` in your
search string matches anything.

**`-C3`** for context. A stack trace's first line is rarely the useful one.

Note `grep -c` counts *lines*, not matches. For occurrences use `grep -o pattern file | wc -l`.

**Regex is the shared language across `grep`, `sed` and `awk`** — and Day 063B's warning applies:
these are backtracking engines too, so a pathological pattern on a huge file can hang.

## `find` — locate files by property

```bash
find . -name "*.log"                        # glob on name (quote it!)
find . -iname "*.LOG"                       # case-insensitive
find . -type f -o -type d                   # f=file d=dir l=symlink
find . -size +100M                          # bigger than 100 MB
find . -mtime -1                            # modified in the last 24h
find . -mmin -30                            # last 30 minutes
find . -user ram -perm -002                 # owned by ram AND world-writable
find . -newer reference.txt
find . -maxdepth 2
find . -path "*/target/*" -prune -o -name "*.java" -print   # skip build dirs
find . -name "*.tmp" -delete
find . -name "*.log" -exec gzip {} \;       # one process PER FILE
find . -name "*.log" -exec gzip {} +        # batched — much faster
find . -name "*.log" -print0 | xargs -0 gzip
```

**`-exec {} \;` versus `-exec {} +`** is a real performance difference: the first forks a process per
file, the second batches as many as the command line allows. On 50,000 files that is minutes versus
seconds.

**`-print0` / `-0`** is the correct pairing when filenames may contain spaces or newlines — it
separates with NUL bytes, which cannot appear in a filename. Get into the habit; the day it matters
you will not be thinking about it.

Day 078's disk-full investigation, properly:

```bash
find /var -type f -size +100M -exec ls -lh {} + 2>/dev/null | sort -k5 -hr | head
```

## `sort`, `uniq`, `wc`, `cut`, `tr`

```bash
sort file                    # lexical
sort -n file                 # numeric   ← "10" before "9"
sort -h file                 # human sizes (1K, 5M, 2G)
sort -r                      # reverse
sort -u                      # unique (sort + uniq in one)
sort -k2 -t, file.csv        # by field 2, comma-separated
sort -k2,2 -k1,1r file       # multi-key: field 2 asc, then field 1 desc

uniq file                    # ⚠️ only collapses ADJACENT duplicates — sort first
uniq -c                      # prefix each with its count
uniq -d                      # only duplicated lines
uniq -u                      # only lines appearing once

wc -l  # lines    wc -w  # words    wc -c  # bytes

cut -d, -f2,4 file.csv       # fields 2 and 4
cut -c1-10 file              # characters

tr 'a-z' 'A-Z' < file        # translate
tr -d '\r' < win.txt         # ← delete CR: fixes Windows line endings
tr -s ' '                    # squeeze repeats
```

**`uniq` requires sorted input.** It is the most common mistake with these tools, and it fails
silently — you get a plausible-looking wrong answer.

The canonical counting idiom, worth memorising as one unit:

```bash
... | sort | uniq -c | sort -rn | head
```

## `sed` — stream editor

```bash
sed 's/old/new/' file             # first occurrence PER LINE
sed 's/old/new/g' file            # all occurrences
sed 's/old/new/gi' file           # + case-insensitive
sed -i 's/old/new/g' file         # in place ⚠️ no undo
sed -i.bak 's/old/new/g' file     # in place, keeping file.bak  ← always do this
sed -n '5,10p' file               # print lines 5–10 (-n = suppress default output)
sed '/^#/d' file                  # delete comment lines
sed '/^$/d' file                  # delete blank lines
sed -n '/START/,/END/p' file      # print a range between two patterns
sed 's|/usr/local|/opt|g' file    # any delimiter — avoids escaping slashes
sed -E 's/([0-9]{4})-([0-9]{2})/\2\/\1/' file   # groups, backreferences
```

Two habits: **`-i.bak` always** (there is no undo), and **use `|` as the delimiter for paths** rather
than escaping every slash.

`sed -n '/START/,/END/p'` is the one people forget and then need — extracting one request's block
from a log, or one section from a config.

## `awk` — a language for columns

`awk` is a full programming language. Ninety per cent of use is one pattern:

```bash
awk '{print $7}' access.log            # field 7 ($0 = whole line, NF = field count)
awk '{print $NF}' file                 # LAST field
awk -F, '{print $2}' file.csv          # comma-separated
awk '$9 == 500 {print $7}' access.log  # condition, then action
awk 'NR > 1 {print}' file.csv          # skip the header (NR = record number)
awk '{sum += $1} END {print sum}'      # sum a column
awk '{s+=$1} END {print s/NR}'         # average
awk '{count[$1]++} END {for (k in count) print count[k], k}' file   # ← group-by
awk 'length > 100'                     # lines longer than 100 chars
awk '{printf "%-20s %8.2f\n", $1, $2}' # formatted output
```

The **associative-array group-by** on that second-to-last line is `awk`'s real power. It is a
`GROUP BY` in one line, and it beats `sort | uniq -c` when you need to aggregate a *value* rather
than count occurrences:

```bash
# total bytes per client IP, top 10
awk '{bytes[$1] += $10} END {for (ip in bytes) print bytes[ip], ip}' access.log \
  | sort -rn | head
```

The structure is `awk 'BEGIN{...} pattern{action} END{...}'` — BEGIN before any input, END after
all of it.

## `xargs` — build command lines from input

```bash
find . -name "*.log" | xargs rm                 # ✗ breaks on spaces
find . -name "*.log" -print0 | xargs -0 rm      # ✅
cat urls.txt | xargs -n1 curl -s -o /dev/null -w "%{http_code} %{url_effective}\n"
cat ids.txt | xargs -P8 -n1 ./process.sh        # ← 8 in PARALLEL
xargs -I{} mv {} /archive/{}.bak                # placeholder form
```

`-P` is the underrated flag: **`xargs -P8` is a parallel executor in three characters.** Combined
with `-n1` it turns a list of work items into an 8-way parallel job, which is often the fastest way
to run something over a thousand inputs without writing any concurrency code.

## Putting it together

```bash
# Top 10 endpoints by request count
awk '{print $7}' access.log | sort | uniq -c | sort -rn | head

# Error rate per hour
grep ERROR app.log | awk '{print substr($2,1,2)}' | sort | uniq -c

# Slowest endpoints (avg response time, field 11 = ms)
awk '{sum[$7]+=$11; n[$7]++} END {for (e in sum) printf "%8.1f %6d %s\n", sum[e]/n[e], n[e], e}' \
    access.log | sort -rn | head

# Every IP with more than 100 4xx responses — a rough abuse detector
awk '$9 ~ /^4/ {c[$1]++} END {for (ip in c) if (c[ip] > 100) print c[ip], ip}' access.log | sort -rn

# Which of my classes are longest?
find src -name "*.java" -exec wc -l {} + | sort -rn | head -20

# Every TODO with its author, from git
grep -rn "TODO" src/ | while IFS=: read -r f l rest; do
  echo "$(git log -1 --format='%an' -L"$l,$l:$f" 2>/dev/null | head -1) — $f:$l"
done
```

**Type these against a real log file.** Generate one if you have none:

```bash
for i in $(seq 20000); do
  printf '10.0.%d.%d - [14/Aug/2026:%02d:%02d:00] "GET /api/v%d/items HTTP/1.1" %d %d %d\n' \
    $((RANDOM%256)) $((RANDOM%256)) $((RANDOM%24)) $((RANDOM%60)) \
    $((RANDOM%3+1)) $(shuf -n1 -e 200 200 200 200 404 500 503) $((RANDOM%5000)) $((RANDOM%800))
done > access.log
```

## When to stop

These tools are for **exploration and one-off answers**. Stop and write a program when:

- the pipeline exceeds about five stages and you cannot read it back,
- you need real data structures or error handling,
- it will run in production on a schedule,
- correctness matters more than speed of writing.

**Never parse structured formats with regex.** JSON has `jq`, YAML has `yq`, XML has `xmlstarlet`,
CSV with quoted commas has `csvkit` or a real parser. `grep '"id": *"[^"]*"'` works until a value
contains an escaped quote, and then it fails silently on the one record you cared about.

```bash
jq '.items[] | select(.status == "FAILED") | .id' response.json
jq -r '.[] | [.name, .count] | @tsv' data.json | sort -k2 -rn
kubectl get pods -o json | jq -r '.items[] | select(.status.phase != "Running") | .metadata.name'
```

## Common mistakes

| Mistake | Consequence |
|---|---|
| `uniq` without `sort` | Silently wrong counts |
| `sort` instead of `sort -n` | "10" sorts before "9" |
| `sed -i` with no backup | Irreversible mistake across many files |
| Unquoted `find -name *.log` | The shell expands it first |
| `xargs` without `-print0`/`-0` | Breaks on spaces in filenames |
| `-exec {} \;` on thousands of files | One fork per file |
| `grep -c` read as occurrences | It counts lines |
| Parsing JSON/XML with grep | Fails on the record that matters |
| Parsing `ls` output | Same |
| A ten-stage pipeline in production | Unreadable and unmaintainable |

## Interview questions

**Q: Count the ten most frequent values in a column of a log file.**
`awk '{print $7}' file | sort | uniq -c | sort -rn | head` — and explain why `sort` must precede
`uniq`.

**Q: `grep`, `sed`, `awk` — when do you use each?**
`grep` selects lines, `sed` transforms them, `awk` works with fields and can aggregate. Reach for
`awk` when you need columns, arithmetic, or group-by.

**Q: How do you handle filenames with spaces?**
`find -print0 | xargs -0`, quote all variable expansions, and prefer `-exec {} +` to shell loops
over `ls`.

**Q: `-exec {} \;` vs `-exec {} +`?**
The first runs the command once per file; the second batches arguments into as few invocations as
possible. Large difference on large file sets.

**Q: How would you find what is filling a disk?**
`du -sh /* | sort -h`, then descend; plus `find / -size +100M` and `lsof +L1` for deleted-but-open
files.

**Q: When do you stop using shell tools?**
When the pipeline stops being readable, when the data is structured (use `jq`), when it needs error
handling, or when it will run on a schedule in production.
