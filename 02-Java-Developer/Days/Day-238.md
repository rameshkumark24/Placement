# Part 1 — The cascade, and why component styling exists

```
⭐⭐ THE PROBLEM CSS HAS THAT NO OTHER LANGUAGE YOU USE HAS:
⭐   ⭐ EVERY RULE IS GLOBAL, AND THE WINNER IS DECIDED BY A
⭐     SPECIFICITY SCORE RATHER THAN BY ORDER OR SCOPE.

⭐   specificity: inline(1000) > #id(100) > .class(10) > tag(1)
⭐   ⇒ ⭐⭐ SO A FIX SOMEWHERE ELSE BREAKS YOUR COMPONENT, AND THE
⭐     ESCALATION IS ALWAYS THE SAME:
⭐     .btn {} → .card .btn {} → #page .card .btn {} → !important
⭐     ⇒ ⭐ AND NOW NOBODY CAN OVERRIDE ANYTHING, EVER.

⭐   ⇒ ⭐⭐ IMAGINE A LANGUAGE WITH NO PACKAGES, WHERE EVERY METHOD
⭐     IS public static AND COLLISIONS ARE RESOLVED BY A SCORING
⭐     FORMULA. ⭐ THAT IS CSS, AND EVERY MODERN APPROACH — CSS
⭐     Modules, Tailwind, CSS-in-JS — EXISTS TO ADD THE PACKAGES.
```

| ⭐ Approach | Trade |
|---|---|
| **Tailwind** | ⭐⭐ Constraint by default (you can only pick from the scale), no naming, ugly JSX. **Recommended here.** |
| **CSS Modules** | ⭐ Real CSS, locally scoped, you still invent every value |
| **CSS-in-JS** | ⭐ Dynamic styling, runtime cost, falling out of favour |

> ⭐ **`!important` is a message, not a fix.** It means "the architecture lost" — the CSS equivalent of
> `@SuppressWarnings` on a whole class.

# Part 2 — ⭐⭐ Tokens

```css
:root {
  /* ⭐⭐ SPACING — one scale. NOTHING ELSE IS ALLOWED. */
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px;
  --space-4: 16px; --space-6: 24px; --space-8: 32px;

  /* ⭐ TYPE — 5 sizes. You do not need 11. */
  --text-sm: 14px; --text-base: 16px; --text-lg: 18px;
  --text-xl: 24px; --text-2xl: 32px;

  /* ⭐⭐ COLOUR — semantic names, not literal ones */
  --fg: #111827;  --fg-muted: #6b7280;
  --bg: #ffffff;  --bg-subtle: #f9fafb;
  --border: #e5e7eb;
  --primary: #2563eb;  --danger: #dc2626;

  --radius: 6px;
}
```

```
⭐⭐ WHY THIS ALONE MAKES IT LOOK PROFESSIONAL

⭐   ❌ AMATEUR: padding 13px here, 15px there, 7px somewhere else.
⭐      ⭐ Nobody consciously notices. ⭐⭐ EVERYONE FEELS IT AS "OFF".
⭐   ✅ DELIBERATE: every gap from ONE scale. ⭐ The eye reads the
⭐      repetition as intent — and it costs NO design talent.

⭐   ⇒ ⭐⭐ NAME COLOURS BY ROLE (--danger), NEVER BY VALUE (--red-600).
⭐     Then dark mode is a second :root block, not a rewrite.
⭐     ⭐ It is the same reason you inject an interface rather than
⭐       a concrete class: the NAME states the ROLE.
```

| ⭐ Rule | |
|---|---|
| **Never write a raw value in a component** | ⭐⭐ Not in the scale? Add it deliberately, or use the nearest |
| **Five type sizes, one family** | ⭐ Two families max |
| **A neutral ramp + one accent** | ⭐⭐ Greys do 90% of the work. **One** brand colour. |

# Part 3 — ⭐⭐ The eight decisions

```
⭐⭐ DO THESE EIGHT AND IT WILL LOOK FINE. SKIP THEM AND IT WON'T.

⭐ ① ⭐⭐ WHITESPACE. Amateur UIs are cramped. Double what feels right.
⭐ ② ⭐ ALIGNMENT. ⭐⭐ ONE MISALIGNED ELEMENT IS THE MOST VISIBLE
⭐    FLAW THERE IS.
⭐ ③ ⭐ CONTRAST. Body text near-black on white. ⭐⭐ Grey-on-grey is
⭐    the #1 accessibility failure AND it looks weak.
⭐ ④ ⭐ ONE ACCENT COLOUR, only for the primary action.
⭐ ⑤ ⭐⭐ MAX LINE LENGTH ~65–75ch. Full-width text instantly marks
⭐    a page as unstyled.
⭐ ⑥ ⭐ CONSISTENT RADIUS AND BORDER.
⭐ ⑦ ⭐⭐ VISIBLE FOCUS RINGS. Never `outline: none` (Day 239).
⭐ ⑧ ⭐ HOVER + ACTIVE + DISABLED on every interactive element —
⭐    ⭐⭐ A BUTTON WITH NO HOVER STATE FEELS BROKEN.
```

> ⭐ **Steal the scale, not the design.** Use a component library (shadcn/ui, Radix) for dialogs,
> menus and comboboxes, because they solve focus trapping, keyboard navigation and ARIA that you will
> otherwise get wrong. **That is not cheating; it is the same reason you did not write your own ORM.**

# Part 4 — Layout that stops fighting you

```css
/* ⭐ THE THREE LAYOUTS THAT COVER ALMOST EVERYTHING */
.stack   { display: flex; flex-direction: column; gap: var(--space-4); }
.row     { display: flex; align-items: center; gap: var(--space-3); }
.grid    { display: grid; gap: var(--space-4);
           grid-template-columns: repeat(auto-fill, minmax(260px, 1fr)); }
                                /* ⭐⭐ RESPONSIVE WITH NO MEDIA QUERIES */
```

| ⭐ Rule | Why |
|---|---|
| **`gap`, not margins** | ⭐⭐ No collapsing, no "last child" exception |
| **Grid for 2D, flex for 1D** | ⭐ Using flex for a grid is where wrapping bugs come from |
| **`min-width: 0` on flex children** | ⭐⭐ The fix for "my text won't truncate" — flex items default to `min-width: auto` and refuse to shrink |
| **Mobile first** | ⭐ Base styles small-screen; `min-width` queries add upward |
| **`clamp()` for type** | ⭐ Fluid without breakpoints |

```
⭐⭐ THE THREE BUGS YOU WILL HIT, PRE-SOLVED
⭐   · ⭐ text overflows its flex container ⇒ min-width: 0
⭐   · ⭐ 100vh is wrong on mobile ⇒ use 100dvh
⭐   · ⭐⭐ a fixed header covers anchored content ⇒ scroll-padding-top
```

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "you're not a designer — how did you make this look decent?"**

Answer with constraint, which is an engineering answer. **By removing choices instead of making them. I
defined tokens — one spacing scale on powers of two, five type sizes, a neutral ramp and one accent —
and nothing in a component uses a raw value. Amateur UIs have thirteen pixels here and seven there;
nobody consciously notices, but everybody feels it as off. Repetition from one scale reads as intent,
and it costs no design talent.**

Then the checklist, briefly. **Beyond that it's about eight decisions: generous whitespace, everything
aligned, real contrast, one accent reserved for the primary action, a max line length, consistent
radius, visible focus rings, and hover and disabled states on everything interactive. A button with no
hover state feels broken even when it works.**

Then the delegation. **I use a component library for dialogs and comboboxes — not for the visuals, but
because they solve focus trapping, keyboard navigation and ARIA, which I'd get wrong. Same reason I
didn't write my own ORM.**

Close on the architecture, since it is the actual engineering. **All of this is scoped styling. CSS's
problem is that every rule is global and the winner is decided by a specificity score — imagine a
language with no packages where every method is `public static` and collisions are resolved by a
scoring formula. So a fix elsewhere breaks your component and you escalate until everything is
`!important` and nothing can be overridden. Tailwind and CSS Modules exist to add the packages.**
