# Day 278 ✨

**J-278** · ✨ **Polish** — ⭐⭐ twelve details, and the seed data that decides everything

**Time:** 3 hrs · **Mode:** BUILD

> ⭐⭐ **The sentence to own: the gap between a demo and a product is not features, it is about twelve

# Part 1 — ⭐⭐ Seed data is the highest-leverage hour

```
⭐⭐ THE SAME SCREEN, TWICE

⭐   ❌ Test User 1 | asdf | 0 | 2024-01-01 | ACTIVE
⭐      Test User 2 | asdf | 0 | 2024-01-01 | ACTIVE
⭐      ⇒ ⭐ READS AS: unfinished, untested, nobody has used it.

⭐   ✅ Ada Lovelace  | Noise-cancelling headphones | £249.00 | 3 min ago  | PAID
⭐      Grace Hopper  | USB-C cable (2 m)          |  £12.99 | 2 hrs ago  | SHIPPED
⭐      Alan Turing   | Mechanical keyboard        | £164.50 | yesterday  | REFUNDED
⭐      ⇒ ⭐⭐ READS AS: a working product with real usage.

⭐   ⇒ ⭐⭐ SAME CODE. THE ONLY DIFFERENCE IS THE DATA, AND IT TAKES
⭐     ONE HOUR. ⭐ IT IS THE BEST RETURN ON TIME IN THE ENTIRE STAGE.
```

| ⭐ Rule | Why |
|---|---|
| **Plausible names and products** | ⭐ Your domain, not lorem ipsum |
| **⭐⭐ Every status represented** | So the badge, the state machine and each empty branch are all *visible* |
| **⭐⭐ Timestamps spread across "recently"** | Everything dated 2024-01-01 screams fixture. **Seed relative to `now()`.** |
| **Realistic volume** | ⭐ Enough rows to page. ⭐⭐ Also seed ~2,000 in one account so you can demo pagination honestly |
| **⭐ One deliberately broken record** | A failed payment, a rejected order — **so you can demo the error path** |
| **Repeatable** | ⭐⭐ A Spring `@Profile("demo")` seeder or `data.sql`. **One command, always the same.** |

> ⭐ **Seed a second user with different permissions.** It lets you demo authorization in ten seconds —
> log in as the other user, the Refund button is gone *and* the API refuses it (Day 236).

# Part 2 — ⭐⭐ The twelve details

```
⭐⭐ EACH IS ~15 MINUTES. TOGETHER THEY ARE THE WHOLE DIFFERENCE.

⭐ ① ⭐⭐ THE PAGE TITLE CHANGES PER ROUTE ⇒ "Order #4471 · Acme"
⭐    ⭐ Tabs are how users navigate. "React App" is a tell.
⭐ ② ⭐ A FAVICON. The default Vite logo is a tell.
⭐ ③ ⭐⭐ NO CONSOLE ERRORS OR WARNINGS. Interviewers open DevTools.
⭐    ⭐ Fix the key warnings; do not silence them.
⭐ ④ ⭐ FOCUS MOVES TO THE HEADING ON ROUTE CHANGE (Day 239)
⭐ ⑤ ⭐⭐ ENTER SUBMITS THE FORM. Escape closes the dialog.
⭐ ⑥ ⭐ NUMBERS ARE FORMATTED — £1,249.00, not 1249. Dates are
⭐    relative with an exact title (Day 272).
⭐ ⑦ ⭐⭐ NO LAYOUT SHIFT — skeletons match content size (Day 241)
⭐ ⑧ ⭐ THE PRIMARY ACTION IS OBVIOUS on every screen
⭐ ⑨ ⭐⭐ LOADING NEVER FLASHES — >200 ms delay before showing
⭐ ⑩ ⭐ TEXT IS SELECTABLE; ids are copyable (a copy button)
⭐ ⑪ ⭐⭐ THE 404 PAGE IS REAL and offers a route back
⭐ ⑫ ⭐ IT WORKS AT 1280×720 — ⭐⭐ THE PROJECTOR / SCREEN-SHARE
⭐    RESOLUTION, WHICH IS WHERE IT WILL ACTUALLY BE SEEN
```

| ⭐ Deliberately not on the list | |
|---|---|
| Animations | ⭐⭐ A slow transition makes a fast app feel slow. ⭐ 150 ms or none. |
| Dark mode | ⭐ Only if it is one token block (Day 238) |
| A splash screen | ⭐⭐ Nobody has ever been impressed by one |

# Part 3 — The polish pass

```
⭐⭐ RUN THIS AS A DRILL, IN ORDER. TWO HOURS.

⭐   ① ⭐ THE MOUSE-FREE PASS — Tab through everything (Day 239).
⭐   ② ⭐⭐ THE DEVTOOLS-OPEN PASS — walk the demo path with the
⭐      console visible. ⭐ FIX EVERY WARNING.
⭐   ③ ⭐⭐ THE SLOW-3G PASS — throttle, reload, click before it is
⭐      ready. ⭐ Anything that breaks under slow will break in the
⭐      interview, on hotel wifi.
⭐   ④ ⭐⭐ THE OFFLINE PASS — go offline mid-demo. Do you say
⭐      "you appear to be offline", or show nothing?
⭐   ⑤ ⭐ THE FRESH-EYES PASS — a new account with NO data.
⭐      ⭐⭐ THE FIRST-RUN EXPERIENCE IS THE ONE YOU NEVER SEE,
⭐        BECAUSE YOUR DEV ACCOUNT HAS BEEN FULL FOR WEEKS.
⭐   ⑥ ⭐ THE 1280×720 PASS — share your screen and look at it.
```

# Part 4 — ⭐⭐ Demo the failure

```
⭐⭐ THE NINETY SECONDS THAT SEPARATE YOU FROM EVERY OTHER CANDIDATE

⭐   ⭐ EVERYONE DEMOS THE HAPPY PATH. ALMOST NOBODY DEMOS A FAILURE
⭐     ON PURPOSE — ⭐⭐ AND FAILURE HANDLING IS THE ENTIRE SUBJECT
⭐     OF STAGES 10–12.

⭐   THE MOVE, MID-DEMO:
⭐   ① ⭐ "Let me show you what happens when the API is down."
⭐   ② stop Spring, or throttle to offline.
⭐   ③ ⭐⭐ THE UI SHOWS A NAMED ERROR AND A RETRY. NOT A BLANK PAGE.
⭐   ④ bring it back. ⭐ Press Retry. It recovers.
⭐   ⑤ ⭐⭐ "AND THE REQUEST ID IN THAT MESSAGE APPEARS IN THE
⭐      SPRING LOG" — grep it live (Day 273).

⭐   ⇒ ⭐⭐ THAT LAST STEP IS THE ONE THEY REMEMBER, BECAUSE IT
⭐     PROVES THE TWO HALVES ARE ONE SYSTEM.
```

## Today's build

1. ⭐⭐ **Write the seeder.** One hour. Real names, every status, timestamps relative to `now()`, ~2,000 rows in one account, one broken record, a second user with fewer permissions.
2. ⭐ Work the twelve. **Tick them off.**
3. ⭐⭐ Run all six passes. **Write down what each found** — the fresh-eyes and offline passes will surprise you.
4. ⭐ Rehearse the failure demo end to end, including the log grep.
5. ⭐⭐ Record your ninety-second demo on your phone. **Watch it.** Fix the two worst moments.

## 🎙️ Articulation drill

⭐⭐ **Two minutes: "what did you do to make it feel finished?"**

Start with data, because it is the unexpected answer. **The highest-leverage hour was seed data. The
same screen with "Test User 1" ordering "asdf" reads as unfinished, and with Ada Lovelace ordering
noise-cancelling headphones three minutes ago it reads as a working product. Same code. So I seeded
plausible records covering every status, with timestamps relative to now rather than a fixed date,
about two thousand rows in one account so pagination is honest, one deliberately failed payment so I
can demo the error path, and a second user with fewer permissions so I can demo authorization in ten
seconds.**

Then the details, briefly. **About a dozen fifteen-minute things: per-route page titles, a real favicon,
zero console warnings, formatted money and relative dates, no layout shift, a real 404, Enter submitting
and Escape closing. And it works at 1280 by 720, because that's screen-share resolution — which is
where it will actually be seen.**

Then the passes. **I ran the app mouse-free, with DevTools open, on throttled 3G, offline, and — the one
that always surprises me — on a brand new account with no data. The first-run experience is the one you
never see, because your dev account has been full for weeks.**

Close on the demo move. **I deliberately demo a failure. Mid-demo I stop the backend, the UI shows a
named error with a retry rather than a blank page, I bring it back and it recovers — and then I grep
the request id from that error message in the Spring log. Almost nobody demos a failure on purpose, and
that last step is what proves the two halves are one system.**
