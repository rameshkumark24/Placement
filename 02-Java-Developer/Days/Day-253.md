# Part 1 — ⭐ Structure and configuration

## ⭐ Package by feature, from the first commit

```
com.acme.booking/                    ⭐ main class HERE — Day 141's scan-root rule
├── BookingApplication.java
├── booking/          ⭐ controller, service, repository, entity, DTOs — one feature, one package
├── room/
├── user/
├── auth/
├── shared/           ⭐ error handling, correlation filter, clock — imports NO feature package
└── config/           SecurityConfig, JacksonConfig, OpenApiConfig
```

**⭐ Make the services package-private** (Day 141). Spring injects them fine, and the compiler now
enforces your feature boundaries. **Then write the ArchUnit test today, before there is anything to
fix:**

```
⭐ Test 1 — shared/ must not import a feature package
⭐ Test 2 — a feature's internals must not be imported by another feature
⭐ Test 3 — no class in domain/ may import org.springframework
```

**⭐ Adding these on day one costs ten minutes. Adding them in week four means fixing sixty
violations**, and you will not do it.

## ⭐ Configuration — validated, typed, external

```
⭐ One @ConfigurationProperties record per feature, @Validated, with @NotBlank on every secret
⭐ @ConfigurationPropertiesScan on the main class
⭐ Every environment-varying value from the environment (Day 142)
⭐ Profiles change VALUES, never implementations (Day 136)
```

**⭐ The rule that pays off immediately: a missing required property must fail startup**, not the
first customer request (Day 185's item 2). **Test it today** — delete a property, start the app, and
confirm it refuses.

## ⭐ The settings that must be right from commit one

```yaml
spring:
  jpa:
    open-in-view: false                    # ⭐⭐ Day 139 — set it NOW, not after the N+1 hunt
    hibernate.ddl-auto: validate           # ⭐ Flyway owns the schema (Day 157)
    properties.hibernate:
      jdbc.batch_size: 50
      order_inserts: true
      default_batch_fetch_size: 25         # ⭐ Day 160's floor
      query.fail_on_pagination_over_collection_fetch: true   # ⭐ Day 157
  datasource.hikari:
    maximum-pool-size: 10                  # ⭐ Day 156 — small, fleet-wide
    connection-timeout: 3000
    leak-detection-threshold: 20000        # ⭐ on, in every non-production environment
```

**⭐ `open-in-view: false` on day one is the highest-value line here.** Set later, it produces a wave
of `LazyInitializationException`s across a built application. Set now, each one appears as you write
the endpoint that causes it — **which is exactly when it is cheapest to fix properly** (Day 160).

# Part 2 — ⭐ Flyway and Testcontainers, together

## Run the migration

```bash
./mvnw flyway:migrate       # ⭐ Day 250's V1, finally applied
```

**⭐ Then immediately verify `ddl-auto: validate` passes** once entities exist — that is the check
that entities and schema agree, at startup, forever (Day 157).

**⭐ And put the habit in place now:**

```sql
set lock_timeout = '3s';          -- ⭐ the first line of EVERY migration (Day 196)
```

## ⭐ Testcontainers from the first test

```
⭐ An abstract IntegrationTestBase with a STATIC PostgreSQL container + @ServiceConnection
⭐ Every integration test extends it → ⭐ ONE Spring context for the whole suite (Day 183)
```

**⭐ Two reasons to do this today rather than later:**

1. ⭐ **Migrations are tested from empty on every run** (Day 184) — a broken migration fails CI
   instead of a deploy.
2. ⭐ **The shared base class is what keeps the suite fast.** Retrofitting it means every test class
   already has its own configuration and its own several-second context (Day 183's cache).

⭐ **Never H2.** Your hard problem is probably an exclusion constraint or `SKIP LOCKED`, and Day 184's
whole argument is that H2 cannot express either — **so a green suite would prove nothing about the
one thing that matters most.**

# Part 3 — ⭐ CI, and what it must enforce from day one

```
⭐ On every push:
   1. build
   2. ⭐ unit + integration tests (Testcontainers)
   3. ⭐ ArchUnit rules
   4. ⭐ OpenAPI generate + diff against docs/openapi.yaml   (Day 251)
   5. ⭐ dependency scan — OWASP or Trivy                     (Day 100A, Day 185 item 38)
   6. ⭐ secret scan — gitleaks                               (Day 085)
   7. build the container image
```

**⭐ Steps 4, 5 and 6 are the ones people add too late and each has a specific payoff:**

- ⭐ **Step 4** turns a breaking API change into a red diff at review time rather than a client
  outage — Day 153's resolution.
- ⭐ **Step 5** catches the most common real-world compromise class: a known CVE in a dependency you
  did not upgrade.
- ⭐ **Step 6** stops a committed secret before it is in the history forever, where Day 085's rule is
  that the fix is rotation, not a delete commit.

**⭐ Add them now while the pipeline takes 40 seconds and there is nothing to fix.**

## ⭐ The container image — layered, from the start

```
⭐ Layered extraction (Day 144) — a code change pushes a megabyte, not sixty
⭐ JRE base, non-root user
⭐ MaxRAMPercentage=75, ExitOnOutOfMemoryError, HeapDumpOnOutOfMemoryError to a volume
```

# Part 4 — ⭐ Deploy it, and see it working

**⭐ Today's most important outcome: the application is running somewhere that is not your laptop.**

| Component | Today |
|---|---|
| ⭐ **The application** | ⭐ deployed, reachable, with a real database |
| ⭐ **Health** | ⭐ liveness and readiness **split**, dependencies only in readiness (Day 143) |
| ⭐ **Startup probe** | ⭐ configured — a JVM takes 30–60 s (Day 143) |
| ⭐ **Metrics** | Prometheus endpoint, ⭐ **common tags added now** (Day 143) |
| ⭐ **Logs** | ⭐ structured JSON to stdout, correlation ID filter with `MDC.clear()` in `finally` |
| ⭐ **`build-info`** | ⭐ so the deployed commit is one curl away |

**⭐ Common tags on day one is worth calling out** (Day 143): adding them later invalidates every
dashboard and alert built before. It is one bean and it is permanent.

**⭐ And do the two proofs today, while it is trivial:**

```
⭐ 1. Stop the database. Confirm readiness goes down and liveness does NOT.
       (Day 128's outage, prevented — verify rather than assume.)
⭐ 2. Delete a required config property. Confirm the app refuses to start.
```

## ⭐ Traps

| Trap | Consequence |
|---|---|
| ⭐ Layer-first packaging | every feature change is a four-package diff (Day 096) |
| Main class in a sub-package | half your beans unscanned, with a confusing error |
| ⭐ `open-in-view: true` | ⭐ N+1s invisible until the end, then a wave of failures |
| `ddl-auto: update` | unreviewable drift (Day 157) |
| ⭐ H2 in tests | your hard problem is untestable (Day 184) |
| Non-static containers | suite time explodes (Day 184) |
| ⭐ No shared test base class | many contexts, minutes of startup (Day 183) |
| ⭐ CI added "once there is something to test" | it never gets added |
| ⭐ No secret scanning | a committed key must be rotated, not deleted |
| Deploying at the end | Day 185's checklist arrives all at once |
| ⭐ Dependency checks in liveness | ⭐ a database outage crash-loops every pod (Day 128) |
| No common metric tags | dashboards rebuilt later |
